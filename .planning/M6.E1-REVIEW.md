### I-1 — `detectP6LegacyMarketplaceSource` promised it never throws, and threw

`plugin/tools/lib/doctor.js` — the function's own comment read *"This never throws, and it
distinguishes three outcomes."* `join(homeDir, …)` sat **outside** the try, so `undefined` or `null`
raised a `TypeError` before any handler. Verified by probing the claim rather than reading it:

```
homeDir=undefined → TypeError: The "path" argument must be of type string
homeDir=null      → TypeError
homeDir=''        → cannotDetermine (correct)
```

**The test named `never throws — the whole detector is fail-open` passed throughout**, because it
supplied a valid `homeDir`. A test whose *name* is broader than its *coverage* is this repository's
recurring shape, and it appeared here in the guard written to be fail-open.

Not reachable through `runAllDetectors` today — `readInstallState` demands `homeDir` first — **which
is precisely why it would have survived**. The next caller is the one that would find it.

**Fix:** a typed guard returning `cannotDetermine`, +9 lines. **Coverage:** a new test over
`[undefined, null, '', 0]`. **Mutation-verified:** removing the guard reddens it.

### I-2 — `AC3.7` claimed the vendored copy was "provable" and nothing in the repo proved it

The only way to check `plugin/node_modules/yaml/` was really `yaml@2.8.3` was to diff it against your
own `npm install` — **which requires already trusting your own install.** This Epic *created* a
supply-chain surface, and `NFR2` ("supply integrity") is about the catalog carrying no `ref`/`sha`;
it does not reach a vendored dependency at all.

**Fix:** a Provenance block in `LICENSES.md` — `npm pack` command, tarball size, file count, **SHA-256
`9539805d…`**, extraction command, and an explicit *"Modifications: none"* — plus the audit results
in § Security. +25 lines of documentation. **Coverage:** a test scoped to that block asserting a
64-hex checksum is present and that **every** version the block names equals the vendored
`package.json`'s.

**This fix's own test was wrong twice, and the second failure is the finding.** The first version
asserted `yaml@{version}` appeared anywhere in `LICENSES.md` — it **passed** a mutation setting the
table row to `2.8.2`, because the *"Package: yaml@2.8.3"* heading two paragraphs above satisfied it.
Scoped to the Provenance block, it **still** passed the same mutation: the block names the version
**twice** (the table row and the re-verify sentence), and `toContain` was satisfied by the second
while the first was wrong. It now asserts every named version is the same one. **Two mutations were
needed to find that, and the first mutation passing is what exposed it** — a token matched in the
wrong place is not evidence about the right one, which is the defect `M5.E10`'s denominator work
exists for, reproduced inside a fix written during the same Epic.

## Suggestions (optional improvements)

- **S-1 — 456 KB of `browser/` ships and Node never loads it.** The `exports` map routes the `node`
  condition to `dist/`. Deliberate: `AC3.7` requires the package **as published**, and a trimmed copy
  whose manifest points at absent files is a worse defect than 456 KB. Recorded as accepted, not
  overlooked.
- **S-2 — `bin.mjs` (4 KB) ships and is never invoked.** Same reasoning as S-1.
- **S-3 — the one-package assertion exists in two test files.** `plugin-dependency.test.js` derives it
  from `readdirSync` (the working tree); `plugin-boundary.test.js` derives it from `git ls-files`
  (what is tracked, therefore what ships). **Not duplication — the two answer different questions**,
  and an untracked package would pass the first and fail the second. Left as is.

## Security Findings

`security_audit: full`. Most of OWASP is **N/A by shape** and is recorded rather than skipped: this
Epic ships no service, opens no port, accepts no request, has no authentication, session, database,
or user input surface. What it *does* have is a new **supply-chain** surface and one new **filesystem
read**, and those are what was audited.

| Area | Result |
|---|---|
| Vendored dependency — transitive deps | **PASS** — `dependencies: {}` and `peerDependencies: {}`; nothing else can be pulled in |
| Vendored dependency — network reach | **PASS** — no `http`/`https`/`net`/`dgram`/`child_process` import and no `fetch` anywhere in `dist/` or `browser/` |
| Vendored dependency — dynamic execution | **PASS** — no `eval`, no `Function` constructor |
| Vendored dependency — install-time execution | **PASS** — its `package.json` carries `prepublishOnly`/`preversion`, which are the **author's** publish scripts and never run for a consumer; and they cannot run here regardless, because the plugin root has no `package.json` or lockfile so nothing ever installs in it |
| Vendored dependency — provenance | **FIXED IN-PHASE (I-2)** — SHA-256 and obtain/extract commands now recorded |
| New filesystem read | **PASS** — `known_marketplaces.json` is read-only, never written; its evidence output carries a marketplace name and a repo slug, no paths outside the finding, no tokens, no secrets |
| Secrets in the delivered payload | **PASS** — the install measurement confirmed no `.env`, no `settings.local.json`, no key material; `plugin/` carries no credential-shaped file |
| Published catalog transport | **PASS** — HTTPS, domain we control, no `ref`/`sha` to pin to a compromised commit (`NFR2`) |
| Install page | **PASS** — static HTML, no script added, no external resource, no form |

**What this audit did NOT do, stated so the PASS is not read as more than it is:** I did **not** read
18,739 lines of `yaml`'s implementation. The package was audited by **declared dependencies,
capability grep, and checksum**, which is a reasonable standard for a widely-used ISC package with no
dependencies — and it is **not** a code audit. A malicious change hidden inside YAML parsing logic
would pass every check above. The checksum proves the copy matches **what npm published**; it proves
nothing about whether what npm published is trustworthy.

## Simplification Opportunities

- **No dead code introduced.** `eslint --rule no-unused-vars` clean on `doctor.js`; lint clean
  repo-wide.
- **No redundant abstraction.** The detector follows the existing `detectPn(fsImpl, homeDir)` shape
  exactly; `runAllDetectors` gained two fields rather than a second code path.
- **Naming holds.** `checked_all` / `undetermined` say what they hold. `cannotDetermine` matches the
  vocabulary `/sig:archive` already established for the same three-outcome idea.
- **S-3 above** is the only apparent duplication, and it is deliberate.

The genuine simplification this Epic made is structural rather than local: **`validate-plugin.js`'s
`REQUIRED_FILES` had silently mixed payload artifacts with repository artifacts**, and pointing
`ROOT` at the plugin is what made the mixture visible (S2). That is now two explicit lists.
