# M6.E13 — Work items as records (Epic 1 of the storage re-architecture)

**Brett, 2026-10-03:** *"we keep doing tiny fixes that don't hold up as long-term, bulletproof
architecture."* Design: [`analysis/STORAGE-ARCHITECTURE-PROPOSAL.md`](../analysis/STORAGE-ARCHITECTURE-PROPOSAL.md).
Decisions: `D-M6E13-1` … `D-M6E13-20` in [`DECISIONS.md`](DECISIONS.md).

## Measured, before designing anything

- 107 of 265 work items are storage or lifecycle defects; 36 closed fixes were followed by a new
  defect in the same function, field or regex (10 chains). Two of those chains got another patch the
  same day this was written (`v0.1.46`, `v0.1.47`).
- **24 code readers** parse a generated list instead of the items; **13 commands** tell the agent to
  read or edit the lists; **~30 test files** pin the current store shape (folder = status, generated
  shape, `B{n}` IDs).
- **268 item files today:** 7 inbox, 107 backlog, 153 done, 1 archived with `M6.E11`. 142 closes carry
  `proof: legacy — not re-verified`. **9 closed items** still say *confirmed*/*needs-triage* in their
  body (SIG-118, 121, 122, 123, 127, 131, 135, 137, 140), and 5 triaged ones say *needs-triage*
  (SIG-129, 130, 133, 134, 139).
- `inboxHasDrainableEntries` (`drive.js`) and `checkStaleInbox` (`sweep.js`) have **no store branch**:
  on this repository they read the generated inbox. `/sig:advise`'s `covers` contract requires
  `.planning/BACKLOG.md:LINE` — line numbers of a generated file.
- 10,000 generated records: read and fold every status ~0.2 s; `git status` 0.06 s; repo 2.6 MB.

## The design

One JSON record per work item at a fixed path; status derived from events inside it; prose in a
sibling `.md` that no code reads for facts; generated views that no code reads at all; one library is
the only writer, and a hook blocks direct edits. Projects without the store keep today's behaviour
exactly.

## Functional requirements

### FR1 — The record format (`D-M6E13-1`, `-2`, `-4`, `-5`)
- **AC1.1** A record lives at `.planning/work/items/NN/SIG-n.json` with `NN` = `floor(n/1000)`,
  two digits; an optional prose body at `SIG-n.md` beside it. No code path moves a record.
- **AC1.2** Serialisation is deterministic: fixed key order, 2-space indent, trailing newline; parse →
  serialise is byte-identical for every record.
- **AC1.3** A record has no stored status. `deriveStatus(record)` returns N/T/Q/P/C or *closing*, from
  the event list alone; every legal event sequence and every illegal one is covered by tests (illegal
  sequences are rejected at write and reported by the store check).
- **AC1.4** Events: `created`, `triaged`, `queued`, `started`, `close_requested`, `closed`, `reopened`,
  and `edited` (added at PLAN, `D-M6E13-19`);
  each carries `at` and `by`. A `closed` event carries `reason` (fixed/stale/wontdo/dup/rejected), and
  `proof` unless `legacy: true`; `dup` requires `dup_of`.
- **AC1.5** Epic membership is derived from events only (no stored field, `D-M6E13-19`); `closeEpic`'s all-closed check is a
  query over records, not a folder listing.
- **AC1.6** A JSON Schema file for the record ships in the plugin and validates every record; unknown
  keys are errors.

### FR2 — The write library (`D-M6E13-6`, `-7`)
- **AC2.1** Every mutation (new, triage, queue, start, close-request, close, reopen, edit fields) goes
  through one module, under the one `work` lock, writes atomically, appends an event and regenerates the
  views. No nested lock.
- **AC2.2** **Enforced:** a write-path inventory test enumerates every exported function that writes a
  record and fails if one does not append an event, unless it is on a reviewed exemption list.
- **AC2.3** ID allocation takes the highest number across the new paths, the old v1 paths and git
  history; a reused number fails the duplicate-ID test.
- **AC2.4** Secret scrubbing on title and body is preserved exactly as today.

### FR3 — Every store-on reader on the library (`D-M6E13-8`, `-16`)
- **AC3.1** Each reader in the DISCUSS inventory reads records through the library when the store is
  on: advise (corpus, digest, priorities), drive (Epic candidates, inbox drain stop, preflight),
  status/resume open questions, sweep (backlog discharge, stale inbox, dangling references),
  published-facts (bug tally, bug-vs-changelog), the Jev bug check, backlog discharge status, inbox
  capture/promotion.
- **AC3.2** **Enforced:** a test fails if any store-on code path imports or calls a Markdown list
  parser (`parseBacklogRows`, `walkBugEntries`, `readRowDischarge`, drain entry parsers, open-question
  parsers, `B\d+` table regexes).
  *Enforcement scope (PLAN Decision 12, 2026-10-04):* runtime, every call to a relocated parser
  throws under a test flag and every AC3.1 reader runs under it on a store-on fixture; static, no v2
  module reaches the parsers; source-text, no list-parsing regex literal in reader modules outside the
  parser module. A parser nobody relocated, on an unexercised path, is the residue.
- **AC3.3** `/sig:advise`'s `covers` cites item IDs (`SIG-n`); validation resolves each against the
  store. Store-off projects keep `BACKLOG.md:LINE` citations.
- **AC3.4** The commands that instruct reading or editing the lists say, for store-on projects, to use
  `/sig:item` and the library.

### FR4 — Projects without the store are unchanged (`D-M6E13-9`)
- **AC4.1** With no `WORK.md`, every command and library function behaves byte-identically to
  `v0.1.47`, pinned by the existing store-off tests plus a fixture run of each converted reader.
- **AC4.2** A v1 store (Markdown items, `schema_version: 1`) found by v2 code refuses writes with a
  message naming the migration tool, and reads nothing silently wrong.

### FR5 — The guard (`D-M6E13-10`)
- **AC5.1** The `PreToolUse` hook (matcher `Edit|Write|MultiEdit`) blocks, with exit 2 and a message
  naming `/sig:item`, any edit to `.planning/work/items/**/*.json` and to the generated views; body
  `.md` files are allowed. Fail-open on a malformed event, as today.
- **AC5.2** A validation test over the live repository fails on any invalid record, any record whose
  events do not fold, and any view that does not match a regeneration.

### FR6 — Generated views (`D-M6E13-11`)
- **AC6.1** `BUGS.md`, `BACKLOG.md`, `ISSUES-INBOX.md`, `OPEN-QUESTIONS.md` and `work/EPICS.md` are
  regenerated from records on every write, committed, carry the generated marker, and show `SIG-n` IDs
  only (no `B{n}`).
- **AC6.2** Views list open and *closing* items, plus closes from the last 30 days (counted back from
  the newest event in the store, `D-M6E13-19`); older closes are
  reachable from per-year history views.

### FR7 — Close-requested → closed (`D-M6E13-15`)
- **AC7.1** `/sig:item close` with a commit proof records `close_requested`; the item reads *closing*.
- **AC7.2** `confirmCloses()` appends `closed` for each *closing* item whose proof commit is an
  ancestor of `origin/main`; run at `/sig:resume`, at SHIP and in the sweep. No remote, offline or an
  unknown commit leaves it *closing* (fail-open, never guessed).
- **AC7.3** advise and drive treat *closing* as done: never proposed as new work.

### FR8 — Migrating Signal's own store (`D-M6E13-12`, `-13`, `-14`)
- **AC8.1** The migration builds the v2 store in a separate directory, then verifies a manifest: every
  v1 item → exactly one record; every field mapped or listed as dropped (the body status/priority/ID
  cells only); every body preserved; every close and reopen → events in order.
- **AC8.2** The 142 legacy closes, plus SIG-123/142/161 (145, `D-M6E13-20`), keep their reason and carry `legacy: true`; a `legacy` close is never
  accepted as proof by any check.
- **AC8.3** Bodies lose the pasted table row's status, priority and ID cells and keep the rest as
  prose; the 14 contradictions above are gone, verified by test.
- **AC8.4** Cutover is one commit; the v1 files are relocated (never deleted) under
  `archive/pre-work-store-v2/`. **`/sig:drive` halts before it** for Brett's go-ahead.
- **AC8.5** After cutover the suite, `checkStore` and the live validation test (AC5.2) pass on this
  repository.

## Non-functional requirements (FULL prompt, answered)

- Health probe, graceful shutdown, request logging, security headers, rate limiting: **N/A**, because
  this is a local CLI plugin with no server. The one remote touch is `confirmCloses` reading
  `origin/main`, which uses local refs and is fail-open.
- **Performance:** listing and folding all records stays under 1 s at 10,000 records (measured
  ~0.2 s).
- **Integrity:** atomic writes, one lock, deterministic serialisation; a broken record is reported by
  ID and does not stop every other record being read.
- **Security:** the M6.E12 rules carry over: records and bodies are read only as regular, non-linked
  files inside the project. Secret scrubbing is unchanged.

## Blast radius

What this touches and does not change:
- **Code:** `plugin/tools/lib` work-* modules (rewritten); the 24 readers (FR3); `check-state-write.js`
  and `hooks.json`; 13 commands; about 30 store-shape tests rewritten.
- **Docs:** the generated lists that `CLAUDE.md` and the docs map link to stay at the same paths.
- **Bookkeeping:** command edits move the directive ceiling, so `ADHERENCE-LOG.md` is regenerated and
  the merge uses `--merge`.
- **Users tracking `main`:** no project but Signal has a store, so their behaviour must not change
  (FR4).
- **Not touched:** STATE.md, Epic artifacts, `deriveUnits`, closure, decisions, milestones.

## Outcome

- **Leading:** after ship, zero store-on code paths parse a Markdown list, enforced by AC3.2.
- **Lagging:** no new storage-class defect is filed against a store-on path in the 30 days after ship.
  Baseline: 41 open storage items and 36 fix-didn't-hold chains before this Epic. One such defect means
  the read path still has a leak, and it is traced before the next stage starts.

## Out of scope, stated so it is a decision

- Epics and units as records; typed verdicts on VERIFICATION and REVIEW; the `STATE.md` split;
  decisions, requirements and retrospectives as records; migrating other projects (`/sig:docs-migrate`).
  These are later Epics, in that order.
- A query cache (`node:sqlite`): not needed at this size (measured).
- `B255` (keep-live holds): becomes a field when units are records.
