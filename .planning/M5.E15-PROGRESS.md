### What the wave found that the plan did not predict

**1. `buildCaveats` could not be tested where it lived, and the plan's RED-first
requirement could not be met in place.** S1.t4 said to migrate `adherence-run.js:666-668`.
But `buildCaveats` sat in a CLI script that exports nothing, and
`tests/adherence-suite-guard.test.js` forbids *any* test file from importing that script —
a deliberate, load-bearing guard, because importing the runner is how a test suite ends up
spawning the paid agent CLI.

Exporting it (the obvious route) turned that guard red. Weakening the guard was rejected
outright. The function was extracted to `tools/lib/adherence-caveats.js` — it is pure string
work over declared data, no agent, no filesystem, no network — and tested there.

This mattered more than a placement detail: `buildCaveats` branched on the very field this
Epic replaces. Left in place, the rename would have made the branch permanently false and
the *"a whole section was removed"* caveat would have silently stopped rendering, **with no
test going red**. That is the `B39` shape reached through a field rename rather than a
missing detector.

**2. S1.t7's scrub had to cover code written during S1 itself.** The task named
`adherence-verdict.js:117` as the apparatus's verbatim copy of the measured instruction.
Writing the AC1.5 doc comment introduced **two new** mentions of the same token in the same
file. Both were scrubbed. The lesson is small and worth recording: a leak-by-comment is
introduced by ordinary careful documentation, which is why S3's walk exists rather than a
one-time cleanup.

**3. AC1.5 needed a mechanical criterion the requirements did not supply.** "A section
anchor that is not its own discrete section" was specified by example, not by rule. The
criterion implemented: *the deleted span must not order any other backticked call.*
Verified against the live corpus before being written into a test — the four `## Phase entry`
sections order only the measured call; `ship.md`'s `### 5. Update State` also orders
`completePhase`, which is precisely why `D-M5E15-8` declares that site by line.

### A defect found by reading the published record against its own requirement

**The record shipped without its descriptive-residue list, which AC6.2 requires.** The
runner read `descriptiveResidue` off the arm **summary** (`summarizeArm`'s return) instead
of the arm **result** — two variables one character apart in the same scope. It resolved to
`undefined`, fell back to `[]`, and the caveat silently did not render.

Every unit test was green, because they handed residue to `buildCaveats` directly and never
exercised the wiring. This is the *same shape* as the `buildCaveats` finding in wave 1 —
tested function, untested wiring — reached by a different route, in code written to fix that
very class. Recorded plainly rather than smoothed: the Epic that exists to make the control
arm honest published a record that understated its own scope.

Fixed three ways: the confusable names are gone (`t`/`c` → `treatmentSummary`/
`controlSummary`, since confusable names were the cause), the sidecar persists the field so
`--combine` cannot drop it by the other route, and the wiring is pinned by a source-reading
test — the technique `guard-callers.test.js` already uses, since the suite guard forbids
importing the runner.

**No re-run.** The measurement is sound and the omission is disclosure-only, so per the
log's append-only rule a `QUALIFIED` annotation now carries the missing list: 14 mentions
across 6 files, recomputed offline by rebuilding the copied tree and re-applying the same
five deletions. That recomputation is also what confirms the verdict — **zero directive
hits**. Spending eight more agent calls to reprint a list that can be derived deterministically
would have been theatre.
