## What EXECUTE found that VERIFY has to calibrate

**The command was run end-to-end on this repository**, which is the check `/sig:drive` is still
missing and the reason it is the gate on further loop work. It read 50 live rows, recommended 5,
declined 45, resolved 51 citations, and wrote exactly one file:
[`BACKLOG-REVIEW-2026-09-05.md`](BACKLOG-REVIEW-2026-09-05.md). That artifact is kept as the run
record rather than deleted.

⚠ **Two of the five recommendations are not actionable work — and the first cause I wrote for that
was wrong.**

**Correction, recorded rather than edited away.** The commit that closed S3 attributed both bad
picks to corpus shape: *"`parseBacklogRows` treats any non-container heading as a row, and this
backlog carries prose sections at row depth."* That was written from the shape of the problem, not
from the run. **Printing the ranking inputs contradicted it.** This is the
[`CLAIM-INTEGRITY-ANALYSIS.md`](../analysis/CLAIM-INTEGRITY-ANALYSIS.md) class — a claim asserted from
plausibility instead of derived from the artifact — committed in the write-up of an Epic whose entire
subject is claims that resolve.

**What the run actually shows.** All four of the top rows scored `triggerMet = true`, and the input
that promoted them is `TRIGGER_MET_RE`, which matches over a row's heading **and its whole body**:

| # | row | what matched |
|---|---|---|
| 1 | Since the re-audit — what `M5.E7` changed (2026-07-26) | `trigger has therefore read **satisfied` — prose describing a *past* state |
| 2 | Add a "first use" step to `/sig:plan` | genuine |
| 3 | Trajectory scoring — **UNPARKED 2026-08-10** | `trigger fired` — genuine |
| 4 | Parked — the trigger watchlist *(not sprint material)* | `Trigger:* first live external tester — **FIRED` — a trigger belonging to **a different item**, listed inside a watchlist |
| 5 | Map drift-guard · hygiene · small | ranked on age alone |

So the cause is **that the heuristic cannot tell a row's own trigger from one it merely mentions**,
not that the row is not a row. Measured: **6 of 50 live rows match `TRIGGER_MET_RE`, and 2 of those 6
are false positives.** Row 4 is the sharper case — a row whose heading says *"not sprint material"*
was promoted into the top four **by the ranking**, using a trigger belonging to something else.

Corpus shape is a real, separate observation — row 1 is a dated historical note, not work — but it is
the second-order problem, and it is not what put either row where it landed.

**Both heuristics now carry a reach declaration** in `advise.js` (`B81`'s form), stating what they
match, what they cannot distinguish, and the measured false-positive rate.

**Not fixed here, deliberately.** `t3.1` enumerates four ranking inputs; narrowing `TRIGGER_MET_RE`
changes what the command recommends, which is a design change and not an implementation detail.
Doing it silently is what this phase's own anti-rationalization table forbids: *"The plan says X but
I think Y is better — update the plan first. Don't silently diverge."*

`M6.E7-REQUIREMENTS.md` pre-committed to reporting a low calibration score honestly rather than
rationalising it. **This is that report, written from the run** — 3 of 5 recommendations were real,
2 were not. Three options were put to Brett; option 2 was chosen. Resolution below.

The three options as put:

1. **Narrow the trigger heuristic** — scope it to the row's own declaration (a leading `**Trigger:**`
   in the row's first paragraph) rather than any mention anywhere in the body. Needs a plan update.
2. **Use the row vocabulary that already exists.** `backlog.js` has `HELD_OPEN_RE` for exactly this
   — a row declaring in its heading that it is not live work. `"Parked"` and `"not sprint material"`
   are the same declaration in different words. Cheapest, and it puts the fix in the shared reader
   rather than in the advisor.
3. **Accept it and say so** in the artifact — the advisory already carries a Citation rule stating
   what the check does not do; a ranking-reach note would be the same discipline one level up.

## RESOLVED — ranking input 5, and the third time measuring changed the answer

**Brett chose the `HELD_OPEN_RE` mechanism** (option 2). The plan was amended **before** the fix was
written — `t3.1` now specifies five ranking inputs, with the measurement and the reason inline —
because this phase's own anti-rationalization table says so.

⚠ **I told Brett this option would fix one of the two rows. Measuring the vocabulary showed it fixes
both.** The claim came from `HELD_OPEN_RE`'s literal contents (`STILL|KEPT|HELD OPEN`), not from the
corpus. Scanning the 50 live headings found `reconciliation` ×2 — which is what the **#1**
recommendation was — alongside `parked` ×2. So the mechanism reached the historical note as well.
**That is the third time in this Epic that measuring contradicted something I had already
written**, in the Epic about claims that resolve. Recorded as a pattern, not three separate slips.

**What shipped.** `declaresNotLiveWork(headingText)` exported from `backlog.js` — the module that
owns backlog row vocabulary — returning `{notLive, kind, declaration}`.

- **It reads the HEADING, never the body.** That is the fix for the class rather than the instance:
  input 2's whole-body read is what let a watchlist row be promoted by a trigger belonging to
  something else. A self-declaration belongs where a reader sees it, which is the rule
  `readRowDischarge` already follows.
- **Vocabulary measured before it was chosen:** `parked` ×2, `not sprint material` ×1,
  `reconciliation` ×2, plus the existing `(STILL|KEPT|HELD) OPEN` — which matches **zero** rows here
  and is currently inert. All four matching rows read individually: zero false positives. `shelved`
  included by analogy at **zero** live instances, declared rather than implied.
- ⚠ **`deferred` deliberately excluded** — it occurs in live-work prose (*"deferred from E2"*), so
  including it would trade two known false positives for an unknown number of false negatives.
- ⚠ **`HELD_OPEN_RE` was NOT widened**, and a test pins that. `backlogDischargeStatus` reads it to
  mean *"declared open on purpose, do not flag as stale"*; widening it changes a shipped check as a
  side effect. Same refusal as `t2.5`'s, for the same reason. The new predicate subsumes its meaning
  for a new caller without touching its use.
