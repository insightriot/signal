## R0 — Method deviation, recorded rather than silently taken

`PROFILE.md` sets `research_parallelism: 4`, and `commands/plan.md` Step 2 specifies four
parallel research agents (domain, codebase, risk, prior art). **This PLAN ran zero research
agents and read the artifacts directly.** Two reasons, and one cost:

1. **The session's operating rules forbid unrequested subagent dispatch.** That is a
   harness-level constraint above the PROFILE.
2. **Subagent summaries are the mechanism this Epic exists to distrust.** A research agent
   returns a description of code it read; the plan is then written from the description.
   That is `analysis/CLAIM-INTEGRITY-ANALYSIS.md`'s named defect — *completeness claims
   written from the shape of the work rather than from the artifact* — and it is what
   M5.E8's retro did when it proposed a mechanism covering one of its own three instances
   (D-M5E13-3). For an Epic whose entire subject is guards that were believed to work,
   first-hand reads are the higher-rigor choice, not the cheaper one.

**The cost, stated plainly:** external/prior-art research did not happen. Nothing in this
Epic's scope is externally-facing (no new dependency, protocol, or API), so the loss is
assessed as low — but it is a loss, not a wash, and REVIEW should treat R0 as an auditable
deviation rather than a footnote.

## R1 — `checkGateArtifacts` is a **fourth** instance of the never-called-guard class

**This is the finding that reshapes FR1.2.** D-M5E13-3 enumerated three instances (`B39`,
`B46`, `I2`). There is a fourth, and it lives in the same file FR1.2 proposes to edit.

`tools/lib/state.js:616` exports `checkGateArtifacts(baseDir, targetPhase)` — an
artifact-existence checker for phase gates. Measured facts:

**(a) Nothing calls it.** Exhaustive grep across `*.md`, `*.js`, `*.json` (excluding
`node_modules/`, `.git/`) returns five hits:

| Location | Kind |
|---|---|
| `tools/lib/state.js:616` | the definition |
| `tests/state.test.js:6,169,172,187` | tests |
| `.planning/CONTEXT.md:170` | doc listing it as part of `state.js`'s API |
| `.planning/STATE-HISTORY.md:222,282` | history describing a fix applied to it |
| `.planning/archive/milestones/MILESTONE-3.md:79` | same fix, archived |

No command file, no hook, no tool invokes it. The two prose hits are the class's signature:
documentation describing a guard as part of the flow while nothing runs it.

**(b) It is not merely inert — it is wrong if called.** Run against this project, now:

```
checkGateArtifacts(signal, 'PLAN')  →  {ready: false, missing: ['REQUIREMENTS.md']}
```

Its `PLAN` list is the hardcoded, unprefixed `['PROJECT.md','CONTEXT.md','REQUIREMENTS.md']`.
Epic mode writes `M5.E13-REQUIREMENTS.md`; there is no bare `REQUIREMENTS.md` on disk. **Wiring
it up as-is would block PLAN on Signal itself.** This is the same false-seam defect FR1.2's own
revision warns about — an existence check keyed to a name that depends on mode.

**(c) Four of its five gates check nothing.** `EXECUTE`/`VERIFY`/`REVIEW`/`SHIP` are empty
arrays behind the comment `// Dynamically checked based on phase number` — dynamics never
implemented. All four return `{ready: true, missing: []}` unconditionally.

**Why it stayed invisible:** its wrongness is only observable when something calls it, and
nothing does. The guard's inertness is what protected its bug from discovery. That is a
sharper form of the class than `B39`/`B46`/`I2`, all of which are merely absent.

**Instance count after this finding: four** — `B39`, `B46`, `I2`, `checkGateArtifacts`.
(Counted from the enumeration above, not carried forward from prose.)

## R2 — FR1.2 placement: the evidence that settles Open Question #1

Open Question #1 asks whether the refusal belongs in `recordPhase` or `transitionPhase`.

- `recordPhase` (`state.js:403`) is **module-private**, not exported.
- Both writers funnel through it: `transitionPhase` → `recordPhase` (`state.js:466`);
  `completePhase` → `recordPhase` (`state.js:574`).

So placement in `recordPhase` means `completePhase` inherits the guard. **That inheritance is
the problem, not the benefit.** `completePhase` exists (M5.E9 FR2, `B43`) for exactly one
purpose: to record **SHIP**, which is terminal and which `transitionPhase` can never record.
And SHIP's artifact is optional by design — `/sig:resume`'s own artifact table reads
*"`{phase}-SHIP.md` (if present) **or** pre-ship checklist from STATE.md."*

A guard in `recordPhase` therefore refuses `completePhase('SHIP')` on any project that never
wrote a `SHIP.md` — which is the normal case. That is a direct AC1.3 collision ("a legitimately
artifact-less phase is not blocked").

**Recommended placement: `transitionPhase`,** with SHIP's exemption then structural rather than
special-cased. AC1.3's enumeration must still be written explicitly — the exemption list is the
deliverable, not an assumption.

## R3 — `B53` reproduced live (FR1.5)

The two seams, measured:

| `current_epic` | artifact | `artifactName` writes | `resolveArtifactPath` pattern 0 tries |
|---|---|---|---|
| `M5.E13` | PLAN | `M5.E13-PLAN.md` | `M5.E13-PLAN.md` ✅ agree |
| `PHASE11` | PLAN | `1-PLAN.md` | `PHASE11-PLAN.md` ❌ **diverge** |
| `PHASE11` | REQUIREMENTS | `REQUIREMENTS.md` | `PHASE11-REQUIREMENTS.md` ❌ **diverge** |
| `v0.1.6` | PLAN | `1-PLAN.md` | `v0.1.6-PLAN.md` ❌ **diverge** |

Root cause is two regexes with different strictness:

- `resume.js:30` — `EPIC_ID_RE = /^[A-Za-z0-9._-]+$/` (lenient; gates `resolveArtifactPath`
  pattern 0, which is tried **first**)
- `state.js:109` — `EPIC_ID_STRICT_RE = /^M\d+(\.\d+)*\.E\d+$/` (strict; gates `artifactName`)

`references/epic-native-flow.md:31` states the guarantee *"whatever `artifactName` emits,
`resolveArtifactPath` with the same opts resolves back."* False for every non-strict value.

Note the second divergence axis, which the requirements do not mention: `LINEAR_UNPREFIXED`
(`resume.js`) makes REQUIREMENTS unprefixed in linear mode, so REQUIREMENTS diverges on a
different rule than PLAN does. A fix must cover both.

## R7 — FR4: `checkVersionConsistency`'s covered set is not in one place

`tools/lib/doc-hygiene.js:286–306`. The covered files are expressed as **three separate reader
functions plus three separate `push` lines**:

```js
const plugin    = readPluginVersion(baseDir);          // .claude-plugin/plugin.json
const market    = readMarketplaceRef(baseDir);         // .claude-plugin/marketplace.json
const changelog = readLatestChangelogVersion(baseDir); // CHANGELOG.md
```

`package.json` is absent — that is all of `B49`'s remainder. Two further facts AC4.2 should
account for:

- **The reference file is positional.** `found[0]` becomes the comparison baseline, so if
  `plugin.json` were unreadable the baseline would silently become `marketplace.json`.
- **It fails open:** `if (found.length < 2) return findings` — fewer than two readable version
  files reports nothing.

AC4.2 ("the set is enumerated in one place, so a fourth file is an edit not a rediscovery")
therefore requires an actual refactor to a single table — it is not satisfied by adding a
fourth reader alongside the other three.

Callers are real: `doc-hygiene.js:393` and `sweep.js:347`. This guard is **not** an instance of
the class — it runs, and it fired correctly on `marketplace.json` during v0.1.13's cut. Only its
scope is short.

## R8 — `B51` is doubly stale (FR1.4)

The requirements cite `commands/discuss.md:158-161`. **Measured: the block is at ~157–166**, and
it is worse than described — it instructs the agent to write the **pre-`schema_version: 1`
markdown-heading format**, not YAML frontmatter:

```markdown
## Current Phase
PLAN

## Completed Phases
- CALIBRATE ({date})
- DISCUSS ({current_date})
```

So the stale instruction is wrong on two axes: the **convention** (M5.E9 moved the transition
to the incoming command) and the **file format** (schema v1 uses frontmatter; these headings
have no meaning to `parseFrontmatter`). An agent obeying it literally appends dead markdown to
STATE.md's body rather than corrupting the ledger — a different and somewhat milder failure
than `B51` describes, but still a false instruction in a shipped command.

FR1.4's audit scope confirmed: `calibrate.md:251` and `ship.md:97` both reference
`transitionPhase`. `ship.md:97` is already corrected prose (M5.E9/`B43`). `calibrate.md:251`
describes ensuring STATE exists and transitioning to DISCUSS — **it is the CALIBRATE→DISCUSS
handoff, a phase no other command claims**, so on this read it does not collide. The audit must
still be recorded with that finding (AC1.5 — *"checked, nothing to change" is a result, not a
skip*).

(no `.github/`), so nothing enforces this automatically.

M5.E9's precedent is **baseline replay against a pinned pre-Epic commit**. The pin for this Epic
is `901c512` (HEAD at PLAN entry). Concretely: check the pre-change tree out into a git worktree,
run the new tests against it, record the failure count. This must be a named task in the plan —
if it is left to EXECUTE to improvise, NFR5 becomes an assertion, which is the defect class this
Epic is named for.
