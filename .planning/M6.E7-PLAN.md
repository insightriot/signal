**Goal:** a read-only `/sig:advise` that reads this project's own `.planning/` corpus and emits a

## What research changed about the plan

Two parallel passes ran. Both moved the design; neither confirmed it.

1. **`parseBacklogRows` defaults to `maxDepth: 3`, and Signal's own promoted rows sit at `####`.** A
   default-depth read returns **zero** of them. The module says so in its own source: *"a READER
   that must not mistake 'nested deeper' for 'no work' passes `maxDepth: 4`."* The advisor is
   exactly that reader. **This is the single most likely way this Epic ships something confidently
   blind** — it is `B94`'s class, and it would look like a working command.
2. **Nothing in this repo resolves a `path:line` citation.** Four link scanners exist
   (`checkInternalLinks`, `checkOrphanDocs`, `checkDanglingReferences`, `scanDanglingLinks`); all are
   `.md`-only, inline-`](…)`-only, and **none checks a line number**. `checkDanglingReferences` is
   about *identifiers*, not paths. `doc-hygiene.js` also carries an explicit contract that its scope
   defaults must not change. **So the verifier is new code, and it is the Epic's load-bearing
   property.**
3. **`readState` THROWS** (`StateSchemaError`) on a missing/unknown `schema_version`. Uncaught, that
   is a crash where FR7 promises a `cannot-check` line.
4. **`walkBugEntries` returns no line number**, so `BUGS.md` citations cannot be `path:line` today.
5. **Two mutually-blind milestone Epic-row parsers exist** — filed as a bug this session, verified by
   running both. Bears directly on FR1's "what is open or closed".

## Slices

Three, each independently verifiable. **S1 first because it is the property everything else claims.**

### S1 — The citation verifier (`plugin/tools/lib/citations.js`)

Pure, no IO except `existsSync` + a line count. No dependency on any other slice.

- **t1.1** `extractCitations(text)` → `[{raw, path, line, lineEnd, offset}]`. Recognises the grammar
  the **known-good artifact actually uses**, not an invented one: backtick-quoted
  `` `path` ``, `` `path:12` ``, and `` `path:112–118` `` — *including the en-dash range form*, which
  appears in [`BACKLOG-REVIEW-2026-08-09.md`](BACKLOG-REVIEW-2026-08-09.md) (`analysis/SIGNAL-V2-ROADMAP.md:112–118`).
  ⚠ **A parser accepting only a single integer silently misses the form the target document uses.**
  Any extension, not just `.md`.
- **t1.2** `verifyCitations(baseDir, text)` → `{ok, resolved[], unresolved[], truncated}`. A path must
  exist; a line must be within the file; a range must have both ends in range and `line <= lineEnd`.
- **t1.3** Root-confinement before any disk touch, borrowed from `checkInternalLinks` (`B22`), and a
  scan ceiling that **reports truncation rather than under-reporting** (`B15`).
- **t1.4** Tests: resolving path; missing path; real path with an out-of-range line; a range with one
  end out of range; en-dash range; non-`.md` extension; zero citations → `ok: true` with an empty
  list (**not** an error — a section legitimately may cite nothing).

> **Why a new module rather than widening `doc-hygiene.js`:** that file's docblock makes *"the
> standing test-suite guard is unchanged"* a contract, its useful primitives are module-private, and
> its `stripCodeSpans` is **backwards for this job** — in a committed doc a backtick marks a sample to
> ignore; in the advisor's artifact backticks are *where the citations live*.

### S2 — Corpus reading (`plugin/tools/lib/advise-corpus.js`)

Reads four sources and reports what it could not read. **Shape B**, matching `collectPreflight`
exactly: `{sources, cannotCheck: [{source, reason}], checked: string[]}` plus a frozen
`ADVISOR_SOURCES`.

- **t2.1 Backlog** — `parseBacklogRows(content, { maxDepth: 4 })`. Filter `inDetails` (preserved
  history, not live work) and `discharged`. Row bodies derived from consecutive `line` values —
  **no second heading walk.**
- **t2.2 Bugs** — **additive change to `walkBugEntries`**: add `line` to each record. Additive so
  `deriveBugCounts` and `readClosureSources` keep working. ⚠ **Do not fork the walker** — that
  module's own docblock says *"writing the walk twice is `B82`'s shape."*
- **t2.3 Retros** — `enumerateRetros(baseDir)`, then read + `parseSections`. **Honour `isStub`: a
  retro carrying `[FILL IN]` is not evidence and must never be cited as a finished unit.**
- **t2.4 State/closure** — read via `resolveClosures` (`closure.js`), **not raw `readState`**, and
  never let a `StateSchemaError` escape. An unreadable state yields `cannotCheck`, never an empty
  set: *"an empty map says 'nothing is closed', which is a result; a null says 'I could not look',
  which is not."*
- **t2.5 Milestone rows** — export **one** reader covering both published formats (`| **E1** |` and
  `` | `M6.E1` | ``) and use it here.
  ⚠ **Re-pointing the two existing private call sites is a SEPARATE task, deliberately.**
  `findEpicStatusRow` feeds `isEpicCloseShip`, so re-pointing it makes `D-E9-5`'s override live again
  across Milestone 6 and **changes when the SHIP retro gate fires**. That is a real behaviour change
  and does not belong inside an advisory Epic by side effect. Land the export here; do the re-point
  under its own bug row, with its own test.
- **t2.6** Tests: each source unreadable in turn → its own `cannotCheck` entry with a reason, and
  **never** an empty result presented as clean. Pattern from `tests/pr-review-findings.test.js`'s
  *"cannot-check is a value, never a silent pass"*, including the double assertion
  `expect(status).toBe('cannot-check'); expect(status).not.toBe('clean')`.
- **t2.7** A `maxDepth: 4` regression test asserting Signal's own `####` rows are seen — the specific
  blindness named above.

### S3 — The advisor, the artifact, and the gate (`plugin/tools/lib/advise.js` + `plugin/commands/advise.md`)

- **t3.1** Rank the top N with *why this and not that*; every reason carries a citation.
- **t3.2** A **declined** section — considered and not recommended, with the reason (`B39`: a
  checked-and-declined item must be distinguishable from an unchecked one).
- **t3.3** `renderArtifact(result)` — pure, file-facing, separate from the terminal formatter, per
  `permissions-report.js`. Header copies the frozen review's five elements: title + date, one-line
  subtitle, the **"changes nothing on its own"** status line, **Corpus read** (the natural home for
  `checked` / `cannotCheck`), and the **Citation rule**.
- **t3.4** ⚠ **A producer attribution line — `via /sig:advise` — because the outcome oracle depends on
  it.** The frozen review has none, and this Epic's own DISCUSS had to label its provenance
  *unverified* as a result. Convention exists: `add.js` and `checkpoint.js` both write `via /sig:…`.
- **t3.5 THE RUN-BOUNDARY GATE.** Before writing, run `verifyCitations` over the rendered artifact.
  **Any unresolved citation fails the run and the artifact is not written.**
- **t3.6** `writeArtifact` → `{status:'written'|'unchanged'|'skipped', path, reason}`, idempotent by
  byte-compare, refusing with a reason when `.planning/` is absent. Use `atomicWrite` +
  `assertRealInsidePlanning` — ⚠ `permissions-report.js` uses raw `writeFileSync` and is **the
  outlier, not the convention**.
- **t3.7** Artifact name `BACKLOG-REVIEW-YYYY-MM-DD.md`. **Constrained, not chosen:**
  `tools/doc-budgets.json` already exempts exactly that pattern; any other name needs a manifest
  entry or fails `doc-budgets.test.js` above 32 KB. ⚠ It also collides with `backlog.js`'s
  `findSnapshot` glob — harmless here, real on a fresh project — and **`ORPHAN_ENTRY_POINTS` does not
  match it**, so `/sig:docs-sweep` will flag it until `INDEX.md` regenerates. **Decision: emit an
  inbound link from `BACKLOG.md` and regenerate the index**, rather than widening the orphan regex.
- **t3.8** The 23rd command touches **four** count sites: `roster.js`'s walk, `doc-hygiene.js`'s
  `ROSTER_SITES` (a **HARD fail** pinned to CLAUDE.md's `22 slash commands`),
  `references/command-taxonomy.md`, and `sweep.js`'s frontmatter check.
- **t3.9 NFR2/AC1.6** — a static scan asserting no import of or shell-out to anything under `prose`,
  following `tests/plugin-boundary.test.js`'s **reach declaration**: state what the detector reaches
  and what it does not, because *"a detector that reports 'no matches' without declaring its reach is
  `B81`."*

**Placement is fixed, not preferred:** everything ships in `plugin/tools/lib/`. Repo-root `tools/*.js`
is maintainer-only and `tests/plugin-boundary.test.js` treats a payload reference to it as a
violation.

## Risks, and what would falsify the plan

- **The `maxDepth: 3` blindness is the one that ships silently.** t2.7 exists solely for it.
- **A mutation test proves the case you thought of, not coverage.** `tests/environment.test.js`
  records the humbling precedent: *"ALL SIX PASSED THE FIRST SHIPPED VERSION. A full suite, three
  mutation tests, and my own read of the code did not find one of them."* Stated here so VERIFY does
  not read green mutation tests as proof of completeness.
- **The ranking may be the less valuable half.** The frozen review's best content came from
  cross-document contradiction finding, which this plan does not attempt. `M6.E7-REQUIREMENTS.md`
  pre-commits to reporting that honestly rather than rationalising a low calibration score.
