### What `resolveClosures` is actually used for at that call site

Narration, not gating. `migrate-memory.js:1974` wraps it in `try/catch` and feeds
`explainArchiveOutcome` — the comment above it says so: *"Fail-open: this is an explanatory read on
a dry-run display."* The **gate** lives elsewhere, in `senseArchiveTree`'s union.

**This matters for FR2.** The closure gate the Epic proposed to build largely **exists**:
`senseArchiveTree` computes `closedUnits = retro-derived ∪ verdict-derived` (stub retros veto), and
`planArchiveMoves` only ever emits moves for units in that list. A unit that is not closed is not
moved — **default-deny, which is a gate, not a warning.** FR2 should be re-scoped from *build it* to
*verify and surface it*.

## The defect, reproduced end-to-end through the real command path

Not through the library in isolation — through `senseArchiveTree`, which is what
`/sig:migrate-memory` calls:

```
## eval-project-A
   closedEpicIds (retro): []
   closedUnits (UNION)  : ["SLICE-SSO"]
   unit SLICE-SSO: derived 5, planned 3, STRANDED 2
                   PLAN-SLICE-SSO-RESEARCH.md, PLAN-SLICE-SSO-VALIDATION.md

## eval-project-D
   closedEpicIds (retro): []
   closedUnits (UNION)  : ["SLICE-SSO"]
   unit SLICE-SSO: derived 5, planned 3, STRANDED 2   (same two files)
```

Three things to read off this:

1. **The union works.** Retro-derived is correctly empty (neither project keeps Epic-ID
   retrospectives); verdict-derived finds `SLICE-SSO`. This is M5.E18's headline mechanism doing
   its job on a non-Epic project.
2. **`B82` is live in shipped code**, on the real command path, in both projects that archive by
   hand today. `/sig:migrate-memory --apply` would **split the unit right now**.
3. **The stranded files are the fold's files.** `deriveUnits` folds `PLAN-SLICE-SSO-*` into
   `SLICE-SSO` (pass 3); `planArchiveMoves` rebuilds `{unit}-{suffix}.md` and cannot express a
   fold. The disagreement is exactly the fold.

and `eval-project-D` archive by hand-written runbook. They are not blocked because closure is
unwired — they are blocked because the only way to trigger it is a command about document layout,
and because when it does run it strands two files per unit.

Checked by grepping for callers and then reading each one, rather than trusting the entry.
