## Important Issues (should fix)

**I1. `parent-run.js` can write outside its temp folder, and the file survives cleanup.**
`plugin/tools/lib/parent-run.js:191-196`. The copied test's destination is never checked to stay
inside the worktree. If the base commit has a symlinked directory on the test's path (`tests -> /abs/dir`),
the copy writes wherever the link points. That breaks AC3.1's cleanup promise, and in a hostile clone
it plants a file at a path of its choosing. Security-auditor, reproduced (the file stayed after the
run). Fix: require the real destination directory to sit inside the real worktree, and refuse a
symlinked destination, as `could-not-run`.

**I2. `parent-run.js` reports proof for a test that failed only because a new file was missing.**
`parent-run.js:98-113` (`classifyReport`), `:270-272` (`exitCodeFor`); `fixer-brief.md`. A test that
reads a fixture, or lazily imports a helper added in the same change, fails on the base with ENOENT or
"cannot find module". That is classified `failed`, exit 0, and the summary line cannot show why. A file
holding one real and one hollow test also reads as proof. Code-reviewer and security-auditor, both
reproduced (`parent-run 3c57c65: 2 of 2 failed on the base`, exit 0). This is the M6.E16 hollow-test
failure the Epic exists to stop. Fix: read `failureMessages`; a file whose failures are all
missing-file or missing-module is `could-not-run`; print each file's first failure reason; and reword
the brief so `failed` means "failed on the base: read why".

**I3. Killing `parent-run.js` leaves the worktree registered and the temp folder behind.**
`parent-run.js:183-238`. Cleanup is a `finally` around synchronous `spawnSync`, which a signal skips.
The next run's `git worktree prune` does not clear it, because the folder still exists. A per-file
timeout of 5 minutes makes a killed run likely (an agent's command timeout, or Ctrl-C).
Code-reviewer, reproduced (exit 143; the worktree was still in `git worktree list`). Security-auditor
raised the same point. VERIFY recorded it as a limit (M4). It is rated Important here by a reader who
did not see that, which is evidence that it matters, not that it is accepted. Fix: signal handlers
that run the same cleanup, which needs an async spawn, plus a startup sweep of stale
`sig-parent-run-*` worktrees. **This is a design change to the tool.**

**I4. The loop ceiling cannot end a chain of fix rounds inside one pass.** `review.md` § 4.6, "The
stop rule". It says the chain stops at a clean read *or* at the ceiling. But nothing writes STATE
between rounds, so `loopStatusFor` reads the same value every round, and only a clean read ends the
chain. Code-reviewer, from the code (not scripted). VERIFY recorded this as AC2.2's limit. Fix: either
bound rounds per pass (count them, or have `checkFixRounds` refuse more rounds than the ceiling), or
change § 4.6 to say the ceiling counts passes only and give rounds their own bound. **This is a design
call.**

**I5. A PASS-WITH-FIXES after a FAIL needs only one fix round, so its in-phase fix can go unread.**
`review-rounds.js:111-124`. The floor is rounds ≥ recorded REVIEW FAILs. After one FAIL, a
PASS-WITH-FIXES needs a round for the EXECUTE fixes *and* one for its own fixes, but passes with one.
Code-reviewer, reproduced. **Confirmed here:** `checkFixRounds(oneCleanRound, 'PASS-WITH-FIXES',
{phasePasses: ['REVIEW FAIL (…)']}).ok === true`. Fix: for PASS-WITH-FIXES, require fails + 1.

**I6. Leaving out `phasePasses` silently turns the floor off.** `review-rounds.js:111`. A caller that
forgets the option gets the check VERIFY D2 was added to replace; only prose in `review.md` makes
callers pass it. Code-reviewer, reproduced. **Confirmed here:** `checkFixRounds('All fixed.', 'PASS').ok
=== true`, and the same call with a recorded FAIL is `false`. VERIFY recorded it as a limit ("that
callers pass `phasePasses`"). Fix: require the option for PASS and PASS-WITH-FIXES, treat `[]` as none
recorded, and update the tests that call without it.

**I7. The `verify.md` recording-step test passes with the step deleted.**
`tests/review-loop-doc-contract.test.js:59-69` (AC1.6). The test checks that the first
`recordPass(baseDir, 'VERIFY'` comes before `### Loop Back`. The Exit Criteria checklist line already
satisfies that, so deleting the whole of § 5a still passes. Test-engineer, by mutation on a copy. Fix:

**I9. The timing guard misses ordinary ways of writing a timing test.**

| Area | Result |

## Performance Findings

- `parent-run.js` runs vitest once per named file, by design: the JSON report separates proof from
