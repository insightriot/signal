## Important Issues

### I1 (new) — a wiring comment asserted a property the code no longer had · FIXED in-phase

`tools/lib/migrate-memory.js:1958` read *"the renderer returns `[]` when there is nothing to say."*
That stopped being true the moment VERIFY pass 2 folded the empty-bound statement into
`explainArchiveOutcome`.

**This is pass 1's I1 shape recurring — in the same file pair, inside the same Epic.** Pass 1's
finding was *"the docblock claimed a property the code did not have."* Two passes later, same
defect, different sentence. That is worth more than the fix: **prose describing behaviour, with
nothing that fails when the behaviour moves, does not stay true.**

**And the first correction was also wrong.** I rewrote it as *"returns `[]` only when no units were
derived"* — **backwards**: that case produces the *most* lines. The test written to pin the comment
caught it immediately. Enumerating all six shapes settled it:

| input | lines |
|---|---|
| no units at all | 4 |
| STATE unreadable | 4 |
| units, moves, all clean | 1 |
| units, no moves, all open | 3 |
| units, `cannotDetermine` | 4 |
| units + dropped | 2 |

**It never returns `[]`.** That is the design — M5.E16's model is that silence is the bug — and it is
now stated accurately and pinned by a test enumerating every shape rather than asserted in prose.
*Three versions of one comment, two of them wrong, is the argument for the test.*

**One note.** The stub-retro veto relies on `enumerateRetros`, which only recognises Epic-ID-prefixed

**Correct as-is**, recorded so the asymmetry is not mistaken for an oversight later.
