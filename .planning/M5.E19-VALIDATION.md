## The defect this validation found, and what it says about the plan

**A safety bug, found by AC-S2.5's test, not by review.**

`buildArchiveReport` composed its `plan` from `senseArchiveTree` and its `refusals` from
`resolveClosures`. Those two disagree about what an unreadable `STATE.md` means:
`resolveClosures` degrades **every** unit to `cannotDetermine`; `senseArchiveTree`'s retro-derived
half needs no STATE at all and still reports a unit closed on the strength of a retrospective file.

So the plan came from the source that **cannot see the danger** while the refusals came from the
source that can. A project with no readable `STATE.md` would have been handed a plan to archive
work that might be the **current unit** — which is the retired tool's exact failure, reproduced in
its replacement, in the module whose doc says an unreadable STATE refuses everything.

`commands/archive.md` asserted the correct behaviour before the code did it. **The prose was right
and the implementation was wrong**, which is the reverse of this repo's usual failure and only
surfaced because the AC was written before the test and the test before the check passed.

Guard added in `buildArchiveReport` with the reasoning inline, and AC-S2.5 now pins it.
