### What the first two tasks changed about the plan's premise

`tools/lib/requirement-ids.js` is the single definition site (AC S1.1, checked by a test that walks
`tools/lib/` rather than asserting against a list). `evict.js` consumes it; its **omission of the NFR
family is now a commented choice at the call site**, not an absence a later reader would "fix".

**AC S1.2's literal example is necessary but not sufficient, and this was found by reading the field
artifact rather than reasoning about it.** The AC asks that `NFR1` match. `field-project-A`'s Phase
11 — the source of the AC1.5 fixture — writes `AC-16.10`, `FR-16` and `NFR-9.2`, and the pre-M5.E10
patterns matched **none of it**. A matcher satisfying AC S1.2 and still unable to read the fixture
would have been this Epic's defect class one level down, so the RED covered both spellings.

The distinction the module now turns on: a **spelling** is one concept written differently
(`FR-16` / `FR2b`) and excluding one would be the second definition the module exists to prevent, so
both consumers inherit every spelling. A **family** is a different concept (`NFR` is not `FR`), so
composition is each consumer's explicit call.

### Found while building S1.t4, and larger than the fixture

The first draft of `M1.E4-VALIDATION.md` put its explanatory sentence **inside** the Nyquist section:
*"`NFR1` has an owning slice above and no row at all here."* The corpus test then read `NFR1` as
present in that section — **the narration became data**. A section-diffing check cannot distinguish a
sentence *about* a requirement from a row *covering* it.

This is a live constraint on **S2.t2**, not a fixture quirk: any real VALIDATION artifact whose
dimension-2 or Nyquist section carries commentary will report requirements as covered that have no
row. Carry it into S2's design.

## S1.t3 — the contract question the PLAN does not answer, and how it resolved

The plan assumes AC1.5's *"artifact pair"* exists as a pair. **On disk it does not.**
`field-project-A` has no phase-scoped REQUIREMENTS artifact: its requirements live in a
**project-scoped** `REQUIREMENTS.md` (713 lines, every phase), while VERIFICATION is
**phase-scoped**. Diffed naively, every id from every other phase reports `missing` — a red wall that
says nothing about Phase 11, and a completeness claim written from the shape of the work rather than
the artifact.

Resolved as `D-M5E10-6` + **AC1.6** / **AC1.7**. Two things are worth carrying forward about *how* it
resolved, because neither was reasoning:

**The first rule I wrote was wrong, and measuring it is what said so.** `D-M5E10-6` originally scoped
the denominator to *"sections whose heading or body names the unit."* Run against the file: `NFR-10`
is a **different unit's** section that mentions this one in its body and would have contributed
**70+ foreign ids**, while `FR-16` — the main group — is not named by its own heading at all. Neither
half survived. **ID-group correspondence** ships instead: the denominator is the union of the
requirement groups the VERIFICATION itself cites, so no prose is read and no prose can be misread.
The decision was **retracted in place**, not annotated.

**Both halves of AC1.5 exist in the field; neither needed authoring.** ⚠ This log previously said the
passing half *"will be an amendment we author."* **That was wrong.** The source project's git history
carries both revisions: the pre-amendment VERIFICATION cites `NFR-9.1` / `NFR-9.3`, and the
post-amendment one adds `NFR-9.2` — the real omission, and the real fix. Both are frozen in
`tests/fixtures/claim-integrity/`.

That also cleared a risk worth stating: because the pre-amendment copy already cited two `NFR-9` ids,
the group was in scope, so group-correspondence **catches the actual field defect**. Had the whole
group been absent, the check would have called the real defect out-of-scope — the blind spot AC1.6
now reports by count instead of passing over.

**What the fixture will not claim.** AC1.5 reads *"the amended pair passes."* On this data it does
not: the amendment fixed `NFR-9.2` and left eight `AC-16.*` requirements unmentioned, which looks like
a real and still-open gap in the source. The honest contrast is scoped to the defect the amendment
addressed, and a test pins the `AC-16` gap in **both** copies so that claim cannot quietly go false.

**The source project is anonymised** — `field-project-A` throughout, in the fixture and in this
Epic's documents. This repository is public and the source is a commercial specification; the
fixture carries its structure, ID scheme and real defect, and none of its subject matter. The
provenance README states what is real and what is written here, because a derived fixture that does
not say so is itself a claim written from the shape of the work.
