### Completeness gap found by this validation — **AC4.3 has no owner**

**AC4.3** reads: *"The 16-finding baseline above is re-measured after the work. **The number that
matters is how many findings still reach a person**, and it is recorded whether it improved or
not."*

**No slice does this.** The plan measures the *new* checks' applicability across 13 projects but
never re-runs the original 16-finding structural baseline across the original four projects
(eval-project-C, eval-project-A, conversor, eval-project-D) to see whether the number that reaches a
person moved.

This is precisely the defect class this repo keeps finding: **an acceptance criterion satisfied by
the shape of the work rather than by the artifact.** Writing "we measured things" is not AC4.3;
AC4.3 names a specific number over a specific baseline.

**Resolution — added to the plan as `S4.t4`:**

> **S4.t4** — Re-run the four-project structural baseline from FR4 and record the before/after
> count of findings that **reach a person**, whether it improved or not. The original was 16
> findings / 15 that should not have reached anyone. `B57` (the migrate-snapshot noise) has since
> been fixed, so a large drop is expected from work that already shipped — **the report must
> attribute the delta rather than claim it**, or the number flatters this Epic with someone else's
> fix.

### Second completeness gap — **a declared category with no implementation** (found after the first pass)

The pass above traced FR4.1 to S1.t1 and asked *"is a category declared?"* — which S1.t1 satisfies.
**That is the wrong question, and asking it is how the gap survived.** The right question is
**"does each declared category have an implementation, and does its promise come true?"**

Asking it found: **check (d) was declared category 2 — *"Signal runs it"* — and no slice ran
anything.** `/sig:sweep --heal` was decided in D-M5E16-1 and appeared in no task table. At EXECUTE,
(d) would have behaved as category 3 while labelled category 2 (**the exact thing FR4.2 forbids**),
and S1.t3 would have rendered *"heals on next phase command"* for a finding that nothing healed.

**Resolved by measurement, not by relabelling:** `markFresh` is not tier-gated in code and
`eval-project-D` is FULL tier, so its next phase close does clear the finding unaided. **(d) is
category 1**, with the SKETCH exception written down and the render wording made tier-independent.

**And the consequence that had to be stated: the category-2 bucket now contains zero shipped
checks.** That is the concrete cost of D-M5E16-1, previously recorded only in the abstract.

**Added: `S1.t5`** — a test that every declared category has an implementation and that each
category-1 promise is exercised against a fixture.

**Verdict: PASS after adding S4.t4 and S1.t5.** Two gaps found, both closed in the plan. Both were
found by walking artifacts against criteria rather than by reading either for plausibility — which
is the same method that has caught every instance of this class in the last three Epics, and still
no mechanism.
