### R11 — the canary coupling (new at PLAN)

`references/adherence-canaries.json` defines `B41-phase-entry` with:

### Slice 1 — Make the artifact-naming seams symmetric (`B53` / FR1.5)

**Why first:** FR1.2 builds an artifact-existence check. Built on today's read seam it would
find a stale Epic-prefixed file and **pass** while the command writes a different name — a
false-green inside the Epic that exists to delete false-greens. The requirements sequence this
ahead of FR1.2 explicitly.

| Task | Description | Complexity |
|---|---|---|
| **S1.t1** | Make `artifactName` and `resolveArtifactPath` agree for **every** value of `current_epic`, not only strict Epic IDs. Must accept the legitimate no-prefix (`PLAN.md`) and numeric (`1-PLAN.md`) forms — `resolveArtifactPath`'s four patterns exist for real projects — while refusing to be satisfied by a phantom Epic-prefix match. **Cover both divergence axes:** the regex split (`EPIC_ID_RE` lenient vs `EPIC_ID_STRICT_RE`) *and* `LINEAR_UNPREFIXED`, which makes REQUIREMENTS diverge on a different rule than PLAN. | **M** |
| **S1.t2** | Make `references/epic-native-flow.md:31`'s guarantee true, or restate it to what the code keeps. The sentence is currently a documented promise the code breaks. | **S** |

**Acceptance criteria**
- **AC1.5a** — For every `current_epic` in `{strict Epic ID, non-strict token, null, empty}` and
  every artifact kind including REQUIREMENTS, `resolveArtifactPath(planningDir, A, opts)` resolves
  the file `artifactName(A, opts)` names, when that file is the only one present.
- **AC1.5b** — With **both** a stale `PHASE11-PLAN.md` and a fresh `1-PLAN.md` on disk and
  `current_epic: PHASE11`, resolution does not silently prefer the stale one.
  **Proof-of-fail: red at `901c512`.**
- **AC1.5c** — Existing strict-Epic-mode behaviour is byte-identical (no regression for
  Signal-on-Signal or any `M{n}.E{n}` project).

**Test strategy** — unit, table-driven over the `{current_epic} × {artifact}` matrix in R3.
Fixture dirs under `tests/` with both filenames present for AC1.5b.

**Not doing in this slice** (from `B54`/`B53`'s catalog entry, deliberately deferred): the
`/sig:sweep` check for a set-but-non-strict `current_epic`, and surfacing `detectMode` in
`/sig:status`/`/sig:resume`. Both are new capability; FR1.5 asks only for symmetry.

#### S5.t3 — the proof-of-fail mechanism, concretely

Five ACs say "red against `main`" and this work happens **on `main`**, with **no CI** to enforce it.
M5.E9's precedent is baseline replay against a pinned pre-Epic commit. For this Epic:

1. `git worktree add <scratch> 901c512` — the pre-Epic tree.
2. Copy the **new test files only** into the worktree.
3. Run them there; record the failure count and the failing test names.
4. Record in `M5.E13-VERIFICATION.md`: *"N of M new tests fail at `901c512`."*
5. Tests that pass at baseline are **not proof of anything** and must be justified individually
   (a test can legitimately pin existing behaviour) or rewritten.

Step 5 is the part that matters. M5.E8's lesson was that a defective instrument yields a
**plausible-looking** result rather than an error; a proof-of-fail run that silently passes at
baseline is exactly that shape.
