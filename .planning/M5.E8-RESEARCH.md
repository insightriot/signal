## R1 — FR5's ceiling is **measurable now**, and it is ~11%

The spec asked for the coverage ceiling as a deliverable. It can be computed before building
anything, so it was — over all 18 `commands/*.md` files:

| | count | share |
|---|---:|---:|
| Directive lines (imperative, bullet/step/table-row shaped) | **202** | 100% |
| …naming a `tools/lib` function call | 15 | 7.4% |
| …writing a named artifact file | 7 | 3.5% |
| **Trace-measurable (either)** | **22** | **10.9%** |
| **No observable trace** | **180** | **89.1%** |

**Read this as an order of magnitude, not a precise figure.** The classifier is a regex over
directive-shaped lines; a hand pass will move individual rows. What does not move is the shape:
**roughly nine in ten of Signal's own instructions cannot be verified by this method.**

**Why this belongs in RESEARCH and not just in the eventual result:** it changes what the Epic is
for. A harness measuring 11% of the corpus is **not** "Signal can now detect whether its
interventions work." It is *"Signal can now detect whether its **mechanical** interventions work,
and still cannot see the other 89%."* Both halves ship, or the number is propaganda.

**It also re-frames M5.E7's headline.** That audit said Signal cannot detect whether its
interventions work. This research says: for ~89% of them, **not with any method currently proposed**
— the rubric-scoring option D-M5E8-2 rejected was the only candidate that reached them, and it was
rejected for measuring with the instrument under test. *That is a real tension, and the honest
position is that the 89% stays unmeasured rather than badly measured.*

**Concentration matters too.** The 15 call-naming directives are concentrated in `ship.md` (5),
`add.md` / `checkpoint.md` / `discuss.md` (2 each). **`execute.md`, `verify.md`, `review.md` and
`calibrate.md` name none** — so the phases doing the most work are the least measurable. The
canary set (FR3) can only be drawn from where the traces are, which is not where the risk is.

## R2 — The agent-invocation surface exists locally and needs no new credentials

`claude` **2.1.220** is on PATH, with `-p` / `--print` headless mode and
`--output-format=stream-json`. So the harness shells out to the same CLI the user already
authenticates — **no API key handling, no new secret in the repo, no CI secret** (which also keeps
D-M5E8-1's "not in CI" boundary honest: there is nothing for CI to be given).

**Consequences for the plan:**
- **Version is a variable, not a constant.** `claude --version` must be recorded per run (FR4's
  "model" field should be *CLI version + model*), because a verdict is only comparable against runs
  on the same surface.
- **Absence must fail loudly (AC1.4).** `which claude` failing has to abort with that message. A
  harness that reports "0 obeyed" because the CLI is missing produces the single most dangerous
  output this Epic can emit.
- **Stranger portability is a limit to state**, not solve: a user without Claude Code CLI cannot run
  the harness. Acceptable — Signal is a Claude Code plugin — but it belongs in the doc.

## R3 — The control arm needs an isolated copy of the plugin, not just the fixture

FR2 deletes an instruction line and re-runs. **The instruction lives in `commands/*.md`, which is
Signal's own source** — so the mutation must be applied to a *copy of the command tree* that the
harness points the agent at (AC2.4). Two consequences the plan must budget:

1. The harness needs a **plugin-root override** so the agent under test loads the mutated copy.
   `commands/*.md` reference `${CLAUDE_PLUGIN_ROOT}` for skill paths, so a copied tree with the
   variable set is the natural seam.
2. **The fixture project and the mutated plugin are two different temp trees.** Conflating them is
   the obvious first bug.

---

## R4 — Nondeterminism budget

AC2.3 requires N runs per arm with the spread reported. With two arms and N runs, a single
instruction costs 2N agent invocations. **At N=3 that is 6 runs per instruction**; a canary set of
5 instructions is 30 invocations per measurement. Minutes and real money.

**Planning consequence:** the canary set starts at **one** instruction (`B41`'s phase-entry rule,
AC3.2), proves the harness end-to-end, and grows only after. An Epic that opens with a 5-instruction
set spends its budget before knowing whether the method works at all.
