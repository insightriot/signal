# M6.E16 — Plan: Epics and units become records

**Goal:** an Epic or unit is one JSON record whose existence, close and hold are recorded events, and
every reader that asks "does it exist / is it closed / what is the next ID" reads that record.

Requirements: [`M6.E16-REQUIREMENTS.md`](M6.E16-REQUIREMENTS.md). Research:
[`M6.E16-RESEARCH.md`](M6.E16-RESEARCH.md). Test mapping:
[`M6.E16-VALIDATION.md`](M6.E16-VALIDATION.md). Decisions `D-M6E16-1` … `-20`. Tier FULL, strict TDD.
Runtime: Node 22+, no new dependency.

## What this Epic does for the first time

1. **The old closure readers are compared, Epic by Epic, against what the milestone tables say.**
   Nobody has run that comparison. Today's resolver answers closed 17, open 2, cannot determine 11
   over 42 shipped Epics, and reads `M5.E17` open. **S0, wave 1** takes that snapshot before any
   reader changes, so the cutover has a "before".
2. **`closeEpic` records a close on a v2 store.** It has returned `no-folder` for every Epic since
   `M6.E11`. Its first real run is this Epic's own SHIP. S4 runs it on a scratch copy first.
3. **The migration runs on a project that is already on the store.** Today it refuses at its first
   check. Signal is the first such project (S8).

## Rules for every task

- Re-grep the rows you are about to change before relying on a line number in the research.
- Write the failing test first. **Run the slice's new tests against the parent commit and record the
  result in `M6.E16-PROGRESS.md`** — a test that passes on the parent proves nothing.
- A project with no unit records behaves as on `v0.1.50`, as AC6.4 defines that (amended at VERIFY, loop 1): every switched reader keeps
  its old path as the fallback, and the existing fixture tests stay green **unchanged**.
- Never `git stash`. Never stub the step the test is about. Read exit codes, not last lines.
- No unit name reaches a shell argument list. Git calls use fixed arguments and `--`.
