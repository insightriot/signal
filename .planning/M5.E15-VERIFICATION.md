The Nyquist table marks AC3.1, AC3.4 and AC5.1 RED-first. **They were not.** The
implementation landed first and the assertions followed, inside the same commit (`7669644`),
so there is no red→green git evidence and attestation (b) would be false.

Rather than assert they *would* have failed, **every one was mutation-tested**: the
implementation was broken, the test was required to go red, and the tree was restored.

## 3. Defects found during VERIFY

### 3.1 Two ACs had no test at all (loop 1 → EXECUTE)

- **AC3.1** — *directive residue throws before any agent is invoked* — unasserted. The
  `AC3.1` grep hits belonged to a **different Epic** (`ship-fr1.test.js`) and to a pre-existing
  describe title using M5.E8's AC numbering. Ordering is the property, and no unit test on
  `checkLeak` can see it: the test would pass identically if the refusal ran *after* the six
  paid agent calls — still a bug, just a more expensive one. Now asserted by source order,
  scoped to `runArm` (a whole-file search finds `probeSeam`'s own legitimate `invokeAgent`
  call first, which produced a false failure on the first attempt).
- **AC5.2** — *header note present* — unasserted. The existing test pinned the old strings
  and could not see whether the new note landed.

### 3.2 `B83` — the pre-existing scope-limit assertion was vacuous

Found by mutation-testing rather than by reading. `AC2.4 — this file states its own scope
limit` read the **whole file** and asserted it contained `SCOPE LIMIT`, `2 of the 4 known
instances`, `B39`, `B46`, `NOT a check for the`. Every one of those literals also appears in
the `expect(...)` line asserting it, so the test matched its own source.

**Deleting the entire header comment block left it green.** Shipped M5.E13, unguarded for
three releases.

This is the exact failure the file exists to catch, and the file says so forty lines above:
`hasCaller` deliberately skips `guard-callers.test.js` because *"a checker that satisfies
itself is the failure it looks for."* The trap was seen for the mechanism and missed for the
label — and the label is `D-M5E13-3`'s deliverable, the thing that stops the mechanism
over-claiming its coverage.

**M5.E15 came within one commit of shipping a second instance:** the new AC5.2 assertion was
written the same way and was equally vacuous. Both are now scoped to a `headerBlock()` helper
reading only above the first `import`, with a further assertion pinning the non-vacuity
itself. Filed and fixed as **`B83`**.

A second-order finding fell out of the same fix: the `auto-discovered count is NOT the
coverage count` assertion had only ever passed because the phrase **wraps across a comment
line** in the header and did not wrap in the assertion. Scoping made it fail honestly.

### 3.3 A defect in the verification harness itself

The first mutation script restored files with `git checkout --`, which **deleted the
uncommitted AC5.2 test it was trying to verify**. The run then reported "does not
discriminate" — because the test no longer existed, so the `-t` filter matched nothing and
vitest exited 0. A green exit meaning *nothing ran*.

Recorded because it is the same shape as the defects this Epic is about, one level up: the
instrument produced a reading that looked like a result. Subsequent mutations used a file
backup instead.

### 3.4 Header note placement (fixed)

The `B81` note was first committed **between `✅ B54` and `❌ B39`**, splitting the
four-instance enumeration that the paragraph below then summarises as *"2 of the 4"*. Moved
below the list; pinned by an ordering assertion.
