### A simplification against the plan, taken in the open

PLAN specified **"strip a leading phase marker, then fold."** Measured against all four real split
pairs, **the strip is redundant** — the fold alone merges all four, including the one the strip
*cannot*: `PLAN-SLICE-VOICE1` strips to `SLICE-VOICE1`, but its sibling is `VOICE1`; the fold matches
it directly because `PLAN-SLICE-VOICE1` ends with `-VOICE1`.

The fold is also **strictly more conservative** — it only renames onto a name the corpus already
evidences, so a `PLAN-ORPHAN` with no `ORPHAN` sibling is left exactly as derived. `AC1.2″` pins that.
**Strip dropped.** One pass instead of two, and the weaker rule was the one removed.

### Two bugs `AC1.7′` caught that "byte-identical" would have missed

`AC1.7` originally required check `(c)`'s findings be **byte-identical** after the extraction. PLAN
corrected it to `AC1.7′` — *differences enumerated and ratified* — because the suffix lists differ.
That correction is what surfaced both of these:

**1. The vocabulary is the caller's question, not a narrower default.** The first attempt shared the
rule *and* the vocabulary. Six of check `(c)`'s own tests went red: the local 4-suffix list was never
a subset-for-convenience. `SCAFFOLD_SUFFIXES` answers *"what archives with a closed unit"*; the 4

**2. I diagnosed the first one from the test names and was wrong.** After the vocabulary fix the same

was masking which was which. *Reading the failure beat reasoning about the failure — the same lesson

### Two corrections found by running against real files, not fixtures

The first `parseVerdict` skipped every heading and required `Verdict` to open the line. Against the
corpus it called **16 of 30 unreadable — and four were Signal's own**, in two formats it wrongly
rejected:

```
## Verdict: **PASS-WITH-A-DOCUMENTED-GAP**          M5.E13-VERIFICATION.md:6
**Tier:** FULL / strict · **Verdict:** ✅ **PASS**   M5.E6-VERIFICATION.md:3
```

**Position on the line was the wrong test.** What matters is whether a *word qualifies* the verdict —
`Nyquist verdict` is a coverage verdict, not an outcome. The rule is now: an **unqualified** `verdict`
anywhere on the line, **and** the outcome token on that same line. A bare `## Verdict` heading still
reads `unreadable`, because it defers its value to the body.

### `AC2.6` confirmed by measurement, not accepted from the plan

**`**All 22 acceptance criteria pass.**`** — a lowercase `pass` inside prose, which a body scan cannot
distinguish from *"Only 3 of 22 criteria pass."* Reading bodies would produce a **confident wrong
answer**. They go to `cannotDetermine`, where FR4 reports them as needing a person.

### Corpus result

### Three decisions worth the record

**Confinement DROPS a hostile unit, it does not throw (AC6.2).** A thrown error would let one bad
name deny the entire plan; dropping keeps every other unit archivable. `isSafeUnitName` requires an
alphanumeric first character — which alone rejects `.`, `..`, `.hidden`, `/abs` — excludes `/` and
`\` by charset, and rejects `..` anywhere *separately*, because `.` must stay legal **inside** a
name: `M4.5.E1` and `v0.1.6` are both real units. `deriveUnitArchiveDir` throws as a second layer,
so a caller that skips the filter still cannot escape `.planning/archive/`. 12 adversarial fixtures;
the corpus has none of these today, which is **luck of inventory, not safety**.

**The `archive/` exclusion is now explicit, and it belongs in exactly one place (AC6.3).** Today
`from` is always a top-level path, so an archived file could never re-match — but that is a property
of how `from` *happens* to be built, and NFR2's idempotency should not rest on a coincidence one
refactor from being false. Excluded in `planArchiveMoves` only: `senseArchiveTree`'s full walk still
includes `archive/`, because archived files' **links** are deliberately rewritten. Exclude it from
the walk and link rewriting breaks silently.

**`opts.closedUnits` is an explicit input, NOT a call into `resolveClosures`.** Wiring S4's resolver
in here would silently change which **Epics** archive — an Epic with a complete retro but a FAIL
verdict would stop archiving — and `AC6.1` forbids exactly that ("No existing Epic move changes").
The default is unchanged: absent the option, the closed set is the non-stub retros, so every
existing caller plans what it planned before. **Wiring closure→archive is S7's**, where the
four-status reporting can show what moved and why.
