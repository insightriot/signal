# M5.E7 — Plan: the v2 direction audit (BR-8)

**Tier:** FULL, Epic-scoped (`M5.E7-PROFILE.md`) — ceremony off, gates strict
**Spec:** `M5.E7-REQUIREMENTS.md` (FR1–FR7, P1–P8) · **Research:** `M5.E7-RESEARCH.md`
**Decisions:** D-M5E7-1…8

---

## Phase goal

Produce `analysis/SIGNAL-V2-ROADMAP.md` — an evidence-grounded, ratifiable v2 roadmap that gives
every port candidate a `build` / `abandon` / `continue` verb, and lands its `build` items
enforceably in `BACKLOG.md` rather than only in a directory nothing checks.

**No code ships.** `nyquist_enforcement: off` — every acceptance criterion is verified by reading
or by a mechanical check, never by a test. *No tests does not mean no verification:*
`M5.E7-VALIDATION.md` maps every AC to a concrete check.

---

## Structure — 4 slices / 3 waves

```
Wave 1   S1 Demand register  ∥  S2 Supply verification     ← MUST be parallel (AC2.4)
Wave 2   S3 Match · counterfactual · disposition  ∥  S4.t10 Correct the record
Wave 3   S4.t9 Roadmap → S4.t11 Supersede · reconcile · land
```

**S4.t10 runs in Wave 2, not Wave 3** (D3 fix). Its corrections depend on **S2 only** — not on the
demand register, the counterfactual, or the disposition table. It was originally sequenced behind
the roadmap, which put the Epic's highest-confidence, lowest-dependency output behind its
lowest-confidence one. **The record is wrong today; it doesn't need the roadmap to exist first.**

**S1 ∥ S2 is an integrity requirement, not an optimization.** AC2.4 requires supply be recorded
**independently of demand before matching** — if the supply verifier already knows what the demand
register wants, it will find it. Separating them is the cheapest structural guard against the
confirmation bias D-M5E7-8a identifies as unavoidable.

## Slice 1 — Demand register (FR1)

**Ships:** the demand register — a deduplicated, theme-clustered, citation-carrying list of what
Signal's own record says it needs.

### S1.t1 — Harvest the retro corpus
- **Do:** extract `## What to feed back into Signal` from the **12 populated** files (not 16 — C2).
  Section extraction is scriptable (`awk` on the literal heading, proven across all 12); item
  segmentation needs judgment. M4.5.E4 / M4.5.E8 use different templates → per-file handling.
- **Budget (P5):** ~1,510 words total, 39 measured items. **~1 hour. This is not the over-run risk.**
- **Second pass** on `## What we'd do differently` **only if t3 nets < 12 items** (~35–40% overlap).
- **Acceptance:** AC1.1, AC1.4 (M4.5.E4/E8 noted as gaps), AC1.5 (**4 stubs reported, NOT
  reconstructed** — reconstruction manufactures inference and contaminates the register).
- **Verify:** every extracted item carries `{file}#{section}`; count ≥ 30 raw; zero items sourced
  from a stub file.
- **Complexity:** S

### S1.t2 — Harvest the work ledgers
- **Do:** `BUGS.md` chains (**documented vs. inferred labelled** — AC1.2), `BACKLOG.md`,
  `ISSUES-INBOX.md`, `OPEN-QUESTIONS.md`.
- **Budget (P5) — this IS the over-run risk:** `ISSUES-INBOX.md` is **1,507 lines**. Cap at the
  39 top-level entry headings plus each entry's `Status` line; **do not** read entry bodies except
  for the ≤ 8 that a theme actually turns on. **Record what was skipped** — a silent cap reads as
  full coverage.
- **Known:** `OPEN-QUESTIONS.md` yields **zero unique signal** (both items already in BACKLOG) —
  confirm and move on, don't re-derive.
- **Acceptance:** AC1.2 (chains, correctly grouped per C1), AC1.3 (recorded recency vs. inferred
  frequency, never presented as equivalent).
- **Verify:** the three chains B24→B27→B28, B29→B34, B26→B30→B36 each appear once as a **single**
  signal; skipped-content note present.
- **Complexity:** M

### S1.t3 — Dedupe, cluster, rank
- **Do:** apply the **mandatory order** (AC1.2a) — subtract `BACKLOG.md` → subtract shipped
  commands (`/sig:add`, `/sig:doctor`) → collapse intra-file duplicates (`#13 ≡ #27`). Then cluster
  by theme and rank.
- **Why the order is load-bearing:** the 2026-07-04 review sharpened 10 inbox entries into BACKLOG
  sprints **without removing them from the inbox**. Any other order re-derives Sprints 2–7 and
  presents them as findings — **~2× inflation on every cluster.**
- **Expected yield:** ~15–17 net-new (measured-sample estimate, ±15pp). **Weight recent retros** —
  M4.5-era items are ~58% already tracked, M5.E4/E5/E6 items ~0%.
- **Do NOT:** present `BACKLOG.md:86` ("cross-Epic pattern detection") or Sprint 5's command
  cluster as discoveries. **BACKLOG already knew** — reconcile against it, don't re-derive it.
- **Acceptance:** AC1.2a, AC1.3 · **Verify:** every cluster names which BACKLOG entry it
  reconciles to or states plainly that it is genuinely new.
- **Complexity:** M

## Slice 3 — Match, counterfactual, disposition (FR3 + FR7)

**Ships:** the disposition table — every candidate with a verb and a rationale.
**Depends on:** S1 **and** S2 complete.

### S3.t7 — The counterfactual pass (**do this BEFORE dispositioning**)
- **Do (AC7.1):** for each of the four ports ask *"would this have prevented a bug we actually
  shipped, or shortened an Epic we actually ran?"* Cite the bug or Epic, or record a plain "no."
- **Why first:** the demand register is structurally silent on the pain of work never attempted —
  nobody logs friction with upstream phases they don't have. Dispositioning straight off the
  register would confirm the existing course using evidence that could not have contradicted it.
- **Live lead:** cross-model adversarial review vs. the v0.1.9 `evict.js` false-green. D-M5E7-7
  says several April capabilities *did* prove necessary, so this can return an uncomfortable
  answer — which is the point.
- **Acceptance:** AC7.1, AC7.2 (memory-loop thesis is a **hypothesis under test**), AC7.3
- **Verify:** four ports × an answer, each citing an artifact or stating "no."
- **Complexity:** M

### S3.t8 — Disposition every candidate
- **Do:** `build` / `abandon` / `continue` + one-paragraph rationale for every candidate in
  `MILESTONE-5.md` § "Candidate v2 feature-port scope", **plus the seed §2 five** (AC3.2 hard floor).
- **Constraints:** **P1 — at least one `abandon`** (or a per-candidate sentence saying why not;
  silence is not a decision — five ports sat un-cut for the project's life). **AC2.3 — staleness
  and dormancy are struck as rationales** (D-M5E7-6); argue fit or overlap. **AC3.3** — each verb
  names the demand entry it serves or states that it serves none. **AC3.4** — demand matched by no
  repo becomes a **Signal-native candidate**; per D-M5E7-1 this column is expected to be
  productive, not a remainder bucket. **AC3.5** — per-repo substrate stays closed.
- **Verify:** count(candidates) == count(verbs); the five seed items each appear by name.
- **Complexity:** M
