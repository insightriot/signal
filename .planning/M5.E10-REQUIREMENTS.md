## The class this Epic exists to kill

**Completeness claims written from the shape of the work rather than from the artifact** — the author
composes *"0 gaps"* / *"all verified"* / *"checklist complete"* from a mental model of what just
happened instead of re-deriving it from the source. The false statement is always **plausible**, which
is what makes it dangerous: an authoritative-looking *"0 gaps"* is worse than no claim, because it
terminates investigation.

Full evidence: [`../analysis/CLAIM-INTEGRITY-ANALYSIS.md`](../analysis/CLAIM-INTEGRITY-ANALYSIS.md) —
its single home, not restated here. Field evidence from `eval-project-C`'s Phase 11 (five false
coverage claims in one FULL-tier phase, **every catch incidental**), plus ≥7 prior un-abstracted instances in
Signal's own corpus.

**The governing principle, generalized from `buildCaveats()`:** every completeness claim must be
**(a) mechanically derived, (b) deterministically checked, or (c) explicitly labeled unverified.**
There is no fourth state.

## Scope decision (`D-M5E10-1`)

**Brett, 2026-08-11 — "checkable parts + writing rules."** In: everything a machine can verify, plus
the guidance changes that cost text rather than machinery. Out, to a named follow-on: the
**adversarial claims-audit agent** (`CLAIM-INTEGRITY` §6 item 3) — an agent re-reading every claim
against its source.

**Why the deferred half is named rather than dropped.** §6 item 3 is the piece that *"kills the class
generally; catches what determinism can't."* Shipping the deterministic half and calling claim
integrity solved would itself be a completeness claim written from the shape of the work — this
Epic's own defect, committed by the Epic. So:

> **AC0.1 — the deferred half must be visible in the output.** Whatever this Epic ships must state,
> in the artifact a reader lands on, that the semantic backstop is **not** built and what it would
> catch. A reader must not be able to conclude from Signal's own docs that claim integrity is fully
> guarded. *Done-when:* a grep for the follow-on's name returns a live row in `BACKLOG.md` and a
> statement in the shipped docs, and neither reads as complete.

## Functional requirements

### FR1 — Deterministic requirement-coverage diff

Every requirement ID declared in `{Unit}-REQUIREMENTS.md` must appear in the VERIFICATION artifact.
Absent = **red**, not a warning.

- **AC1.1** — A `tools/lib` check extracts every `FR*` / `NFR*` / `AC*` ID from a REQUIREMENTS
  artifact and diffs it against IDs present in the matching VERIFICATION artifact.
- **AC1.2** — A requirement present in REQUIREMENTS and absent from VERIFICATION fails the check and
  is **named** in the output. A count alone does not satisfy this.
- **AC1.3** — The check reports **three** outcomes, never two: `covered`, `missing`, and
  `cannot-evaluate` (no REQUIREMENTS artifact, unreadable file, no ID scheme). *"Could not look"*
  must never render as *"checked and clean"* — `B39`'s shape, and `M5.E16`'s hardest-won lesson.
- **AC1.4** — `commands/verify.md` instructs the run to call it. The instruction names
  `REQUIREMENTS.md`, which today it **never does** — VERIFY's whole coverage loop enumerates
  `{phase}-PLAN.md` tasks, so a requirement that never became a task AC is structurally outside it.
- **AC1.5** — Replaying `eval-project-C`'s Phase 11 artifact pair **fails** the check; the amended
  pair **passes**. The fixture is the field case, not a synthetic one.
- **AC1.6** *(added at EXECUTE, 2026-08-12 — `D-M5E10-6`; the pair does not exist as a pair)* — When
  the REQUIREMENTS artifact covers **more than one unit**, the check derives the unit's denominator
  by **ID-group correspondence** — the union of the requirement groups the VERIFICATION artifact
  itself cites (cite `AC-16.8` → all of `AC-16.*` is in scope) — and reports the basis it used. No
  group cited, or no ID scheme found: `cannot-evaluate` — never a diff against every requirement in
  the file. A group the VERIFICATION cites nothing from is **unattributable**, and is reported by
  count rather than passed over. *(Scoping by prose sections was written into this AC first and
  measured wrong within the hour: `NFR-10` — Phase 13's section — mentions Phase 11 and would have
  contributed 70+ foreign ids, while `FR-16`'s heading does not mention it at all. See `D-M5E10-6`.)*
  **Why this is an AC and not a detail:** the field project's REQUIREMENTS is project-scoped (713
  lines, every phase) and its VERIFICATION is phase-scoped. Diffed naively, every id from every other phase
  reports `missing` — a red wall derived from the shape of the files rather than from Phase 11, which
  is the defect class this Epic exists to kill.
- **AC1.7** *(added at EXECUTE, 2026-08-12 — `D-M5E10-6`)* — A requirement the REQUIREMENTS artifact
  itself marks as **deferred or struck out of the unit** is not counted missing. It is reported in
  its own category, named. Root `REQUIREMENTS.md` line 227 strikes `AC-16.3` and says it was deferred
  out of Phase 11; naming it uncovered would be the check being wrong in the field on its first run,
  and dropping it silently would be `B39`'s shape.

### FR2 — VALIDATION intra-file consistency

Phase 11's root defect was a **single file contradicting itself** that nothing read.

- **AC2.1** — A check compares a VALIDATION artifact's dimension-2 assignments against its Nyquist-map
  rows and fails when they disagree.
- **AC2.2** — Same three-outcome rule as AC1.3.
- **AC2.3** — Fails on the Phase 11 fixture.

### FR3 — VERIFICATION template: denominator + what this could not establish

- **AC3.1** — The VERIFICATION template carries a **denominator table** — `{n} of {total}`, never a
  bare count. The only artifact in the repo demanding this today is
  `agents/verifiers/nyquist-auditor.md`, which no command dispatches.
- **AC3.2** — The template carries a **required** *"What this could not establish"* section.
- **AC3.3** — An artifact missing either the table or the section **fails the phase gate**.
- **AC3.4** — This requirement is explicitly **paired with FR1** and says so in its own text: its
  done-when is structural (section present), so alone it proves only that a heading exists. A
  present-but-empty section must fail.

### FR4 — Correction protocol, retracted at the granularity people search at

- **AC4.1** — A correction is complete only when a corpus grep for the claim **and its restatements**
  returns solely corrected instances — root **and** carriers, not the files that happened to be open.
- **AC4.2** — The check tests whether each matching **line, read alone**, still asserts the false
  claim — not merely whether a correction exists somewhere in the file. `grep -rn` prints one line; a
  correction three lines below is invisible to it, and grep-shaped reading is exactly how the Phase 11
  falsehood propagated VERIFY → REVIEW.
- **AC4.3** — The resolution of *amend, never rewrite* vs. *the grep must come back clean* is that the
  matching line is **self-correcting**, not absent: `~~still owed~~ **[RETRACTED — see amendment
  below]**`.
- **AC4.4** — Runs at the SHIP gate. **Blocks at FULL, advisory below** — consistent with how every
  other tier-gated gate in Signal behaves.

### FR5 — Provenance rule + anti-rationalization reclassification (`B38`)

- **AC5.1** — Every anti-rationalization table entry is classified **discipline** (keep the
  prohibition form) or **shaping** (convert to a positive recipe), on a one-page table.
- **AC5.2** — Every shaping entry is expressed as a positive recipe.
- **AC5.3** — A new shaping entry states the **provenance rule**: never restate — and never
  *escalate* — an upstream claim about a third artifact without opening that artifact.

### FR6 — Fold the denominator discipline into the command text

`agents/verifiers/verifier.md` names REQUIREMENTS.md as input and emits a Requirement Coverage table;
`agents/verifiers/nyquist-auditor.md` demands `{n} of {total}`. **No command dispatches either** —
`commands/verify.md` spawns no agents at all.

- **AC6.1** — The enumerate-with-a-denominator discipline is present in the **command text**, so it
  runs without an agent dispatch. *This is the `D-M5E10-1` resolution of `CLAIM-INTEGRITY` §6 item 7's
  explicit either/or* — dispatch was the machinery option and is out of scope.
- **AC6.2** — The now-unreachable agents are either reachable or **documented as unreachable**. An
  agent that no command can invoke, left undocumented, is the never-called-guard class (`M5.E8`'s
  named defect) sitting inside the Epic about claims.

### FR7 — Retro-index freshness check

- **AC7.1** — A check, sibling to `checkIndexFreshness`, fails when `RETROSPECTIVES.md` disagrees with

- **AC7.2** — Same three-outcome rule as AC1.3.

### FR8 — `STATE.md` narrative vs. frontmatter (folded in by `D-BR0810-2`)

- **AC8.1** — A check compares the body's phase claim for `current_epic` against the frontmatter's
  and fails when they disagree. Narrow and deterministic by design — the phase-name token nearest the
  `current_epic` mention, not a general prose reading.
- **AC8.2** — It fires on **all five** recorded instances. Five is not a guess: instances 1–4 are
  catalogued in `STATE.md` § In-flight, and **instance 5 occurred during this Epic's own opening
  commit** — *"Nothing in flight"* while `current_epic: M5.E10` sat twenty lines above, in the very
  section that argues the defect is structural. **The catalogue did not protect the file it lives in.**
- **AC8.3** — `runDriftChecks` reported **6/6 clean** across every instance, correctly:
  `body-omits-current-epic` tests `mentioned.has(epic)` — presence, not agreement — and
  `phase-behind-artifacts` never reads prose. The new check must fail where those two pass; a check
  that merely duplicates their reading adds nothing.

### FR9 — `BACKLOG.md` never records that a row's work shipped (`B94`, folded in 2026-08-13)

`.planning/BACKLOG.md` is append-only. `tools/lib/backlog.js` has exactly two write paths —
`createBacklogIfMissing` and the promote-append — and **no discharge function was ever written**.
`commands/ship.md` reconciles five document surfaces at Epic close and touches the backlog in none of
them. So the one document users treat as *the queue* is the one document with no closing mechanism,
and it asserts *pending* about shipped work indefinitely. That is not missing coverage; it is a
document actively claiming false completeness — **this Epic's own defect class, in the file a user
trusts most**, and none of the six checks already shipped here detect it.

- **AC9.1** — A backlog row can be recorded as discharged, and **what changes is what a reader
  sees**. An HTML comment alone leaves the rendered document asserting the same false status, so the
  marker cannot be the whole fix.
- **AC9.2** — The write path has four distinguishable outcomes — `discharged`, `already-discharged`,
  `not-found`, `ambiguous`. Hand-groomed rows have no stable id, so a heading match is the only
  handle; a match hitting more than one row **refuses**, never "first wins". `already-discharged` is
  distinct from `not-found`, or a re-run no-ops by accident and *"clean"* reads as *"never looked"* —
  the defect, inside its own fix.
- **AC9.3** — `/sig:ship` discharges at Epic close, symmetrical with §6.5's inbox sweep, and **the
  Epic names the rows**. Nothing is inferred on the write path. Discharging nothing is reported, not
  skipped silently.
- **AC9.4** — A `/sig:sweep` check reports rows whose work is provably closed, under NFR4's three
  outcomes. A project whose rows name nothing this check can resolve reports **cannot-evaluate** —
  never clean.
- **AC9.5** — The detection rule is **narrowed against the real file, not reasoned into**. The
  literal reading — *any* unit id mentioned in a row heading — flags 4 rows on Signal's own backlog,
  of which **3 are references rather than subjects** (*"absorbed into `M5.E12`"*, *"the class behind
  `B87`–`B90`"*, and two `##` section headers). The shipped rule reads the id a row **leads with**
  and flags **1**, which is the real one. Same move FR8 made when 62 episodes became 5.
- **AC9.6** — Evaluability is measured on the corpus and lands in the NFR5 table, alongside the six.
- **AC9.7** — A row that stays open **on purpose** can say so, in the heading a reader sees, and the
  check honours it. Added during S7 rather than at DISCUSS: work legitimately outlives the unit that
  named it, and with no way to declare that, such a row is flagged every run forever — which is how a
  detector earns the mute that makes it useless. Recorded as an amendment because a shipped behaviour
  with no requirement is invisible to this Epic's own FR1 coverage diff.
- **AC9.8** — A closure source that **could not answer** never renders as a source answering *no*.
  The two sources — unit closure and the bug catalog — are asked separately, and a row whose source
  was blind is reported blind. Found by the Epic's own review: with no readable `STATE.md` every unit
  resolves `cannotDetermine` while a readable `BUGS.md` kept the merged map non-empty, so the check
  reported **clean** on Epic-named rows — `M5.E19`'s exact defect, inside the release whose NFR4
  forbids it.

## Non-functional requirements

- **NFR1 — RED against `main`.** Every guard shipped here lands with a test **demonstrated to fail**
  against `main` before the fix. A guard whose test has never been seen red is the class this Epic
  exists to kill, committed by the Epic. Where a test is written after its implementation, it is a
  **declared deviation** (`D` 2026-08-06), never counted as strict-Nyquist compliance.
- **NFR2 — Offline and deterministic.** Every check runs with no network and returns the same answer
  on the same input.
- **NFR3 — Fail-open at read surfaces.** Checks wired into `/sig:status` / `/sig:resume` never break
  the briefing (`B70`).
- **NFR4 — Three outcomes, everywhere.** No check in this Epic may render *"could not evaluate"* as
  *"clean."* Stated once here and binding on FR1, FR2, FR7, FR8, FR9.
- **NFR5 — Measured on the real corpus.** Each check reports how many of the ~12 local projects it can
  actually evaluate. A detector silent on 11 of 12 reads as clean when it never looked.
