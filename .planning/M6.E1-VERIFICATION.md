`AC1.2b` are invisible to `diffRequirementCoverage` (`B100`, letter-suffixed ids). The tool reported

hand-verification of those two is exactly the unverifiable class this Epic's own milestone was named

**2. The VALIDATION cross-check did not run.** `checkValidationConsistency` returned
`cannot-evaluate` because `M6.E1-VALIDATION.md`'s completeness dimension names no requirement ids in
a form it can read. So the claim *"every planned test exists"* under § Nyquist rests on my reading of
the mapping, **not** on a machine comparing the two documents. This is a *could-not-check*, not a
clean result, and it is the second of two independent checks that failed to evaluate this Epic.

**3. `AC4.4` and half of `AC5.1` are structurally unverifiable from a branch.** The published catalog
must be served from `signal.insightriot.com/install/marketplace.json`, and the custom domain serves
the **production** deployment, which tracks `main`. The same applies to the GitHub fetch half of
`AC5.1`. Both are owed at merge. **Nothing in this report should be read as evidence that the
published install path works** — it has never been executed.

**4. The install was proven on one machine, one OS, one Node.** macOS 23.6.0, Node 22.13.0, a local
`file://` clone. Not proven: Linux or Windows, a real network fetch, a `git-subdir` fetch of any
kind (the mechanism the published catalog depends on was **read from a cached catalog entry, never
executed**), or any Claude Code version other than this machine's.

**5. The migration nudge is unmeasured, and the ceiling says so.** This Epic added 5 directive lines
to `doctor.md`; **all five landed in *no observable trace*** (483 → 488 directives, trace-measurable
unchanged at 104), so published adherence coverage **fell** 21.5% → 21.3%. Signal cannot observe
whether a user who sees the P6 nudge acts on it. The nudge is a better mechanism than a web page,
and it is still prose.

**6. `.planning/` is out of a user's *install*, not out of the public repository.** This Epic stops
270 files being copied into every plugin cache. It does nothing about them being readable on GitHub,
which is a separate deferred decision (`B99`, `MILESTONE-6.md` § Out of scope). Reading this report as
*"the working notes are private now"* would be wrong.

**7. No user other than the maintainer has installed from the new path.** Every number here comes
from this machine. The four non-Signal testers have not seen it.

**8. The four NFRs are outside the coverage check entirely.** `unattributableGroups` returns
`NFR-1`…`NFR-4`: they carry no `AC` ids, so `diffRequirementCoverage` cannot attribute evidence to
them and correctly does not pretend to. Their status is prose in `REQUIREMENTS.md` — `NFR1`
(reversibility) and `NFR2` (supply integrity) hold by construction, `NFR3` is **moot** rather than
met, `NFR4` is N/A by shape. **None of that was machine-checked**, and the coverage verdict of
`covered` says nothing about any of them.
