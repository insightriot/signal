### FINDING 1 — 10 of 93 new tests passed against their own pre-implementation baseline

Measuring rather than attesting is what surfaced this; an attestation would have said "written
first" and been true, while concealing that ten of them could not have failed.

Classified honestly, not waved through:

**Legitimate regression guards (3)** — they assert *preserved* behaviour, so passing before and after
is correct:
- `still records the phase — the index write is a side effect, not the job`
- `two sweeps over unchanged input render byte-identically`
- `keeps the briefing inside its 50-line cap`

**Legitimate posture locks (2)** — already disclosed in `M5.E16-PROGRESS.md` as *"a lock rather than
a fix"*. AC5.3 asks for a posture to be *asserted*; it was already true:
- `every hook is warn-only — none writes to the filesystem`
- `no hook imports the index regenerator`

**Vacuous at baseline (5)** — every one is an **absence assertion** (*"X does not appear"*), and an
absence assertion is trivially true before the thing exists:
- `a failing index regeneration never breaks the transition`
- `the sweep is still read-only with the drift checks wired in`
- `says nothing at all when there is nothing a person must act on`
- `does NOT surface self-clearing findings`
- `is absent entirely when no drift result is passed`

**This is structural, not carelessness: you cannot write a red-first absence test for a feature that
does not exist yet.** The mitigation is that each of the five has a *positive* sibling that WAS
measured red, and the pair is what carries the evidence:

| Vacuous absence assertion | Red-first sibling carrying the evidence |
|---|---|
| failing regen never breaks the transition | `writes INDEX.md` + `refreshes a stale INDEX.md` |
| sweep still read-only | `a STATE contradiction is not filed under structural or advisory` |
| the three resume-absence tests | `renders one line for category-3 findings, with a count and a pointer` |

**Stated plainly so REVIEW does not have to rediscover it: this Epic's Nyquist evidence is 83 of 93
tests measured red-first, 5 legitimate guards/locks, and 5 absence assertions whose red baseline is
vacuous by construction.** It is not 93/93, and claiming 93/93 would be exactly the
completeness-claim defect `analysis/CLAIM-INTEGRITY-ANALYSIS.md` names.

### FINDING 2 — check `(a)` still has fixture-only evidence

`phase-behind-artifacts` fired **zero** times across all 13 real projects. Its red fixture is
measured (part of S3's 18/18), so it demonstrably *can* fire — but **the live corpus cannot
distinguish "precise" from "inert."**

The plan said so, `tools/lib/state-drift.js` says so in its own source, and it is repeated here
because it is the claim most likely to be waved through: **(a)'s silence in the field is not
evidence that it works.** Its only evidence is the fixture.

Not a failure — the check is correct and cheap, and dropping it would trade a known-narrow detector
for no detector. Recorded as a known limit.

## 6. What VERIFY could not establish

Stated rather than omitted, in the tradition this project has been keeping:

1. **Whether check `(a)` ever fires in the field.** Zero hits across 13 projects. Only time and more
   projects settle this.
2. **Whether the six checks are the *right* six.** Precision is measured; **recall is not, and cannot
   be** — there is no oracle listing every STATE-vs-world contradiction that exists. The corpus can
   only show that what fired was true, never that everything true fired.
3. **Whether `/sig:update` works end-to-end against a real marketplace.** The pure half is tested;
   the `claude plugin update sig` call itself was **not executed** — running it would have mutated
   this machine's plugin install mid-Epic. The subcommands were confirmed to exist by running
   `claude plugin list` (exit 0), which is weaker than an end-to-end run and is labelled as such.
4. **Whether the heal categories are correctly assigned for checks with no live instance.** `(a)`'s
   category-3 assignment is a judgement, not an observation.
