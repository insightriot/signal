## What this Epic does for the first time — and it is scheduled FIRST (M5.E17 FR1)

**`commands/plan.md` Step 1b has a "no candidates" branch that has never executed.**

Not the thing this Epic builds — a branch that has existed since the drain shipped, was written for
a real situation, and **cannot be reached in this repository**. Step 1b says:

> **No candidates** → emit the one-line note `(no inbox candidates to drain)` and continue to Step 2.

Signal's inbox holds exactly **one** live candidate: the trigger-watchlist standing entry, marked
*"never promote, merge, or delete."* Every disposition verb is illegal or nonsensical for it, so the
only lawful action is `skip`, and `skip` returns it next drain. **The live count is structurally
pinned at ≥1, so the zero-candidate branch has never run — on this repo, not once.**

`FR2` is precisely what unpins it. So:

**Therefore S2 is wave 1**, and its first act after the marker lands is to **re-run the drain and
watch that branch execute**. If it is broken — a bad template string, a wrong variable, an
exception — it breaks here, against a two-entry inbox, rather than the first time some stranger's
project reaches a clean inbox and the drain throws on the happy path.

**A second, weaker first, named and deliberately not scheduled first:** this Epic will be the first
non-`M6.E2` Epic to add a row to the `REACH` table. That is additive to a frozen object with an
existing accessor; the risk is ordinary and does not earn wave 1.

## Slices

### S1 — the plan reads its own numbers · **wave 2** · **L**

**Vertical:** a plan carrying a threshold that cannot satisfy its own criterion is surfaced to the
reviewer by name, end to end, on a real plan.

- **Covers:** `FR1.1` (`AC1.1a`–`AC1.1d`), `FR1.2` (`AC1.2a`–`AC1.2c`).
- **Deliverable:** a plan-task parser (`###`-slice aware — `parseSections` is h2-only and does not
  fit, RESEARCH §1); a detector returning tasks carrying **both** a number and an acceptance
  criterion; a `plan-internal-consistency` row in `REACH` populated from a **corpus measurement
  taken during this slice**, rendered via `describeReach`; and the `testability` obligation in
  `agents/verifiers/plan-checker.md`.
- **⚠ Recall over precision, stated at the point of use.** The detector produces a **worklist**, not
  a finding list (RESEARCH §5). A false positive costs one paragraph of reviewer attention; a false
  negative lets a contradiction through unexamined. Precision is deliberately **not** this check's
  headline number — the inverse of `M6.E2`'s contract, and it must be written next to the code so
  the next reader does not "fix" it toward precision.
- **Test strategy (TDD, RED first):** the `M4.5.E9` S1.t11 excerpt as a **copied fixture** (never a
  live read of `.planning/archive/` — `/sig:archive` exists to move that file) → detector returns
  it. A numberless plan → empty list **and `clean`**, not `cannot-evaluate`. An unreadable/absent
  plan → `cannot-check`, asserted **distinct** from `clean` (`B39`). One test asserts `REACH`
  carries the new id, so a detector shipped without a measured reach turns the suite red.
- **Not in this slice:** judging whether a formula *satisfies* a criterion. That is semantic, it is
  what `M5.E10` refused to fake (`AC0.1`), and the obligation hands it to the prompt.

### S2 — a standing entry stops being an undrainable candidate · **wave 1** · **M**

**Vertical:** the inbox can report itself clear.

- **Covers:** `FR2.1` (`AC2.1a`–`AC2.1c`), `FR2.2` (`AC2.2a`–`AC2.2e`).
- **Deliverable:** `parseEntries` returns `standing: true` for an entry carrying `<!-- standing -->`
  in its header region; `listDrainCandidates` excludes standing entries; standing entries are
  retrievable as their own category; the marker added to the trigger-watchlist entry.
- **Marker read reuses `parseEntries`' existing header-region, fence-aware discipline**
  (`drain.js:176-186`), rather than inventing a scan (RESEARCH §4).
- **Test strategy (TDD, RED first):** marked entry → `standing: true`, excluded from candidates.
  Marker inside a fenced block or deep in a body → **not** marked (`AC2.1b`). An inbox with no
  markers → candidate list **byte-identical** to today (`AC2.2d`), which is the regression guard for
  every other project. A test asserting `parseTriggerWatchlist` is untouched (`AC2.1c`).
- **Then run the never-run branch** (see above) and record what it printed.
- **Not in this slice:** any `/sig:add --standing` flag (`D-M6E4-5`).

### S3 — the research reaches the builder · **wave 3** · **M**

**Vertical:** an executor dispatched on a task whose research names an exemplar follows it instead
of re-deriving the pattern.

- **Covers:** `FR3.1` (`AC3.1a`–`AC3.1c`), `FR3.2` (`AC3.2a`–`AC3.2d`).
- **Deliverable:** `{phase}-RESEARCH.md` declared in `agents/executors/executor.md` `## Inputs`;
  a per-task exemplar reference; **Files likely touched** and **Out of scope** in
  `commands/plan.md`'s required-contents list; the `completeness` fold in `plan-checker.md`.
- **Advisory, not fatal** (`AC3.2d`, `D-M6E4-7`): a plan lacking the fields is **reported**. Corpus
  plans predate the fields and were correct when written; failing them retroactively is the
  retroactive-guard mistake, not a fix.
- **Test strategy:** a cross-document test asserting `executor.md`'s declared inputs include
  RESEARCH — the `M5.E17` shape (one document checked against another), which is the only kind of
  test that can catch a prompt-layer omission. A test that `plan.md`'s contents list and the
  planning skill's field set **agree**, so leak 2 cannot silently reopen.
- **Not in this slice:** bulk-injecting RESEARCH.md into every task context (`AC3.1c`).
