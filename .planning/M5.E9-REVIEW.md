## C1 (Critical, **FIXED**) — the new sweep check told every healthy project its history had been destroyed

`checkPhaseLog`'s truncation heuristic flagged *"one entry per phase name"* as the fingerprint
of the pre-v0.1.12 collapse. **That is exactly what a normal single run looks like.**

Proven, not reasoned: a mid-run fixture at `phase: VERIFY` holding
`[DISCUSS, PLAN, EXECUTE]` — a completely healthy project — produced

> *"completed_phases holds exactly one entry per phase name — the fingerprint of the
> pre-v0.1.12 dedupe … earlier entries were destroyed. THERE IS NO REPAIR."*

**Signal's own repo escaped only by accident** — it happens to have a `STATE-HISTORY.md`, and
the heuristic's `!existsSync` guard suppressed it there. Dogfooding would never have caught
this.

**Why Critical rather than Important:** it is a false alarm that is *alarming, unactionable and
wrong*, aimed at users who have nothing to fix. It is the exact mirror of the reassuring lie
AC7.4 forbids — a frightening one. And it shipped inside the very check written to be honest
about what cannot be repaired.

**The deeper finding, which is why the fix is removal and not a better heuristic:** *a past
collapse is not detectable from the file.* The evidence was destroyed by the bug being
detected, and a collapsed list is byte-indistinguishable from a healthy run. A cleverer
heuristic would only fail less obviously.

**Fix:** the truncation check is **removed**, with the reasoning left in the code so it is not
re-invented. The one-time disclosure moves to the **v0.1.12 release notes**, where a one-time
fact belongs, instead of a per-run alarm that cries wolf forever. Three regression tests: a
healthy project reports nothing; a malformed entry still reports structural; an over-long list
still reports advisory — so the check is demonstrably *narrowed*, not disabled.

## I1 (Important, **ACCEPTED with documentation**) — `/sig:resume` reads "0/7 phases done" immediately after a linear ship

FR5 clears the live list at ship, so the first thing a user sees after shipping is
`Phase: SHIP (0/7 phases done)`.

Defensible (the *next* run has zero done) but jarring at exactly the moment the user wants
confirmation something completed. **Not fixed here** — the honest fix is for the resume banner
to render the archived run's count, which means teaching `resume.js` to read
`STATE-HISTORY.md`. That is a **new capability in a phase-close, not a defect fix**, and
Slice 2 is already the largest unit in the Epic.

**Recorded as a `BUGS.md` entry rather than absorbed**, so it is a tracked item and not a
surprise the next reader has to rediscover.

## I2 (Important, **FIXED at VERIFY**) — `NFR2` was violated by the FR4 implementation

Quarantined entries were dropped from the live list and merely *returned*, so any caller
ignoring the return value destroyed them. Caught and fixed during EXECUTE (deviation 8);
recorded here because it is the same defect class the Epic exists to fix, committed by the fix
itself. **The lesson generalizes: "returns the removed items" is not "does not delete."**

## Security — full audit, no findings

| Vector | Assessment |
|---|---|
| **Path traversal via `current_epic`** | `epicArchiveDirFor` reads `current_epic` **straight from the file**, which is user-editable. Traversal is **structurally impossible**: the anchored regex `^(M\d+(?:\.\d+)*)\.E(\d+)$` returns `null` for anything else, and a `null` dir skips the archive entirely. `../../etc` cannot produce a path. Verified by the drift-guard test's malformed inputs. |
| **Write confinement** | Both archive targets are literals or regex-derived under `.planning/`. No user string reaches a path segment. |
| **Atomicity** | All writes go through `atomicWrite`; archive-before-mutate ordering means a failed archive throws **before** the state write, so history cannot be lost to a partial failure. |
| **Lock discipline** | Every new write path runs inside `withStateLock`. `recordPhase` re-reads inside the held lock — redundant but not racy. |
| **Denial of service** | The trim bounds `completed_phases` at one run; unbounded growth (the `B8` 529 KB `STATE.md` shape) is now structurally prevented. |
