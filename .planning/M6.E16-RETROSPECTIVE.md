# M6.E16 — Retrospective: Epics and units as records

**Label:** *"Epics and units as records"*. The third storage Epic after `M6.E13` (items as records) and
`M6.E15` (other projects move onto the store). FULL tier, `attention: checkpointed`. An Epic, or the unit
of a project that does not use Epic IDs, was worked out from filenames, a hand-kept milestone table and
which folder a file sat in. It is now a record: `.planning/work/units/<ID>.json`, status from events, a
close that needs proof on the default branch.

## What changed mid-flight

- **AC6.4 was rewritten twice.** "Behaves as on `v0.1.50`" was false the day it was written. It ended as
  four named kinds of difference, each with a reason, and a fixture of `v0.1.50`'s real answers that the
  suite compares against (`D-M6E16-20`).
- **S10 was added after S9** for three gaps the build had exposed: a finished Epic's narrative leaves
  `STATE.md` when its close is confirmed, `/sig:docs-archive` says how to place a hold, and one stale
  archive message.
- **The squash recovery was designed three times.** Refuse (pass 2 found the documented recovery could
  not be followed), swap automatically (pass 3 found it closed unmerged work), list and ask
  (`D-M6E16-26`, held under pass 4).
- **Two things outside the Epic's stated scope went in at the ceiling, on Brett's word:** the
  default-branch guess (`D-M6E16-27`) and reading the stored default branch directly. Both change item
  closes on every project, with or without unit records.
- **"Closed milestones' files are not touched" was narrowed** (`D-M6E16-30`): a milestone file that
  already carries the table markers is rewritten when its table is out of date. Without that, the last
  Epic of a milestone could read "closing" for good.

## What assumptions broke

- **That "as on the last release" can be asserted.** It had to be measured against the last release's
  code, answer by answer. Two VERIFY loops went to finding that out.
- **That a test written with a fix holds the fix.** Pass 2 reverted four fixes and their tests stayed
  green. From round 3 on, every fix had to show its test failing with the guard removed.
- **That git can tell a squashed branch from a branch nobody merged.** It cannot; after a squash both are
  "a commit not in this history". Any rule that acts on that alone closes unmerged work.
- **That removing a guess only removes risk.** A safety check depended on the guessed default branch.
  Taking the guess away switched the check off in exactly the clones the change was for.
- **That `rev-parse --abbrev-ref origin/HEAD` names the default branch.** It prints the shortest
  unambiguous name, and a pushed tag changes what that is. This was on `main` since `v0.1.48`.

## What surprised us

- **Every full pass found real defects in a different corner, and none repeated.** Pass 1 the close
  gate, pass 2 the table and the migration, pass 3 the squash recovery, pass 4 the default branch and
  the done-Epic guard. The diff is about 32,000 lines; four passes did not exhaust it.
- **Fix rounds 3, 4 and 5 each introduced a defect the next reader found**: the automatic swap, the
  switched-off safety check, and two regressions in round 5. The narrow review of round 5 found its two
  in under fifteen minutes.
- **The highest-severity security finding predated the Epic.** It was reached only because the Epic put
  Epic closes and narrative eviction on top of the same lookup.
- **Signal's own records never showed any of it.** After each finding the live store was checked
  read-only: 0 open items in closed units, 0 closes off the default branch, one small wording loss in one
  row. The defects were in routes Signal's own history had not taken.

## What we'd do differently

- **Measure a parity claim before writing it as a criterion.** Generate the old version's answers first
  and write the criterion from the differences.
- **Require the mutant from the first fix round, not the third.** "Show the test fails with the guard
  removed" would have caught pass 2's four hollow tests a day earlier.
- **Give every fix round its own fresh read, sized to the round.** One reviewer on 1,000 lines found
  more per minute than three reviewers on 32,000, and the full passes were not converging.
- **Put a design that changes recorded status to the user before building it.** The automatic swap was
  treated as plumbing. It decided what counts as done, which is the user's call (`D-M6E15-25` had already
  said so for the migration).
- **Split the Epic.** Records and close-with-proof, the migration, and the generated table are three
  Epics' worth of surface. One 32,000-line diff is past what a fresh reviewer can hold.

## What to feed back into Signal

- **The REVIEW loop count is kept by hand.** `loopStatusFor(state, 'REVIEW')` read 0 through four passes,
  because `completed_phases` records a phase when it is left and REVIEW was never left. The ceiling held
  only because the report said so in prose. A driver would have looped.
- **`review.md` has no step for "re-review the fix round".** PASS-WITH-FIXES caps the fix at 50 lines and
  says nothing about who reads it. A narrow fresh read of the fix diff should be the stated step after
  any FAIL loop.
- **A fixer's brief should carry "red on parent, mutant killed" by default**, and the executor agent
  should report both without being asked.
- **Timing tests fail under load** (`SIG-303`). Reviewers running mutants in a worktree hit them
  repeatedly; each false red costs a re-run and teaches people to discount red.
- **Residue is filed:** `SIG-303` … `SIG-311`. The largest: the units dry run does not list what it
  replaces in a marked milestone file other than the current one (`SIG-310`).

## Anti-rationalization moment

At pass 4 the count was 1 Critical, 1 High and 5 Important after four passes and a promise of a "bounded"
round, and one option was to ship with documented limits: the Critical needed an unusual clone, and
the row deletion was in a region the docs call generated. Both arguments are how a wrong status and a
deleted line get shipped. The other temptation ran the opposite way: a fifth full pass, to be able to
say the whole Epic had been read clean. Four passes had shown it would find a new corner, not a clean
one. What was put to Brett was the narrower, checkable thing: fix the six, have someone new read only
those fixes, and say plainly that the whole was not re-read.

At the narrow review the bar Brett had set was met with five Important findings still open. Two were
regressions from that round. They were fixed and disclosed rather than shipped under "the bar was met",
and the report says that those 28 lines have not themselves had a fresh read.
