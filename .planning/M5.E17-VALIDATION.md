### A finding from running it — the test must normalise markdown emphasis

The probe's **first** run reported **5/5 fail**, including `plan.md` and `discuss.md`, which the audit
had found correct. The probe was wrong, not the audit: `plan.md:173` reads
`Run it **after** the commit`, and a naive `/after\s+the\s+commit/` does not match across the `**`.

**Spec consequence, binding on S2.t1:** the ordering assertion **must strip markdown emphasis
(`**`, `__`, `*`, `_`) before matching.** Without it the test false-REDs the two files that are
already right — and a test that fails on correct input gets "fixed" by weakening it.

*Worth noting where this sits: a measuring instrument producing a plausible-looking wrong result is
M5.E8's retro sentence, and it happened again here, at PLAN, inside the Epic about it. It was caught
because the number was checked against an independently-derived one — the same way all five of
M5.E13's were caught, and again not by a mechanism.*

### Test-type rationale

- **Why the two corrected ACs are integration, not unit.** NFR1′ asks that one instruction be pinned
  against another. A substring grep pins nothing — it asserts a string exists, which is satisfied by
  the string existing in a file that contradicts itself elsewhere. AC2.1′ and AC3.1′ **parse multiple
  statements and compare them**. That is the difference M5.E16 exists to institutionalise, and doing
  it by grep here would rebuild the class this Epic is closing.
- **No E2E.** There is no user flow: three of four items are instruction text, the fourth is a data
  pass over a local markdown file.
- **Coverage floor.** 9 ACs → 9 named assertions, no AC without one, no assertion that passes today.

### Known non-coverage, stated

- **The audit test (AC3.2) is a record, not a guard.** It asserts the audit's *conclusion* is written
  down; it cannot detect a future sixth `markFresh` call site appearing. AC3.1′ covers that —
  it enumerates call sites dynamically rather than against a fixed list. **Deliberate split:** the
  guard is AC3.1′, the record is AC3.2.
- **AC4.2's mechanical flag is only as good as the CHANGELOG/BUGS status fields.** If a bug is fixed
  but its row still reads `confirmed`, an entry will not be flagged superseded. Batched approval is
  the backstop — Brett sees the group and can reject it. Stated rather than assumed away.
