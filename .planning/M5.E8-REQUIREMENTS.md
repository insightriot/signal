# M5.E8 — Requirements: the measurement foundation

**Epic:** M5.E8 · **Tier:** FULL (inherits `PROFILE.md`) · **Decisions:** D-M5E8-1 … D-M5E8-3
**Opened:** 2026-07-27, immediately after v0.1.12 · **Deliverable:** a harness **and a number**

---

## Objective

Answer, with evidence, the question M5.E7 said Signal cannot currently answer: **does a Signal
instruction change what an agent does?**

**The occasion is not theoretical.** M5.E9 (shipped hours ago) added a phase-entry instruction to
four command files and **could not prove any agent follows it** — it labelled that limit in its own
test-file header rather than let a passing test imply otherwise. Every prompt-shaped port parked in
`SIGNAL-V2-ROADMAP.md` is gated on this Epic for the same reason.

**Success looks like:** a maintainer runs one command, and gets a dated file saying *"of the N
instructions that can be measured this way, M were obeyed"* — plus an honest statement of how large
N is against the whole corpus.

**Explicit non-goal:** measuring Signal's prose-shaped guidance. See FR5 — the ceiling is a
deliverable, not an excuse.

---

## Functional Requirements

### FR1 — A harness that runs a Signal command against a real agent and captures traces

**AC1.1** One entry point runs a named command against a scratch fixture project and records what
changed: files created, `STATE.md` fields, commits, artifact contents.
**AC1.2** It is **out of the test suite** (D-M5E8-1). `npm test` stays deterministic, offline and
free. A test-suite guard asserts the harness is not imported by any test.
**AC1.3** Runs are **isolated** — a scratch fixture per run, never the invoking project.
**AC1.4** A run that cannot reach an agent (no credentials, offline) **fails loudly with that
reason**. It must never report "0 obeyed", which is indistinguishable from a real finding.

### FR2 — The control run: delete the instruction, compare

**AC2.1** For each measured instruction the harness runs the command **twice** — as written, and
with that instruction line removed — against identical fixtures.
**AC2.2** The verdict is the **difference**, not the presence of the trace. A trace that appears in
*both* runs proves the instruction is **inert**, which is a finding, not a pass.
**AC2.3** Nondeterminism is surfaced, never hidden: **N runs per arm** with the spread reported. A
single-run verdict is not permitted.
**AC2.4** The deletion is applied to a **copy**; the real command files are never mutated.

### FR3 — A canary set of instructions that actually have traces

**AC3.1** An enumerated set of instructions from `commands/*.md`, each paired with its observable
trace, in a file a reader can audit.
**AC3.2** **`B41`'s fix is in the set** — *"call `transitionPhase(baseDir, '{PHASE}')` at phase
entry"*, trace = `phase` advanced + `completed_phases` grew. It is the instruction M5.E9 shipped
without being able to verify, which makes it the honest first subject.
**AC3.3** Each entry states its trace **before** any run — a trace chosen after seeing the output is
a rationalization.

### FR4 — A dated, committed result record

**AC4.1** Each run appends to `.planning/ADHERENCE-LOG.md`: date, commit sha, model, per-instruction
verdict, spread.
**AC4.2** **Append-only** — a later run never rewrites an earlier one. This file is a measurement
history; the Epic that shipped `B44` does not get to collapse another log.
**AC4.3** A run is reproducible from what the record states.

### FR5 — The coverage ceiling, quantified and published

**AC5.1** Count the instructions in `commands/*.md` and classify each as **trace-measurable** or
**not**, with the rule for the split written down.
**AC5.2** The resulting fraction is published in `ADHERENCE-LOG.md` **and in the Epic's
retrospective.** If it is small, the small number ships.
**AC5.3** The record states plainly that the unmeasured remainder is **unmeasured, not passing.**
*This is the AC most likely to be quietly softened later, so it is written as its own criterion.*

### FR6 — The anchor: a pre-ship checklist line

**AC6.1** `commands/ship.md` § 1 gains a line prompting an adherence run when command *wording*
changed, beside the existing `docs/map` line.
**AC6.2** Anchored to the checklist, **not a trigger** (D-M5E8-3) — `B39` proved Signal's triggers
have never been walked.
**AC6.3** A test asserts the line exists. *Presence only — it cannot prove the maintainer acts on it,
and per M5.E9's precedent that limit is labelled where the test lives.*

## Non-Functional Requirements

**NFR1 — The suite stays deterministic, offline, free.** The harness is opt-in; nothing in `npm test`
calls an agent or the network.
**NFR2 — Cost is visible before it is spent.** The harness reports its planned run count and asks
before spending.
**NFR3 — No fabricated results.** A failed or partial run is recorded as failed. Never a number that
looks like a measurement but is a default.
**NFR4 — Honest nulls.** "The instruction had no measurable effect" is a first-class result and is
recorded as such, not retried until it passes.

**FULL-tier ops checklist:** health probes, graceful shutdown, request logging, security headers,
rate limiting — **all N/A.** Local CLI harness, no server, no listener. Recorded rather than skipped.
