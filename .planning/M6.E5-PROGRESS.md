### Findings 5 and 6 — both found by RUNNING the report, neither by a test

`S4` finished with 25 green tests. Then the report was rendered against this repo, and it was wrong
in two ways at once.

**`Bash(git:*)` was proposed** — alongside the specific `Bash(git log:*)`, `Bash(git add:*)` and the
rest. A bare `git` rule grants `git reset`, `git rebase` and `git push --force`, which is exactly
what `AC1.2b` exists to withhold. ⚠ **`classify('git reset')` was correct the entire time.** The
defect lives *between* a correct classification and the rule rendered from it, so no test of
`classify` could ever have caught it. Fixed by refusing a bare-binary rule whenever the table holds
any non-`propose-allow` key beneath that binary.

**The flow half proposed `cargo build`, `go test`, `bundle exec`, `jest run`, `yarn test` and
`npx prisma` — for a Node project.** Every one arrived from `plugin/agents`, where command files
*describe other people's stacks*. This is precisely the over-proposal `D-M6E5-3` and probe 2 warned
about, and the plan amendment had already said provenance must be a classification input — **it
simply was not, until the render made it visible.** Fixed by a rule that gives the flow/stack split
real work: an ecosystem-specific binary can never be proposed by the flow half, only by the stack
half, which is derived from the host's actual manifests.

**Both are now pinned by tests that fail if either returns.** The lesson is the Epic's own wave-1
rule arriving a second time: shipped-but-never-run is the best defect predictor, and 25 green tests
did not substitute for looking at the output once.

### Finding 3 — the extractor rule, measured rather than assumed

Requiring an argument was not enough. It admits **74 distinct "binaries" over 224 occurrences**, and
the overwhelming majority are prose: code identifiers (`result.wrote`, `state.phase`,
`findings.length`), enum values (`trivial`, `familiar`, `off`), and English inside backticks
(`documentation lives in …`, `tests co-located with source`). A structural extractor cannot tell
`npm test` from `plain markdown` — both are a lowercase word followed by another word.

**The rule that works: a known binary OR a flag-shaped argument.** Measured: **74 distinct → 21**,
every dropped span genuinely prose. The flag clause is what preserves the point — `frobnicate
--hard` is unknown, flagged, detected, and reported unclassified, so a **new** binary is still
visible. A bare allowlist would have destroyed that.

⚠ **Published residual:** an unknown binary written as `binary subcommand` with no flag is not
detected. Measured 2026-08-27: **zero such instances in this corpus.**

### Finding 4 — `gh` is never prescribed in the payload

The only `gh` in `plugin/` is the bare word inside prose (`ship.md:271` — *"no `gh`, no auth, no
network"*). The real guidance — `gh pr create --fill`, `gh pr merge --squash` — lives in the
**repo-root `CLAUDE.md`**, which is not part of the shipped payload and is therefore not scanned.

**So a flow-derived proposal offers no `gh` rules, while the hand-cleaned project settings carry
three** (`gh auth`, `gh repo`, `gh api`). That is a genuine under-proposal, pinned by a test rather
than patched away, and it is the first real data point for `S5.t3`'s outcome metric — which exists
to publish exactly this direction of miss.
