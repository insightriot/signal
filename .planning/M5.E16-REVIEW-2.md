### Suggestions

**S3 — the applicability probe misses the unprefixed `RETROSPECTIVE.md`.**

```js
files.some((f) => f.endsWith('-RETROSPECTIVE.md'))   // 'RETROSPECTIVE.md' => false
```

A linear project whose only retrospective is the unprefixed `RETROSPECTIVE.md` is judged *"has no
retrospectives at all"* and reports **not-applicable**. `conversor` has both forms so it is
unaffected, but the narrower case exists.

**Not fixed, deliberately.** The failure mode is **fail-safe** — it yields `not-applicable` with a
reason, never a false `clean`, so it is not C1's class and does not threaten the module's contract.
Fixing it means another test plus another full-corpus re-measure, and looping a third time for a
non-defect is how a Suggestion gets promoted by momentum rather than by merit. **Recorded, not
actioned** — the honest trade, stated.

## What both review passes cost, and whether it was worth it

The first pass found a Critical that **1933 passing tests, a green validator, a clean lint, a clean
network audit and a full VERIFY had all missed** — because it was a *wrong answer*, not a broken
build. The Epic's own thesis is that a detector reporting "clean" when it cannot see is worse than
no detector, and the first version of check `(c)` did exactly that.

It was caught by **reading four sibling checks against each other** and noticing that three handled
non-strict Epic IDs and one did not. That is the same method that caught every other instance in
this Epic — re-deriving something already written down — and **still not a mechanism**.
