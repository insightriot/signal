## FR1 applied to itself — what this Epic does for the first time

FR1's new rule is *name the thing this Epic will do for the first time, and schedule it in the first
wave.* Applying it to M5.E17:

**The first-time thing: the drain's write path has never run at scale.** `applyDispositions` and
`evictTerminalToLedger` have only ever executed over a handful of entries. FR4 puts **48** through
them in one pass. Second first: **routing an entry INTO the trigger watchlist** (D-M5E17-2) is a
path that has never been executed at all.

**Therefore S1 is wave 1** — the mechanical pass and the *dry runs* of both write paths, before any
real mutation and before Brett is asked to approve anything. If the bulk path is broken, it breaks
against a dry run, not against 48 of Brett's captured ideas.

*The Epic applies its own new rule to itself on the first attempt. That is the cheapest possible
test of whether the rule is writable.*

#### S2.t1's enumeration predicate — specified, because the judgment must live in the test

AC3.1′ says *"for every command that instructs a `markFresh` call."* That predicate is not obvious —
the naive grep hits 7 files, and two of them must not be there. Encoding the judgment is part of the
task, not something EXECUTE improvises:

| Rule | Value | Why |
|---|---|---|
| **Include** | file matches `/markFresh\(/` — **call syntax, open paren** | Distinguishes an instruction-to-call from a mention. Verified: this admits the 6 real call sites and excludes `execute.md:50`, whose "Why this exists" prose names `markFresh` with no parens. |
| **Exclude** | hardcoded allowlist `['checkpoint.md']`, **with the reason in a code comment** | `/sig:checkpoint` **is** the manual refresh command — `markFresh` against HEAD is its whole purpose, not a phase-close stamp. An explicit, reasoned exclusion is honest; a regex tuned until it happens to miss the file is not. |
| **Assert** | the file states after-the-commit ordering, **after stripping markdown emphasis** | Required — see VALIDATION § "the test must normalise markdown emphasis". Without it the test false-REDs `plan.md` and `discuss.md`, which are already correct. |

A **new** command that calls `markFresh` is caught automatically (the predicate enumerates; it does
not read from a fixed list). A new command that must be exempt fails loudly until someone adds it to
the allowlist with a reason — which is the intended cost.

#### `B55` note — S2.t3 knowingly widens the shared-wording problem

Making `verify.md` and `review.md` byte-identical to `plan.md`/`discuss.md` puts **four copies** of
the ordering instruction in the corpus. That is exactly the tension `B55` records: the adherence
canary's control arm mutates **one file**, so a shared wording it cannot isolate leaks to the agent
via a sibling.

**Doing it anyway is the right call** — silent drift between four call sites is the worse failure, and
it is the failure that produced FR3. But it is recorded here rather than discovered later: **any
future canary on the `markFresh` ordering instruction inherits `B55`'s defect and cannot be trusted
until M5.E15 fixes the control arm corpus-wide.** M5.E17 must not widen that problem silently.

**Dependency.** None. Touches `ship.md`, `verify.md`, `review.md`.

## Drain disposition deferred at Step 1b — recorded, not skipped

`commands/plan.md` § 1b offers **"defer all remaining"** for a large first run. **Rejected here, deliberately.**

`listDrainCandidates` filters on `!e.dispositioned` (verified in code, F4.1). A `defer` stamps the
entry, so it never resurfaces as a candidate again. Batch-deferring the 48 would **permanently bury
this Epic's entire subject matter** in the name of clearing the wall — the exact failure FR4 exists
to fix, executed by the step that offers to help.

The disposition pass is therefore **skipped at PLAN** (the step is explicitly skippable) and done
properly in S1/S5: mechanical first, batched approval, then write.
