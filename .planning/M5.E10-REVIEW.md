## Important Issues (should fix)

### I1 — `diffRequirementCoverage` reported a spelling variant as a **missing requirement** · FIXED in-phase

`tools/lib/requirement-coverage.js:118` compared raw strings (`verifiedSet.has(id)`), so a
REQUIREMENTS artifact writing `AC-16.1` against a VERIFICATION writing `AC16.1` reported the
requirement **missing**.

**Why this is Important and not a nit.** FR1's own module header states its failure mode: *"a red
wall derived from the shape of the files rather than from the unit under verification, which is this
Epic's own defect class."* A false `missing` derived from **punctuation** is that failure one layer
down, in the Epic's flagship check, whose whole contract is that *absent is RED, not a warning*. A
check that cries wolf on a hyphen is a check people learn to overrule.

**It is also an asymmetry S1 exists to prevent.** `checkValidationConsistency` — same slice, same
extractor, one file over — has canonicalized on **every** comparison since it shipped
(`validation-consistency.js:198–219`). `canonicalId` was already exported and already used next
door. This half simply never called it.

**Fix:** match on `canonicalId`, **report the original spelling** — an id a reader cannot find in
their own file is worse than no report. Deferred ids canonicalize too. `requirement-coverage.js`,
+13 / −5.
**Coverage:** two new tests in `tests/requirement-coverage.test.js` (cross-spelling covered;
cross-spelling deferred), both failing before the fix.

### I2 — Catastrophic backtracking in `LEADING_ID_RE`, reachable from any `BACKLOG.md` heading · FIXED in-phase

`tools/lib/backlog.js` — the leading-id matcher was written as
`^[\s`*_~✅▶⚠✂]*(?:\d+\.\s*)?[\s`*_~]*(…)`. The two decoration runs are **adjacent, unbounded, and
overlapping**, so a heading that never matches backtracks quadratically.

**Measured, not theorised:**

| Heading decoration | Before | After |
|---|---:|---:|
| 1,000 backticks | 1.6 ms | 0.4 ms |
| 5,000 | 39.7 ms | — |
| 20,000 | 629 ms | — |
| 50,000 | **3,956 ms** | 0.1 ms |
| 200,000 | (not run) | 0.3 ms |

`parseBacklogRows` runs this over **every heading in the file**, and `/sig:sweep` runs
`parseBacklogRows`. A single pathological line — machine-generated content, a pasted block, a
corrupted file — stalls the sweep.

**Threat model, stated honestly:** the input is the user's own `.planning/BACKLOG.md`, so this is
robustness rather than an attack surface. It is still a defect: the tool should not become
unresponsive on a file it was handed.

**Fix:** bound both runs (`{0,40}` and `{0,10}`). Real heading decoration is a handful of characters,
so the bound costs nothing and removes the class. `backlog.js`, +8 / −2.
**Coverage:** a timing assertion in `tests/backlog-discharge.test.js` (200k-char heading under 1 s)
plus a companion asserting a real decorated heading still parses. The first fails before the fix.

## Suggestions (optional improvements)

- **S1 — `readClosureSources` uses `await import()` for two modules that could be static imports.**
  Checked for the reason that would justify it: **there is no import cycle** (`backlog.js` →
  `closure.js` → `state.js` / `work-units.js` / `verdict.js`; nothing in that graph reaches
  `sweep.js`). So the dynamic form buys nothing but does no harm — Node caches the module, and the
  surrounding `try/catch` still covers the call. **Left alone deliberately:** converting it changes
  where a module-load failure surfaces, for zero functional gain, and every changed line should trace
  to a finding.
- **S2 — `renderDischargedHeading` interpolates `by` and `at` into a heading without escaping.** A
  newline in `by` would inject lines into `BACKLOG.md` and silently shift every row's line number
  away from the one just reported to the caller. **Not fixed, and the reasoning matters more than the
  verdict:** `by` is `state.current_epic` and `at` is an ISO date, neither of which can contain a
  newline by any path that exists. Adding a guard for an unreachable input is the kind of speculative
  code this repo's *surgical edits* rule exists to prevent. Recorded so the next person who widens
  the caller sees the constraint.
- **S3 — `parseBacklogRows` counts `<details>` tags inside fenced code blocks.** The fence guard
  suppresses *headings* inside fences but the `<details>` depth counter runs unconditionally, so a
  fenced example containing `<details>` would shift the in-details flag for the rest of the file.
  Narrow (a backlog documenting HTML in a fence), cheap to fix later, and reported rather than
  patched blind.
- **S4 — `backlog.js` imports from `node:fs/promises` twice** (lines 24 and 26). Pre-existing, not
  this Epic's; noted per the *mention, don't silently fix* rule.

## Performance Findings

- **The one real finding is `I2`** — quadratic backtracking, measured and fixed. That is a
  performance defect that presents as a hang, which is why it is filed as Important rather than here.
- **`readClosureSources` is on the expensive side but correctly gated.** `resolveClosures` reads
  every terminal artifact in `.planning/` — real I/O per unit. `backlogDischargeStatus` returns
  **before** calling it when no row leads with an id, which is 11 of 12 corpus projects, so the
  expensive path runs only where it can produce an answer.
- **`parseBacklogRows` is a single O(lines) pass** with no nested scanning; the container/row decision
  is a one-step lookahead over the collected headings, not a re-walk.
- **`walkBugEntries` extraction is neutral by construction** — `deriveBugCounts` now consumes the
  same single pass instead of running its own, so the refactor removed a walk rather than adding one.
  16 pre-existing `bugs-tally` tests pass unchanged.
- **No N+1, no pagination, no bundle, no re-render concerns** — this is a CLI library with no
  database, no list endpoint, and no UI. Saying so beats leaving four checklist rows blank.

## Simplification Opportunities

- **One duplication was removed rather than added.** `walkBugEntries` was extracted from
  `deriveBugCounts` when FR9 needed per-id statuses, instead of writing a second row walker —
  `B82`'s shape is two implementations of "which lines are entries" that agree only by construction.
- **`readClosureSources` returning `null` per source rather than an empty map** is the simplification
  that mattered most: it collapsed a three-way condition (`closed === null`, `closed.size === 0`,
  `!closed.has(id)`) that was silently answering two different questions with one value.
- **`REASON_NO_BACKLOG` is exported and compared by equality**, replacing a `startsWith` prefix match
  across a module boundary. A reworded string would otherwise have turned the sweep noisy on 8 of 12
  projects with nothing failing.
- **Naming checked, nothing renamed.** `parseBacklogRows` / `dischargeBacklogRows` /
  `backlogDischargeStatus` / `checkBacklogDischarge` follow the existing `parse*` / `*Status` /
  `check*` conventions in `sweep.js` and `state-drift.js`.
- **Dead code:** none introduced. `LEADING_ID_RE`, `HELD_OPEN_RE`, `REASON_NO_BACKLOG` each have a
  consumer and a test. No unused imports (lint clean).
