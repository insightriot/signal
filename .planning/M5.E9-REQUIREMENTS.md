# M5.E9 — Requirements: the linear-mode & phase-ledger close-out (v0.1.12)

**Epic:** M5.E9 · **Tier:** FULL (inherits `PROFILE.md` — no Epic-scoped profile; this is code in the
state-mutation core at a P1, which is exactly what the project profile already describes)
**Decisions:** D-M5E9-1 … D-M5E9-7 (`DECISIONS.md`, 2026-07-27)
**Deliverable:** **v0.1.12** — a patch release. **Slice 1 of the Epic; not the whole Epic.**
**Runs ahead of M5.E8** by D-M5E9-2; IDs are not resequenced (`PROJECT.md` § Vocabulary).

---

## Objective

Make Signal usable by a project that does not use Epics, and stop the phase ledger from
silently destroying its own history.

Four confirmed bugs, one origin: **`completed_phases` was designed against an Epic-shaped
scope that nothing enforces, and `/sig:ship` treats the absence of an Epic as a broken
state rather than a supported mode.** All four were invisible for nine releases because
Signal-on-Signal has run Epic-mode since M4.5.E11 and **structurally cannot reach them**.

**Success looks like:** a project with `current_epic: null` and a multi-run history can run
`/sig:ship` to completion, and finishes with its phase history intact and readable —
verified by a test that fails against `main`.

**Non-goal:** reconstructing history already lost. Collapsed entries are gone from the file
and no pass can rebuild them (D-M5E9-4). Where we can only warn, we warn — and say so.

## Functional Requirements

### FR1 — `/sig:ship` runs in linear mode (`B42`, **P1**)

The FR1 retrospective gate becomes **Epic-only**. A project with no Epic owes no
retrospective at SHIP and must not be blocked (D-M5E9-1).

**Three gates assume an Epic and all three must move — fixing only the first leaves ship blocked.**

- **AC1.1** `shipFR1Check` in **linear mode** returns `{halt:false, skipped:true, reason:<linear>}`
  — not `{halt:true, code:'NO_CURRENT_EPIC'}`. **Mode is decided by `detectMode` (`state.js:634`),
  the canonical detector every other command already uses**, not by a second local test.
- **AC1.2** **`!state` still halts** — a missing STATE.md is a broken project, not a linear one.
  A test asserts the two inputs diverge, so a blanket "always skip" cannot pass.
  *(Corrected at EXECUTE entry, S1.t2. The first draft said a **non-null but unresolvable**
  `current_epic` must halt. That contradicts `detectMode`, which fail-opens **malformed and
  version-string values to linear** by ratified design (D-E11-4) — so `"v0.1.6"` is linear
  everywhere in Signal, and having this one gate read it as "broken" would re-open the exact
  **regex schism** `state.js:100-108` records as already fixed once: a permissive read-half
  accepting IDs the strict retro code then threw on. The genuinely unresolvable case —
  a **strict-shaped** `current_epic` whose `MILESTONE-{n}.md` does not exist — still halts,
  at `ship.md` §0.5 step 2 (AC1.3), which is its correct home.)*
- **AC1.3** `ship.md` §0.5 step 2 (milestone-file derivation from `current_epic`) is skipped
  in linear mode rather than halting on a milestone file it cannot name.
- **AC1.4** `isEpicCloseByState` returning `false` on a null `current_epic`
  (`retrospective.js:412`) no longer strands the SHIP path — either it is not consulted in
  linear mode, or its linear branch is defined. **No dead code left implying an unreachable
  guarantee.**
- **AC1.5** `tests/ship-fr1.test.js`'s two `NO_CURRENT_EPIC` cases (`:125`, `:138`) are
  **rewritten, not deleted**, and the M4.5.E9 AC1-extended row in
  `archive/M4.5/E9/M4.5.E9-VERIFICATION.md` gets a dated superseded-by pointer. Retiring a
  shipped acceptance criterion is done in the open.
- **AC1.6** The Layer-1/Layer-2 disagreement is resolved, not left standing: Layer 2
  (`checkProposedStateWrite`, `retrospective.js:500-502`) fails **open** on the same input
  where Layer 1 failed **closed**. Both layers agree on what a missing Epic means.
- **AC1.7** End-to-end: a fixture project with `current_epic: null` completes `/sig:ship`'s
  §0.5 without halting. **This test fails against `main`.**

### FR2 — `transitionPhase` records the phase entered, with the real close date (`B43`)

> **⚠ FR2 redesigned at EXECUTE, Wave 2 entry (2026-07-27). Recorded in full because the
> first design was wrong in a way that would have broken two consumers silently.**
>
> Drafts 1 and 2 both had `transitionPhase` append the phase being **entered**. Writing it
> revealed that this **corrupts the meaning of the field**: `completed_phases` would list the
> phase currently in flight. Two consumers break immediately — `resume.js:272` would count an
> unfinished phase as done, and **`isEpicCloseByState` would fire a whole phase early**
> (entering REVIEW would satisfy "REVIEW is covered"), which is precisely the Epic-close
> detector that M4.5.E9, `B26` and `B30` spent three Epics getting right.
>
> **The real defect in `B43` is narrower than "it records the wrong phase."** Appending the
> phase being *left* is **correct** — that phase genuinely is complete. The defect is that
> **`SHIP` is terminal**, so nothing ever leaves it and no `SHIP` completion is ever recorded.
> The fix is therefore an addition, not an inversion.

**AC2.1** `transitionPhase` keeps recording the phase being **left** — it is the phase that is
actually complete, and `completed_phases` must not become a list of phases in flight.
**AC2.2** A new **`completePhase(baseDir, phase)`** records a phase complete **without**
transitioning away from it, so a terminal phase can be recorded at all. `/sig:ship` calls it on
a successful ship, and `SHIP (YYYY-MM-DD)` finally appears — the thing `ship.md:96` has
claimed since v0.1.3. **Ordering matters:** it runs **before** FR5's linear trim, so the
archived run includes its own `SHIP`.
**AC2.2b** The date is the date the phase was **recorded complete**. *A phase closed days
before the call is stamped with the call date — a known, stated imprecision, not a silent
one. Fixing it properly needs per-phase start/end tracking, which is out of scope and is
**not** worth a schema change here.*
**AC2.3** `ship.md:96` is corrected to describe actual behavior, and
`references/state-schema.md` states left-not-entered semantics alongside FR3's log rule.
**AC2.4** `isEpicCloseByState` + `checkProposedStateWrite` are re-checked against the new
behavior: both currently key on pre-SHIP coverage *because* SHIP was never written
(`retrospective.js:493` says so in a comment). Their `coversPreShip` logic still holds, and
a test proves an Epic-close is still detected once `SHIP` can appear in the list.

### FR3 — `completed_phases` is an append-only log (`B44`)

**AC3.1** The `Map`-based dedupe (`state.js:393-395`) is **removed**. A list of 53 entries
survives a `transitionPhase` call as 54.
**AC3.2** `references/state-schema.md:128` states the log semantics and the trim rule (FR5).
The line today specifies the dedupe without ever naming the scope it assumed.
**AC3.3** A regression test asserts a multi-run history is preserved across a transition —
**this test fails against `main`**, where it collapses to ≤8.
**AC3.4** No writer rebuilds an array by derivation. The 2026-07-27 audit found
`transitionPhase` was the only one; a test or lint keeps it that way.

### FR4 — Malformed entries are quarantined, never keyed on (`B45`)

**AC4.1** An entry not matching `PHASE (YYYY-MM-DD)` for a `PHASES` member is never treated
as a phase.
**AC4.2** It is **relocated, not deleted** — Signal's ratified relocate-never-delete rule.
**AC4.3** The count and the first offender are **surfaced**, not silently handled.
**AC4.4** Regression fixture: the real-world entry `"**▶ Active: Slice SEC1"` (live instance,
2026-07-26) does not become a phase key.

### FR5 — The log has a trim rule in both modes

Ratified at the DISCUSS gate, 2026-07-27. A log that never trims trades silent deletion for
silent growth — the same failure wearing the other mask.

**AC5.1 (linear)** At `/sig:ship`, the finished run's entries relocate to
`.planning/STATE-HISTORY.md` under a dated section, and the live list starts fresh.
**AC5.2 (Epic)** `setCurrentEpic` **archives before it resets** — the closing Epic's entries
append to `.planning/archive/<milestone>/<epic>/STATE-NARRATIVE.md`, the file that already
holds that Epic's evicted STATE content.
**AC5.3** The archive write is **inside the state-mutation seam, not in the command prose.**
"The command was supposed to do it" is precisely the B41 failure mode; the guarantee must
not be skippable. The coupling cost is accepted and recorded (D-M5E9-7).
**AC5.4** Zero-loss gate: entries out == entries in. A trim that drops one fails.
**AC5.5** Both paths are idempotent and survive a re-run without duplicating.

### FR6 — The four middle phase commands record their phase (`B41`)

Lands **after** FR3/FR4/FR5, never before — wiring four more callers to `transitionPhase`
ahead of the log fix multiplies the collapse sites (D-M5E9-3).

**AC6.1** `plan.md`, `execute.md`, `verify.md`, `review.md` each transition **at entry**, not
exit — entry is what makes `plan.md:50`'s *"verify current phase is PLAN"* precondition
satisfiable. Today no command can make it true.
**AC6.2** A full command-driven run ends with all of DISCUSS/PLAN/EXECUTE/VERIFY/REVIEW
recorded — not `[DISCUSS]`.
**AC6.3** `markFresh` no longer stamps a fresh timestamp over a stale position: after each
phase command, position and freshness agree.
**AC6.4** A test drives the sequence and asserts the ledger, rather than asserting the
command file contains a string.

### FR7 — Detect in `/sig:sweep`, repair in `/sig:migrate-memory` (D-M5E9-4)

`/sig:doctor` is **out of scope** — it diagnoses the plugin install, never the invoking
project's docs. The two commands below already have the right shapes; no new command.

**AC7.1** `/sig:sweep` reports malformed phase entries (**structural**) and a
suspiciously-truncated history (**advisory**), in its existing severity split.
**AC7.2** Sweep stays **read-only** — it names the command to run, per the interaction Brett
specified: warn → recommend → user agrees → repair.
**AC7.3** `/sig:migrate-memory` gains a vector that relocates malformed entries, keeping its
dry-run-default, propose-then-apply, git-reversible contract.
**AC7.4** For **already-collapsed** history sweep warns and states plainly that **no repair
exists** — it must not point at a fix that cannot deliver.

### FR8 — The blind spot gets a test

**AC8.1** One end-to-end test drives a **linear-mode project with a multi-unit history**
through the phase commands to a completed ship.
**AC8.2** It **fails against `main`** — on the FR1 halt and on the FR3 collapse.
**AC8.3** It is named and commented as a **coverage-gap guard**, stating why
Signal-on-Signal cannot reach this path (Epic-mode since M4.5.E11). This is the mechanism
that would have caught all four bugs; it is not coverage ceremony.

## Non-Functional Requirements

**NFR1 — No silent state writes.** Every mutation that removes or relocates an entry
surfaces a count. The 2026-07-26 collapse was caught only by a hand-run `git diff`.
**NFR2 — Relocate, never delete.** Applies to trims (FR5) and quarantines (FR4).
**NFR3 — Reversible.** Every file the release moves is recoverable through git.
**NFR4 — Backward compatible.** An Epic-mode project sees no behavior change beyond FR5's
archive step and FR6's recording. No migration required to keep working.
**NFR5 — Tests fail against `main`.** FR1, FR3 and FR8 each carry a RED-first proof. A test
that passes before the fix has not tested the fix.

**FULL-tier NFR prompt — surfaced and dispositioned, not skipped.** Health/liveness probes,
graceful shutdown, structured request logging, security headers, rate limiting: **all N/A.**
Signal is a local CLI plugin — no server, no network listener, no request path. The
tier's ops-hygiene checklist assumes a deployed service and does not map here. Recorded
rather than skipped so the disposition is visible.
