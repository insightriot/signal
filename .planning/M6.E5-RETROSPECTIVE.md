## What surprised us

**The wave-1 probe changed the plan on the Epic's first task — which is what it was for, and it
still surprised us that it fired.** `S1.t0` existed because *shipped-but-never-run* is this
repository's best defect predictor. It found that `detectProjectKind` calls **every** non-git
directory `greenfield` (`add.js:192` returns before the `hasSource` scan at `:198`), so a full
codebase and an empty directory are indistinguishable and both get told *"no project detected, start
fresh."* Filed **`B112`**. The Epic's own headline claim — that `M6.E5` would be the first code path
to call that function and *proceed* — did not survive: the right move was **not to call it at all**.

**Twenty-five green tests did not substitute for looking at the output once.** `S4` finished green,
and the first real render was wrong in two ways simultaneously. It proposed `Bash(git:*)`, which
re-grants `git reset`, `git rebase` and `git push --force` — the exact things `AC1.2b` withholds.
⚠ **`classify('git reset')` was correct the entire time**; the defect lived *between* a correct
classification and the rule rendered from it, where no test of `classify` could reach it. It also
proposed `cargo build`, `go test` and `bundle exec` for a Node repo, all arriving from
`plugin/agents` where command files describe other people's stacks — the over-proposal `D-M6E5-3`
and probe 2 had both warned about, in a plan amendment that said provenance would be a
classification input and then wasn't.

**The extractor's first rule was wrong and only measurement showed it.** "Require an argument"
admits 74 distinct binaries over 224 occurrences, nearly all prose — `result.wrote`, `state.phase`,
`trivial`, `off`, `documentation lives in …`. A structural extractor cannot tell `npm test` from
`plain markdown`. The rule that works — a known binary **or** a flag-shaped argument — took it to
21, and the flag clause is the half that matters, because a bare allowlist would make a *new* binary
invisible and destroy the point of the whole-population check.

**We published a headline finding that was an artifact of our own bug.** The Epic reported that
`git commit` appears **zero times** as a runnable command string anywhere in the payload, and made
that the honest limit of the whole design.

⚠ **CORRECTED (PR #211 review).** This Epic published *"`git commit` appears zero times as a
runnable command string anywhere in the payload"* as its headline limit. **That was false, and the
cause was a defect in this Epic's own scanner**: the code-layer scan captured each `execFileSync`
subcommand and then discarded it, so `execFileSync('git', ['commit', …])` in
`adherence-harness.js:278` was recorded as `git`. A second defect compounded it — `INVOCATION_RE`
could not match inside fenced code blocks, hiding more prescriptions still. With both fixed the
scan returns **200 entries** and `Bash(git commit:*)` **is** proposed.

**The real limit is narrower and still worth stating:** `gh` genuinely is prescribed nowhere in the
payload — the guidance lives in the repo-root `CLAUDE.md`, which is not shipped and not scanned. And
the generator only emits `Bash()` rules, so the seven `Read()`/`WebFetch()`/`Skill()`/`mcp__` rules
in the hand-cleaned set are out of reach by construction.

**The lesson survives its own correction, in a sharper form:** a measurement taken with a broken
instrument reads as a finding about the world. This one was published in five documents before an
independent reviewer caught it.

**Registration took six sites, not the four the plan named.** `roster.test.js` and
`map-roster-reconcile` went red on cue — that gate worked. `checkRosterCounts` and the adherence
ceiling were found by the suite, not by us.

## What we'd do differently

**Render the output before writing the tests that pin it.** Both `S4` defects were visible in the
first render and invisible to a well-formed test file. The tests were not wrong; they tested the
units. Next time, produce one real artifact early and read it, then write the tests that lock what
you saw.

**Say what the plan's mechanism actually is, then check it was used.** The plan amendment after
probe 2 said *"provenance is a classification input"*. It was written down and not implemented, and
nothing caught the gap until the render. That is `UNREACHED-MECHANISM-ANALYSIS.md`'s class committed
inside the Epic that quotes it twice.

**Measure with a tool that has been checked against a known case — twice over.** The outcome
measurement's first run reported 41 under / 22 over because the two pattern dialects (`Bash(git add *)` vs
`Bash(git add:*)`) normalised to different keys. A comparison that treats identical rules as
disagreements measures its own normaliser. Nearly published.

**Enumerate ids; never write a range.** The VERIFICATION's first draft wrote `FR1.1`–`FR5.3` and
`diffRequirementCoverage` returned **seven missing**. That is `M5.E10`'s headline defect, committed
here for the **fourth** time, in the artifact whose job is to prove coverage.

## What to feed back into Signal

**1. `AC_ID_RE` is missing `[a-z]?` — `B100`, and it was ALREADY FILED.** ⚠ This Epic rediscovered it, filed it as `B111`, and cited that id in five documents before the PR reviewer pointed out `B100` had said the same thing two weeks earlier. `BUGS.md` was not grepped before filing. **A capture command with no duplicate check makes that the default outcome, not bad luck** — worth more as a feed-back item than the regex itself. Sub-lettered acceptance criteria
collapse to their group on **both** sides of `requirement-coverage.js`'s diff, so the shipped tool
reported **5** criteria where **34** exist. This Epic's coverage denominator had to be derived by
hand. A tool built to catch completeness claims currently cannot count this Epic's criteria.

**2. `detectProjectKind` — `B112`, filed and unfixed.** A wrong onboarding message for any non-git
codebase.

**3. The PASS-WITH-FIXES cap counts comment lines.** It excludes *test* lines explicitly so that
*"a rule that penalises the reviewer who tests is a rule that trains reviewers not to test."* By the
same logic it penalises the reviewer who **explains**: 19 of the 47 insertions that pushed this
Epic's Critical fix from 50 to 51 were the docblock recording what the defect was. We took the loop
back rather than argue the cap down — but the asymmetry is real and is filed rather than absorbed.

**4. A `/sig:` command that runs outside a Signal project is a new shape, and `FR5.3` is the first
one.** Everything else either requires `.planning/`, creates it, or is about the install. If more
commands go that way, the "does this project have `.planning/`?" branch deserves one owner rather
than an `existsSync` per command.

**5. A capture command with no duplicate check produces duplicates.** `B111` was filed for a defect
`B100` had recorded two weeks earlier, and the id was cited in five documents before the PR reviewer
caught it. `/sig:add --bug` writes without ever looking at what is already there. That is a
mechanism gap, not a lapse of attention — the same tool and the same route found the same defect
twice and neither run knew about the other.

**6. The generator only emits `Bash()` rules.** Seven of the 43 hand-cleaned rules are
`Read()` / `WebFetch()` / `Skill()` / `WebSearch` / `mcp__…`. Real gap, stated rather than fixed.
