([`BACKLOG-REVIEW-2026-10-06.md`](BACKLOG-REVIEW-2026-10-06.md)), picked by Brett. FULL tier, run by

## What changed mid-flight

- **Scope grew at DISCUSS by Brett's call** (`D-M6E14-8`): `SIG-280` and `SIG-276` were added to the
  six he had picked. Offered as three options; he took the widest.
- **The plan's out-of-scope line for `closeEpic` and the archive moves was reversed at VERIFY.** PLAN
  (on the plan checker's M3) named those two other callers of `regenerateViews` out of scope; the
  verifier showed that left SIG-280 (6)'s defect class open in them, so the Epic's own goal ("every
  writer") was not met. Brought in as a stated deviation, not silently.
- **AC6.1's test changed method.** The plan said an injected `execFn`, because the plan checker
  estimated a real 7-hex commit collision at ~20k commits. The test file already had
  `plantAmbiguousCommits`, a birthday search over synthetic commits that finds one in milliseconds, so
  the real-repository test was used instead.
- **The proof-ambiguity rule was revised twice in REVIEW** — commits only (a regression), then commits
  and tags (a false refusal), then commits and tags that lead to a commit, which is git's own rule.

## What assumptions broke

- **"A test written to fail first proves the fix."** Two did not. AC7.2's test passed against the old
  code because the seam it injects was added in the same commit; and AC3.3's end-to-end test stayed
  green with the guard deleted, because an earlier check refused first. Both were found by running
  tests against the parent commit and by mutation, not by reading them.
- **"Linked `.planning` inside the repo" meant inside the project folder.** It also accepted the
  project folder itself and `.git/` — found by the security auditor and the code reviewer separately.
- **"Injecting `regenerate` is a test-only act."** It also switched the new safety check off; a test
  seam must have a name that cannot be mistaken for a real option (`_skipViewsCheck`).
- **"Nothing was written" is true wherever the view code says it.** It is false once a record has
  landed, and "then re-run" duplicates the change. Error text written for one caller was passed
  through by another.

## What surprised us

- **Every fresh reader found something the previous pass did not,** eight readers in all: plan checker,
  verifier, the verifier's second read, three REVIEW specialists, and two readers of fixes. The
  in-session pass found two Suggestions and nothing Important.
- **The worst defect of the Epic was introduced by a fix.** `9ca41c7` changed the proof count to "commits
  only" to answer a Suggestion, and that let through the exact SIG-276 failure the Epic set out to
  close — now via tag objects. Its own fresh reader caught it within the hour.
- **A grep can lie by omission.** At S7 the claim "docs-sweep.md has no remedy wording" came from a
  `grep -o` whose context window was too narrow for a very long line; it returned nothing and that
  was read as absence. The verifier found the sentence.
- **Lint was reported clean when it was not**, read from an empty last line instead of the exit code
  — and CI does not run lint, so nothing downstream would have caught it (`SIG-283`).
- **The `/sig:drive` run itself mostly worked** from DISCUSS: one floor halt (inbox), every phase
  advanced, no `loop-unknown`. Its own rough edges were filed (`SIG-282`, the floor's wording).

## What we'd do differently

- **Run each slice's tests against its parent commit as part of EXECUTE, not VERIFY.** It costs a
  worktree and a minute, and it is what showed AC7.2 proved nothing on its own.
- **Grep for every caller of a shared mechanism at PLAN and bring them in by default.** Leaving two
  of four writers out of scope "for focus" left the goal unmet.
- **Read a command's result from its exit code.** Never from the last line of its output.
- **Write a test seam's name as a seam** (`_x`), from the start.

## What to feed back into Signal

- **`SIG-283`** — add lint to CI.
- **`SIG-284`** — `/sig:advise` stamps the pick with the UTC date.
- **`SIG-282`** — PLAN's drain floors describe the drain while the store is on (the step is triage).
- **EXECUTE could run "new tests against the parent commit" for each slice** and record the result —
  the mechanical form of strict Nyquist's evidence (a), which this Epic did by hand at VERIFY.
- **"Fixes to fixes get their own fresh reader" paid off a fourth Epic running** and found the
  Epic's worst defect. It is still a habit, not a REVIEW step; it should be a step.
- **A deliberate stop for the reader chain needs a rule.** Here it stopped after a 15-line prescribed
  fix, by judgement, recorded in the REVIEW report. M6.E12 stopped at the loop ceiling. Neither is a
  rule.

## Anti-rationalization moment

At REVIEW the five Important findings were all well understood and the fix felt routine, and
PASS-WITH-FIXES was within reach in spirit. The count said otherwise: **189 lines of non-test source
across three writers' shared error path**, over the 50-line cap, with design impact. It was recorded
as **FAIL and a loop**, not rounded down. That decision is also why the fix got its own fresh reader
as a matter of course — and that reader found the Important regression the fix had introduced. Had
REVIEW closed as PASS-WITH-FIXES on the first pass, the regression would have shipped behind a green
suite.
