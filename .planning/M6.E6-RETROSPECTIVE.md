# `M6.E6` — Retrospective

*Wire the decision queue. The Epic that made `/sig:drive` able to park a question instead of halting
on it — and then had to wait for a release before anything could prove it.*

## Timeline

**DISCUSS 2026-09-03** (`D-M6E6-1`…`-5`) → **PLAN / EXECUTE 2026-09-04** (`6f4f5d7` router,
`0daef41` drive parks a question, `bc4a13a` AC2.6 becomes a check; merged as PR #233 / `c8bad52`,
Epic-lane `--merge` honoured) → **VERIFY 2026-09-04** (`4e2cbe0`; PASS on 18 ACs, outcome oracle
reported NOT MET) → **PR #234 review + fixes** (`45997ab`) → **`v0.1.37` released** (`ba5d1c3`,
17:06) → **REVIEW 2026-09-04** (`ee60510`, PASS-WITH-FIXES) → **SHIP 2026-09-04**.

Wall clock two days. **The whole Epic ran inside one calendar day except DISCUSS.**

⚠ **The ordering is not the flow's ordering, and that is the first thing to say.** The code merged
and released *before* REVIEW ran. VERIFY → PR → release → REVIEW is what happened, so REVIEW could
only find things to fix forward, and both of its Important findings were live in a released version
for about half an hour.

## What surprised us

**1. The oracle was met by the first run that could physically reach the code — about an hour after
the release that made it reachable.** VERIFY said, correctly, that it could not be met from where it
stood: no cached copy carried `routeDecision`, because M6.E6 had merged to `main` unreleased. The
`/sig:drive` run on 2026-09-04 that produced this retro hit a genuine unforeseen gray-area question
at the VERIFY→REVIEW boundary, tagged it `product` + `painful`, and `routeDecision` parked it as
`Q-M6E6-1`. **The run continued.** That is the oracle, and it took three `/sig:drive` invocations
across two days to get a run that could reach it — two halted at the front door, one ran retired code.

**2. Two guards each stood down in the exact case they were written for.** Found in REVIEW, in code
written this Epic:

- `formatQueuedDecision` omitted **both** tag rows for a decision tagged on **neither** axis. Three
  lines above the guard, its own comment says an untagged axis *"renders as `untagged`, never
  omitted... the whole fail-closed default exists because that is the case worth seeing."*
- `queueDecision`'s adopt-guard stood down whenever the caller supplied its own `routeWhy`. A
  `plumbing` + `trivial` decision — one the router adopts, that nobody has to answer — filed
  successfully as a parked question reading *"Why it is here: because I said so."* Verbatim the
  entry the guard's comment says it exists to prevent.

**3. The test written for the first one covered the case that already worked.** `an UNTAGGED axis
renders as untagged, never omitted` passes `altitude: 'plumbing'` and asserts the *reversibility*
row — the half-tagged path. Not vacuous; aimed one case to the left of the defect. In the Epic whose
own PR review had already caught a vacuous test set.

**4. Three claim-integrity slips in one Epic is a rate, not a slip.** *"19 of 19 acceptance
criteria"* against an 18-row table; the vacuous `B115` tests; and `status.js`'s comment rewritten to
claim the queue's write half *"has a caller"* at a moment when no `/sig:drive` run had ever reached
step 3b. All three are `CLAIM-INTEGRITY-ANALYSIS.md`'s named class — a completeness claim written
from the shape of the work rather than from the artifact — and all three were caught by someone
else, never by the suite.

**5. STATE.md's narrative was four phases behind its own frontmatter.** It read *"DISCUSS is written,
PLAN is next"* while the frontmatter said `VERIFY` and four artifacts existed on disk. `markFresh`
advanced `last_updated` and `last_updated_commit` faithfully the whole time. **A stale pointer under
a fresh timestamp reads as current** — which is the exact failure mode `markFresh` was built to
prevent, displaced one layer up into the prose it does not touch.

## What we'd do differently

**Cut the release before VERIFY, not after, when the oracle needs a released artifact.** The Epic's
own outcome oracle required an installed copy. Nothing in PLAN noticed that the acceptance criterion
was unreachable from the branch, so VERIFY spent its budget proving *why* it could not answer rather
than answering. Where an oracle names a shipped artifact, the release is a *prerequisite* of VERIFY,
not a consequence of it.

**Mutation-verify every test that pins a fail-closed default, at the moment it is written.** Both
test defects this Epic were the same shape: a green test over the passing neighbour of the defect.
REVIEW's three new tests were mutation-verified before being committed — reverting `drive.js` while
keeping them fails exactly those three and no others — and that took under a minute. It is cheap
enough to be unconditional.

**Run the full suite after the *documentation* writes, not only after the code change.** The code was
green at 3206 three commits before the ledgers were. The BUGS tally still published 123 after a new
row landed, and INDEX was missing the review artifact. Both were caught only because the suite ran a
second time.

**Grep for the guard's own escape hatch when reviewing a guard.** Both I1 and I2 were a conditional
whose extra clause had no stated purpose. `&& decision?.routeWhy === undefined` and
`if (reversibility !== undefined || altitude !== undefined)` are each one clause longer than the
rule they enforce, and in both cases the extra clause *was* the defect.

## What to feed back into Signal

**1. `transitionPhase` regenerates INDEX.md at phase ENTRY — so INDEX structurally never contains the
current phase's own artifact.** This is not specific to M6.E6. Every phase calls `transitionPhase`
before it writes anything, so the index of the corpus is always exactly one artifact behind, for
every phase of every Epic, until some later transition sweeps it up. Filed to
[`BUGS.md`](BUGS.md). Fix shape: regenerate at phase *close* as well, or have the
artifact write trigger it.

**2. Nothing checks that STATE.md's narrative agrees with its frontmatter.** `markFresh` is a
freshness stamp on the YAML, and the resume pointer above it is prose nothing validates. A cheap
advisory: if `phase` or `completed_phases` changed and the `▶ WHERE THE WORK IS` block's date did
not, say so. This is a **convention → advisory** promotion candidate under the house rules ladder,
not an enforced check — the prose is a judgement call a tool cannot make.

**3. REVIEW at `quality-only` writes three empty sections that read like three clean passes.** The
artifact now says *"empty because nothing looked, not because nothing was found"* by hand. That
sentence should come from the template, not from the reviewer remembering to write it — an empty
Security Findings section is otherwise indistinguishable from a passed one.

**4. `review_depth: quality-only` sits beside `security_audit: basic` in every FEATURE profile, and
the second is dead config.** `review.md` documents the precedence correctly. But a profile that
states a security posture which cannot take effect is a profile that will be read as promising one.
Worth either deriving the inert flags or marking them inert at write time.

**5. The queue's first live entry validates `D-M6E6-4`'s bet.** The tagging convention cost nothing
in practice — the decision was tagged honestly on both axes at the moment it arose, and the router,
not the author, decided where it went. The predicted "chatty queue while tagging is new" did not
materialise on run one: **one decision met, one adopted silently (plumbing + moderate, the STATE
refresh), one queued.** That is the intended ratio, not a fail-closed flood.
