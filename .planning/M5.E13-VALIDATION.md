## Part 1 — 8-dimension plan validation

### 1. Goal alignment — **PASS**

Phase goal: *close the four defects that share one shape, and leave behind one mechanism, one
honestly-labelled gap, and a re-measured verdict.*

Every slice traces to it. The one task that could look like drift — **S1** (`B53` naming
symmetry) — is load-bearing rather than adjacent: FR1.2's existence check built on today's read
seam would find a stale Epic-prefixed artifact and **pass**, which is a false-green manufactured
inside the Epic that exists to delete false-greens. The requirements sequence it ahead of FR1.2
for exactly this reason.

### 2. Completeness — **PASS WITH A NAMED GAP**

All six FRs plus `B54` are covered:

**The named gap, stated rather than smoothed over.** FR2.3's hygiene test covers **code-shaped**
guards. `B54` moved the class's instance count from three to four, and the new instance is
code-shaped — so the test's coverage went from **1 of 3** to **2 of 4**. That is better and still
not the class. AC2.4 requires the test to say so in its own name. Anything that reads as "the
class is now covered" is false and REVIEW should reject it.

> This is D-M5E13-3's own lesson applying to this plan: the mechanism is scoped honestly, not
> described as more than it is.

### 3. Dependency correctness — **PASS**

Two real dependencies, both justified by evidence rather than convention:

- **S1 → S2** — the false-green argument above. Measured in R3.
- **S2.t4 → S5.t1** — the canary measures the reworded text. Discovered at PLAN (R11): the canary's
  `deleteSection` anchors on the exact heading FR1.1 rewords.

**Minimal:** S3 and S4 have no dependency on S1/S2 or each other, and are marked parallel. No
task waits on anything it does not consume.

**One dependency deliberately *not* declared:** S2.t1 (delete `checkGateArtifacts`) does not
depend on S1, even though both touch artifact resolution — the deletion removes a caller-less
function and cannot be affected by the seam fix.

### 4. Testability — **PASS WITH ONE GENUINE EXCEPTION**

19 of 20 acceptance criteria map to an automated test (Part 2). **AC1.4 does not, and cannot.**

`tools/adherence-run.js` invokes the `claude` CLI, spends money, and is deliberately excluded from
`npm test` (M5.E8 D-M5E8-1 — the suite stays deterministic, offline, free; a guard test asserts no
test spawns it). So the canary re-run is **manual and budgeted**, verified by the presence of a
fresh dated verdict pair in `ADHERENCE-LOG.md`, not by a green test.

This is a real limit, not a workaround. It is the same limit M5.E8 shipped and documented. The
mitigation is the log's own convention: **unmeasured is not passing** — if the run cannot happen,
the log records the verdict as withdrawn rather than leaving the stale `OBEYED` standing.

### 5. Scope discipline — **PASS**

The plan **adds** one item (`B54`) and **refuses** several:

- `B53`'s other two fix parts (sweep check, mode surfacing) — new capability, explicitly parked.
- Rewriting historical records to erase `checkGateArtifacts` — history records what was true then.
- Status-tracking machinery for `B46` — the standing non-goal; Signal has been incrementally
  rebuilding an issue tracker out of markdown and this Epic adds nothing to it.
- `B38`, `B47`, the tracker Epic, Lanes — unchanged from requirements.

`B54`'s addition is the one scope increase, and it was **ratified by the project owner** rather
than absorbed silently — which is the correct handling for a change to a locked DISCUSS decision.

### 6. Context feasibility — **PASS**

Largest slice is S2 (5 tasks), but each task is a bounded edit to 1–4 named files with the seams
already located in R1/R2/R8. No task requires holding the whole codebase. S3.t2 is the widest
(reads two large markdown files) and is explicitly allowed to **report rather than resolve**
ambiguous mappings, which caps its reasoning load.

### 7. Risk coverage — **PASS**

Five risks identified, each with a mitigation (plan § Risks). The two that matter:

- **S1 stranding a live project.** `traction-engine`'s reads work *today only because the lenient
  regex matches*. Mitigation is directional: make the **write** seam agree with the read, don't
  delete the read's leniency. AC1.5a pins non-strict values.
- **S2.t4's near-miss control arm.** M5.E8's near-`INERT` failure was a control that still
  contained the instruction three more times. The canary's own test guards this; S2.t4 must
  **re-verify it against the new wording** rather than assume it carries over.

**One risk this plan cannot mitigate, recorded honestly:** `M5.E13-RESEARCH.md` §R0 documents that
no research subagents ran despite `research_parallelism: 4`, so no external/prior-art research
happened. Assessed low (nothing in scope is externally-facing) but it is a deviation, and REVIEW
should audit it as one.

### 8. Vertical slicing — **PASS**

Each slice is independently shippable and leaves the suite green:

| Slice | Ships on its own as | |
|---|---|---|
| S1 | "artifact naming is symmetric for every project shape" | ✅ |
| S2 | "the phase-entry instruction and the code beneath it agree" | ✅ |
| S3 | "three dead guards fixed; one narrow mechanism added" | ✅ |
| S4 | "three release gates actually gate" | ✅ |
| S5 | "the reworded instruction is re-measured; proof-of-fail recorded" | ✅ |

No slice is a horizontal layer (no "all the tests" or "all the docs" slice). S5 is the closest to
horizontal — it is measurement across the Epic — but it is a genuine user-visible deliverable (a
published verdict), not an integration tax.

1. **AC1.4 is unautomatable** by design (cost + non-determinism). Verified by artifact, not by green.

   a target. A target here would invite tuning the mapping to reach it.

   position and AC2.4 makes the test say so.
