## §2 — AC6.3: recommend a staleness check for `analysis/`

**Recommendation only. Building it is explicitly out of scope** (`M5.E7-PLAN.md:193`, § Out of scope).

**The problem, stated from this Epic's own evidence.** Five load-bearing claims in `analysis/`
decayed with nothing noticing, and one of them (**C6**) propagated out of a research note into a
**locked decision** before anyone re-read the source. `analysis/` holds the inputs Signal's roadmap
decisions are made from, and it is the **one directory the doc-runtime does not govern for
freshness**. The standing hygiene guard *does* walk `analysis/` — but only for link integrity,
`[FILL IN]` stubs, roster counts, and version consistency (`tools/lib/doc-hygiene.js`). **None of
those four checks can detect a claim that was true in April and false in July.**

**Shape recommended** — deliberately modest, matching what the corpus shows actually works:

1. **A freshness stamp, not a fact-checker.** Every `analysis/*.md` carries a
   `verified-against: <ref> on <date>` line for claims about external repos. A check flags any file
   whose newest stamp is older than a threshold. It asserts *"this was last checked on date X,"*
   never *"this is true"* — an automated truth-check of prose about other people's repos is not
   buildable and should not be attempted.
2. **Advisory, never blocking.** Same tier as the STATE-size and layout banners: it nudges, it does
   not fail the suite. A hard gate here would wedge a stranger's repo over a stale research note.
3. **`/sig:sweep` is the natural home**, not a new command and not a hook. Sweep is already the
   read-only, invoking-project hygiene surface and already carries advisory checks
   (`checkClaudeMdBloat`, `checkStaleInbox`). This is one more check of the same species.
4. **Trigger, not a position in a queue** (P4): build it when a *second* instance occurs — an
   `analysis/` claim propagating into a decision or a plan before being re-verified. C6 is instance
   one. If it happens twice, the pattern is real; if it does not, this correction pass was the
   whole cure.

**Cross-reference for S4.t9:** this recommendation is a **Signal-native candidate** (AC3.4) — no
source repo supplies it, and it comes from Signal's own pain. It belongs in the roadmap's
Signal-native column, not in any port's disposition.
