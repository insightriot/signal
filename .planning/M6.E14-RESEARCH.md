## Codebase angle — where each defect lives

### FR1 / `SIG-277` — promote dedupe
- `backlog.js:175` `promoteInStore` looks for a twin with `listRecords(...).find(source_ref === dedupeKey)`
  **before** calling `newItem`, which takes the `work` lock inside `newItems` (`work-records.js:878`).
  The read and the write are under different (no / one) locks.
- `newItems` already plans every record inside one lock (`withWorkLockV2`, `work-records.js:888`) and
  calls `nextIdV2` there. A dedupe check belongs at the same point, before `planNew`.
- Callers of `newItems`/`newItem` pass no dedupe today, so an opt-in option is backward compatible.
- Still unreachable: `drain.js:562` `promoteDrainEntry` calls `refuseWhenStoreOn`. Tests must call
  `promoteToBacklog` / `promoteToBugs` directly with the store on.

### FR2 / `SIG-278` — discharge
- `backlog.js:608` `dischargeInRecords`: `unreadable` (broken paths) is consulted only in the branch
  where nothing readable matched. The `open.length === 1` branch ignores it. Fix is local: when
  `unreadable.length > 0`, the single-match branch reports `UNREADABLE` naming the broken paths.
- `SIG-253`'s abort path no longer exists (`9abcc45`); closed at DISCUSS.

### FR3 / `SIG-279` — linked `.planning`
- `path-confine.js:77` `linkedComponent(baseDir, rel)` lstat's every prefix of `rel` from the first
  component, so `.planning` itself being a link is reported.
- Two callers only: `work-views.js:400` `confineView` (every view write) and
  `work-migrate-v2.js:388` `confineWrite` (the migration's build-aside).
- `assertRealInsidePlanning` (`path-confine.js`) already refuses a `.planning` whose real path is
  outside the repo, so allowing the root link for views does not open an escape.
- The migration copies `.planning` with `cpSync(..., {verbatimSymlinks: true})`
  (`work-migrate-v2.js:607`): copying a linked `.planning` produces a link in `outDir`, so the
  migration needs its own up-front refusal (`CONFIG`), not the narrowed check.
- Design: add an option (e.g. `{ from: '.planning' }`) so `confineView` checks components **below**
  `.planning`; `confineWrite` keeps the full check, and the migration entry gets an explicit refusal.

### FR4 / `SIG-280` (6) — record written, views refuse
- Every store writer (10 call sites of `withWorkLockV2` in `work-records.js`) writes the record(s),
  then `regenerateAfter` (`work-records.js:650`) runs `regenerateViews`. Its failure is wrapped as
  "X was written, but the views were not regenerated" — the record stays, the views are stale.
- `regenerateViews` (`work-views.js:443`) refuses for: a v1 store; any broken record (`renderStore`);
  a linked or non-file `WATCHLIST.md` (`readWatchlist`); invalid YAML in an archived Epic README
  (`readEpicFolders`); a linked view path (`confineView`); a hand-kept view (`handKept`).
- **Measured (2026-10-07, 282 records):** `listRecords` 12.9 ms, `regenerateToMemory` 19.9 ms. A full
  dry run before each write costs ~20 ms here; M6.E13 measured ~0.2 s for listing at 10,000 records.
  So the pre-write check can be the **whole** dry run — `renderStore` plus `confineView`/`handKept`
  over the rendered paths, without writing — which covers every refusal above exactly, instead of a
  partial list that drifts. NFR satisfied by measurement.
- Placement: `withWorkLockV2`, after the lock is taken and before `fn` runs — one place for all ten
  writers. Tests that inject `opts.regenerate` (5 files: `work-records-{close,confirm,epic,write}`,
  `work-views-fresh`) need the check skippable the same way, so the option travels with `opts`.
- A failure can still happen after the write (a new history-year file that is hand-kept, a race);
  AC4.2's message already says "was written"; it must also name the rebuild command.

### FR5 / `SIG-280` (1)–(5)
- (1) `refuseBroken` (`work-records.js:1509`) and `ship.md:268` say `git checkout -- <path>`; true only
  when `HEAD` holds a good copy. For a conflicted record: `git checkout --ours|--theirs <path>`.
- (2) `refuseBroken` says "nothing was written"; it is also reached from `classifyClosing`, shared by
  read-only `probeCloses` (`/sig:resume`). Needs a wording that is true for both, or a parameter.
- (3) `sweep.js` reports a broken record from `checkRecords` (`:420`) and again from the
  closes-confirmed check (`:494`, via `confirmCloses` → `refuseBroken`).
- (4) `tests/work-records-concurrency.test.js` two-process test: never asserts the processes overlapped.
- (5) `confirmCloses` `@throws` (`work-records.js:1441`) omits `NOT_FOUND`, which `readForWrite` throws.

### FR6 / `SIG-276` — ambiguous proof
- `ancestryFailure` (`work-records.js:1386`) resolves `${sha}^{commit}`; git prefers a ref of that
  name over an abbreviated id, and the `startsWith` check then passes when the ref points at a commit
  that shares the prefix. The comment at `:1385` claims an ambiguous id makes `rev-parse` fail; with
  a same-named ref it does not.
- Fix: for a proof shorter than 40 hex, `git rev-parse --disambiguate=<sha>` lists every object with
  that prefix; more than one **commit** → new reason `ambiguous-proof`. Reasons are only rendered as
  their token (no renderer maps them), so a new token needs no formatter change; `@returns` docs list
  them (`:1428`).
- Request time: `requestClose`/`requestCloses` call only `assertProof` (format); no git. A git check
  there is best-effort (skip outside a repo); confirm time is the guaranteed check.

### FR7 / `SIG-251`, `SIG-252` — `file-lock.js`
- `heldError` (`:67`) always prints `retry in <ttlSec`; `staleReason` (`:57`) holds a live local pid
  for `10 * ttlMs`. `heldError` needs to know whether the holder is a live local pid.
- `:123` `statSync(..., {throwIfNoEntry: false})?.mtimeMs ?? 0`: a vanished file reads as mtime 0, and
  an unreadable (empty) lock is then judged stale. Fix: `continue` when stat returns undefined, as the
  `readOrNull === null` branch above it does.
- `file-lock.js` is shared by `state.js`, `add.js`, `archive-tree.js`, `work-migrate-v2.js`,
  `work-ops.js`, `work-records.js`: run their lock tests in full.

## Risk angle
- **FR3 widens what is accepted.** The regression to fear is a link *below* `.planning` getting
  through. AC3.2/AC3.3 tests stay, and the narrowing is opt-in per caller.
- **FR4 adds work to every write**, inside the lock. ~20 ms now; the lock ttl (`WORK_LOCK_TTL_MS`) is
  minutes, so no expiry risk.
- **FR4 changes failure order:** some writes that used to land (then complain) now refuse up front.
  That is the intent; tests asserting the old "was written, but" wording for pre-existing conditions
  must be updated deliberately, not loosened.
- **FR1 concurrency test flakiness** (`SIG-139`, `SIG-266`: the suite already times out under load).
  Use the `_beforeTakeover`-style seam or a barrier file rather than timing, and assert the overlap.
- **FR6 git versions:** `--disambiguate` exists since git 1.8; CI uses ubuntu-latest.
