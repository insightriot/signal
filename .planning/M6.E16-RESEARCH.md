## 1. The item machinery, and what stops a second record type reusing it

- **`L/work-record.js` is bound to one schema at load.** `check()` (`:93-126`) is generic; the schema
  constant (`:33`), `resolveRef`, `checkEvent`, `EVENT_TYPES`, the field orders, `LEGAL_FROM` and `fold`
  (`:280-374`) are item constants. Units need a factory or a parallel module.
- **Every reusable write helper is private to `L/work-records.js`:** `withWorkLockV2` `:666`,
  `regenerateAfter` `:692`, `recordText` `:731`, `readForWrite` `:745`, `confine` `:755`,
  `writeRecord` `:774`, `withEvent` `:787`, `writeRecords` `:1231`, `defaultBranchRef` `:1457`,
  `ancestryFailure` `:1522`, `classifyClosing` `:1619`.
- **Three tests fail by design on a second record module:** `T/work-record-writers.test.js:39` (one
  `OWNER`), `T/helpers/write-inventory.js:245` (`RECORD_RE`, items only),
  `T/work-record-schema.test.js:144,322` (pins the Epic and item ID patterns).
- **Nothing refuses a legacy close as proof.** `event.legacy` is read at `L/work-record.js:139,334`
  only. The rule holds because nothing reads a `closed` event's proof. `M6.E13-VERIFICATION.md:114`
  cites a test for it in `work-records-confirm.test.js`; that file does not contain the word. AC8.2
  needs a real check and a real test.
- **Widening `epic_id` skips a guard:** `refuseArchivedEpic` returns early when the string fails
  `EPIC_ID_RE` (`L/work-records.js:1028`).
- **Membership is derived** from item events (`epicOf`, `L/work-record.js:412`). Storing it on the unit
  would be a second copy of one fact.
- **`epic_id` pattern sites:** schema `:21`; `L/work-records.js:1336`; `L/work-convert.js:37`;
  `L/state.js:109`; looser copies in `resume.js:35`, `legacy-lists.js:308`, `state-drift.js:716`,
  `evict.js:48`, `planning-index.js:28`, `migrate-memory.js:1450`.
- **Close-confirm:** `confirmCloses` (`L/work-records.js:1580`) classifies, then under one lock appends
  `closed` and regenerates once. Default branch is `refs/remotes/origin/<branch>`, never fetched.
  Item-specific parts: `listRecords`, the sort, the wording.
- **`closeEpic`** (`L/work-ops.js:287-450`) ✔: gate, then looks for `work/epics/<ID>/`; missing →
  `no-folder`, nothing written (`:321`). Nothing creates that folder.
- **Views:** whole files starting with a generated marker. Nothing in the store writes between
  markers. The one marked-region writer is `upsertCeiling` (`L/adherence-log.js:88-103`), with
  constant markers — a pattern to copy. `atomicWrite`'s generated-file guard does not cover a region.
- **Hook:** `L/work-write-guard.js:59-65` lists the blocked paths; add a `units` branch, the message
  (`:42-47`) and `T/hook-work-write-guard.test.js:40-57`.
- **`M6.E13` cutover** (`L/work-migrate-v2.js:561-699`): refuse wrong state, clean tree, symlink
  preflight, build aside, verify, manifest, apply under the lock, re-verify. Its diff generator is in
  git history only.

## 3. Risks, from the last three storage Epics

| What went wrong | Rule | Where it lands here |
|---|---|---|
| Counts without lists were wrong (E13) | Save the list; re-grep at task start | Inventory file; every task |
| In-place rewrite would be red for three slices (E13) | Build beside, switch once | Records beside the old readers; cutover is one commit |
| A regression with 5,473 green tests (E13) | Differential read: old answer vs new, every difference classified | S0 baseline; S8 diff |
| Tests that proved nothing (E14) | Run each slice's new tests against the parent commit, in EXECUTE | Every slice |
| Two of four callers left out (E14) | Grep every caller of a shared mechanism | § Reader list |
| A wording rule closed open entries, three reviews (E15) | Mutation-test a rule's tests; ask who sees it if the rule is wrong | The retro-placeholder check; legacy proposals |
| "Default branch" coded as `HEAD` (E15) | Code the requirement's words | AC4.2 |
| A fix regressed in each Epic | Each fix gets a fresh reader | REVIEW |
| The step under test was stubbed (E13) | Never stub it | Unit confirm runs the real git check |

Review finding classes to pre-empt: writes and reads through symlinks; an unconfined lock; a ref or tag
that looks like a commit hash; quadratic time on hostile text; invisible Unicode in confirm text; a
gate that never runs (`closeEpic` today); "nothing was written" when something was; the dry run and
the apply seeing different inputs; a second lock; refusal order; an ID shaped like another kind of ID;
unscrubbed text.

**Unit names.** Corpus shapes in committed tests: `GATE-A`, `SC1`, `SLICE-SSO`, `PHASE7`, `PHASE10-S4`,
`M1`, `M4.5.E1`, `v0.1.6`, `phase-11`. Characters: letters, digits, `-`, `.`. `isSafeUnitName`
(`L/archive-tree.js:107-114`): 1–100 characters, no `..`, `^[A-Za-z0-9][A-Za-z0-9._-]*$`,
case-sensitive, no collision check. Three collisions to refuse: names differing only by case; a name
shaped like one of the project's own item IDs; a name equal to a phase name.

**The migration** (`L/work-migrate-lists.js`): `assess` (`:236`) refuses first when `WORK.md` exists
(`:242-246`). A store-on project with no unit records — Signal — has no path today. A units-only
branch belongs **at** that check (refusal order mattered in E15), needs the lock, the clean tree and
the tag, must hash its own inputs, and needs a byte-snapshot test that `items/` is untouched.

**Guards:** `CONTEXT.md` is close to its 50,300-byte ceiling; the adherence log must be regenerated
after the last command-file edit (`T/adherence-ceiling.test.js:93`); `T/work-records-inventory.test.js`
classifies one module's exports only; `T/work-commands-doc-contract.test.js` pins command wording;
no committed fixture is store-on with non-Epic units (build one with `makeStore()`,
`T/work-records-inventory.test.js:60-75`).

**Performance:** a bare "< 100 ms at 500 units" will flake under the parallel pool. Precedent:
2,000 → 32,000 (16×) with a 64× limit, best of five, one warm-up (`T/work-migrate-propose.test.js:495`);
and 10,000 records asserted `< 2000` ms with the real figure logged (`T/work-records.test.js:229`).
Keep git out of the timed path.
