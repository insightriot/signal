# M6.E11 — The work-item store, step 1: one file per thing, and it moves

**Brett, 2026-09-27:** *"revisit this whole architecture vs. keep applying band-aids."* (`D-M6E3-16`)
**Brett, 2026-09-29:** *"1 file = 1 thing, and nothing is ever destroyed, it 'moves' through a process
— MUCH better than writing to 6 docs simultaneously and hoping for consistency."*

Direction: `D-BR0928-1` … `D-BR0928-7`, [`analysis/WORK-ITEM-SYSTEM-DESIGN.md`](../../../../analysis/WORK-ITEM-SYSTEM-DESIGN.md).
Decisions for this Epic: `D-M6E11-1` … `D-M6E11-14` in [`DECISIONS.md`](../../../DECISIONS.md).

## The problem, measured (2026-09-28/29)

- A thing lives in a different file at each stage, and "done" is written differently in each.
  `M6.E3` was named in 20 `.planning/` files and its "done" written in ~6 places by hand; one of them
  hid the Epic from `/sig:advise` (`B127`).
- ~17 checks exist only to reconcile those copies after the fact. None can tell a fixed bug from an
  open one reliably (`M6.E3-RESEARCH.md`; `bug-status-vs-changelog` ~~flagged 2 rows here, 1 real~~ judges 31 rows and flags **1** — measured at PLAN, `D-M6E11-19`).
- Only bugs and Epics have IDs. Inbox entries, questions and backlog rows are identified by wording.
- What this Epic replaces on Signal's own repo: `BUGS.md` ~~127 rows~~ **140 bugs** — 127 table rows (31 `confirmed`, 91 `fixed`,
  4 `dismissed`, 1 `needs-triage`) plus 13 un-numbered `##` entries (`D-M6E11-15`, measured at PLAN); 378 KB, `BACKLOG.md` ~~91 headed rows~~ **92 rows** as `parseBacklogRows` reads them at depth 4 (174 KB), `ISSUES-INBOX.md`
  6 entries, `OPEN-QUESTIONS.md` 11 entries. **19** `plugin/tools/lib` modules and **14** commands
  mention these files; **9** of those modules contain write calls.

## Scope

**In:** the item model, the repo store (`inbox/`, `backlog/`, `epics/<id>/`, `done/YYYY-MM/`),
`/sig:item`, `/sig:add` writing through it, generated lists, Epic folders with a close gate at ship,
and migrating **Signal's own** records into it.

**Out (later steps of the design doc):** smarter triage and intake from every channel (step 2);
sprints, `Fixes: SIG-n`, STATE.md current-task ↔ status `P`, retiring the inference checks (step 3);
the GitHub Issues add-on (step 4); migrating **other** projects, and moving existing Epics' artifacts
into folders (step 5, via `/sig:docs-migrate`). Re-triaging the 31 `confirmed` bugs.

## Requirements

*Convention: each `AC-N.x` is a child of `FR-N` (the `M5.E10` shape), so the coverage check reads
the ACs as the denominator and the FR headings as group labels — the shape `B116` does not break.*

### FR-1 — Opt-in by presence; absent the store, nothing changes

- **AC-1.1** — The store is on for a project if and only if `.planning/work/WORK.md` exists with a
  valid `key:` in its frontmatter (`D-M6E11-3`).
- **AC-1.2** — With no `WORK.md`, every existing test passes unchanged, and a new test runs
  `/sig:add` (all routes), `/sig:status`, `/sig:resume` and `/sig:advise` against a fixture without
  the store and asserts byte-identical `.planning/` output to a pre-Epic baseline.
- **AC-1.3** — A `WORK.md` with a missing or malformed key fails loudly with a message naming the
  file and the fix; it never silently falls back to the legacy files.

### FR-2 — The item file

- **AC-2.1** — One Markdown file per item, named `{KEY}-{n}.md`, with YAML frontmatter carrying the
  fields in `D-M6E11-7`. The body is the capture, verbatim.
- **AC-2.2** — `type` ∈ `NEW`/`BUG`/`FEAT`/`CHORE`/`Q`; `status` ∈ `N`/`T`/`Q`/`P`/`C`; close
  `reason` ∈ `fixed`/`stale`/`wontdo`/`dup`/`rejected`, and a close always carries `by` and `at`. A
  `dup` names the item it duplicates; the schema rejects any other value.
- **AC-2.3** — The rendered label is `{KEY}-{n}-{TYPE}-{STATUS}` (e.g. `SIG-412-BUG-T`). No tool
  looks an item up by anything but the front (`SIG-412`).
- **AC-2.4** — A parse/validate function returns every schema violation in a file, not the first.

### FR-3 — Folders, and status and folder cannot disagree

- **AC-3.1** — `inbox/` holds only `N`; `backlog/` only `T`; `epics/<id>/` only ~~`Q` or `P`~~ `Q`, `P` or `C` (`D-M6E11-29`: Epic items close in place);
  `done/YYYY-MM/` only `C` (`D-M6E11-8`).
- **AC-3.2** — A consistency check reports every item whose status and folder disagree, and every
  duplicate ID. It is a failing test on this repository.
- **AC-3.3** — `/sig:docs-sweep` reports the same findings (advisory) in any project with the store on.
- **AC-3.4** — Nothing is deleted by any command in this Epic (`D-M6E11-12`); a test asserts every
  store operation leaves the count of item files unchanged or higher.

### FR-4 — IDs

- **AC-4.1** — A new ID is one past the highest ID found in the working tree **and** in git history —
  ~~every local and fetched branch, read with `git ls-tree`~~ `git log --all` plus `HEAD`, falling back to
  per-ref `git ls-tree` in a shallow clone (`D-M6E11-26`) — no network (`D-M6E11-10`).
- **AC-4.2** — An ID is never reused, including IDs of closed and archived items.
- **AC-4.3** — The duplicate-ID test (AC-3.2) fails on a fixture with two branches that allocated the
  same number, and names both files.
- **AC-4.4** — Outside a git repository, allocation falls back to the working tree and says so.

### FR-5 — `/sig:item`: every move goes through one command

- **AC-5.1** — `new`, `triage`, `move`, `close`, `show`, `list` exist, as a command file and as
  `tools/lib` functions the command calls (`D-M6E11-5`).
- **AC-5.2** — A move is a `git mv` when the project is a git repo (history follows the file), and
  updates the frontmatter in the same operation; a failure leaves the file where it was, unchanged.
- **AC-5.3** — `triage` walks `inbox/` one item at a time, proposes type, priority, theme, a title and
  possible duplicates, and moves the item to `backlog/` (or to `done/` as `dup`/`rejected`) on the
  answer. Attention setting governs confirmation as in every other phase.
- **AC-5.4** — `close` refuses without a `reason`; `fixed` asks for proof (commit, PR or test) and
  records `proof: none given` rather than an empty field when the user declines.
- **AC-5.5** — `list` filters by status, type, theme, priority and Epic, and renders labels.

### FR-6 — Capture writes an item

- **AC-6.1** — With the store on, `/sig:add` (default, `--bug`, `--question`) writes a new
  `inbox/{KEY}-{n}.md` with the words verbatim and `source`, `created`; its existing scrub and atomic
  write still apply (`D-M6E11-6`).
- **AC-6.2** — With the store on, **no** code path appends to `BUGS.md`, `BACKLOG.md`,
  `ISSUES-INBOX.md` or `OPEN-QUESTIONS.md`. PLAN classifies each of the 9 modules with write calls;
  a test asserts the generated files are only ever written by the generator (`D-M6E11-4`).

### FR-7 — Generated lists keep existing readers working

- **AC-7.1** — With the store on, `BUGS.md`, `BACKLOG.md`, `ISSUES-INBOX.md` and `OPEN-QUESTIONS.md`
  are regenerated from items, headed *generated — do not edit*, and regeneration is idempotent.
- **AC-7.2** — Each generated file parses with the reader that consumes it today to the same result as
  the items, compared per reader: `walkBugEntries` → the set of (B-id, status); `parseBacklogRows`
  → the set of live row titles; `listDrainCandidates` → the set of (heading, status line) of open
  captures, plus a standing count of 1; `countOpenQuestions` → the number of open `Q` items, and
  `extractTopOpenQuestions` → the first three open titles. *(Refined at PLAN: two of the four
  readers identify entries by position or return only a count.)*
- **AC-7.3** — `/sig:advise` run on Signal's own migrated repo produces an advisory whose live set
  equals ~~the items in `backlog/` (plus open Epic items) — with no discharge inference involved~~ the
  items the generated BACKLOG.md carries (`D-M6E11-32`); no row is discharged by inference.

### FR-8 — Epic folders

- **AC-8.1** — `epics/<EpicID>/` holds the items moved into it; an agent's answer to *"what is in
  this Epic?"* is a `list --epic` that reads that folder and nothing else (`D-M6E11-13`).
- **AC-8.2** — The Epic index (list of Epics, their items and statuses) is generated, never hand-written.
- **AC-8.3** — `/sig:ship`, with the store on, refuses to close an Epic while any item in its folder is
  not `C`, naming each; it proceeds once each is closed or moved back to `backlog/`.
- **AC-8.4** — On close, the Epic folder moves to `archive/epics/<EpicID>/` with the close recorded
  (when, PR, release). Its items keep their IDs and remain findable by `show`.
- **AC-8.5** — ~~`M6.E11` itself runs from `work/epics/M6.E11/` once the store exists on this repo~~
  `M6.E11`'s items and artifacts end EXECUTE in `work/epics/M6.E11/`; its VERIFY, REVIEW and SHIP
  artifacts are written there and `/sig:status` / `/sig:resume` resolve from it (`D-M6E11-23`).

### FR-9 — Migrate Signal's own records

- **AC-9.1** — A migration writes one item per bug (table row **or** un-numbered `##` entry), backlog
  row, inbox capture and open question; numbered bugs keep their number (`B75` → `SIG-75`,
  `legacy_id: B75`); the 13 un-numbered bugs take `SIG-128`…`SIG-140`, then backlog, inbox, questions
  in file order (`D-M6E11-9`, `D-M6E11-15`). The standing watchlist is not an item (`D-M6E11-18`).
- **AC-9.2** — Statuses map per `D-M6E11-14` and `D-M6E11-16`; ambiguous rows take today's parser verdict plus a
  `migration_note` (`D-M6E11-17`); every migrated close carries
  `proof: legacy — not re-verified`. No status is re-judged.
- **AC-9.3** — Dry-run by default, reports counts per source and per resulting status; `--apply`
  writes; the original files are preserved verbatim under `archive/`.
- **AC-9.4** — Lossless: every byte of every migrated row appears in exactly one item body, checked by
  a test that reassembles the sources' row text from the items **with relative link targets
  normalised** (`D-M6E11-22`); text belonging to no row (preambles, section intros, the BUGS footer,
  BUGS lines 128–151) is kept in the archived original, and the test names each such region.
- **AC-9.5** — Counts reconcile: items created = ~~127~~ 140 bugs + backlog rows + inbox captures + open
  questions (**248** at PLAN, `D-M6E11-15`) as measured by the migration's own dry-run, and the dry-run's numbers are the ones written
  into VERIFICATION (derived, not asserted).

### FR-10 — Housekeeping

- **AC-10.1** — `BACKLOG.md`'s structural-status row and `CLAUDE.md`'s *Next* line stop presenting
  *"a marker in the files, or GitHub Issues"* as open (`D-M6E11-2`).
- **AC-10.2** — `CHANGELOG.md` names **`/sig:docs-migrate`** as the path for other projects (step 5,
  not yet built), so the reminder Brett asked for is in the release notes, not only in memory.

## Non-functional

| Item (FULL prompt) | Disposition |
|---|---|
| Health / liveness probe | N/A — a CLI plugin with no long-running process. |
| Graceful shutdown | Covered by AC-5.2: a move either completes or leaves the item untouched. |
| Structured request logging | N/A — no server; each command prints what it moved, from where, to where. |
| Security headers | N/A — nothing is served over HTTP. |
| Rate limiting | N/A — no public surface. |
| Path safety | Item IDs and Epic IDs become path segments: both are validated against a strict pattern and confined to `.planning/work/` (the `path-confine.js` rule; `B14`'s symlink lesson applies). |
| Offline | Every operation works with no network; ID allocation reads local refs only. |
| Performance | `list` over this repo's ~235 items returns in under a second. |

## Blast radius — what this touches that we are not changing

- **The 19 reader modules and 14 commands** that name the four files: kept working by the generated
  lists (FR-7), converted in later steps. `/sig:advise` reads `BACKLOG.md` at `maxDepth: 4` — the
  generated file must keep rows at the depths it reads.
- **208 test files**, several of which read this repo's live `.planning/` files (e.g. `B120`'s
  `drain-standing` test pins the live inbox). Migration will move those files' content; each such test
  is identified at PLAN and repointed at a fixture, not weakened.
- **Every project tracking `main`** receives this code. FR-1 is the whole guard.
- **Published citations**: `path:line` citations into `BUGS.md`/`BACKLOG.md` in past advisories,
  retros and CHANGELOG stop resolving once those files are generated. The originals are kept verbatim
  under `archive/` (AC-9.3), so a citation stays checkable at its commit — the same answer `B119` gives.
- **Eval corpus**: read-only; nothing here runs against it.

## Outcome

**How we will know it worked**, on Signal's own repository after migration:

1. **Each item's status is written in exactly one place** — its frontmatter, with the folder checked
   against it. Measured by the consistency check (AC-3.2) returning zero findings, and by a grep for a
   sample of 10 IDs showing no hand-written status anywhere else in the live tree.
2. **The guessing goes to zero.** `bug-status-vs-changelog` and `/sig:advise`'s backlog discharge
   inference have nothing to infer from: run before and after, the count of rows each must *judge*
   drops from today's numbers (measured at PLAN as the baseline) to 0.
3. **"What is in this Epic?" is answered by one folder.** `M6.E11`'s own items live in
   `work/epics/M6.E11/`, and the next Epic opens there too.
