| B109 | `fixed` | P3 | **FIXED 2026-08-25.** `setChangelogTestCount` reconciles the pending section's trailer from the same gating run that supplies `facts.md`'s count, composed into the same `releaseEdits` entry as the fold so the two cannot diverge. ⚠ **The design stated when this row was filed — *throw on absence* — was WRONG, and measuring is what said so:** 14 of 33 released sections carry a trailer and **19 do not**, so throwing would have failed the cut for the more common shape (`B42`'s defect). Absence returns unchanged **and reports**, because a silent no-op is `rewriteBugTally`'s bug. The baseline is checked against `facts.md` and deliberately not rewritten. `pendingSectionBounds` is now shared with `foldChangelog` (`B82`) — they must agree or the trailer could rewrite history while the fold refuses (`B84`). **Proof-of-fail in three directions** (fold-before-trailer → 4 red; throw-on-absence → 7 red; first-match → 2 red) **and replayed against the real pre-cut `CHANGELOG.md` from git**: corrects `2927 → 2979`, history byte-identical. ⚠ **The first implementation shipped this bug's own shape and CI review caught it:** the regex took the **first** match in the section, and the notes for the fix quote a trailer as a prose example above the real one — so it rewrote the quoted example, left the trailer stale, and reported *"corrected"*. A **false green inside the function written to prevent one**, found by running the tool against the real file rather than by the suite (`B82`, third instance). Now anchored on the **last** match, with multi-candidate sections disclosed in the note. **Original entry:** **`cut-release.js` does not reconcile the CHANGELOG section's own test-count trailer, so every release publishes whatever number was true mid-Epic.** Found 2026-08-24 by CI review on the `v0.1.33` cut (PR #203), not by reading the file: `CHANGELOG.md`'s pending section closed with `2841 → **2927 tests**` while `facts.md`, `CLAUDE.md` and `.planning/CONTEXT.md` — all written in the same PR — said **2979**. A 52-test gap for one release, in the document that *is* the release notes. ⚠ **This is `B106` one layer over, and `B106`'s own fix is why it is visible.** `B106` taught `releaseEdits` to write `facts.md`'s count **and** its attribution by one edit so they cannot diverge; the CHANGELOG trailer is the same class of release-time fact — only knowable at the cut, unre-derivable between cuts — and no edit touches it. It is hand-typed into the `[Unreleased]` section while the Epic is still adding tests, so it is stale **by construction** at every cut, not occasionally. **The detector gap is the sharper half:** `M6.E2`'s `facts-attribution` check reads `facts.md` and nothing reads this trailer, so the condition is invisible to the suite and was caught only because a reviewer compared two files by hand. **Fix shape:** set the trailer in `releaseEdits` from the same `vitest` run that supplies `facts.md`'s count, and **throw rather than no-op** when the pattern is absent (`rewriteBugTally`'s lesson). ⚠ **The trailer's shape is not guaranteed** — it is prose an author writes freehand, so a strict pattern that throws will fail a cut whose author phrased it differently. That is the design question, and it is why this was filed rather than fixed inside a release commit. |
