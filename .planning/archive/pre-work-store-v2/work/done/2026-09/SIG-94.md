| B94 | `fixed` | **P1** | **`BACKLOG.md` is append-only: nothing in Signal ever marks a backlog row done when the work ships, so the queue asserts false status indefinitely.** Verified 2026-08-13 in Signal's own tree — four rows describing work completed that same day (requirement-coverage diff, VERIFICATION template, `B38` reclassification, correction protocol) still read as pending. **Mechanism, checked in the code rather than inferred:** (1) `commands/ship.md` reconciles FIVE document surfaces at Epic close — retro index §6, evict-on-close §5.5, STATE §5, CHANGELOG §1, and a **light inbox sweep §6.5** — and touches `BACKLOG.md` in none of them. (2) `tools/lib/backlog.js` has exactly two write paths, `createIfMissing` and promote-append; **no discharge function was ever written**. (3) `BACKLOG.md` and SHIP's inbox sweep were built by the SAME Epic (M5.E3 FR2), which gave the inbox both ends of the pipeline and the backlog only the intake end. (4) Signal's lifecycle machinery is **Epic-scoped** (`transitionPhase`, PROGRESS, retro gate, evict-on-close, archive tree); a backlog row is pre-Epic, so on promotion it becomes orphaned data with no owner and **no structured link back** — `M5.E10-REQUIREMENTS.md` and `-PLAN.md` each mention `BACKLOG` once, in prose. Even a diligent SHIP has nothing to follow. **Field evidence (eval-project-A, 2026-08-13):** `BUGS.md` accurate (26/28 closed, closure is commit-tied); `ISSUES-INBOX.md` accurate as a historical capture log (115 entries routed 2026-07-28, routing recorded — the PLAN drain works); `BACKLOG.md` **two weeks stale with ~15 shipped slices reading as pending**. The one document users treat as the queue is the one document with no closing mechanism. **Why it stayed invisible:** Signal's own backlog is hand-groomed by the maintainer in conversation, so drift presented as *"Brett re-grooms occasionally"* rather than *"the tool never does this"* — `B82`'s dogfood blindness exactly. **Severity is P1 and the reason is claim integrity, not convenience:** a stale queue is not missing coverage, it is a document actively asserting false completeness — `M5.E10`'s own defect class, in the file a user trusts most. **None of the six checks `M5.E10` shipped detect it**, and the NFR5 corpus measurement did not look for it. *Fix:* `dischargeBacklogRows()` in `backlog.js` reusing the `discharged`/`dischargedBy` shape `obligations.js` already defines; a SHIP §6.6 step symmetrical with the inbox sweep, requiring the Epic to name the rows it discharges; a `/sig:sweep` check flagging rows whose work looks shipped. **FIXED 2026-08-13 (`M5.E10` S7, `92ad0df`)** — `dischargeBacklogRows` + `parseBacklogRows` in `backlog.js`, `ship.md` §6.6 (Epic-close, rows named by the Epic), and a `/sig:sweep` `backlog-discharge` check. The discharge rewrites the **heading** rather than dropping an HTML marker: a comment does not render, so the document a reader opens would still assert the same false status. **The detector is 1 of 12 on the corpus and cannot evaluate `eval-project-A`, the project this bug was filed from** — its rows name no unit ids. The *closing mechanism* reaches it; the detector half is Signal-shaped and the measurement says so rather than implying coverage. |
