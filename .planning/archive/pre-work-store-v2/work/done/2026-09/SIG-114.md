| B114 | `fixed` | P3 | **FIXED 2026-09-02, same day as filing.** **`/sig:docs-migrate` told a legacy project *"nothing to migrate"* — a dead-end refusal in front of a door that was already open.** A pre-frontmatter `STATE.md` is scoped out at `migrate-memory.js`'s `splitFrontmatter` gate, and the refusal read *"STATE.md has no YAML frontmatter — not a schema_version:1 file; nothing to migrate."* The refusal itself is **correct** (render `:1851` and apply `:2229` share the gate, so there is no preview/apply drift, no write, no tag). **"Nothing to migrate" is false.** The file does need converting; `upgradeStateFile` (`state.js:166`) does it — synthesising `schema_version: 1` frontmatter, relocating the legacy narrative verbatim to `.planning/STATE-HISTORY.md`, idempotent — and `readStateForMutation` (`state.js:777`) **calls it automatically** on the next state-writing command. So a stranger was told they were stuck by a tool whose remedy fires on its own the next time they run `/sig:discuss`. **Found 2026-09-02 by running `/sig:docs-migrate --dry-run` against a real pre-frontmatter project outside this repo** while rigging the `/sig:drive` end-to-end run; reproduced byte-for-byte on the non-dry-run form, same `inputHash`. ⚠ **The message cost more than the confusion it caused:** reading the refusal at face value, this session drafted a five-step manual conversion procedure for the maintainer and characterised the tool as unable to onboard an existing project — **three of those five steps were unnecessary**, and the correction only came from reading `readStateForMutation`. A message that names no next step does not merely fail to help; it invites a wrong model of the system, and the wrong model gets acted on. **Fix:** one shared exported `LEGACY_STATE_REFUSAL` constant (one string, both paths — they must not describe the same refusal differently) naming what the file is, that the conversion is automatic, where the narrative goes, and to re-run afterwards for the layout migration this command does handle. Two tests: the wording assertion (mutation-verified RED against the old string) and a render/apply parity assertion. ⚠ **Not fixed here — `/sig:docs-migrate` still does not perform the legacy upgrade itself.** Chaining it was considered and left out of the fix lane: it turns a read-only dry-run into a write path, which is a design call, not a message fix. |
