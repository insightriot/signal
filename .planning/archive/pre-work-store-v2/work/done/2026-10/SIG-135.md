## dischargeBacklogRows is blind to rows nested below h3

**Status:** needs-triage

dischargeBacklogRows cannot see any row nested deeper than h3. Found 2026-08-24 at M6.E4 SHIP §6.6. parseBacklogRows matches /^(#{2,3})\s/ (backlog.js:325), so rows at #### are invisible — and #### is CORRECT markdown for a row nested under a ### section heading, which is how BACKLOG.md's "Twelve promoted from the inbox drain" section is built. All three rows M6.E4 closed returned not-found and had to be struck by hand. This is B94's own class recurring: the mechanism built so the backlog stops asserting false completeness cannot reach the rows that need discharging. Scope: 12+ rows in that section today, plus any future section that nests its rows. Fix candidates: (a) widen to #{2,4}, weighing the container-fold comment at backlog.js:331 which reasons explicitly about ## vs ### depth pairs and would need re-checking at depth 4; (b) flatten the section so rows sit at ###, which loses the grouping. Note the instruction in ship.md §6.6 says not-found means "check the wording" — it assumes a wording problem and has no branch for a structural one.
