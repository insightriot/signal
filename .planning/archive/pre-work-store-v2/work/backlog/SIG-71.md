At the v0.1.15 ship commit (`8acd1d2`) `STATE.md` read **`phase: PLAN`**, **`completed_phases: [DISCUSS (2026-07-31)]`**, `current_epic: M5.E17` — and `MILESTONE-5.md` contained **zero** `E17` rows. The release commit touched five files (`plugin.json`, `package.json`, `marketplace.json`, `CHANGELOG.md`, `STATE.md`): **no retrospective, no SHIP artifact, no phase advance.** The whole Epic was three commits — DISCUSS, one combined work commit, the release. **`/sig:ship` was never invoked, and the retro gate lives inside `/sig:ship`** (`ship.md` §0.5 → `shipFR1Check`), so nothing ran and nothing said so. **The gate would not have fired even if it had been invoked**, and this is the actual defect: both Epic-close detectors return `false` for this shape. `isEpicCloseShip` (`retrospective.js:352`) returns `false` when `findEpicStatusRow(...) === null` — **there was no row**. `isEpicCloseByState` (`:410`), the `B26`/`M5.E5.T2` fallback that exists precisely for row-absence, requires `phase === 'SHIP'` **and** `completed_phases` covering every tier-enabled pre-SHIP phase — it had **one of five**. **An Epic that runs all six phases is the one least likely to skip its retro; an Epic compressed into two commits is the one most likely — and is exactly the shape both detectors are blind to.** **This is the class M5.E13 and M5.E16 both named, in a third shape:** the gate verifies one *document's claim* (a milestone row, a STATE phase ledger) against another, and never against the world — *did a release actually get cut?* `B36` was the near-miss on this same gate (a **stale** row silently skipping it, made loud in v0.1.11); this is a **missing** row plus a phase ledger that never advanced, and `B36`'s loud-skip path cannot reach it because that path only runs once the gate has already decided this is an Epic close. **Not caught by the gate — caught after the fact by `/sig:sweep`'s `epic-without-retro` check** (M5.E16, v0.1.16), on **2026-08-03 at the `/sig:resume` that opened M5.E18**: its first fire in normal use, one day after shipping, working exactly as designed. **Detection exists; prevention does not.** **Noted, not blamed:** `M5.E17` is the Epic that removed `ship.md`'s direct-to-main self-exemption, and its own release was cut directly to `main` without running `ship.md`. **The branch-and-PR ruleset (`D-M5E17-5`) does not close this** — a PR is not a ship, and no rule requires `/sig:ship` to run before a tag. **Live consequence, low severity today:** `isEpicDone` is `existsSync(retroPath)` (`retrospective.js:168`), so `isEpicDone('M5.E17')` is **`false`** — `/sig:discuss`'s done-Epic guard would not halt on it, leaving `M5.E17-REQUIREMENTS.md` clobberable by anyone who sets `current_epic` back to it. **Fix shape (not attempted here):** the gate needs a third detector keyed on something outside `.planning/` — a tag, a `plugin.json` version bump, a release commit — so *"a release happened for this Epic"* is answerable without the phase ledger's cooperation. That is a **world-check**, and it is `M5.E18`'s FR2 question (*what proves a unit is closed*) pointed at Signal's own repo rather than at a user project. **Homed at M5.E18** — same mechanism, same Epic; see `D-M5E18-3` and the FR5/AC5.3 open question, which this makes answerable: **`isEpicDone`'s tightening should be in scope, not deferred.** Filed 2026-08-03. |
