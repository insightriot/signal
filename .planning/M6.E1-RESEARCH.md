research questions this Epic actually has are **mechanical questions about this tree** — what
references what, and what a package contains — answerable by `grep` and `du` in less time than

## 2. The two path expressions that change meaning — the actual risk of this Epic

Two shipped files derive the **plugin root from their own module path**:

| File | Expression | Today | After the move |
|---|---|---|---|
| `tools/lib/plugin-binding.js:56` | `dirname(dirname(dirname(realpath(import.meta.url))))` | repo root | `plugin/` |
| `tools/lib/roster.js:22` | `join(__dirname, '..', '..')` | repo root | `plugin/` |

**Both stay correct — but only because the move preserves the depth**, `tools/lib/x.js` sitting two
levels below the plugin root in both layouts. **That is a coincidence the plan must not rely on
silently.**

**`plugin-binding.js` is the one that matters.** It is `B52`'s mechanism — *which copy of Signal is
actually running* — and its comment states the design: derived from `import.meta.url`, **never**
`CLAUDE_PLUGIN_ROOT`, because the env var says where the plugin is *supposed* to be and the bug is
exactly that disagreement. If the move breaks it, the failure is silent and it is the failure that
*"silently discarded M5.E8's six-phase ledger."*

**`roster.js` is the quieter one:** its `ROOT` is the default `baseDir` for `listCommands` /
`listAgents` / `listSkills`, which feed the roster-count checks. Post-move it points at `plugin/` —
which is **where those directories will be**, so it is right for a new reason.

## 3. `hooks/` → `tools/lib` imports survive untouched

Four hooks import `../tools/lib/*.js`. Because `hooks/` and `tools/lib/` move **together**, the
relative geometry is preserved: `plugin/hooks/x.js` → `../tools/lib/y.js` → `plugin/tools/lib/y.js`.
No rewrite needed. **This is the argument for moving the payload as one unit** rather than
cherry-picking directories.

## 4. `yaml` — the three options, measured

`yaml@2.8.3`: **ISC**, **zero dependencies**, CommonJS (`main: ./dist/index.js`), 233 files / 1.2 MB
(`dist/` 796 KB + `browser/` 456 KB).

| Option | Install runs? | Network at install? | Cost |
|---|---|---|---|
| **A — manifest** (`plugin/package.json` + lockfile, `yaml` only) | yes, ~1.2 MB | **required** | two manifests can drift (`AC3.3` pins it) |
| **B — commit `plugin/node_modules/yaml/`** | **no** | none | `.gitignore:1` is `node_modules/`, so it needs an exception; manual dependency updates |
| **C — vendor `dist/` + rewrite the two imports** | no | none | deep-importing a CJS package past its `exports` map; named-export interop is the fragile part |

**Recommendation: A, with B named as the fallback and its trigger written down.** A is idiomatic,
keeps `tools/lib/*.js` as source (the stated reason bundling was rejected in `D-M6E1-3`), and Signal's
users are developers who have npm. **The residual risk is real and is `AC3.4`'s subject:** a failed
dependency install *"never blocks the plugin"*, so a restricted-network user gets a plugin where the
18 commands that never touch `profile.js`/`state.js` work and the rest fail at the import. That
outcome must be made legible, not prevented.

**C is rejected outright**, not deferred: it trades a 1.2 MB problem for a module-resolution problem
in the two files that parse `STATE.md`, and `B61` is a live bug about `yaml`'s exact
type-coercion behaviour in that path.

**B's trigger, so it is a decision rather than a drift:** adopt B if the install proves unreliable in
the field — one report of `AC3.4`'s failure mode from a real user is enough.

## 5. Blast radius, counted

- **136 test files** reference `tools/lib`; **135** carry a `../tools` import. The DISCUSS figure of
  138 came from a **broader pattern** (`tools/lib` *or* `../tools`), not from a different file set —
  stated precisely because "corrected by re-running the count" was the first explanation written here
  and it was **wrong about why**, which is the defect class this repo closed Milestone 5 on.
- **168 files repo-wide** reference `tools/lib` outside `tools/` itself — the number that matters for
  `FR2`'s grep, since it includes command files, agent files and docs, not just tests.
- **4 build/config entry points**: `package.json` `build`/`lint`/`validate` scripts, `vitest.config.js`
  `include` globs.
- **`validate-plugin.js`'s `ROOT`** is `join(__dirname, '..')` and the script **does not move**, so its
  `ROOT` keeps meaning the repo root while everything it validates moves to `plugin/` — the one place
  where a path expression breaks rather than silently retargets.
