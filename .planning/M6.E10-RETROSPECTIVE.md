# M6.E10 — Retrospective

**Shipped:** `/sig:drive` can advance. It asks how you want it run, in the same question that picks
the work. Floors fire on their condition instead of on a phase's name. **3354 → 3379 tests.**

## The finding

**The command had never worked, and nothing could tell — because nothing ever asked whether
`proceed` was true.**

Every guard around this loop was real and none of them checked the one thing that mattered. There
were tests for the floor list, the fail-closed posture, the loop ceiling, the doc-symbol contract.
There was no test asserting that **any** setting, at **any** phase, ever returned `proceed: true`.
A single line — *at least one mode reaches REVIEW without stopping* — would have failed from the day
the command shipped.

**Worse: two tests were holding the defects shut.**

| Test | What it pinned |
|---|---|
| `drive.test.js` — *"checkpointed stops at the phase boundary"* | that the middle mode must never advance |
| `drive-router.test.js` — *"queues at unattended and checkpointed"* | that the two modes must behave identically |

Both were written deliberately, both described real behaviour, and both made the bug the contract.
**Coverage asserting the wrong thing is worse than no coverage**, because it converts a defect into a
requirement and anyone who fixes it turns the suite red.

## The reported symptom was accurate and I spent a week not hearing it

Brett's report was *"every time I use it, something pops up as 'that didn't work'"*, and the response
was a diagnosis about closed feedback loops and missing external users — **built on the premise that
Signal had no real usage.** It has 42+ repositories using it. The bug reports were the signal, and
they got treated as a symptom of something else.

**The measurement that settled it took four minutes** once the actual question was asked: trace
`canProceedUnattended` over every phase at every attention level and print the answers. Nothing about
that needed a week.

**The lesson is not "measure more."** It is that a user saying *it doesn't work* is a claim about the
software, and the first move is to reproduce it, not to reframe it.

## What the fresh-context reviewers are worth, measured twice

| Epic | Specialists found | `claude-review` at PR-open |
|---|---|---|
| `M6.E9` | 4 Critical, 7 Important | **clean** |
| `M6.E10` | 7 Important, 1 Medium | **clean** |

Both times they found a **false claim the Epic had made about itself** — and both times the
in-session review found none of it. That is not a knowledge gap; it is the author's blind spot,
which is the property the dispatch was built to exploit.

⚠ **This Epic's own worst finding is one of them.** FR3 says *"no setting may be documented with
behaviour that has no code path."* The Epic removed one such description (`checkpointed` "runs free
inside a phase") and **wrote another one into three documents** (`checkpointed` "asks" while
`unattended` "queues" — the code made them identical). Not a lapse in rigor: FR3 was on screen while
it happened.

## The rule that keeps having to be relearned

**A proof must assert the specific outcome, not that the suite passes.** Third instance in two Epics:

1. `M6.E9` — a shell-escaped mutation whose backticks did not survive quoting, so it silently no-op'd
   and a passing suite read as *"the guards are vacuous."*
2. `M6.E9` — two "proof" tests that appended a string and asserted the string's presence.
3. `M6.E10` — a fixture for the drain-parser guard that carried a live entry above the fence as well,
   so both parsers returned non-zero and the mutation produced **zero red**.

Every mutation in this Epic now aborts if its pattern did not match. That is cheap and it is the only
thing standing between a proof and a decoration.

## Process

**Phase boundaries were crossed deliberately and announced**, per the standing preference after a
week of low output. That is the second Epic run that way, and it is now the norm rather than an
exception — which argues the profile should say `unattended`-with-floors instead of being overridden
by hand each time.

**Scope held.** The build was the smallest thing that made the command work: two behaviours and a
question. No dispatch machinery, no queue drainer, no sub-phase granularity — all named out-of-scope
in the requirements rather than discovered missing later.
