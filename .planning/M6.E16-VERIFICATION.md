## Verdict

**FAIL — two things are not met. Both are small, and neither is a wrong decision by the code.**

1. **AC6.4 is not met as written.** It says a project with no unit records behaves *exactly* as on
   `v0.1.50`. Run side by side against `main` on the same temp project, four things differ (listed
   under AC6.4 below). No refusal, closure answer or file move differs — the differences are two
   message texts, two added result fields and one validation rule the requirements themselves
   announce. The existing suites the criterion names all pass unchanged; they do not pin these four.
2. **Strict Nyquist is not met for three criteria.** [`M6.E16-VALIDATION.md`](M6.E16-VALIDATION.md)
   maps a live test to AC8.1 and one to AC8.4; neither test exists in `tests/`. AC4.7 has a test and
   no row in that file. All three criteria hold on today's data — checked here by hand — but nothing
   in the suite would notice if they stopped holding.

Everything else is met: 28 of 36 criteria with no reservation, 7 of 36 with a limit stated below,
and 3 of 3 non-functional requirements. The suite and lint are clean and equal the baseline.

**What it takes to fix:** for (1), either amend AC6.4 to name the four differences (as AC7.3 and
AC2.1 were amended at EXECUTE) or restore the old text and shape — a product call, not a code

  end to end on a temp project, not on this repository.

  `regenerateViews` writes the Epic table of one file only — the milestone of `current_epic`
  (`currentMilestoneOf`, `plugin/tools/lib/work-views.js`). If `current_epic` moves to a new
  milestone before a close is confirmed, the older file's row is not rewritten and is not checked

  names that are not Epic IDs were exercised on fixtures only. The on-disk case-twin test has never
  run on any machine.
- **Per-commit health.** The suite was run at the branch head only. That it was green at the
  cutover commit `010262f7`, and at each slice's end, is the progress file's statement.
- **Mutation passes and the S1 byte-compare** were not re-run; their scripts are not in the
  repository.
- **Concurrency.** Whether the close gate excludes a concurrent item write (S4's own "not
  verified") was not tested here.
- **Where the evidence index reads from.** `buildEvidenceIndex` reads unit records from the working
  tree, not from the default branch. A `shipped` close is only written after a confirm against

  `WORK.md` (S6's own note); the hold is read from the unit record either way.
- **A kept narrative is not retried** (S10's own note): if eviction is refused when a close is
  confirmed, no later run evicts it. AC4.7 does not ask for a retry; the gap is real.
- **The suite is known to be flaky under load (`SIG-139`).** Two clean runs do not show it is not.
- **The derived checks.** `diffRequirementCoverage` proves each ID is cited, not that it is met.

- **Uncommitted at the time of this check:** `.planning/STATE.md` (the phase change to VERIFY) —
