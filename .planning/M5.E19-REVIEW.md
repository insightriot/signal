## Step 1 — Code quality

### C1 (Critical, fixed) — a comment asserted a property the code did not have

`buildArchiveReport` grouped moves by reverse-engineering the unit from the destination path
(`archive/M1/E1` → `M1.E1`) via a `dirOwns` helper — **under a comment stating the mapping was "NOT
re-derived from the unit name here."** The comment described the intent; the code did the opposite.

This is listed by name in M5.E18's retrospective as a found defect (*"a wiring comment asserted a
property the code no longer had"*), and it is the same family as `B82`, which this Epic began by
fixing: **two implementations of one mapping.** Fixing `B82` in the mover and then reintroducing it
in the reporter one week later would have been the worst possible outcome for the Epic.

**Fixed:** membership now comes from `deriveUnits` — the same authority `planArchiveMoves` consumes
— and the destination directory comes from the move itself. `dirOwns` deleted.

### C2 (Important, fixed) — a guard that guards nothing

The same block tested `m.to.startsWith(`${dir}/`)` where `dir` was sliced out of `m.to` **one line
above**. Vacuously true, always. It read as validation to anyone skimming and validated nothing —
the `v0.1.14` "guards that don't guard" shape, in code written by the Epic that keeps citing it.

**Fixed:** removed with the rewrite in C1.

### C3 (Important, fixed) — a stated cause that was never checked

Every `closed`-but-not-archiving unit was reported as *"its retrospective is a stub."* True for the
common case (`B64`), **false** for a unit dropped on an unsafe name — which would have published a
confident, wrong diagnosis. Asserting a cause without checking it is `CLAIM-INTEGRITY-ANALYSIS.md`'s
whole subject.

**Fixed:** `refusalReason` consults `sense.dropped` first and names the actual mechanism. The
near-unreachability of the drop path (`isSafeUnitName` rejects names filenames cannot produce) is
**not** the reason to leave a false claim in place.

### C4 (Minor, fixed) — `applyArchive` hardcoded `applied: true`

It returned a literal instead of passing `res.applied` through — this module asserting a fact it did
not observe. Fixed.

### Not fixed, deliberately

- **`ownerOf` is O(files × units) to build.** Irrelevant at corpus scale (tens of files) and the
  clearer shape. `performance_pass: false` for this tier, and the profile says why.
- **`empty` is only used on one branch.** Keeping it named documents the shape the function
  guarantees; inlining would save nothing and lose that.

## Step 2 — Security (`security_audit: basic`)

The relevant boundary is **path confinement**, since this module's output becomes filesystem
destinations.

- **No path is constructed here from a unit name.** Every destination comes from
  `planArchiveMoves` → `deriveUnitArchiveDir`, which throws on anything failing `isSafeUnitName`
  (rejects `..`, separators, non-alphanumeric starts, > 100 chars). The rewrite **reduced** exposure:
  the deleted `dirOwns` was the only code here that parsed a path.
- **`readdir` scope** is `baseDir + .planning/`, non-recursive, filtered to `.md`. No symlink
  traversal, no user-supplied glob.
- **Rendered reasons** are resolver-produced strings containing filenames, written to a terminal.
  No interpolation into a shell, path, or query.
- **Writes** are confined to `applyArchiveTree`, unchanged by this Epic, which asserts a
  byte-identical read-back before removing a source.
- **The unreadable-STATE guard is a security-relevant control**, not just correctness: without it
  the command proposes destructive moves on a project whose current unit it cannot identify.

No findings.

## Step 3 — Performance (`performance_pass: false` for this tier — run anyway, briefly)

Two directory reads and two in-memory passes over a corpus of tens of files. `senseArchiveTree` and
`resolveClosures` each walk `.planning/` independently — a duplicated read that would matter at
thousands of files and does not at 21. Noted, not changed: collapsing them means changing two
modules this Epic otherwise does not touch, which is scope the profile explicitly declines.

## Step 4 — Simplification

The C1 rewrite is net **simpler**, not merely more correct: one helper deleted, one nested loop
replaced by a map lookup, and the double `deriveUnits(names)` call collapsed to one. That last one
mattered beyond tidiness — **two derivations of one fact is exactly what this Epic exists to
remove**, and it had crept back in within the same file.

No further simplification proposed. The `plan`/`refusals` split is the shape the FRs demand.
