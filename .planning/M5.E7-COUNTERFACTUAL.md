### What this pass can and cannot conclude

record, and cite the ID. It **cannot** say the mechanism would have fired — most of these are
prompt assets with no enforcement (see §5).

## 2. Four counterfactual answers

### 2.1 gstack — **No**

No bug in `BUGS.md` and no Epic in the retro corpus traces to a capability gstack fills.
Candidate by candidate:

**`/cso` (15-phase security audit) — no.** Signal shipped two security-relevant findings, B14
(lexical symlink confinement) and B22 (unbounded disk read outside the walk root). Both were
found by Signal's own existing REVIEW panel: `BUGS.md:37` — "Confirmed 2026-07-18 by the M5.E2
security audit"; `BUGS.md:49` — "Deferred (Suggestion, M5.E3 REVIEW rev-sec)". `/cso`'s Phases
2–11 target secrets archaeology, dependency supply chain, CI/CD, infrastructure, webhooks and
STRIDE (`M5.E7-SUPPLY-GSTACK.md` §1.1) — an attack surface a markdown-plus-Node-CLI plugin does
not have. The one phase that maps to Signal's shape is Phase 8 (skill supply chain, "SKILL.md
files are NOT documentation… they are executable prompt code", `cso/SKILL.md:988`) — and no
cataloged Signal bug falls in that class.

**The carve / manifest pattern and size-budget harness — no.** `tools/measure-phase-costs.js`
run 2026-07-25 puts every phase between 1.9% and 6.4% of a 200K budget
(`M5.E7-SUPPLY-GSTACK.md` §2.5). Signal's largest single skill is 14,041 bytes; gstack's
*smallest carved* skeleton is budgeted at 56,000. The risk this addresses has never bitten, and
no Epic lost time to it.

**`/office-hours` six forcing questions, `/plan-ceo-review` four modes — no.** Upstream
capabilities; see §5 blind spot 2 for why this "no" carries almost no information.

One near-miss worth recording rather than counting: `/plan-ceo-review`'s Step **0B, Existing
Code Leverage** — *"Is this plan rebuilding anything that already exists?"* — matches M5.E6's
FR7, where the plan's premise ("the RMW paths are unlocked") was factually stale
(`M5.E6-RETROSPECTIVE.md:14`). But Signal's own 4-agent PLAN codebase research caught it at
PLAN, produced D-M5E6-5, and the Epic got *smaller*. The mechanism Signal already has worked.

**The learnings loop (`Capture Learnings` → `learnings.jsonl` → `Prior Learnings`) — no.** This
is the candidate most likely to look like a hit, and it is the most important "no" in this
document. Its reasoning is the spine of §3.1, so it is argued there rather than here.

The single closest candidate is **B13's recurrence**: the lesson "a raw NUL byte makes a file
grep-blind" was learned and fixed in source on 2026-07-18, then violated on ~2026-07-25 when the
bug's own writeup pasted the offending snippet verbatim into `BUGS.md`, leaving the file
grep-blind from `5062526` until found at `/sig:resume` (`BUGS.md:36`). That is a genuine
cross-session recurrence across Epics. It still resolves to **no**: gstack's read-back surfaces
a top-10 digest filtered by decayed confidence at *skill start* in 10 of 54 skills
(`M5.E7-SUPPLY-GSTACK.md` §5.3) — the probability that "don't paste control bytes" surfaces at
the moment someone edits a bug entry is not credible, and Signal's actual defense for this class
is a deterministic content check of the kind `doc-hygiene.js` already hosts.

### 2.2 pm-skills — **Yes**, narrowly. Cited: **B39**, **B40**, **B37**

**The upstream PM half is a plain no.** `/discover`, `/strategy`, `opportunity-solution-tree`,
assumption mapping, the six-skill GTM cluster — no bug, no Epic. See §4.

**The hit is `intended-vs-implemented`** (`pm-ai-shipping`, 42 lines,
`M5.E7-SUPPLY-PMSKILLS.md` §2.3). Signal has **no analog** — §3.5 of that file states it
outright, and notes that `doc-hygiene.js` is a structural/link check that "never asks whether
code implements what a doc claims." The skill's two teeth: *"Documented-but-unenforced is a
finding on its own"* (`:38`), and *"Undocumented-but-enforced is usually fine, but flag it"*
(`:39`).

Three cataloged Signal findings are exactly that shape, and all three were found by hand in the
last two days of this Epic, by no mechanism:

- **B39** (`confirmed`, **P2**) — the purest instance available. A standing entry
  (`ISSUES-INBOX.md:1407`, ratified BR-6 2026-07-04) instructs `/sig:plan` to walk a trigger
  watchlist at each drain. `grep -ril "watchlist" commands/ tools/` returns nothing —
  re-verified independently for this pass. **The mechanism was specified and never
  implemented**, and sat undetected for 22 days across at least two drains (M5.E6, M5.E7).
  Documented intent, zero implementation.
- **B40** (`confirmed`, P3) — citation integrity. M5.E7's C8 markers in `analysis/` cited
  *"Evidence: `.planning/M5.E7-RESEARCH.md` §0"* while C8 had never been written into that
  section; `BUGS.md:66` (B38) carried the same false citation. This is
  `/security-audit-static`'s stage 5 verbatim: *"re-open every cited location and confirm the
  line number is current and the quoted code is verbatim"* (`security-audit-static.md:55`).
  Note B40's own remedy — *"grep the cited section for the ID before writing any marker that
  cites it"* — **is that rule, re-derived independently on 2026-07-26.**
- **B37** (`confirmed`, P2) — `commands/checkpoint.md:12`, `resume.md` and `discuss.md` instruct
  a dual-write that `references/doc-runtime-model.md:56` ("unit-homed single-home") forbids.
  Documented intent versus implemented instruction. In a prompt-code plugin the command prose
  *is* the implementation, so this is in-shape.

**Strength and honest limits.** pm-skills' prerequisite is that intent be written down first
(`intended-vs-implemented:16`; absent docs make the absence the first finding). Signal satisfies
that prerequisite unusually well — `references/doc-runtime-model.md`, `PROJECT.md`,
`DECISIONS.md`, per-command specs. That is what makes this the best-matched port in the audit.
Against it: the whole `pm-ai-shipping` kit is 548 lines of prompt with **zero enforcement
machinery** (`M5.E7-SUPPLY-PMSKILLS.md` §2.8.1), so a straight port yields a method an agent may
run, not a gate that fires — and B39 sat 22 days precisely because nothing ran. The method's own
provenance is a third repo Signal has not evaluated (Anthropic's Apache-2.0 `security-guidance`,
`security-audit-static.md:15-16`).

**`/derive-tests` — no**, despite the surface appeal. Its falsely-green-map rule guards against
*claiming coverage that does not exist* (`:30`). Signal's false-greens are the different failure
of *tests that exist, are mapped, and pass without discriminating* (B19, B25, B23(a)). Signal's
Nyquist AC→test map already does the mapping half (`M5.E7-SUPPLY-PMSKILLS.md` §3.5, row 3).

**`strategy-red-team` — no**, with a near-miss. Its target is load-bearing plan claims. The
best-fitting Signal case is not a bug: the April disposition *"Port as enforcement module"* for
`<HARD-GATE>` rested on the factually wrong premise that "code literally can't proceed past
them" (`analysis/SIGNAL-INTEGRATION-RUNDOWN.md:174,187`; falsified at
`M5.E7-SUPPLY-SUPERPOWERS.md` §1). That premise held a queue slot for three months
(`M5.E7-RESEARCH.md:307`) but never consumed Epic time, because it was never built.

### 2.3 superpowers — **Yes**, narrowly. Cited: M4.5 exit criterion; M5.E4's ~36 min/task

**`verification-before-completion` — yes.** Its Iron Law is *"NO COMPLETION CLAIMS WITHOUT
FRESH VERIFICATION EVIDENCE"* with a 7-row `| Claim | Requires | Not Sufficient |` table
(`M5.E7-SUPPLY-SUPERPOWERS.md` §5.2). Grep confirms **zero hits** for it anywhere in Signal's
corpus.

The matching failure is the highest-value prior art in this Epic's own research
(`M5.E7-RESEARCH.md:350-355`): M4.5's exit criterion — "≥3 non-Signal users **with feedback

containing tester feedback exists anywhere**. Signal's own quality gate was satisfied by
assertion. The claim is still live today at `CLAUDE.md:32`.

Two things make this a real hit rather than a stretch. First, it is a completion claim accepted
without evidence — the exact target. Second, **Signal re-derived the rule itself**: P2 of this
Epic's requirements (`M5.E7-REQUIREMENTS.md:194-196`) reads *"Every factual claim cites an
artifact path, or is labeled `(recollection — no artifact)`… would have stopped '4 non-Signal
users with feedback merged' from hardening into a satisfied exit criterion."*

**Cross-reference to B39, per the shape:** this failure has two layers. The intake mechanism
(A3, "Tester-friction intake protocol", `archive/BACKLOG-REVIEW-2026-07-04.md:33`) was
identified as the missing piece on 2026-07-04 and never built — that half is B39's shape,
specified-and-unimplemented, and no skill fixes it. `verification-before-completion` addresses
only the second half: accepting the claim anyway.

**`task-brief` + the file-handoff rule — yes, and it is the only "shortened an Epic" claim in
this document with a number behind it.** `M5.E4-RETROSPECTIVE.md:28` measures the cost: *"The
first executor took ~36 min/task (mostly rediscovery + repeated full-suite runs). At that rate
18 tasks ≈ 10 hours; I switched to direct implementation."* Superpowers targets exactly that:
`scripts/task-brief PLAN_FILE N` extracts one task's text so *"Never make a subagent read the
whole plan file"* (`SKILL.md:216`), plus *"Everything you paste into a dispatch prompt… stays
resident in your context… Hand artifacts over as files"* with the measured failure *"a real
session's dispatch hit 42k chars of which 99% was pasted history"* (`:196-198`, `:224-225`).

State the counterfactual precisely: Signal's actual response was to **stop delegating**, so the
claim is "would have made delegation viable at scale," not "would have run faster."

**`writing-skills` / B38 — no valid counterfactual, but worth stating.** B38 (`confirmed`, P2)
records that Signal applies the prohibition/anti-rationalization-table form universally while
the source measures it as counterproductive for *shaping* failures (`writing-skills/SKILL.md:459-474`;
the live Signal instance is `commands/resume.md:189`, verified). It is tempting to score this as
"an April port would have prevented B38." **That claim cannot be established.** The superpowers
verification ran against a depth-1 clone with no history (`M5.E7-SUPPLY-SUPERPOWERS.md`, "Limits
of this verification"), so whether § "Match the Form to the Failure" existed in April is
unverifiable — and a counterfactual against content that may post-date the bug is not a
counterfactual.

The honest and stronger statement: **reading the source produced a confirmed P2 in Signal's
shipped corpus on first contact.** That is evidence about supply value, not about prevention.

**The five-round breaker + ledger — no.** No Signal fix loop has failed to converge. M5.E2 ran 5
RED-first REVIEW batches and ~19 new tests, and its retro records *"not one finding required
re-planning… Volume ≠ re-plan."* Near-miss on the ledger's compaction-survival purpose: M5.E6's
phantom session, an orphaned executor carrying a stale `M5.E3.S1` assignment, latched onto a
leftover task board and picked up Slice 1 — *"a T4 collision was one step away."* Signal was
saved by the stray agent's own discipline plus human intervention, and it does keep per-Epic
`PROGRESS.md`. Recorded as a near-miss.

**`using-git-worktrees` — no.** M5.E5 and M5.E6 both ran sequential dispatch for shared-index
safety and M5.E5's retro names worktree isolation as the alternative. But superpowers itself
runs strictly sequential implementers (*"Never dispatch multiple implementation subagents in
parallel (conflicts)"*, `SKILL.md:230`), and the measured cost was rediscovery, not index
contention. The `task-brief` hit above is the same evidence, better matched.

### 2.4 compound-engineering — **Yes** on technique 5. **No** on cross-model.

#### Cross-model adversarial review versus Signal's false-greens — **no**, structurally

Judged from the primary reading, not inherited. Three facts settle it:

1. **It replaces a lens; it does not add one.** The peer receives *"the **same**
   `references/personas/adversarial-reviewer.md` brief the in-process reviewer uses"*
   (`cross-model-review.md:3`), is adversarial-only (`:5`), and is **mutually exclusive** with
   the in-process reviewer — *"A started peer and the fallback are mutually exclusive"*
   (`persona-catalog.md:38`).
2. **It mechanically buys exactly two things**: a one-notch confidence promotion when two
   independent reviewers agree (`findings-mechanics.py:75-84`, `{50:75, 75:100}`), and
   permission to skip a validator (`finish-review.md:49`). Neither is a detection path.
3. **Signal's diversity is lens-diversity, and it worked on the case in question.** The v0.1.9
   evict.js false-green was caught by a same-model 3-specialist panel (code / security /
   test-integrity), with two independent reviewers reproducing the bypass by PoC
   (`M5.E4-RETROSPECTIVE.md:33`). Cross-model swaps the *model* inside a *single* lens. On this
   case it would have had nothing to add.

The supply record independently notes no measured cross-model-vs-same-model comparison exists —
the repo's one rigorous eval (150 runs, blind judge) states independence is *"Not a variable
here"* (`M5.E7-SUPPLY-COMPOUND-NEW.md` §1.8) — but the verdict above does not depend on that
absence. It rests on the mechanism's shape.

#### Technique 5 of the adversarial persona brief — **yes**. Cited: **B19**

`adversarial-reviewer.md:64-66` — *"**Silent-pass verification-mechanism fidelity.** When the
change *is* a guard that stands in for the real thing… its risk is not blast radius, it is
fidelity: **it can go green while production is red.** Construct the scenario where the guard
passes but the thing it protects fails… A guard that exercises a different context than
production, mocks away the code path that actually breaks, or asserts on a proxy rather than the
real output is the green-while-red failure."* With a depth override that outranks the size
heuristic (`:15`). It is a prompt asset, model-independent, and runs identically on the
in-process reviewer — it is **not** the cross-model feature.

Ranked by fit, strongest first:

- **B19 — the strong hit, and the only one that shipped.** The marker guard released in v0.1.8
  keyed its skip predicate on `ann.legend === null`, but the old curated INDEX format *carries*
  the legend block, so the guard never fired on the real repro (`BUGS.md:80`;
  `M5.E4-RETROSPECTIVE.md:25` — *"The Epic's flagship fix was itself a bug"*). The change under
  review **was** a guard; it went green while the thing it protects — a stranger's hand-curated
  INDEX — stayed red; it "exercises a different context than production." It escaped Signal's
  REVIEW panel and was found only by M5.E4 PLAN research, one release later.
- **B25 — the cleanest shape-match, no shipped harm.** *"`rmw-lock.test.js`'s throw-under-held-lock
  tests pass even for a wrapper that reads OUTSIDE its lock"* (`BUGS.md:52`) — a test harness
  that passes while the thing it protects fails, verbatim. Signal's eventual fix (`8cbb8b7`)
  *is* technique 5 applied: build the twin that must fail. Read-enclosure was correct by
  inspection, so nothing broke — this is a test-strength gap, not a shipped defect.
- **B14 — weaker.** The evict test planted its symlink at the parent, not the leaf. Technique 5
  would have moved detection from REVIEW to EXECUTE; it would not have enabled a catch that
  already happened.
- **B23(a) — also plausibly.** The dangling/rollback tests inject synthetic dangles, so the
  organic path is never exercised — "mocks away the code path that actually breaks." Cataloged
  as a coverage bundle; the literal AC turned out unreachable.

**The findings contract (anchored confidence, quote-the-line gate, `findings-mechanics.py`
deterministic merge) — no.** Real machinery Signal lacks — verified absent by grep — but no
cataloged bug traces to its absence. M5.E6 records the *opposite*: prose synthesis produced
complementary mutation coverage the panel had not planned.

**`ce-compound` learnings corpus — no.** Same reasoning as gstack's loop; see §3.1.

**`ce-retune` — no.** Signal fails all three Phase 0 gates — no run archive, no build selector,
no scripted repeatable task (`M5.E7-SUPPLY-COMPOUND-NEW.md` §2.3). Its A/A noise-floor *finding*
is nonetheless the sharpest input in this audit; it belongs to §3.2, not here.

**`ce-pov`'s `precedent-activity-scout` — near-miss, not a hit.** Its stated value —
*"it stops the caller re-litigating a settled question"* — matches M5.E6's FR7, where a stale
premise was *"masked by an un-ticked `BACKLOG.md` entry."* But Signal's 4-agent PLAN research
caught it, at PLAN, which is the right place.

## 3. The two theses under attack

### 3.1 "Signal should fix its memory/compounding loop before porting anything" (AC7.2)

**Attack: the evidence usually cited for this thesis does not say what it is taken to say.**

The strongest apparent support is the three carry-over chains `M5.E7-REQUIREMENTS.md` AC1.2
names as documented: **B24 → B27 → B28**, **B29 → B34**, **B26 → B30 → B36**. Read as "Signal
keeps re-learning the same lesson," they look decisive. Read with their dates and Epic IDs
attached, they say the opposite:

| Chain | Where each link surfaced |
|---|---|
| B24 → B27 → B28 | B24 fixed **M5.E5.T1**; B27 surfaced **during M5.E5.T1**, building B24's own fixture; B28 confirmed in **M5.E5 REVIEW**. One Epic. |
| B29 → B34 | B29 surfaced M5.E5 REVIEW, fixed **M5.E6 T19** (`78c433e`); B34 found by the **M5.E6 REVIEW security panel**. Same Epic as the fix. |
| B26 → B30 → B36 | B26 fixed M5.E5 (`d62e5f2`); B30 found **dogfooding B26 on M5.E5's own SHIP**; B36 found at **M5.E6's own SHIP**. |

In every case the knowledge was **in-context at the moment of the miss**. Nobody forgot
anything. A cross-session store with confidence decay, latest-winner dedup and a trust gate
contributes nothing to a same-session failure.

The actual gap has a name, and Signal wrote it down: *"**Scope security-class hardenings to the
whole class up front.** B29 hardened `_afterRead`; had 'harden all injectable-fn seams' been the
framing, `renameFn` (B34) would have been in scope, not a REVIEW find"*
(`M5.E6-RETROSPECTIVE.md:32`). That is class-completeness at fix time — a review-scope rule, not
a memory mechanism.

**Second attack: Signal's memory is working where it is consulted.** `BUGS.md` carries 40 dated,
cross-referenced entries from which this pass reconstructed all three chains in a single read.
Its one genuine failure was **grep-blindness** (B13's recurrence) — an encoding bug, now fixed,
not a compounding gap.

**Third: the best-evidenced retrieval failure points the other way.** **B39** is `confirmed`,
P2, and independently re-verified for this pass. But its content is not "Signal has no memory."
It is: *Signal has a memory artifact that instructs a command to read it, and the command was
never taught to.* The store exists; the reader was never built. Porting a second store
(`learnings.jsonl`, `<root>/solutions/`) adds an artifact with the identical structural risk and
does not build the reader. B39's own fix is one drain step in `commands/plan.md` +
`tools/lib/drain.js`.

**Does the thesis survive?** **Only in a much narrower form, and its usual justification is
falsified.** The broad claim is not supported by the record. What survives: *one specific
retrieval mechanism (B39's watchlist walk) is specified-but-unbuilt, and it is cheap.* That is a
Signal bug fix, not a port.

**What would still kill even the narrow form:** if B39's fix turned out to require a store
Signal lacks — it does not; the watchlist is an existing `ISSUES-INBOX.md` entry — or if a
second, independently-evidenced cross-session retrieval failure surfaced. B13's recurrence is
the only candidate found, and §2.1 explains why a learnings digest would not have caught it.

### 3.2 "The sources have method depth; Signal has enforcement machinery, so port methods into Signal's machinery rather than porting whole commands"

**Attack on clause two — Signal's machinery is weakest exactly where a ported method would
plug in.**

Signal's aggregate enforcement is genuinely strong: an exit-2 STATE write-guard, a `PreToolUse`
hook, a roster guard, `doc-hygiene.js`, 1,623 tests. But the machinery closest to *"gate a phase
on a judgment call"* — the shape every ported method needs — is the FR1 retro gate, and it has
the worst reliability record in the repo: **B26** (silently skips on the self-hosted flow),
**B30** (pre-check runs before the SHIP transition), **B36** (`needs-triage`, **P2, open today**
— *"Layer-1 enforcement is structurally inert for a row-maintained project at ship-start"*,
confirmed by dogfooding M5.E6's own SHIP, where a real FULL Epic-close with no retro returned
`{skipped}`). Three residuals across three Epics on the one gate Signal cites as its
`<HARD-GATE>` equivalent (`M5.E7-RESEARCH.md:324`). Add **B39**: an enforcement mechanism
ratified 2026-07-04 and never implemented at all. A method dropped into this layer inherits that
record.

**Attack on clause one — the sources ship machinery, not only method, and it is the machinery
Signal most lacks:**

- compound-engineering's `findings-mechanics.py` (252 lines) enforces the quote-the-line gate,
  the fast-pass cap and the independence requirement **in code**. Grep confirms Signal has no
  equivalent; `commands/review.md:83-107` emits prose.
- gstack's `carve-section-loading.test.ts` drives a **live model** through the `claude -p` SDK to
  assert the agent actually Read a deferred file (`M5.E7-SUPPLY-GSTACK.md` §2.3). **Signal has no
  test anywhere that asserts a prompt instruction was obeyed.** Every Signal gate is either
  deterministic Node code over files or an instruction with no obedience check.
- superpowers' `testing-skills-with-subagents` is a RED/GREEN/VERIFY-GREEN harness for exactly
  that (`M5.E7-SUPPLY-SUPERPOWERS.md` §5.1b) — zero hits in Signal's corpus.

**The sharpest blow, and it is measurement, not opinion.** `ce-retune`'s A/A noise floor: *"12
runs across two identical builds gave workflow adherence 7 of 12 and output tokens from 21,872
to 155,682, **a 7.12x spread on identical code**"* (`M5.E7-SUPPLY-COMPOUND-NEW.md` §2.1). If
run-to-run variance on a byte-identical prompt corpus is that large, then **"port the method
into Signal's machinery" is an unmeasurable intervention for Signal today.** Signal's 1,623
tests exercise `tools/`; they are not behavioral runs of the 21 skills and 26 agent prompts
(same file, §2.3) — and the skill itself names the confusion: *"A green test suite is not done:
it proves nothing broke, not that behavior improved."*

**Does the thesis survive?** **Not intact.** It routes prompt-shaped content into file-shaped
enforcement, with no way to tell whether the routing worked. That is the same substitution that
produced B38 — Signal adopted a *wording form* as a universal convention on no measurement at
all.

**What survives, and it is a real half:** for candidates that are genuinely deterministic and
file-shaped, the move is exactly right and Signal's machinery is the best in the landscape for
it. pm-skills' `intended-vs-implemented` bound to a doc-hygiene-style check, and gstack's
`maxSkeletonBytes` / union-vs-skeleton size assertion, are both in that class.

**What would kill even the surviving half — and there is already one recorded instance.** B40
warns explicitly against "fixing" citation integrity by converting references to markdown links:
*"the guard could not have caught it either way: `checkInternalLinks` tests **file existence**,
and this failure was *file exists, cited section does not contain the claim* — a **claim-level**
integrity problem, not a link-level one."* That is the method-into-machinery move failing in
precisely the predicted way, documented in Signal's own ledger before this pass was written.

## 4. The ideation-silence caveat (AC7.3)

**Signal's retro corpus is silent about ideation, and that silence is not evidence of no
demand.**

Across 18 retrospectives, 40 catalogued bugs and a 1,507-line inbox, nothing surfaced as *"I
couldn't figure out what to build"* (`M5.E7-RESEARCH.md:331-336`). Every displacement in the
0-for-6 chain was downstream pain — doc bloat, state corruption, resume drift, lost updates.

But Signal is built by someone who already knows what to build, from a spec written up front.
That is close to a worst case for detecting demand for an upstream ideation layer. **Absence of
signal here is weak evidence about the gap for other users.** It is the only evidence available,
and it points one way — but a reader should discount it accordingly, and should not treat the
"no" verdicts on `/office-hours`, `/discover`, `/strategy`, the OST, assumption mapping and the
GTM cluster as findings against those capabilities. They are findings about what this question
can see. See §5, blind spot 2.

## 5. What this pass cannot see

1. **Only the written record.** A failure that produced no artifact is invisible here. Signal's
   "document in the moment" norm makes the corpus unusually complete, but nobody logs the bug
   they did not write down.
2. **The question is structurally biased toward downstream ports.** Bugs and Epic costs are
   downstream artifacts. Any upstream capability is guaranteed a "no" by the question's *shape*,
   not by its merit. Every upstream candidate in §2 fails for this reason, and those failures
   carry near-zero information. This is AC7.3 generalized beyond ideation.
3. **The demand register was not read** before §§1–5 were written, by design. §6 records what the
   cross-check changed.
4. **Supply is entirely second-hand.** No source repo was cloned or read for this pass; every
   supply claim comes from the five S2 files, each of which declares its own unread surface —
   49 of 54 gstack skills unopened, pm-skills' 8-of-9 plugins' non-target skills, superpowers'
   depth-1 clone, and "nothing was executed" in all of them.
5. **Dating asymmetry.** Supply was verified 2026-07-25 against current HEADs; the counterfactual
   asks about ports available months earlier. superpowers' breaker is 2 days old upstream and
   § "Match the Form to the Failure" is undatable from a depth-1 clone. Where this bites, §2 says
   so and downgrades the claim (B38).
6. **Shape-match is not firing.** This pass can say a mechanism matches a failure's shape; it
   cannot say the mechanism would have fired. Technique 5 is three lines in a persona brief with
   no enforcement. Whether an agent reading it would have caught B19's `ann.legend === null`
   predicate is unknowable from either repo.
7. **"Shortened an Epic" is mostly unanswerable.** Signal records Epic *content* well and Epic
   *duration* poorly; M5.E4's ~36 min/task is the only number in the corpus. Every "no" on that
   half should be read as **not measurable**, not as measured-and-refuted.
8. **Survivorship in the bug ledger.** `BUGS.md` records defects Signal's existing REVIEW panel
   and dogfooding were good enough to find. A class of defect that Signal's process cannot see at
   all would be absent from the very corpus used to judge whether a port was needed — and that is
   exactly the class a new lens would address.

## 6. Register cross-check (read after §§1–5 were written)

`M5.E7-DEMAND-REGISTER.md` was read only at this point. **It changed no verdict in §2 and no
conclusion in §3.** What it adds:

**Independent convergence, worth more than agreement.** The register's rank-2 cluster — **B,
"Test-strength and the false-green class," its largest** — is the same target this pass reached
from the supply side via technique 5. Two passes with different inputs and a deliberate
information barrier landed on the same place. That is the strongest single result of the
cross-check.

**One factual disagreement, recorded not reconciled.** The register's cluster B states its
hardest evidence as *"two guards **shipped as false-greens** — `B14`… `B19`."* **This pass finds
only one shipped.** B19's guard was released in v0.1.8 and found holed a release later
(`M5.E4-RETROSPECTIVE.md:18`, *"shipped-but-holed"*); B14's false-green test was authored during
M5.E4 and caught by that same Epic's REVIEW panel before v0.1.9 tagged (`BUGS.md:75`,
`M5.E4-RETROSPECTIVE.md:32`). The pre-existing `evict.js` confinement *gap* did ship — the
false-green *guard* did not. This is load-bearing, not pedantic: at two-of-two the existing panel
has a 50% miss rate on this class and a new lens is worth a lot; at one-of-two the arithmetic
changes and technique 5's value is narrower. §2.4 ranks the citations on that basis.

State the panel's record in its strongest honest form, because the two cases are not
symmetrical. What the panel caught in B14 was **an incomplete fix authored inside the Epic it was
reviewing** — a real catch, but of in-flight work, not of something users had. What it **missed**
was B19: a guard released to users in v0.1.8, green and inert for a full release, found by M5.E4
PLAN research rather than by any REVIEW. **The panel is good at catching its own Epic's work and
demonstrably missed the one guard that reached users.** That asymmetry — not a miss rate — is the
argument for adding a lens whose stated target is "it can go green while production is red."

**A cluster the register does not have.** B37, B39 and B40 — the `intended-vs-implemented`
class in §2.2 — are not a register cluster. B39 appears only as a blocker on the register's own
trigger mechanism (§0, §1); **B37 and B40 do not appear at all.** This is the barrier working as
designed: all three were cataloged 2026-07-25/26, during this Epic, alongside or after the
register's harvest of retros and ledgers. The pm-skills hit is net-new against the register.

**Where the register strengthens a verdict this pass under-credited.** Its rank-1 cluster,
**F — EXECUTE dispatch guidance** (*"0-hit, all 4 ledgers"*, with a live incident this Epic:
commits amended into siblings, `git reset` recovery), is dispatch *safety*; §2.3's `task-brief`
hit is dispatch *cost*. Superpowers ships both halves — `scripts/sdd-workspace`, the strictly
sequential rule, and the compaction-surviving ledger. This pass recorded the ledger half as a
near-miss on the strength of M5.E6's phantom session; F says the demand side is stronger than
that. The superpowers verdict stays **yes**; its basis is broader than §2.3 credits.

**Where the register and this pass ask different questions and both answers stand.** Cluster H
ranks B38 fourth on demand. §2.3 declines B38 as a *counterfactual* on dating grounds. Compatible:
"does Signal want this" and "would an April port have prevented it" are different questions, and
only the second is defeated by an undatable source.

**One place this pass supplies evidence the register asked for.** Cluster A carries an explicit
note to this task: *"this cluster flatters Signal's existing practice… exactly the profile the
counterfactual is required to attack rather than confirm."* Attacked: the panel's record is
genuinely mixed, not uniform. It caught M5.E2's rollback Critical, M5.E3's B19-parity defect and
M5.E4's B14 bypass — and it **missed** B19's own false-green predicate, which reached users and
was found by M5.E4 PLAN research one release later, and missed B34 until the following Epic. A
default-on panel is well-supported; a panel presented as sufficient is not.
