## Purpose

Signal can check whether a document has the **right words in it**. It cannot check whether the
document is **telling the truth**. This Epic builds the first slice of the second thing, under one
governing constraint: it may only stop you when it can show you why.

**Founding evidence, produced rather than argued:** on 2026-08-19 this repository's own `STATE.md`
narrative was wrong in three places for days, while `narrative-phase-contradicts-frontmatter` and
`body-omits-current-epic` both returned **clean** on it. Found by a person reading. That is
`AC0.1` / `D-M5E10-1`'s deliberately unbuilt half, on the state file of the project that named the
class.

## Scope

**In:** the false **"still open"** — a record claiming open/owed when the work is done — across
**two** record types (`BUGS.md` rows, `OPEN-QUESTIONS.md` entries), surfaced in `/sig:sweep` and
enforced at the SHIP gate.

**Out, and named so nothing reads as covered:** the false **"done"** (`D-M6E3-3` inverts the build
order; that is a later slice); `BACKLOG.md` rows, obligations / `dischargeObligation`, and
`ISSUES-INBOX` captures (`D-M6E3-4` — three record types deliberately deferred); the REVIEW phase
gate (`D-M6E3-5`); and any unbounded *"is this behaviour implemented anywhere"* question, which has
no honest receipt and is out of scope permanently, not just for this slice (`D-M6E3-2`).

## Functional requirements

### FR1 — The receipt contract

A finding either carries a receipt or it cannot block. This is the shared spine; FR2–FR5 are its
applications.

- **AC1.1** — A finding record carries a typed `receipt` field. A finding with `receipt: null` is
  **report-only** and no code path may use it to refuse anything.
- **AC1.2** — A receipt names its two sides: the claim (file, line, verbatim excerpt) and the
  contradicting evidence (file, line or commit sha, verbatim excerpt).
- **AC1.3** — A receipt renders in under 15 lines, both excerpts elided to one line each. A reader
  adjudicates without opening either file.
- **AC1.4** — A test asserts that a finding constructed without a receipt **cannot** reach any
  refusal path, by construction rather than by convention.
- **AC1.5** — The bare-verdict shape (a conclusion with no excerpt pair) is rejected at construction
  time, not filtered downstream.

### FR2 — Case (a) for `BUGS.md`: a row reads open, the work shipped

- **AC2.1** — For every row whose status is `confirmed`, the check looks for evidence of closure in
  the CHANGELOG and in commit history.
- **AC2.2** — A flag is raised **only** with a receipt naming the specific entry or commit that
  closed it. No receipt, no flag — not a lower-confidence flag.
- **AC2.3** — `B75` produces **no** flag under the new rule, and the reason is recorded: `v0.1.24`
  cites it as prior evidence and it is genuinely open. The current check flags it and always will.
- **AC2.4** — `B102`'s historical shape (subject of a release entry's lead line) still produces a
  flag when replayed against the `v0.1.29` tree. The check does not lose its only true positive.
- **AC2.5** — Precision is re-measured over the same 28-row corpus and **published in the check's own
  `describe` string**, whatever the number is.

### FR3 — Case (a) for `OPEN-QUESTIONS.md`: a question outlived its answer

- **AC3.1** — For every unresolved question heading, the check looks for an answer in `DECISIONS.md`
  and in the file's own resolved-marker convention.
- **AC3.2** — A flag is raised only with a receipt naming the decision that answered it.
- **AC3.3** — The `B46` case is used as the fixture: a question that stood three days after its
  answer landed.
- **AC3.4** — The check declares its reach across the corpus and renders that reach beside its clean
  count, per `M6.E2`'s precedent.
- **AC3.5** — A question with no answer anywhere produces **no** finding and **no** silence: the
  count of questions checked is reported, so "checked and clean" is distinguishable from "did not
  look" (`B39`).

### FR4 — `/sig:sweep` surface

- **AC4.1** — Both checks run from `/sig:sweep` in any project, with no `.planning/` phase required.
- **AC4.2** — Findings render with their receipts inline.
- **AC4.3** — Checks that could not evaluate report that they could not, separately from the clean
  count. Silence about blindness is the defect this class exists to catch.
- **AC4.4** — The sweep is read-only and writes nothing, unchanged from today.

### FR5 — SHIP gate refusal

- **AC5.1** — At an Epic-close SHIP, a receipt-backed stale record **refuses** the close.
- **AC5.2** — The refusal prints the receipt and the exact edit that would clear it.
- **AC5.3** — A finding **without** a receipt never refuses; it appears in the SHIP report as advice.
- **AC5.4** — The refusal is overridable by an explicit named flag, and the override is recorded in
  the SHIP artifact — never a silent bypass.
- **AC5.5** — A test asserts the gate fires in the fix lane as well as the Epic lane, since the fix
  lane is where these rows are produced.

### FR6 — The fourth matching rule, measured before adoption

- **AC6.1** — The subject-position rule is measured over the same 28-row corpus that produced the
  three published rules (13 flags/1 real, 3/1, 2/1).
- **AC6.2** — The measurement is written down before the rule is adopted, and the rule ships with its
  number, including if the number is bad.
- **AC6.3** — If it does not beat the shipped rule, the shipped rule stays and the negative result is
  published rather than discarded.

### FR7 — Disclosure of what stays open

- **AC7.1** — The shipped docs state in plain words that an unbounded *"we said we handled it and I
  cannot find where"* has **no honest receipt** and stays advisory permanently.
- **AC7.2** — The three deferred record types are named in the shipped docs, not only in `.planning/`.
- **AC7.3** — A live `BACKLOG.md` row and a test keep the false-**done** half visible, mirroring how
  `AC0.1` was kept visible after `M5.E10`.

## Non-functional requirements

- **NFR1** — Deterministic parts stay deterministic and offline. Any model-judged step is separable
  and independently testable.
- **NFR2** — Every check is fail-open: a failure renders `[UNVERIFIED]`, never a clean-looking pass
  (`B39`).
- **NFR3** — Sweep-path cost stays within its current budget; the expensive path runs at SHIP.
- **NFR4** — No check may depend on Signal's own `.planning/` shape. Signal's shape is the minority
  shape (`M5.E16`: 4 of 12 Epic-mode), and assuming it produced `B82`.

### FULL-tier NFR prompt — answered, not skipped

| Item | Disposition |
|---|---|
| Health / liveness probe | **N/A** — a CLI plugin, no long-running service. |
| Graceful shutdown signal handling | **N/A** — same. |

| Security headers (CSP/HSTS/X-Content-Type-Options) | **N/A** — no HTTP surface. |
| Rate limiting | **N/A** — not publicly exposed. |
| Input handling (the real one) | **In scope** — `BUGS.md`, `OPEN-QUESTIONS.md` and `CHANGELOG.md` are read as **data, never as instructions** (`B104`). A record whose text contains a directive is content, not a command. |

*The five standard items are genuinely N/A here and are recorded rather than skipped, so a later
reader can tell "considered and not applicable" from "never asked."*

### Blast radius — what this touches that it does not change

- **`bug-status-vs-changelog`, already shipped and user-visible.** Changing its rule changes output
  users have seen since `v0.1.29`. Its published precision figure moves with it.
- **`/sig:sweep` output**, consumed by four non-Signal users.
- **The SHIP gate** — a new way for a release to be refused. `AC5.4`'s named override is the
  release valve.
- **`BUGS.md` and `OPEN-QUESTIONS.md` are read, never written**, in this slice.
- **Not touched:** `/sig:add`'s capture path, the phase commands' `.planning/` reads,
  `dischargeObligation` (still called by nothing — this Epic does not change that and does not claim
  to).
