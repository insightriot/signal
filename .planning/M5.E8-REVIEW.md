## The review's organizing question

VERIFY ended by asking *what else wears the costume of a legitimate finding?* Two verdicts had known
impostors and got guards (`absent` ← unreachable fixture; `inert` ← incomplete deletion). The other
two had never been examined that way. **A false `obeyed` is the dangerous one — it makes Signal
over-trust its own instructions, and it is the verdict this Epic just published.**

### Impostor analysis — all four verdicts

| Verdict | Instrument failure that produces it | Distinguishable? |
|---|---|---|
| `absent` | The fixture never reaches the instruction. | **Now yes** — fixture ships PLAN + VALIDATION + git; transcripts always retained. *(Happened. `B48` came out of it.)* |
| `inert` | The mutation does not remove the instruction (line-level deletion leaving the rationale), or never reaches the agent (broken seam). | **Now yes** — section deletion + residue assertion + seam precondition. *(Happened. Near-miss.)* |
| **`obeyed`** | **The control removed MORE than the instruction**, so the arms differ for an unrelated reason. Section-level deletion is the direct cause: fixing "too little" traded toward "possibly too much." | **Partially — C1 below.** Now disclosed in every record; not mechanically bounded. |
| `indeterminate` | A split caused by instrument flakiness (timeout, transient error) rather than genuine agent nondeterminism. | **Partially** — failed runs force `indeterminate`, and a `SPLIT` is flagged; but a run that exits 0 having done something odd counts as real data. Transcripts are the only recourse. **Accepted limit, recorded.** |

**The honest summary:** the two verdicts that fire on *difference* (`obeyed`) and on *no clean
answer* (`indeterminate`) cannot be fully mechanically defended. They are now **disclosed** rather
than silently trusted, which is the achievable standard.

## C1 — CRITICAL · the source state was captured after the run, not before

**`tools/adherence-run.js`** called `currentCommit()` when writing results — 20+ minutes after the
arm started.

**Why Critical.** It defeats `--combine`'s own guard. That guard refuses to pair arms from different
commits, and it is the entire reason splitting the arms is safe rather than merely convenient. But
if a commit lands mid-run, **two arms measured against different code can record the same sha and be
accepted as a valid pair** — the failure the guard exists to prevent, inverted. It also breaks AC4.3
quietly: the record names a commit that is not the code that ran.

**Not hypothetical.** I nearly triggered it during this Epic — I held back a commit mid-run
specifically because I noticed the arms would disagree.

**Fixed.** `captureSourceState()` runs before the probe and before any run. It also records whether
the **working tree was dirty**, because a run against uncommitted changes records a sha that cannot
reproduce it — a larger version of the same lie, previously invisible.

## I1 — IMPORTANT · a verdict shipped without its scope, and scope was remembered rather than generated

The published `OBEYED` record carried no caveats. It needed an appended correction naming `B48`, the
N=3 weakness, tool-access conditionality, and the 77.6% unmeasured remainder.

**The deeper defect is that those caveats were *authored by hand*.** The next verdict would have
depended on someone remembering again.

**Fixed.** `buildCaveats()` generates them from the run's own parameters, and `renderRunRecord`
prints them inline under **"Scope of this verdict."** The N-weakness caveat fires automatically at
`runsPerArm <= 3`; the dirty-tree caveat fires from C1's new flag; the section-deletion caveat fires
whenever a canary deletes a section — which is the disclosure half of the `obeyed` impostor above.

## I2 — IMPORTANT · the test guarding the published number could not detect staleness

`expect(content).toContain('91')` passes on any occurrence of those digits anywhere in the file.
Meanwhile `tools/adherence-ceiling.js --check` did the correct structural comparison and **nothing
ever called it** — a guard written, shipped, and never wired up. *Same shape as `B39`
(a watchlist never walked) and `B46` (dispositions nothing reads back).*

**Fixed** in VERIFY: the test now spawns `--check` and asserts exit 0, plus asserts the structural
table rows. **Proof-of-fail:** corrupting one row fails both assertions; restoring passes.

## I3 — IMPORTANT · a second writer to the append-only log inherited none of its guarantee

`appendNotice` was added to `ADHERENCE-LOG.md` with no test. AC4.2's argument is structural — *"no
code path reads an existing record"* — and that argument covers writers, not files. **Fixed:** the
append-only property is now pinned for `appendNotice` too, plus an unknown-kind rejection.

## S1 — SUGGESTION · hand-maintained dependency list

`PLUGIN_RUNTIME_DEPS = ['yaml']` mirrored `package.json` by hand; drift means the plugin copy cannot
execute the library call a canary measures, scoring as *"not obeyed"* for a missing-package reason.
**Fixed:** asserted equal to `package.json` `dependencies`.

## What was NOT changed, and why

  `references/adherence-canaries.json` has never moved.
- **The `OBEYED` verdict itself.** Nothing found here weakens it. C1 is a reproducibility and
  pairing defect, not a measurement error: both arms provably ran at `f3ca9b2` on one surface.
- **`B48`.** A defect in M5.E9's shipped instruction, not in this Epic's code. Fixing it here would
  be scope creep; it is cataloged, and it is **live in v0.1.12**.
- **`indeterminate`'s residual impostor.** Genuinely not separable from instrument flakiness without
  re-running, which costs money. Recorded as an accepted limit rather than papered over.

## Security

Local CLI harness, no listener, no network beyond the agent call. Two real surfaces, both bounded:

1. **The harness runs an agent with `Bash` in a temp directory.** Bounded by
   `assertIsolatedFixture` (four refusal cases: is / inside / contains the invoking project, and
   outside the OS temp dir). Tool access is granted **narrowly and explicitly** — the probe gets
   `Write` only. **Verified against the tree:** `git status commands/` is clean after 20+ mutated
   runs.
2. **No credentials are handled.** The harness shells out to the CLI the user already authenticated
   — no API key in the repo, no CI secret. This is also what keeps D-M5E8-1's not-in-CI boundary
   honest: there is nothing for CI to be given.

## Performance

Not a hot path. One deliberate choice: the plugin copy takes production deps only (`yaml`, 1.2 MB)
rather than the full 47 MB `node_modules`, since it is rebuilt for **every run**.
