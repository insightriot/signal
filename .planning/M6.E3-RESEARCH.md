# M6.E3 — Research

**Epic:** `M6.E3` — the claims-audit backstop. **Written:** 2026-08-19.

## ⚠ Declared deviation: research fan-out trimmed below `research_parallelism: 4`

`PROFILE.md` sets `research_parallelism: 4`, and this Epic ran **one** researcher — the session
itself, reading the modules directly.

**Why, and why it is not a shortcut.** The domain is Signal's own internals: `state-drift.js`,
`published-facts.js`, `bugs-tally.js`, `drain.js`, `add.js`, `retrospective.js`, `ship.md`,
`sweep.md`. This session read each of them **directly and for a reason other than this Epic** — the
`CONTEXT.md`/`STATE.md` refresh, the `B75` precision investigation, the `bugs-tally` argument bug, the
orphaned-archive find. A four-agent fan-out would re-derive findings already in hand and evidenced by
file and line.

**`PROFILE.md` anticipated this exact revisit.** Its own note: *"`research_parallelism: 4` retained
… Revisit if the first FULL-tier `/sig:plan` run produces redundant research."* This is that revisit,
and it is recorded rather than taken silently.

**What the trim costs, stated:** no independent adversarial reading of the design. `D-M6E3-1`'s
receipt rule was pressure-tested in conversation, not by a second agent. If REVIEW finds the rule
underspecified, this trim is the first place to look.

## Finding 1 — the SHIP gate has never refused a close on document CONTENT

**Verified 2026-08-19, by grep, not by memory.**

- `runDriftChecks` appears in `plugin/commands/sweep.md` and `plugin/commands/resume.md`. It appears
  **zero times** in `plugin/commands/ship.md`.
- Every halt `ship.md` can currently produce is a **precondition** failure: no `PROFILE.md`; a
  `current_epic` whose milestone file is absent; a missing or invalid retrospective (`shipFR1Check`
  → `{halt: true}`); `on-default` branch.
- **Not one of them is a finding about what a document says.**

`D-M6E3-5` introduces exactly that new class of refusal. **This is the Epic's "first time" item**
(see PLAN § *What this Epic does for the first time*), and the precedent is not reassuring: `B36`
records this same gate shipping **three consecutive Epics** (`M5.E6`, `M5.E9`, `M5.E8`) *silently
inert*, and at `M5.E8`'s own ship the retrospective existed only because someone wrote it before the
gate ran.

## Finding 3 — `bug-status-vs-changelog`'s published precision is correct at 2 flags / 1 real

Re-verified this session by replaying the check against the tree at the `v0.1.29` ship commit
(`5c7c354`): it returned **`B75` alone**. At that commit `B102` already read `fixed`, confirming the
original pair was `B102` (true) + `B75` (false).

A same-session claim that the figure had moved to `3 / 1` was **wrong and was withdrawn before it
reached any file** (`D-M6E3-6`). The published figure stands.

**`B75` will flag forever under the shipped rule:** `v0.1.24`'s lead paragraph cites it as prior
evidence and `B75` is genuinely open. The obvious narrowing — match the heading line only — was
tested and **rejected**: `B102` also matched in the body, so that narrowing loses the only true
positive. `FR6` measures the surviving candidate (subject-position) rather than adopting it.

## Finding 4 — `INDEX.md`'s own link list is a closed set

Filed this session as a captured-untriaged bug: two `.planning/archive/M6/**` phase logs were
written and never staged, while tracked `INDEX.md` linked to both.

**Why it is research and not just a bug:** *"every path `INDEX.md` links to is tracked"* is an
**absence check against a closed, enumerable list** — the precise shape `D-M6E3-2` says absence is
provable against. It is the cleanest available demonstration that the closed-list rule generalises
beyond requirement IDs.

**Scope call: NOT in this Epic** (see PLAN § *Scope discipline*). Slice 1 is `BUGS.md` +
`OPEN-QUESTIONS.md` per `D-M6E3-4`, decided the same morning; adding a third record type would
overturn a same-day decision. Recorded here so the connection is not lost.
