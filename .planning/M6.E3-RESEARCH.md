## Finding 1 — Jev's API (domain; read 2026-09-26 from docs.typesafe.ai/api.md)

- `POST https://api.typesafe.ai/v1/systemone`, `Authorization: Bearer <key>`, JSON.
- Body: `{ state, model, questions: { <id>: { type: "choice", instructions, criteria: { <option>: <description> } } } }`.
- **`state` is shared by every question in one request.** Every question is judged against the same state.
- Response: `{ model, answers: { <id>: { type: "choice", choice, probabilities, confidence } }, usage }`.
- Errors: `401` bad key, `422` malformed request, `429` rate limit, `529` overloaded. No timeout, size or
  rate-limit headers documented. Node 22's global `fetch` is enough — no SDK, no dependency.

**Consequence for the design.** The spike (assessment §6, set 3) asked one question per paragraph with the
paragraph and the facts as that request's state — ~94k input tokens over 94 cases, ~1k per case, which is
consistent with one request per case. Putting all paragraphs into one shared state would change the shape
that was measured, and Jev's weakness #5 (*accuracy drops with irrelevant state*) says that change is
exactly the one likely to hurt. **So: one request per paragraph, state = { paragraph, facts }, run with
bounded concurrency** — which revises `NFR6`'s "one request per run" (a PLAN-time correction, recorded in
the plan).

## Finding 4 — size of real inputs

`STATE.md` body paragraphs (split on blank lines) across local Signal projects (counts only, no names):
0, 0, 0, 2, 4, 16, **20 (this repo)**, 23, 42, 63, **527**. One project's `STATE.md` is 490 KB.

**Consequence.** An uncapped per-paragraph design sends 527 requests from `/sig:resume` on that project.
Needed: a paragraph cap, a per-request timeout, and a total time budget, with the output stating how many
paragraphs were checked of how many (`B39`: "checked and clean" must differ from "did not look"). A
single paragraph larger than the 32k-token state limit is skipped and counted, not truncated silently.

## Finding 5 — risks

1. **Latency at `/sig:resume`.** Resume is run constantly; a slow model call there is felt every time.
   Mitigation: total budget (PLAN default 8 s) + concurrency cap; unanswered paragraphs reported as
   unchecked; the briefing never waits past the budget (`AC10.4`).
2. **Nondeterminism.** No seed; 2 of 94 decisions flipped between runs, all within 0.1 of the line.
   Mitigation: report-only (`D-M6E3-8`); show confidence; never pin a Jev result to a commit (`AC9.7`).
3. **Model drift.** `jev-latest` may change under us. Mitigation: request the measured model
   (`jev-1.13.0`) by default and print the `model` the response returns; a retired model becomes a
   "did not run: <reason>" line, not a failure.
4. **Fixture honesty.** Tests use recorded responses; a recorded response can drift from the live API
   shape. Mitigation: one parser, tested against both the documented shape and the spike's stored answers.
5. **Low-confidence noise.** Spike errors all sat at confidence ≤ 0.37 (para 15 at 0.23, para 39 at
   0.11). Mitigation: show every `contradicts` with its confidence, sorted, and state that low-confidence
   ones are for a person to judge — no hidden threshold (a threshold is what `D-M6E3-8` defers).

## Finding 6 — prior art

- TypeSafe's own *citation check* cookbook uses the same shape: code pairs a claim with its source, the
  model sorts, confidence routes to a person. Eight hand-made cases — a demonstration, not a measurement.
- Inside Signal: `/sig:advise`'s stale-read guard and `M5.E10`'s coverage check are the precedent for
  "code assembles the receipt; the judgment only sorts" (`D-M6E3-1`).

## Finding 7 — the codebase seams (file:line under `plugin/tools/lib/`)

- **Everything that ships is under `plugin/`.** Root `tools/` is maintainer scripts; there is no root
  `commands/`, `skills/` or `agents/`.
- **Drift findings** are `{check, healCategory, healMechanism, file, message}` (`state-drift.js:306-314`).
  A check is `defineCheck({id, healCategory, applicability, run, healMechanism?, describe?})`
  (`110-152`); "could not evaluate" is `applicability → BLIND` with a reason (`268-277`) or a throw.
  **`runDriftChecks(baseDir, checks)` is async** (`227`), so an async model-judged check fits the
  existing runner with no change to it.
- **Registries:** `STATE_DRIFT_CHECKS` (`state-drift.js:989`), `PUBLISHED_FACT_CHECKS` and
  `ALL_DRIFT_CHECKS` (`published-facts.js:418-435`). `/sig:docs-sweep` runs `ALL_DRIFT_CHECKS` via
  `sweep.js:553`. **Consequence:** the Jev check must NOT be added to `ALL_DRIFT_CHECKS`, or
  docs-sweep would make a network call (`AC10.3`). It gets its own registry, passed only by
  `/sig:resume` and SHIP.
- **No receipt concept exists anywhere in `lib/`** — `FR1` is authored from scratch, additively (an
  optional field on the finding; existing checks are untouched).
- **No paragraph splitter with line numbers exists.** `checkNarrativePhaseContradiction` splits by
  line (`state-drift.js:966`) and reports no line number. The closest pattern is `bugs-tally.js`
  `walkBugEntries` (`130-154`). `parseFrontmatter` (`state.js:64`) returns `{data, body}` but not the
  body's starting line. A small helper is needed; it must return 1-based file line numbers so a
  receipt can cite `STATE.md:<line>`.
- **`/sig:resume`'s drift line** is rendered at `resume.js:344-375`, only when
  `summary.needsAPerson > 0`. **The 50-line cap is documented, not enforced in code** (`resume.md:82`,
  `:274`) — the new line has to be counted by hand in the test that pins its shape.
- **The bounded, fail-open network pattern already exists twice:** `isStaleVsOrigin`
  (`state.js:1251-1337`, 2 s timeout, SIGKILL, any throw → not-stale) and `fetchLatestTag`
  (`doctor.js:869`, `{ fetchFn = fetch }`, `AbortSignal.timeout(5000)`, null on failure). Tests stub
  it with `vi.fn().mockResolvedValue({ok, json})` (`tests/status-version-check.test.js:27-64`). **The
  Jev client copies `fetchLatestTag`'s shape.**
- **No code reads an API key from `process.env` today** (`state.js:1333` and `branch-guard.js:318`
  only spread it). The Jev client is the first.
- **`ship.md` never calls `runDriftChecks`** (headings `ship.md:74-235`; Epic-close-only steps are
  §5.5, §6.5, §6.6 and key on `shipFR1Check`'s `isEpicClose`). The SHIP refusal and the Jev advice
  list are new steps in that Epic-close group.

## Finding 8 — the network audit has never scanned shipped code (`B125`, filed this PLAN)

`tools/audit-network-calls.js:38-41` scans `['tools','skills','agents','commands']` under the repo
root. The shipped code is under `plugin/`, so the audit never reads it. **Reproduced by hand:** a raw
`fetch("x")` placed in `plugin/tools/lib/` → exit 0. The existing injected-fetch call passes only
because `fetchFn(` does not match `\bfetch\s*\(`; there is no list of known calls. `AC8.5` says the
audit lists the Jev call, which is impossible until the audit looks at `plugin/` — so the fix is in
S1, ahead of the client. `tests/sweep.test.js:409-421`'s comment claims the audit covers `sweep.js`;
it does not, and that test's reasoning is corrected with it.

## Finding 9 — the fact list vs. "nothing numeric" tension (flagged at DISCUSS), resolved

Jev's weaknesses #2–#3 are **counting and ordering** (arithmetic, dates as quantities). The spike's
strongest catch was *"`plugin.json` reads `0.1.30`"* against `0.1.40` at confidence 1.00 — an
**equality** judgment on an identifier, which it did well. So the rule `AC9.5` needs is narrower
than "no digits":

- **Passed as text facts, for sameness only:** `phase`, `current_epic`, `current_tasks[].id`,
  `completed_phases` **names without their dates**, the manifest version string, and a derived
  sentence *"in flight: `<epic>` at `<phase>`"*.
- **Never passed:** dates, counts (how many phases, tasks, tests), `last_updated*`, blockers' ages.
  A paragraph whose only claim is a count gets no finding from Jev — by design, and documented
  (`AC7.4`).
