### Verdict: the geometry holds

Both module-path expressions resolve to the **plugin root** at the post-move depth, and both are
proven **depth-sensitive** — a wrong-depth fixture yields a different answer, so the assertions
cannot pass for a function that ignores depth. `roster.js` reads `commands/`, `agents/` and `skills/`
from the root it derived, pinned with a **decoy** at the old location so a regression to the repo root
cannot pass silently.

**S2 is therefore unblocked on its stated gate.**

### The finding: the detector shipped as a false green, and only mutation-testing found it

`AC1.2a` asked for the detector's population and blind spots to be published. Writing that section is
what prompted actually testing the detector, and the detector was **broken in the exact way the AC
exists to catch**.

The first `escapes()` was the obvious one — `relative(PAYLOAD_ROOT, abs).startsWith('..')`. It reads
correctly. It is **structurally incapable of firing before S2**: today the payload root *is* the
repository root, so `../../tests/fixtures/nope.js` resolves to a path *inside* it. A deliberately
escaping import planted in `tools/lib/` **passed clean**.

**It would have reported "no escapes" for the whole pre-move period and then been trusted after the
move** — a check whose green means *could not look*, guarding this Epic's central invariant. `B39`'s
class, inside the check written to enforce the boundary.

**The fix is a different rule, not a wider one:** the payload boundary is the **set of payload
directories**, not the root that happens to contain them. Post-move the two coincide; pre-move they
do not, and pre-move is the case that has to work for the check to have value before S2 lands.

**Verified three ways** rather than declared: clean tree passes → escaping probe fails with the file
and specifier named → probe removed, green returns.

### Two smaller things the slice turned up

1. **My own path arithmetic was wrong first.** The hooks-geometry test asserted `dirname` twice where
   the payload root is three up; it failed on first run and caught its author. Kept as a comment
   rather than silently corrected.
2. **The citation population is 31, not the 12 I measured at PLAN.** The PLAN-time grep covered
   `commands/` and `agents/` only; the detector walks all six payload directories, and `skills/` and
   `references/` cite more. **Roughly nine of the 31 are false positives by design** — a skill telling
   a *user* to keep ADRs in `docs/decisions/`, an example naming `tests/path/to/test.ts`. Rule 3
   matches text shaped like a path and cannot tell Signal's repo from the user's repo from an
   example, which is why it is a **ratchet over a recorded set** ("nothing new appeared" — sound under
   a false-positive rate) rather than a prohibition ("every match is a defect" — not sound).

### What the move cost, against what the plan predicted

The plan said *"repoint the 136 test imports"*. That was the smallest part. The failure count went
**137 → 0** across roughly a dozen passes, and the work split into five kinds the plan did not name:

1. **The nine maintainer scripts broke.** They stayed at `tools/` and import `./lib/` — which moved
   out from under them. 27 imports across 8 scripts.
2. **Two shipped libraries hardcoded moved paths.** `doc-hygiene`'s `readPluginVersion` and
   `VERSION_SOURCES`, and `checkRosterCounts`, which counted the roster from the same `baseDir` it
   read the count *sites* from — one directory before, two now.
3. **`README.md` carried two dead links** into `references/`. Real user-visible breakage on GitHub,
   not a test artifact.
4. **Test path-construction had six distinct forms**, not one: quoted specifiers, `join(ROOT, 'x')`,
   `join(ROOT, 'x/y.md')`, `join(__dirname, '..', 'x')`, `join(import.meta.dirname, ...)`, and
   `new URL('../../' + rel)`. Each needed its own pass, and each pass revealed the next.
5. **`state/` was missing from the payload list entirely** — see S2.t1.

### The distinction the move forced into the open

**There are two roots now, and code that conflated them was correct only by coincidence.**
`tests/helpers/roots.js` names it once — `PLUGIN_ROOT` vs `REPO_ROOT`, plus `resolveSignalPath()` for
artifacts that mix both in a single list. The adherence apparatus list is the clearest case:
`tools/lib/adherence-log.js` ships and `tools/adherence-run.js` does not, **two lines apart**.

`checkRosterCounts` is the one worth remembering: given the repo root it counted **0 commands, 0
agents, 0 skills** and reported every documentation site as a mismatch. It failed **loudly**, which
is the only reason it cost minutes. The same bug in a check that fails quietly is `B39`.

### Three assertions changed on purpose, not to get to green

Each was testing a fact the move legitimately changed, and each carries its reasoning in place:

- **`boundPluginRoot() === REPO`** → `=== join(REPO, 'plugin')`. This is `B52`'s mechanism, and the
  plugin root is the value it actually wants; equality with the repo root was a coincidence of layout.
- **`validate-plugin.js`'s `REQUIRED_FILES`** mixed payload with repository artifacts.
  `marketplace.json` and two launch docs have **never** been in a user's install; pointing `ROOT` at
  the plugin is what made the mixture visible. Split into two lists.
- **The plugin copy no longer contains `tools/adherence-run.js`** — and that is `AC2.2` arriving. The
  original comment argued the script had to be copied *because `ship.md` orders it*. The honest fix
  is the other direction: `ship.md`'s line is now marked a **Signal-repository step**. The
  instruction and the tree agree again by amending the instruction, not by shipping a script to
  satisfy it.

### The finding: `RESEARCH` §4's failure-mode sentence was inverted, and it was the deciding number

The plan's default was **A** (the manifest), and `RESEARCH` recommended it while describing a failed
install as costing *"the 18 commands that never touch `profile.js`/`state.js`"* — i.e. a minority
tail, with `AC3.4` asking only that it be **made legible, not prevented**.

Computed as a **transitive closure** over `plugin/tools/lib` rather than as a grep for two filenames:

| | |
|---|---|
| `tools/lib` modules reaching `yaml` | **28 of 51** |
| Commands that break without it | **17 of 20** |
| Survivors | `doctor`, `escalate`, `update` |

`archive`, `sweep`, `index` and `migrate-memory` are in the broken set and reach `yaml` through
`archive-command.js`, `sweep.js`, `planning-index.js` and `migrate-memory.js` — **never** through
`profile.js`/`state.js`, which is precisely why a grep for those two names missed them.

So `AC3.4`'s subject was never a degraded mode. It was **"the plugin does not work, silently, at
import, on a restricted network"** — because a failed dependency install *"never blocks the plugin."*
At that magnitude, prevention was both available and free at the boundary: the ~1.2 MB is bytes the
manifest would have installed into the same cache anyway.

**The AC did its job.** `AC3.4` demanded the outcome be *characterised* — and characterising it
honestly is what destroyed the option it was written to accompany.

### Two smaller things the slice turned up

1. **`.gitignore`'s `dist/` would have committed a dependency containing nothing that runs.**
   Unanchored, it matched `plugin/node_modules/yaml/dist/` — the 796 KB that *is* the package.
   `git add -An` reported `LICENSE`, `README.md` and `bin.mjs` and silently dropped the rest. Caught
   by checking the dry-run's file count against the tarball's own `233`, not by reading the pattern.
   Fixed by anchoring the repo's build output as `/dist/`; both directions are now pinned by test.

2. **`RESEARCH` rejected option C on a false premise.** Its stated ground was that deep-importing a
   CJS package past its `exports` map makes *"named-export interop the fragile part."* Verified
   directly: a relative deep import of `dist/index.js` yields both named exports, because an
   `exports` map governs **bare specifiers only** and vendoring imports by relative path. C was
   genuinely viable; it was declined on **citation fidelity** (the import line should keep reading
   `from 'yaml'` so command files citing these modules still describe what runs), and `D-M6E1-7`
   records that as the reason rather than inheriting the wrong one.

`plugin/vendor/` + rewritten imports = `RESEARCH`'s **C**. `PLAN` S3.t1 said *"Decide A-vs-B"* and
