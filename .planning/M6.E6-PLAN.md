## ⚠ Raised at PLAN: DISCUSS decided ONE routing axis; the design specifies TWO

`D-M6E6-3`/`-4` settled **reversibility**. But `LOOP-ENGINEERING-ANALYSIS.md` states the routing
rule as *"already exist[ing] in two established pieces"*, and reversibility is the second:

> - **Altitude:** plumbing / tooling / test-mechanics decisions auto-resolve with sensible defaults;
>   product / scope / positioning decisions queue. *(This is the standing "gate at product altitude"
>   working norm, made machine-readable.)*
> - **Reversibility:** `trivial` / `moderate` → auto-adopt provisional; `painful` / `irreversible`
>   → queue.

**Building only the reversibility half would ship half a specified rule** — and it would be the less
important half in practice. Altitude is the axis that already governs this repository by convention
(`discuss.md:142` cites the norm by name; it is a standing instruction in every session), and it
catches the case reversibility misses: **a product decision that is perfectly reversible.** Picking
the wrong default tier for a new command is `trivial` to revert and is exactly the sort of call a
person wants to make.

**Planned as: both axes, OR-composed.** A decision queues if it is product-altitude **or**
irreversible; it is adopted only when it is *both* plumbing-altitude *and* reversible. That is the
conservative composition, it is faithful to both stated rules, and it collapses to
`D-M6E6-4`'s default cleanly — an untagged decision is missing both tags, so it queues.

**This extends what DISCUSS decided and is flagged rather than absorbed.** If the altitude axis is
unwanted, `S1` drops to one input and `S2`/`S3` are unaffected — the veto is cheap and it is the
plan gate's to make.

## Slices

Three vertical slices, each shippable and independently reviewable.

### S1 — The router: a pure decision, testable without a run

**The whole routing rule as one pure function**, so the policy is readable in one place and provable
without invoking a command. `drive.js` gets `routeDecision({ reversibility, altitude })` returning
`{ route: 'adopt' | 'queue', why, missing }`.

| Task | What |
|---|---|
| `S1.t1` | `ROUTE_REVERSIBILITY` / `ROUTE_ALTITUDE` vocabularies — reversibility reuses calibration's four terms **verbatim, imported not re-listed** (the `CANONICAL_PHASES` lesson from #230: a second copy drifts and then disagrees) |
| `S1.t2` | `routeDecision` — OR-composition, fail-closed on an unknown or missing value |
| `S1.t3` | `why` is a sentence naming which axis routed it, so a queue entry can say why it is there |

**Acceptance criteria**

- `AC1.1` — plumbing + `trivial` → `adopt`; plumbing + `moderate` → `adopt`
- `AC1.2` — plumbing + `painful` → `queue`; plumbing + `irreversible` → `queue`
- `AC1.3` — **product + `trivial` → `queue`** (the case reversibility alone misses)
- `AC1.4` — no tags at all → `queue`, and `missing` names **both** absent axes
- `AC1.5` — one tag present, one absent → `queue`; `missing` names only the absent one
- `AC1.6` — an unrecognised value (`"sort-of"`, `null`, `42`, `{}`) → `queue`, never a throw
- `AC1.7` — `why` names the deciding axis, and on a double-miss names both
- `AC1.8` — the reversibility vocabulary is the **same binding** calibration uses (identity, not
  equality — a value-equality assertion passes over two copies that agree today, which is the thing
  being prevented)

### S2 — `/sig:drive` writes to the queue instead of halting

| Task | What |

| `S2.t4` | `drive.md` anti-rationalization rows for the new failure shapes |

**Acceptance criteria**

- `AC2.1` — a queued entry carries reversibility, altitude, the route, and the recommendation
- `AC2.2` — an entry **without** a recommendation still renders the existing defect notice (the
  module's current behaviour must survive the new fields)
- `AC2.3` — the rendered entry states which axis queued it, in `routeDecision`'s words
- `AC2.4` — `readQueue` round-trips an entry written with the new fields (parse what we write)
- `AC2.5` — `drive.md` §3 names `routeDecision` and `queueDecision`, and the reference list resolves
- `AC2.6` — ⚠ **the queue write never fires at `attended`.** A person sitting at the gate should be
  *asked*, not have their question filed. Queueing is what `unattended` and `checkpointed` buy.
