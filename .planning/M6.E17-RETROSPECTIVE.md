# M6.E17 — Retrospective: the REVIEW fix loop becomes a mechanism

**Label:** *"Make the REVIEW fix loop a mechanism, not a habit"*. Priority 1 of
[`BACKLOG-REVIEW-2026-10-14.md`](BACKLOG-REVIEW-2026-10-14.md), picked by Brett. FULL tier,
`attention: checkpointed`. Three habits that had paid off in earlier Epics became things the code
does or checks: a REVIEW or VERIFY pass is recorded when it ends and the loop ceiling counts the
records (`recordPass`, `phase_passes`); every round of fixes carries a fresh read and a stated stop,
checked before a verdict (`checkFixRounds`); and "this new test fails without the fix" is proven by a
tool (`parent-run.js`) rather than asserted. Wall-clock tests got their own serial run.

## What changed mid-flight

- **The report check grew a structure.** S4 shipped `checkFixRounds` reading rounds anywhere in the
  report. VERIFY D2 added a floor from `phase_passes`; REVIEW pass 1 made the pass record required,
  counted a PASS-WITH-FIXES's own round and bounded rounds per pass; pass 2 tied `## Pass N` sections
  to the record and had the heading written before dispatch; pass 3 made the section count always
  apply.
- **A linear run got a boundary in the REVIEW report.** A linear project keeps one report for every
  run, so the next run's REVIEW read the last run's passes. SHIP now appends `## Run ended — <date>`
  (P3-I5), and `markRunEnded` is the recovery when it cannot (P4-I1, P5-I1). Not in the requirements;
  forced by the check's own correctness.
- **REVIEW ran past its ceiling twice, by a person's decision each time** (passes 4 and 5), and pass
  5 was one reader on the round's diff instead of the full three-agent dispatch. Both are recorded in
  the report's Loop Backs so they do not read as steps skipped.
- **Deferred:** archiving `phase_passes` on an Epic roll (`SIG-327`); the timing detector's blind
  spots (`SIG-346`).

## What assumptions broke

- **"A test that failed on the base proves the fix."** A test that failed because its fixture file
  did not exist yet on the base fails there too, and proves nothing. Fixed for whole files at pass 1
  and again per test at pass 4 (P4-I2), after a file mixing one real failure with one missing-file
  failure still passed as proof.
- **"`git worktree prune` only touches our worktrees."** It unregisters any worktree whose folder is
  missing, including the user's own (P4-I3). Now pruned only when every prunable entry is ours, with a
  known limit filed (`SIG-341`).
- **"The report can show its own rounds."** It cannot show a round nobody wrote down (VERIFY D2), and
  a typed `## Pass` heading could open a fresh bound of three (P2). The record in `STATE.md` had to set
  the floor.
- **"Re-running `/sig:ship` reaches `completePhase`'s new branch."** I wrote that in code, in
  `ship.md` and in a contract test, from the shape of the function and not from the order `ship.md`
  calls things in. The round-5 reader ran that order and found it never got there.

## What surprised us

- **The mechanism caught its own Epic.** From pass 1, `loopStatusFor(state, 'REVIEW')` counted every
  pass (M6.E16's read 0 through five). `checkFixRounds` refused PASS at pass 4 and at round 4 for the
  right reason ("the last fix round reads stop: no"), and accepted pass 5 only once the chain had
  stopped clean. The ceiling stopped the loop each time and asked a person, as designed.
- **Almost every REVIEW finding was in `parent-run.js`.** A tool that makes git worktrees, links
  `node_modules`, runs vitest twice and kills stray processes has a large surface. Each full pass
  found a new corner of it: hostile working trees, missing files, worktree cleanup, process
  identity. The pass-record and report-check code settled earlier.
- **Fix-on-fix needed its fresh read again.** Round 5 introduced a false claim; only round 6's read
  was clean. Same lesson as M6.E3, M6.E14 and M6.E16, now enforced by the check rather than
  remembered.

## What we'd do differently

- **Prove a claim about a command's flow by running the flow.** The round-5 test called
  `completePhase` alone; `ship.md` calls `transitionPhase` first. A test for "re-running X does Y"
  runs X's documented steps in order.
- **Scope a tool that touches git state against the user's state first.** `prune`, `worktree add`
  hooks, and a shared runs folder were each found by a reviewer. A short "what of the user's does
  this touch" list at PLAN for any tool that runs git would have found most of them.
- **Narrow the read sooner.** Passes 2–4 each found nine-ish new things in a different corner. The
  narrow read (one reader, the round's diff) converged in three rounds. For a well-understood
  remaining set, it is the better default after the ceiling.

## Anti-rationalization moment

At pass 5, the first narrow read found one Important: if SHIP's failure to write the run boundary was
reported and then missed, the next run had no working way back. Two easy exits were there. The case
needs a missed failure on top of a failed write, so it could have been called out of scope, or quietly
absorbed into PASS-WITH-FIXES since the bar was "one reader". Neither was taken: Brett had said any
Important comes back to him, and it did.

Then the fix for it carried a false sentence: "a re-invoked `/sig:ship` writes it". The `keep` half
worked, the tests were green, and the reader rated it Important rather than Critical because a way
out still existed. Keeping the sentence would have shipped a promise the code does not keep, in the
Epic built to stop claims written from the shape of the work. The sentence, its code and its test
were removed, and `ship.md` now says the opposite, which is true.
