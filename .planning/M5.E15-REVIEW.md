## Important Issues

### I1 — `assertRegistryShape` never validated the one field the leak check depends on · **FIXED IN-PHASE**

`tools/lib/adherence-verdict.js` · `tools/adherence-run.js:390`

The control arm's old check guarded the token before using it:

```js
if (residue && mutated.includes(residue))
```

S5 replaced that with the independent walk and **dropped the guard**. `walkResidue` hands
the token straight to `String.prototype.includes`, so a canary with no
`trace.functionName` searches for the literal string **`"undefined"`** — which occurs
throughout a JavaScript corpus.

**Measured, not reasoned:** a two-line fixture containing `const a = undefined;` returns a
hit. The run would then refuse, naming `undefined` as the leaked instruction.

It fails **closed**, so no bad verdict can escape — which is why this is Important and not
Critical. But the operator is handed a nonsense cause for a measurement that costs money, and
the real fault (an under-specified canary) stays invisible. The registry validated `isolation`
and every `deletions[]` entry while never checking the field the entire control-arm
verification rests on.

**Fix:** `assertRegistryShape` now requires a non-empty string `trace.functionName`, placed
*after* the deletions checks so the existing shape errors still fire first. An empty string is
rejected explicitly — it would match every line of every file. 13 LOC, 3 tests, the live
registry asserted to pass.

## Nits

### N1 — orphaned `buildCaveats` docstring left above `VERDICT_NOTE` · **FIXED** *(independent review)*

`tools/adherence-run.js` — found by the independent cloud review, not by this self-review.

Extracting `buildCaveats` to `tools/lib/adherence-caveats.js` removed the function body and
left its four-line docstring behind. It came to rest above `const VERDICT_NOTE`, a per-verdict
console-gloss table it does not describe, so a reader grepping for where scope caveats are
built lands on a docstring for a function that is no longer beneath it. Zero runtime effect;
`no-unused-vars` cannot see a JSDoc block, so nothing mechanical would surface it.

**Confirmed against `main`:** the docblock sits directly above `function buildCaveats` there,
so this Epic orphaned it. The same commit *did* correctly drop the `applyDeletion` /
`applySectionDeletion` imports — one orphan cleaned, one missed.

**What made it worth more than a deletion.** Its second sentence — *"the OBEYED record shipped
without them and needed an appended correction"* — is M5.E8-era text recording that a verdict
once shipped without its scope boundaries. **That is precisely what happened again at S7**, by
a different mechanism (the residue read off the arm summary instead of the arm result). Twice,
in the same place, two mechanisms. The fact was carried into `adherence-caveats.js` with the
recurrence recorded and the generalisation stated: a caveat whose absence is indistinguishable
from a clean result must either render unconditionally or be pinned by a test that fails when
it stops rendering.

**This is the finding the self-review limitation predicted.** It is only a nit, but it was
missed by the pass that reviewed its own work and caught by the one that did not.

## Security Findings (`security_audit: full` — OWASP + ASVS L2)

This is an offline developer CLI with no network surface, no user accounts, no request
handling. Most OWASP categories are structurally inapplicable. The categories that *do* apply
were checked against the actual diff:

| Area | Finding |
|---|---|
| **Path traversal** | Clean. `walkResidue` descends only from `readdirSync` entries under a `mkdtemp` root; no path is built from external input. |
| **Symlink escape** | Clean, and load-bearing. Entries that are neither `isDirectory()` nor `isFile()` are skipped, so symlinks are never followed — a symlinked file in the copied tree cannot pull the walk outside it, nor make it read an arbitrary host file. |
| **Command injection** | Not reachable in new code. Neither `adherence-leak.js` nor `adherence-caveats.js` spawns anything. The one `spawnSync` (`invokeAgent`) is unchanged, passes an argv array (never a shell string), and its prompt is not attacker-controlled. |
| **Arbitrary file write** | `PLUGIN_COPY_EXCLUDE` is a frozen literal array of one repo-relative constant, `rm`'d under the temp copy root. No interpolation from registry data. |
| **Untrusted deserialization** | `loadCanaryRegistry` parses a repo-controlled JSON file, now with stricter shape validation than before this Epic. |
| **Resource exhaustion** | Files over 2 MB are skipped and `node_modules` / `.git` are pruned, so the walk cannot be made to read a large binary tree. |
| **Secrets** | None introduced. No credentials, tokens, or env reads added. |
| **Dependencies** | Zero added. `package.json` untouched. |

**Net: no security findings.** The one genuinely security-relevant behaviour — refusing to
follow symlinks out of the measured tree — is a property of the new code and is correct.

## Review limitations, stated plainly

structurally weaker than an independent pass and is exactly the condition under which the
`B83` class survives. Two mitigations were used rather than claimed: findings were **measured**
(the `undefined`-token behaviour was reproduced on a fixture; the timings were run; the
symlink behaviour was read off the code path), and VERIFY's mutation testing had already
forced each assertion to prove it discriminates.

It remains true that an independent reviewer would likely find things this pass did not.
