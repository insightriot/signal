# M5.E16 — PLAN

**Epic:** M5.E16 — STATE-vs-world drift detection · **Tier:** FEATURE (`M5.E16-PROFILE.md`)
**Written:** 2026-08-01 · **Target release:** v0.1.16
**Requirements:** [`M5.E16-REQUIREMENTS.md`](M5.E16-REQUIREMENTS.md) · **Research:** [`M5.E16-RESEARCH.md`](M5.E16-RESEARCH.md)

---

## Phase goal

Ship a set of deterministic checks that compare what a project's `.planning/` **asserts** against
what is on disk and in git — each one declaring whether it heals itself, is healed by a command, or
needs a person — and report **what could not be checked** as loudly as what was.

---

## What this Epic does for the first time (M5.E17 FR1 — and it goes in wave 1)

**The thing that runs for the first time is not a check. It is `readProfileFromPath`,
`artifactName` and `resolveArtifactPath` used as *drift oracles* over foreign `.planning/` trees.**

That machinery was built to **resolve**: find the artifact I am about to read, name the one I am
about to write, load the profile that governs this phase. It has never been pointed at a project and
asked *"is what this file claims actually true?"* — and it has only ever run against Signal's own
repo plus fixtures.

**It was partly run at PLAN, and it immediately produced three things nobody was looking for:**

- **`B59`** — Signal's own `M5.E16-PROFILE.md` carried two out-of-enum values, so the Epic that
  declares FEATURE ran DISCUSS at the project's FULL. Found at this command's tier-gating preamble,
  the first time any code read that file. Fixed and shipped in the fix lane before this plan was
  written.
- **Check (h)** — a candidate check that is not in the requirements, found only by measuring:
  2 of 4 Epic-mode projects have a `current_epic` that no resolver accepts.
- **The applicability numbers** — checks (a) and (b) can evaluate 2 of 13 real projects.

**Therefore S1 is wave 1**, and its job is to *finish* that probe rather than start it: the
`affiliate-mojo` throw path, the red fixtures for the checks the live corpus cannot exercise, and
the "cannot evaluate" branch that the numbers above proved is mandatory. If the oracle framing is
wrong, it breaks against a scratch harness in wave 1 rather than against six half-built checks.

**What this is deliberately *not*:** it is not "the check registry is new." A newly-authored thing
has no history to be wrong about. The risk lives in machinery that already exists, was built for one
purpose, and is about to be used for another.

## The check set — what ships, what does not, and why (FR1.1, AC1.4)

Six ship, two are dropped. Every disposition is backed by a measurement in `M5.E16-RESEARCH.md`,
not by judgement about how the check "feels."

| # | Check | Ships? | Heal category | Evidence |
|---|---|---|---|---|
| a | `phase` vs. a later-phase artifact for `current_epic` | **yes** | 3 — needs a person | red fixture only (see below) |
| b | body never mentions `current_epic`, **narrowed** | **yes** | 3 — needs a person | **red on 3 real historical commits, green on the 4th** |
| c | an Epic with phase artifacts and no retrospective, **restructured** | **yes** | 3 — needs a person | **1 live true positive** (`M5.E17`, this repo) |
| d | `last_updated_commit` is not an ancestor of `HEAD`, **narrowed** | **yes** | 2 — command-healable | **1 live true positive** (`cm-mentor-coach`) |
| e | `current_tasks[]` orphans | **no — dropped** | — | duplicates `detectOrphans` |
| f | `blockers[]` names a closed Epic or bug | **no — dropped** | — | **0 of 13 projects have a non-empty `blockers[]`** |
| g | every `PROFILE.md` in the project parses | **yes** (added, Brett 2026-08-01) | 3 — needs a person | `B59`, found by this logic before it was a check |
| h | `current_epic` is set but is not a strict Epic ID | **yes** (added, found by measuring) | 3 — needs a person | **2 live true positives** (`agent-tools-sync`, `traction-engine`) |

### The two drops, stated as results (AC1.4)

- **(e) is dropped as a duplicate.** `detectOrphans` already finds this and `/sig:resume` already
  prompts on it interactively, always-on regardless of `gate_strictness` (D12). A second finding for
  one condition is noise, and the requirements' own open question 2 anticipated this.
- **(f) is dropped because it cannot be validated.** FR2.1 requires every check to run against a
  real non-Signal project before shipping. **No project in the corpus has a non-empty `blockers[]` —
  zero of thirteen** — so (f) cannot meet that bar even in principle today. Its bug-status half also
  depends on `BUGS.md`'s `| B59 | \`fixed\` |` table, which is a **Signal convention**, not something
  a Signal-managed project has. Re-open when a real project carries a blocker.

### The two additions

- **(g)** — approved by Brett 2026-08-01. Highest precision on the board: a file either parses or
  throws, so there is no threshold and nothing for FR2.2 to kill. It widens the Epic from
  "STATE-vs-world" to "what the docs declare vs. what the code can read," which is the honest
  description of what the other six already do.
- **(h)** — **not in the requirements; it exists because the probe found it.** `current_epic: "M1"`
  and `current_epic: "PHASE12"` both fail `EPIC_ID_STRICT_RE`, so every resolver silently falls open
  to linear mode while the project believes it is running Epics. This is **`B53`'s class observed in
  the field** after being fixed as a Signal-side bug in v0.1.14. It is included without a second
  approval round because it sits squarely inside FR1.1's existing frame — a STATE field versus how
  the code reads that field — where (g) genuinely changed the frame.
  **It also earns its place structurally:** the 2 projects where (h) fires are exactly the 2 where
  (a) and (b) are blind. **(h) is the check that reports why the other checks cannot see.**

## The finding that shapes everything below: most checks cannot evaluate most projects

Measured across 13 real `.planning/` trees (full table in `M5.E16-RESEARCH.md`):

```
check   can evaluate   correctly N/A   BLIND (silently sees nothing)
  a          2               8                    2
  b          2               8                    2
  c         12               0                    0
  d          8               4                    0
  g         12               0                    0
  h          4               8                    0
```

**Checks (a) and (b) — the two aimed at the incident that opened this Epic — apply to 2 of 13 real
projects.** Signal's own hand-maintained, Epic-mode, `schema_version: 1` shape is the *minority*
shape: only 4 of 12 readable projects are in Epic mode, only 7 of 12 have a canonical `phase`, and
`readState` **throws** on one project outright.

A sweep that runs these checks against `traction-engine` today prints nothing, and the user reads
that as *clean*. It is not clean — the check could not look.

**This is the muted-detector failure FR2 exists to prevent, built in at construction.** It is also
the same shape as `B39` (an instruction nothing executed) and `B54` (a guard that was wrong
*because* nothing called it). Shipping it inside the Epic written to catch this class would be the
fourth recurrence.

**Therefore a shipped requirement, not an observation:** the report must distinguish **checked and
clean** from **could not check**, and the published applicability numbers go in the docs the same
way M5.E8 published its 22.4% ceiling with the words *"the remainder is unmeasured, not passing."*

## Decisions this plan makes

### D-M5E16-1 — `/sig:sweep` stays read-only; healing lives elsewhere (Brett, 2026-08-01)

**The requirements contradicted themselves and PLAN could not resolve it alone.** FR4.1 category 2
says *"**Signal runs it**; it does not tell the user to go run it."* NFR2 says *"**No writes, no
network.** `/sig:sweep` is detect-and-report; that holds."* FR1.3 repeats the read-only contract.
Sweep cannot both run a fix and never write.

**Resolved: sweep stays pure.** NFR2 is the older contract, and M5.E9's REVIEW set the precedent of
**removing** a bad sweep behaviour rather than softening it. Category-2 healing is delivered two
other ways:

- **FR5's phase-transition regeneration** — the stale-`INDEX.md` finding, which is the *only*
  category-2 case the 16-finding baseline actually produced, heals during normal work without anyone
  typing anything.
- **`/sig:sweep --heal`** — explicit, opt-in, for anything else.

**The cost is recorded because it is real:** a user who never types `--heal` is back to detect-only
for those findings, which is the outcome FR4 was written against. FR4's argument survives because
its own evidence pointed at one case, and FR5 covers that case automatically.

### D-M5E16-2 — STATE findings surface at `/sig:resume`, but only category 3, as one line (FR3, AC3.1)

FR3 asked PLAN to decide **with a written reason**, and both sides are real: the live incident
happened *at* `/sig:resume`, which people run constantly — but resume's briefing is capped at 50
lines and a detector nobody runs is `B39` in a new costume.

**Decision: resume renders exactly one line, only for category-3 findings, with a count and a
pointer.** Categories 1 and 2 never appear there — one heals itself and the other is a command away,
so both are noise in a briefing. The line sits in the **advisory tier**, below the schema-drift and
staleness banners: a STATE *content* contradiction makes the briefing's narrative suspect, but it
does not make the briefing's **parse** suspect the way a schema mismatch does, and banner order
already encodes that distinction.

One line for the finding that a whole Epic exists to catch is the right trade against a 50-line cap.

### D-M5E16-3 — the applicability numbers are published, not just measured

Every shipped check declares, in `references/`, which project shapes it can evaluate and which it
cannot. The sweep report states the same thing per-run. **A check's coverage is part of its
contract**; a detector that silently no-ops on the majority of real projects while reporting
"clean" is worse than absent, and this is Signal's third measurement in a row (adherence ceiling,
claim integrity, now this) to find the instrument covering less than it appeared to.

### D-M5E16-4 — FR6 is the last slice, and it splits rather than shrinks

The requirements delegate this: *"If PLAN finds the scope does not slice cleanly, split FR6 into its
own Epic rather than dropping requirements."* FR6 has **zero dependency** on FR1–FR5 and its
feasibility is confirmed by execution (`claude plugin list` exits 0 on this machine).

**It stays in the Epic as S6, the final independent slice, with a standing rule: if S1–S5 overrun,
S6 becomes M5.E18 intact. It is never trimmed to fit.**

## Slices

Each slice is independently shippable. Complexity is S/M/L, not time.

### S1 — the oracle harness, the "cannot evaluate" branch, and the red fixtures · **wave 1** · L

**This is the first-use slice. Nothing else starts until it lands.**

| Task | What | AC |
|---|---|---|
| S1.t1 | A check-registry module: each entry declares `id`, `run(baseDir)`, `healCategory` (1/2/3), and `applicability(state)` returning `EVAL` / `NA` / `BLIND`. **A check with no category cannot be registered** — enforced by the constructor, not by review. | AC4.1, AC4.2 |
| S1.t2 | Every check runs inside a catch that yields **`cannot evaluate` + the reason**, never a crash and never silence. Proven against `affiliate-mojo`, which makes `readState` throw. | — |
| S1.t3 | Report renders four states: **checked-clean**, **needs you** (cat 3), **heals on next phase command** (cat 1/2), **cannot evaluate**. A test pins that zero-findings and not-applicable render **differently**. | AC4.2 |
| S1.t4 | Re-run the 13-project probe as a committed script so the numbers are reproducible rather than a claim in a document. | AC2.2 |

**Test strategy:** TDD. `S1.t3`'s test is written RED first against a fixture where one check is
`EVAL`-clean and another is `BLIND` — if the renderer collapses them, it fails.

**Why wave 1:** everything downstream assumes the registry's category and applicability contract. If
"cannot evaluate" is not a first-class result from the start, it becomes a bolt-on and the blind
column stays invisible.

### S2 — checks (c), (d), (g): the three that work everywhere · M

Sequenced first among the checks because all three are **fully general** — (c) and (g) evaluate
12/12, (d) evaluates 8/8 — and each already has a **live true positive** to test against.

| Task | What | AC |
|---|---|---|
| S2.t1 | **(c)** an Epic with `-PLAN`/`-PROGRESS`/`-VERIFICATION`/`-REVIEW` artifacts, no `-RETROSPECTIVE`, and not `current_epic`. Red fixture + the live `M5.E17` instance. | AC1.1, AC1.2 |
| S2.t2 | **(d)** `last_updated_commit` is not an ancestor of `HEAD` — **narrowed to the not-an-ancestor case only**, leaving "N commits behind" to `isStateStale` so the two never double-report. Category **2**. Live instance: `cm-mentor-coach`, whose baseline commit is reachable from **no ref at all**. | AC1.1, AC1.2 |
| S2.t3 | **(g)** every `PROFILE.md` and `{EpicID}-PROFILE.md` loads. Red fixture reproduces `B59`'s exact two-bad-value file. **Must report both bad fields, not just the first** — validation short-circuits, and a fix driven by the error message alone repairs one of two. | AC1.1, AC1.2 |

**Note on (c):** it is **restructured** from the requirement as written. FR1.1's version keys off
`completed_phases` containing `SHIP` — which **does not fire on the live instance**, because this
repo's `completed_phases` is `[]` while `M5.E17` sits shipped with no retrospective. The
requirement's version would have been silent on the one real case available to it. Keyed off
artifacts-on-disk instead, it fires.

### S3 — checks (a), (b), (h): the Epic-mode three · M · *depends on S1*

| Task | What | AC |
|---|---|---|
| S3.t1 | **(h)** `current_epic` set and not matching `EPIC_ID_STRICT_RE`. Two live true positives. Ships **before** (a)/(b) because it explains their blindness. | AC1.1, AC1.2 |
| S3.t2 | **(a)** phase vs. a later-phase artifact for `current_epic`. **Red fixture is the only evidence this works** — 0 live hits — so the fixture must be built from a real drift shape, not a convenient one. | AC1.1, AC1.2 |
| S3.t3 | **(b)** narrowed: fires only when the body names ≥1 *other* Epic ID and not the current one. **Regression-pinned against real history** — red at `4421105`, `137b9ca`, `8acd1d2`; green at `18741a8`. | AC1.1, AC1.2 |

**The impostor problem, stated rather than assumed.** Checks (a), (g) and — on the current corpus —
(b) fire **zero** times across 13 real projects. That is either excellent precision or an inert
check, and **the live corpus cannot tell the difference**. For (a) in particular the red fixture is
the *only* evidence it works. This is M5.E8's impostor-table lesson: a pre-authorised clean result
needs a pre-committed way to distinguish the real thing from its impostor. (b) escapes this because
its evidence is real history rather than a fixture, and (g) escapes it because `B59` was found by
this exact logic before it became a check.

## Risks

| Risk | Mitigation |
|---|---|
| (a) never fires in the field, and nobody notices it is inert | Red fixture built from a real drift shape; stated in S3 as the *only* evidence for that check |
| The blind column gets rendered as "clean" anyway | S1.t3 pins the distinction with a RED-first test before any check ships |

| Sweep slows down (NFR3) | Every check is a string compare or `existsSync`; (d) is the only `git` call. Budget: **no more than +200 ms** on Signal's own tree, measured at VERIFY |
| FR4's middle bucket is hollowed out by D-M5E16-1 | Cost recorded in the decision; FR5 covers the one real category-2 case automatically |
