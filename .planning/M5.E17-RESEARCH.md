## F2 — `ship.md` references a commit that no step creates

FR3 describes this as a step in the wrong place. It is worse, and the worse version explains the
symptom better.

Four separate steps instruct staging **"into the SHIP commit"**:

- `ship.md:117` (§5.5 evict) — *"stage the modified `.planning/STATE.md` **and** the new `…/STATE-NARRATIVE.md` into the SHIP commit"*
- `ship.md:132` (§6 retro index) — *"Stage the modified `.planning/RETROSPECTIVES.md` … One atomic commit captures all three."*
- `ship.md:141` (§6.5 inbox sweep) — *"stage the modified inbox **and** the ledger into the SHIP commit"*
- `ship.md:164` (§8 INDEX regen) — *"stage the modified `.planning/INDEX.md` into the SHIP commit"*

**No step in `ship.md` ever instructs making that commit.** §2 (Git History) discusses history
quality; §3 is PR creation. `markFresh` sits at §5.3 — *ahead of all four staging steps*.

So following `ship.md` as written stamps a HEAD that predates every file those steps produce —
**by construction, not by accident.** That is exactly what was observed live on 2026-07-30.

**Consequence for the plan:** FR3.1 is not "move a line." It is *add the missing commit step, place
it after §5.5–§8, and put `markFresh` after it.*

### F2.1 — Adjacent, deliberately not fixed here

§3 (PR Creation) runs **before** §5–§8, which stage files "into the SHIP commit." A PR opened at §3
cannot contain artifacts committed after it. This is an ordering oddity in the same file and the
same neighbourhood, but it does not trace to FR1–FR4 and is not `markFresh`-related.
→ **Captured as an observation, not folded in.** Recommend `/sig:add` after this Epic closes.

## F6 — Test infrastructure (where FR1–FR3's tests land)

`tests/commands-wording.test.js` is the existing home for cross-document instruction pinning, built
by M5.E13. It already demonstrates all three shapes this Epic needs:

- `'all four middle commands carry the conditional clause'` — presence across files

  **normalised cross-file comparison**, the exact shape FR3's ordering test needs

another; a substring presence check pins nothing and is the precise failure M5.E16 exists to
prevent. FR2's and FR3's tests are specified in the PLAN as **cross-document comparisons**.

## F8 — Incidental find: `references/facts.md` test count is stale by 912, and the guard cannot see it

Found while establishing the test baseline. **Not in scope; catalogued as `B56`.**

`references/facts.md:22` reads `**Test count:** 894`. The suite is at **1806**.

`tests/cross-file-consistency.test.js` is the guard over exactly this file. It asserts
`expect(TEST_COUNT).toBeTruthy()` and that any doc mentioning "N tests" **matches facts.md** — it
**never compares facts.md's number to the actual test count**. So `facts.md` and `README.md` agree
with each other, drift together from the thing they describe, and the test stays green.

This is the Epic's class in a fourth location — a guard pinning two documents to each other while
both drift from reality — and it is a **live, currently-wrong published number**.

→ `B56`, `confirmed`, P3. Recommended for M5.E16 (or a one-line fix if Brett wants it pulled in);
**not** folded into M5.E17's FRs.
