# M5.E16 — STATE-vs-world drift detection

**Epic:** M5.E16 · **Tier:** FEATURE (Epic-scoped override — see [`M5.E16-PROFILE.md`](M5.E16-PROFILE.md))
**Opened:** 2026-08-01 · **Target release:** v0.1.16

---

## Why this Epic

**20 of the 56 entries in `BUGS.md` are STATE.md-related — 36%, the largest cluster in the catalog
by a wide margin.** One sub-class accounts for six of them on its own (`B41`, `B43`, `B44`, `B45`,
`B47`, `B51` — the phase ledger asserting something that did not happen).

Nothing checks STATE.md against the world it describes. `isStateStale` compares one field
(`last_updated_commit`) to git. Every other field — `phase`, `current_epic`, `completed_phases`,
`blockers` — is **asserted and never verified against the artifacts on disk that would prove or
disprove it.**

### The live instance, from this Epic's own opening session (2026-07-31)

`STATE.md` frontmatter read `current_epic: M5.E17`, `phase: DISCUSS`.

`STATE.md`'s body, under *"Next candidates, in the order the evidence argues for"*, listed
**M5.E15, M5.E16, M5.E10** — and **M5.E17 was not in it.** The frontmatter advanced when M5.E17
opened; the prose saying what comes next was written before M5.E17 existed and was never updated.

**`/sig:resume` read both halves and reported neither the conflict nor the omission.** The briefing
quoted the frontmatter for the phase line and the body for the narrative, and the two disagreed in
the file it had just called authoritative. A human caught it from memory, hours later.

That is the whole Epic in one file: *the data moved, the prose did not, and the command whose job is
orientation read straight past it.*

---

## The reframe — this ships as a capability, not as Signal hygiene

M5.E16 previously meant *"the guard class's document-shaped and data-shaped detectors"* — Signal
checking Signal. **That framing is retired here** (both of its original homes moved: `B39` was fixed
in M5.E13, `B46`'s remedy went to M5.E14, so the slot was vacant).

**These checks run on the invoking project.** Signal's own repo is one consumer among several. The
motivating complaint is that Signal-managed projects accumulate documentation that drifts, and the
drift-correction is manual and constant. This Epic is the first one aimed at that directly.

---

## FR1 — `/sig:sweep` gains STATE-vs-world checks

**All deterministic. No LLM, no network, no heuristics that need tuning.** Each check is a file-existence
or string comparison between what STATE.md asserts and what is on disk or in git.

**FR1.1** The following classes of contradiction are detected. PLAN picks the final set and may drop
any that cannot reach the precision bar in **FR2** — *dropping one with a written reason is a
result, not a skip*:

| # | STATE asserts | Contradicted by | Existing coverage |
|---|---|---|---|
| a | `phase: {P}` | An artifact for a **later** phase of `current_epic` exists on disk | none |
| b | `current_epic: {E}` | The body never mentions `{E}` anywhere | none |
| c | `completed_phases` contains `SHIP` | No retrospective / ship artifact for that Epic exists | none |
| d | `last_updated_commit` | Not an ancestor of `HEAD` | partial — `isStateStale` |
| e | `current_tasks[]` | No matching commit, task older than the orphan window | partial — `detectOrphans` |
| f | `blockers[]` | References an Epic or bug already closed | none |

**FR1.2** Findings render in the existing sweep report under a **new group**, distinct from
`structural` and `advisory`. Naming is PLAN's call; the requirement is that a STATE contradiction is
not silently folded into the same bucket as a dead link — it is a different kind of wrong.

**FR1.3** Every check is **read-only, offline, and deterministic**, preserving `/sig:sweep`'s stated
contract (`sweep.md` §2: *"two runs on unchanged input are byte-identical"*). A check that cannot
meet this does not ship here.

**Acceptance criteria**
- **AC1.1** — Each shipped check has a fixture proving it goes **red on real drift**.
- **AC1.2** — Each shipped check has a fixture proving it stays **silent on a clean project**.
- **AC1.3** — Two consecutive sweeps on unchanged input produce byte-identical output.
- **AC1.4** — Any check from FR1.1 that is **not** shipped is recorded with the reason it was dropped.

## FR2 — Precision is the deliverable; a muted detector is worse than none

**The failure mode is not a missed contradiction. It is a false one.** A checker that cries wolf gets
muted within a week, and a muted checker looks like coverage while providing none. This is the same
shape as the M5.E9 REVIEW Critical that told *every healthy project* its history had been destroyed —
**removed rather than re-tuned**, because the honest fix was admitting undetectability.

**FR2.1** Every check runs against **at least one real project outside Signal's own repo** before it
ships. A check validated only against Signal is validated against the one project shape that is
hand-maintained, Epic-mode, and FULL-tier — the configuration `B42` and `B53` proved is unlike every
other consumer.

**FR2.2** A check that produces a false positive on a healthy real project is **removed or narrowed,
not tuned into silence with a threshold.**

**Acceptance criteria**
- **AC2.1** — Sweep runs clean (zero STATE findings) on at least one healthy non-Signal project.
- **AC2.2** — The projects used and their results are recorded — **including any check killed by
  this gate**, which is a success of the gate, not a failure of the Epic.

## FR3 — The checks must be reachable where the confusion happens

`/sig:sweep` is opt-in: it only helps someone who runs it. The live instance above happened at
`/sig:resume`, which people run constantly and which **already** renders drift banners.

**FR3.1** PLAN decides — **with a written reason** — whether these findings also surface at
`/sig:resume`, and if so which. This is a real question with a real cost on both sides: resume's
banner budget is finite and the briefing is capped at 50 lines, but a detector nobody runs is the
`B39` failure (an instruction nothing executed) in a new costume.

**Acceptance criteria**
- **AC3.1** — The decision is recorded in `DECISIONS.md` either way.

## Non-functional

- **NFR1 — No schema change.** Every check reads fields that already exist. If a check needs a new
  field, it is out of scope (see PROFILE escalate-if).
- **NFR2 — No writes, no network.** `/sig:sweep` is detect-and-report; that holds.
- **NFR3 — Sweep stays fast.** A sweep that noticeably slows down is a sweep nobody runs. PLAN sets a
  budget and VERIFY measures against it. This is a floor, not a profiling pass.
- **NFR4 — Reversible.** `git revert` restores.

---

## Not doing

- **Semantic / LLM-judged contradiction detection.** The deterministic checks cover the largest
  cluster at zero cost and with no false-positive tuning problem. The judge-based version —
  claims-vs-artifacts, the `analysis/CLAIM-INTEGRITY-ANALYSIS.md` class with its traction-engine
  Phase 11 evidence — is **real and still wanted**, but it goes after this, not with it.
- **Fixing the drift.** `/sig:sweep` is read-only by design (`sweep.md` AD1). Detect and report.
- **`B55` / M5.E15.** Unaffected, still queued.
- **The 48-entry inbox triage.** M5.E14, per `D-M5E17-3`.

## Open questions for PLAN

1. **FR3.1** — do these surface at `/sig:resume` too, and at what banner cost?
2. **Which of FR1.1's six ship.** (d) and (e) already have partial coverage — extend them or leave
   them alone? Overlapping findings are their own kind of noise.
3. **What counts as "the body mentions `{E}`"** for check (b)? A bare ID match is cheap but a stale
   *reference* to an Epic is not the same as a current one — this check has the highest false-positive
   risk of the six and may be the first one FR2.2 kills.
