# M6.E17 — Plan: the REVIEW fix loop becomes a mechanism

**Goal:** a REVIEW or VERIFY loop stops for a person at its third pass because code counted the passes,
every round of fixes is read fresh and proven with a test that fails without it, and the suite stops
failing for reasons other than the code.

Requirements: [`M6.E17-REQUIREMENTS.md`](M6.E17-REQUIREMENTS.md). Research:
[`M6.E17-RESEARCH.md`](M6.E17-RESEARCH.md). Test mapping:
[`M6.E17-VALIDATION.md`](M6.E17-VALIDATION.md). Decisions `D-M6E17-1` … `-6`. Items `SIG-323`
(FR1), `SIG-324` (FR2), `SIG-325` (FR3), `SIG-303` + `SIG-139` (FR4), all queued under M6.E17.
Tier FULL, strict TDD, `attention: checkpointed`.
**Runtime:** Node 22+ (dev machine 22.13.0), vitest 3.2.4, git ≥ 2.38. No new dependency;
`npm install --dry-run` resolves clean on the dev machine (2026-10-15).

## What this Epic does for the first time

1. **A slice's new tests are run against the commit before it by a tool, for real.** M6.E14 and
   M6.E16 did it by hand in a worktree; nothing has ever done it on its own. **S1 is wave 1**, and every
   slice after it records the tool's output in `M6.E17-PROGRESS.md` — the tool's first users are this
   Epic's own slices.
2. **`loopStatusFor` reaches its ceiling from recorded passes in a live phase.** This Epic's own VERIFY
   and REVIEW are the first passes ever recorded. **S2 is wave 1**, so they are.

## Amendments to the requirements, forced by research (recorded here and in REQUIREMENTS)

- **AC3.2** — the new test is *absent* on the base commit by definition under strict TDD, so "missing
  file on the parent" cannot mean "could not run". The tool **overlays the named test files from the
  working tree onto a worktree of the base commit**. "Could not run" is: git failure, the worktree not
  created, no matching file in vitest's results, or a load/import error (a test that cannot import the
  new module proves nothing about its assertions — M6.E16 pass 2's hollow-test case).
- **AC3.1** — the tool takes the base explicitly (`--base <sha>`, or `--of <commit>` meaning
  `<commit>^`). A slice spans several commits and a fix round's base is the head at the pass that found
  the issues, so "the parent" is ambiguous; a stated base is not.
- **AC4.1** — the perf run takes **two** tests, not three. `tests/planning-index.test.js` has no
  wall-clock assertion; its failures are timeouts, covered by the worker cap (AC4.3).
- **AC4.4** — the guard ships with a **grandfather list, one reason per file**, covering the ~15 test
  files that already assert a budget (several are slow-regex guards that belong in the main suite). It
  fails only on a budget in a file not on the list and not in the perf run.
- **AC2.3** — nothing reads a REVIEW report's rounds today (`verdict.js` reads VERIFICATION/SHIP only).
  The check is new: `checkFixRounds` in `plugin/tools/lib/review-rounds.js`.

## Rules for every task

- Re-grep before relying on a research line number.
- Write the failing test first. From S1's merge onward, **run the slice's new tests with
  `parent-run.js --base <slice base>` and paste its summary line into `M6.E17-PROGRESS.md`.** S1 and
  S2 record their base runs by hand until S1 lands, then re-run with the tool.
- Read exit codes, not last lines. Never `git stash`. Every git call takes `gitEnv(cwd)`.
- `tests/loop-ceiling.test.js:140-160`'s required strings in `review.md` survive every edit.

## Slices

### S1 — `parent-run.js`: prove a test fails on the base (wave 1) · M — `SIG-325`
- **t1.1** `plugin/tools/lib/parent-run.js` exports `runOnBase(baseDir, {base, tests})` →
  `{base, depsDiffer, results: [{file, outcome: 'failed'|'passed'|'could-not-run', reason, failed}]}`
  and `formatParentRun(result)` (one summary line plus one line per file).
  Steps: resolve `base` (`git rev-parse --verify <base>^{commit}`); `git worktree add --detach` into a
  realpath'd `mkdtemp`; copy each named test file from the working tree into it; symlink
  `node_modules`; run the main checkout's vitest once per file with `--root <wt> --reporter=json
  --outputFile=<tmp>`; classify from `testResults[]`; `finally`: unlink the symlink,
  `git worktree remove --force`, `git worktree prune`, remove the temp dir. `depsDiffer` when
  `package-lock.json` differs between base and working tree.
- **t1.2** CLI by the `import.meta.url` check: `node parent-run.js (--base <sha> | --of <commit>)
  <test file>...`, `node:util` `parseArgs` with `strict: true` (unknown flag → usage, exit 2). Exit 0
  only when every file is `failed`; 1 otherwise.
- **AC:** AC3.1, AC3.2 (amended). A fixture repo whose new test fails on the base → `failed`; a test
  that passes on the base (hollow) → `passed`; a test importing a module absent on the base →
  `could-not-run` with the import reason; a bad base / git failure → `could-not-run`, never `failed`;
  the worktree list and temp dir are clean after every outcome, including a thrown error.
- **Tests:** `tests/parent-run.test.js` on `git init` fixtures (unit + integration).
- **Files:** `plugin/tools/lib/parent-run.js`, `tests/parent-run.test.js`.
- **Out of scope:** where the result is recorded (S4); running the whole suite.
- **Exemplar:** temp dir `adherence-harness.js:257`; git env `git-env.js:184`.

## Risks and mitigations

| Risk | Mitigation |
|---|---|
| Worktree left behind on a crash | `finally` cleanup + a test that throws mid-run and checks `git worktree list` |
| Symlinked `node_modules` resolves from the wrong root | run the main checkout's vitest with `--root`; integration test imports a dependency |
| Double counting a pass and an exit | `max`, not sum (`D-M6E17-1`) |
| A broken pass entry reads as zero | `null` → `loop-unknown` (`D-M6E17-6`), tested |
| Grandfather list grows quietly | the guard refuses a list longer than the committed one |
