# M5.E7 Calibration — the v2 direction audit (BR-8)

**The first Epic-scoped PROFILE in Signal's history.** Per-Epic calibration shipped in
v0.1.7 (M4.5.E11 / FR3) and has never been exercised on this repo — no `{EpicID}-PROFILE.md`
has ever been committed. This is its first real use, so treat any friction here as a finding
for the retro, not as noise.

## Why this Epic needs its own profile

M5.E7's deliverable is a **document** — an evidence-grounded v2 roadmap. Inheriting the
project's FULL profile unchanged would apply `tdd_required`, `nyquist_enforcement: strict`,
a full ASVS-L2 `security_audit`, and a `performance_pass` to a markdown file. There is no
code to test, no attack surface to audit, and nothing to profile. Applying them anyway
means waving each one off ad hoc at every gate — exactly the rationalization pressure
Signal's anti-rationalization tables exist to resist. Ceremony you routinely skip is worse
than ceremony you never declared.

The opposite move — dropping to SPIKE, whose shape genuinely fits ("output is learning,
not production code"; "a findings document… not a PR") — was **rejected on substance**, twice:

1. **SPIKE skips SHIP**, and the retro gate lives in the SHIP path
   (`tools/lib/retrospective.js:837`). No SHIP → no `M5.E7-RETROSPECTIVE.md` →
   `isEpicDone('M5.E7')` is false forever and the Epic never enters the compounding record.
2. **The SPIKE retro template has no `## What to feed back into Signal`**
   (`references/retrospective-template.md:116–128` — it carries only *What we learned*,
   *Did the spike resolve its question*, *Next: build, abandon, or continue*). This Epic's
   entire evidence base **is** that section, harvested from 16 prior retros. Running it at
   SPIKE would produce the one retro shape that feeds nothing back — an Epic that consumes
   the corpus it exists to mine.

## What this profile actually says

**Strict thinking, zero test theater.** The code-rigor flags are off because there is no
code. Everything governing *judgment* is kept at maximum:

| Override | Value | Why |
|---|---|---|
| `tdd_required` | `false` | No code ships in this Epic. |
| `security_audit` | `none` | No attack surface in a markdown deliverable. |
| `performance_pass` | `false` | Nothing to profile. |
| `simplification_pass` | `false` | Prose editing is part of authoring, not a separate gate. |
| `nyquist_enforcement` | `off` | Nyquist maps acceptance criteria to *tests*; this Epic's criteria are verified by reading, not running. |
| `plan_validation_dims` | `all` | **Kept.** The 8-dimension plan check is about reasoning quality, not code — it applies cleanly to a research plan. |
| `research_parallelism` | `4` | **Kept at FULL.** Research *is* the work here; this is the one knob the deliverable is most sensitive to. |
| `gate_strictness` | `strict` | **Kept.** This Epic sequences the v2 roadmap. A wrong answer misdirects months. |
| `context_rot_reread` | `true` | **Kept.** Long, document-heavy Epic across a large corpus — re-reading is the whole defense against drift. |
| `review_depth` | `quality-only` | REVIEW is **not skipped**; it is repurposed as an adversarial read of the roadmap's reasoning. The security/perf specialists have nothing to review; the quality lens (does this hold up?) does. |

`tier: FULL` is retained deliberately — the retro gate validates against `profile.tier`
(`validateRetroContent(content, profile.tier)`), so FULL is what makes the FULL retro
template mandatory at close, including `## What to feed back into Signal`.

## Calibration answers

- `scope: product` — sets Signal's v2 direction, not one feature.
- `stakes: major` — a wrong sequence misdirects months of build.
- `novelty: rare` — Signal has run audits before (`REPO-ANALYSIS.md`), but never one grounded
  in its own accumulated retro record.
- `reversibility: moderate` — a roadmap can be re-sequenced; work already built to a wrong
  roadmap cannot be un-built. Deliberately *not* `painful`: the document itself is cheap to
  revise, which is precisely why it is worth getting right before any port Epic starts.
- `horizon: years` — this is the input to v2, which is Signal's multi-year arc.

## Finding to carry into the retro

**Signal's tier system conflates "how careful must the thinking be" with "how much
code-rigor ceremony applies."** A high-stakes research Epic wants strict gates and zero
test ceremony, and no tier expresses that — SPIKE gives light gates (wrong for roadmap
stakes), FULL demands TDD on a document. This profile is a hand-tuned workaround. Whether
that gap deserves a fifth tier, a documented "hand-tune for doc Epics" pattern, or nothing
at all is a question for `## What to feed back into Signal` at close — not a change to make
mid-Epic.
