# M6.E11 — Plan: the work-item store, step 1

**Phase goal:** Signal's bugs, backlog, inbox and open questions live as one file per item, moved
through folders by one command, with Epics as folders — and every project without the store sees no
change.

Inputs: [`M6.E11-REQUIREMENTS.md`](M6.E11-REQUIREMENTS.md) (FR-1…FR-10, 39 ACs),
[`M6.E11-RESEARCH.md`](M6.E11-RESEARCH.md), `D-M6E11-1` … `D-M6E11-26`. Environment: Node 22.13,
`yaml` only runtime dep, no new dependency (RESEARCH § Environment).

## What this Epic does for the first time — and therefore wave 1

1. **The four shipped readers parse a GENERATED file.** `walkBugEntries`, `parseBacklogRows`,
   `parseEntries`, `countOpenQuestions` have only ever read hand-written files.
2. **A segmenter runs over the real 378 KB `BUGS.md`** — multi-line rows (B52, B99), unescaped `|`
   inside code spans (B63/B72/B88/B96), 13 un-numbered entries, orphan text at 128–151, a 43 KB
   footer line — and over BACKLOG's struck siblings and `<details>` bodies.
3. **A file is moved from `plugin/tools/lib`** (`git mv`) — nothing there moves files today.
4. **ID allocation reads 61 refs.**

**Therefore S1 + S2 are wave 1**, and S2 runs **read-only against the live files**: dry-run migrate,
generate into a temp dir, parse the generated files with the shipped readers, compare to the source.
If the segmenter or a reader breaks, it breaks against a dry run, not against 248 records.

## Architecture (contract first)

```
.planning/work/
  WORK.md                    frontmatter: key, schema_version       ← opt-in switch (FR-1)
  WATCHLIST.md               standing trigger table (not an item)    (D-M6E11-18)
  inbox/     SIG-n.md        status N
  backlog/   SIG-n.md        status T
  epics/<EpicID>/SIG-n.md    status Q | P   + the Epic's artifacts   (D-M6E11-23)
  done/YYYY-MM/SIG-n.md      status C
.planning/archive/epics/<EpicID>/   closed Epics (FR-8.4)
.planning/archive/pre-work-store/   verbatim originals of the four files (AC-9.3)
```

**New modules** (`plugin/tools/lib/`): `work-item.js` (schema, parse, validate, render label),
`work-store.js` (opt-in, paths, ID allocation, list, move, close — the only writer of item files),
`work-generate.js` (the four generated files + Epic index), `work-migrate.js` (segmenters + mapping +
dry-run/apply). **New command:** `plugin/commands/item.md` (`/sig:item`).

**Contracts** (all return data; none prints):
- `isStoreOn(baseDir) → {on, key}` — throws `WorkStoreError` code `CONFIG` (FR-1; corrected at EXECUTE: one error class, as the Errors paragraph says)
- `parseItem(text) → {item, errors[]}`; `validateItem(item) → errors[]`; `renderLabel(item)` (FR-2)
- `nextId(baseDir) → {id, basis: 'git-log'|'ls-tree'|'worktree-only'}` (FR-4)
- `newItem`, `moveItem(id, to)`, `closeItem(id, {reason, by, proof, dupOf})`, `getItem(id)`,
  `listItems(filter)` — every mutation: validate → `git mv`/`fs.rename` → atomic frontmatter write →
  link rewrite → regenerate (FR-5, D-M6E11-22)
- `checkStore(baseDir) → findings[]` (status≠folder, duplicate ID, schema errors) (FR-3)
- `generateAll(baseDir)` / `GENERATED_MARKER` (FR-7, D-M6E11-25)
- `planMigration(baseDir) → {items[], orphans[], counts, notes[]}`; `applyMigration(baseDir)` (FR-9)

Errors: one `WorkStoreError` class with a `code` (`CONFIG`, `SCHEMA`, `NOT_FOUND`, `CONFLICT`,
`GENERATED`, `OPEN_ITEMS`), each message naming the file and the fix.

#### S4 — Writers switch to the store · L (split into five tasks) · depends on S3
Store mutations take a **`work` lock** (`.planning/work/.lock`, `acquireLock`), distinct from
`withStateLock`, so they are callable from inside it (`checkpoint.js:354` and `drain.js:632/814/907`
already hold `withStateLock`, which is not reentrant). Regeneration runs under the same `work` lock.
- **t4.1 Generated-file write guard** (`D-M6E11-25`). `atomicWrite(path, content, {generated: true})`
  is the only way to write a marked file. The guard reads **at most the first 200 bytes** and throws
  `GENERATED` only when the **first line equals `GENERATED_MARKER` exactly** (Signal's own docs quote
  the marker text, so a substring check would misfire). A store-off project can never carry the
  marker, so its behaviour is unchanged — proved in S6. AC-6.3. *Files:* `atomic-write.js`,
  `work-generate.js`, `tests/atomic-write-guard.test.js`. Test: marked file refused; unmarked
  written; marker quoted mid-file ignored; `{generated:true}` passes.
- **t4.2 `/sig:add` + checkpoint** — all `/sig:add` routes → `newItem` in `inbox/`; scrub + verbatim
  unchanged; `checkpoint.appendOpenQuestions` → `newItem(type Q)` from inside `withStateLock`.
  AC-6.1, AC-6.2 (part). *Files:* `add.js`, `checkpoint.js`, tests.
- **t4.3 `backlog.js`** — `promoteToBacklog`/`promoteToBugs` → item moves; `dischargeBacklogRows` →
  `closeItem`. AC-6.2 (part). *Files:* `backlog.js`, test.
- **t4.4 drain + `plan.md` + `ship.md` (single owner of `ship.md` in S4)** — `drain` write functions
  refuse on a generated inbox; `plan.md` §1b branches to `/sig:item triage` when on (covers the
  `promoteDrainEntry` route, `plan.md:116`); `ship.md` **eviction step (`:173-174`,
  `evictTerminalToLedger`) and discharge step (`:183`)** both branch to the store when on. AC-6.2
  (part). ⚠ **Do not edit `ship.md`'s `` `await transitionPhase(baseDir, 'SHIP')` `` line** (canary).
  *Files:* `drain.js`, `commands/plan.md`, `commands/ship.md`, tests.
- **t4.5 `archive-tree` + `migrate-memory`** — link rewrite skips generated files;
  `createBacklogIfMissing` no-ops when on; the **snapshot rollback of `BACKLOG.md`
  (`migrate-memory.js:2458`)** writes with `{generated:true}` or skips when on, so a rollback cannot
  throw half-way. AC-6.2 (part). *Files:* `archive-tree.js`, `migrate-memory.js`, tests.

## Risks and mitigations

| Risk | Impact | Mitigation |
|---|---|---|
| A segmenter loses bytes of a real row | High — silent data loss | S2 runs read-only in wave 1; lossless reassembly test; originals archived verbatim |
| A reader silently sees fewer rows in a generated file | High — the `B116`/`B121` false-clean shape | t2.4 compares ID *sets*, not counts; `B{n}` kept (`D-M6E11-20`) |
| Store code changes behaviour for projects without it | High — every user tracks `main` | S6 byte-identical fixture; every module branches on `isStoreOn` only |
| Moving the Epic's own artifacts wedges a phase command | Med | resolver first (t5.1); the move is t7.5, last |
| Fix-lane edits to `BUGS.md` on `main` lost at apply | Med | apply after rebase (t7.2); numbering from the highest B-id at apply |
| Store lock deadlocks inside `withStateLock` | Med | separate `work` lock (S4 preamble) |
| Adherence anchor orphaned by squash | Med | `--merge` only (ruleset enforces) |
| ID collision across worktrees | Low | duplicate-ID test (t1.4) |
