## What changed mid-flight

**Three deviations from the plan, each recorded rather than absorbed.**

1. **`buildCaveats` moved to a new module instead of being edited in place.** S1.t4 said migrate
   `adherence-run.js:666-668`. But the function lived in a CLI script that exports nothing, and
   `adherence-suite-guard.test.js` forbids any test importing that script — deliberately, because
   importing the runner is how a suite spawns the paid CLI. The plan's own RED-first requirement was
   therefore unsatisfiable in place. Extracted to `tools/lib/adherence-caveats.js`. **The guard was
   not weakened**, which was the only other option and the wrong one.

2. **`D-M5E15-5` did not land as written.** Registering the leak check with `findCliGuards` would have
   *appeared* to work while checking nothing — `adherence-run.js` contributes zero of its twelve flags
   to that population. Filed as `B81`; a bespoke named assertion (`B54`'s shape) used instead.

3. **AC1.5 needed a criterion the requirements did not supply.** "A section anchor that is not its own
   discrete section" was specified by example. Implemented as *the deleted span must not order any
   other backticked call*, verified against the live corpus before being written into a test.

**Scope did not grow.** The 50-entry inbox drain, `B48`, and `B81` were all refused explicitly.

## What assumptions broke

**The load-bearing assumption of the whole Epic held, and two smaller ones did not.**

- **HELD — that the instruction is multi-homed and that deleting all five sites would isolate it.**
  The walk returned **zero directive hits** against the mutated tree, and the verdict flipped from
  `INDETERMINATE` (3/3 vs 1/3) to `OBEYED` (3/3 vs 0/3). This was the Epic's central bet.

- **BROKE — that a tested function means a tested behaviour.** Twice, in the same shape. `buildCaveats`
  had unit tests and a caller that passed it the wrong variable; the caveat rendered empty on a
  published record and every test stayed green. Then at VERIFY, two ACs had no test at all while
  `grep AC3.1` returned hits — from a **different Epic's file**. Coverage was being read from the
  presence of a marker rather than from what the marker asserted.

- **BROKE — that the registry validated what the code depends on.** REVIEW found
  `assertRegistryShape` checking `isolation` and every `deletions[]` entry while never checking
  `trace.functionName`, the token the entire leak walk greps for. Absent, it searches for the literal
  string `"undefined"`.

## What surprised us

**1. The Epic reproduced its own defect class, in code written to fix that class.** S7's published
record shipped without its descriptive-residue list because the runner read the field off the arm
*summary* instead of the arm *result* — `c` versus `control`, one character apart in the same scope.
The Epic exists to stop a record understating its scope, and its own record understated its scope.

**2. And it had happened before, in the same file.** The orphaned docstring the independent review
flagged carried M5.E8-era text: *"the OBEYED record shipped without them and needed an appended
correction."* Same defect, same place, different mechanism, three months apart. Nobody noticed the
echo until an outside reviewer pointed at the sentence for an unrelated reason.

**3. `B83` — the scope-limit assertion was vacuous, and the file knew better forty lines up.**
`guard-callers.test.js` read the *whole file* and asserted it contained `SCOPE LIMIT`, `B39`, `B46`
— every one of which also appears in the `expect()` line asserting it. Deleting the entire header
left it green. The same file explicitly skips itself in `hasCaller` because *"a checker that
satisfies itself is the failure it looks for."* The trap was seen for the mechanism and missed for
the label. Shipped M5.E13; unguarded for three releases.

**4. The verification harness produced a false reading.** The first mutation script restored files
with `git checkout --` and deleted the uncommitted test it was verifying, then reported "does not
discriminate" — because the test no longer existed, so the filter matched nothing and vitest exited
0. Caught only because the test count didn't add up (2227, not 2228). A green exit meaning *nothing
ran* is the exact thing this Epic is about, one level up.

## What we'd do differently

- **Test the wiring, not just the function.** Both S7's residue defect and wave 1's `buildCaveats`
  near-miss were untested *call sites* behind tested functions. Where the suite guard forbids
  importing the caller, a source-reading assertion is weak but real — and it is what caught the
  regression once written.
- **Never verify with a restore path that can delete the artifact under test.** Back up the file;
  don't `git checkout --` something uncommitted.
- **Treat an AC marker as a claim to check, not evidence.** `grep AC3.1` returning hits from another
  Epic's file is exactly the `CLAIM-INTEGRITY-ANALYSIS.md` shape — a completeness claim read off the
  shape of the corpus rather than the artifact.
- **Write wave-2 tests first.** Wave 1 was honestly RED-first; wave 2 was not, and mutation testing
  is a weaker substitute that had to be declared as a deviation rather than counted as compliance.

## What to feed back into Signal

- **`buildCaveats` and `checkLeak` are the general lesson, and it is now written into
  `adherence-caveats.js`:** *a caveat whose absence is indistinguishable from a clean result must
  either render unconditionally or be pinned by a test that fails when it stops rendering.* The
  isolation scope now renders `undeclared` out loud rather than omitting the line. This generalises
  well beyond the harness — it is `B39`'s shape stated as a design rule.
- **`review.md`'s PASS-WITH-FIXES rule worked, first time out.** Fixed one day earlier as `B78`, it
  gave an unambiguous verdict on a 13-LOC in-phase fix with new coverage. The cap excluding test
  lines mattered: the fix carried 3 new tests and would have been penalised under the old wording.
- **A self-review cannot be the last word, and Signal should say so.** REVIEW's own report had to
  hand-write its self-review limitation. The independent pass then found the one thing the
  self-review missed. Worth considering whether FULL tier should *require* an independent pass at
  REVIEW rather than leaving it to the maintainer to remember.
- **`B83` argues for a lint on self-reading assertions.** Any test that reads its own source and
  asserts on a literal is vacuous by construction. That is mechanically detectable.

## Anti-rationalization moment

**The one that mattered: refusing to weaken `adherence-suite-guard.test.js`.**

S1.t4 required a RED-first test on `buildCaveats`. The obvious move — export it and import it in a
test — turned the suite-isolation guard red. That guard exists so `npm test` can never spawn the paid
`claude` CLI. The available rationalization was right there and sounded reasonable: *the entrypoint is
guarded anyway, the import is harmless, it's one line in the exclusion list.* Taking it would have
traded a standing money-and-determinism guarantee for a convenience in one test. The function was
extracted to `lib/` instead — more work, and it turned out to be the change that made the whole
finding possible.

**A second one, at S7.** The record shipped missing its residue list. Re-running would have produced
a clean single record — and it was authorized, so nothing stopped it. The temptation was to spend the
eight agent calls and have a tidy artifact with no correction hanging off it. Rejected: the
measurement was sound, the omission was disclosure-only, and the residue list is *deterministically
derivable offline* — which is how it was recomputed. Buying a cleaner-looking record with real money
would have been theatre, and the append-only rule exists precisely so corrections are visible rather
than tidied away.

**Recorded because it was close:** the "71 of those are deletions" argument from M5.E18's REVIEW was
available at REVIEW here too, in the form of *"the residue omission is only a caveat, not a verdict
error."* It is true, and it is also exactly how a disclosure defect gets waved through. It went in the
report as a named defect with its own annotation.
