## What is genuinely NOT already built

Stated so the disposition is a choice between real options rather than a cut.

1. **A trigger.** `auditor`'s judgement is intact; *its trigger is what lapsed* — it is invoked by a
   person remembering. `B39` is this repo's standing finding that **Signal's triggers have never
   once been walked.** Nothing schedules a corpus sweep.
2. **Signal-specific corpus semantics.** `/prose:backlog` does not know what a *trigger*, a
   *disposition stamp*, an *Epic ID*, or a *closed milestone* is. `F1` and `F4` required exactly
   that knowledge; a generic reviewer would not have found either.
3. **Landing the result.** The review *"changes nothing on its own"* (`D-M5E18-1`), so every pass
   needs a person to transcribe recommendations into `BACKLOG.md`. That is the repeatability gap the
   Epic was actually named for.

**⚠ Automatic selection stays OUT, on measured evidence.** `LOOP-GOAL-DIRECTION.md` measured the
best honest selection rule over these real rows at **77% precision / ~37% recall** and recommended
not building it. Nothing here changes that; the advisor proposes and cites, and a person picks.

---

## The decision this Epic cannot make for itself

Three dispositions, and the differences are real:

- **A — Cut it.** The capability exists between `/prose:backlog` and `auditor`. Record the check,
  strike the row, and stop paying for a build. *Cost:* the trigger gap and the Signal-corpus
  semantics stay unsolved, and the next pass is still hand-run.
- **B — Reshape it small.** Build only what is missing: a trigger, the Signal-corpus vocabulary, and
  a path from recommendation to `BACKLOG.md`. Delegate gaps/sharpening/clustering to the tools that
  already do it. *Cost:* Signal takes a dependency on a separate plugin, which `D-BR0814-1` says is
  deliberately not guaranteed to be installed.
- **C — Build it as specified.** A Signal-native advisor that owes nothing to prose. *Cost:* it is
  the fourth instance of the row named above, and the honest justification is no longer *capability*
  — it is **not wanting the dependency**.

**Recommendation: B**, and the reason is `D-BR0814-1` cutting both ways. The rule sends *whole-corpus,
on-demand* work to prose — but it also says prose *"must run in any repo, including one with no
`.planning/` and no Signal install,"* which is precisely why prose cannot own triggers, Epic IDs, or
writing to `BACKLOG.md`. The split falls on the same line the rule already draws.
