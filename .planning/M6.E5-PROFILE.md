# M6.E5 — Epic Profile

**FEATURE, not the project's FULL.** Chosen 2026-08-26 at the DISCUSS preamble, as a direct
either/or with the cost of each side named. Second use of the per-unit dial after `M6.E4`
(`D-BR0823-2`), and the reasoning is the same: new work on an existing system, applying a known
pattern (a dry-run reporter, the shape `/sig:doctor` and `/sig:archive` already ship), revertible
with the commit, and none of FULL's stated triggers in `references/tier-definitions.md` — no auth,
no payments, no data integrity, no public API, no one-way architectural decision.

**The argument for FULL was heard and rejected on a stated ground.** The deliverable is a
*permission* artifact, and `security_audit: full` plus `review_depth: full` are the two overrides
that would look hardest at a generated `allow` rule. What settles it the other way is that
**Signal never installs anything**: the command emits markdown, and a human performs the install
into a file Signal cannot write. The blast radius of a bad proposed rule is bounded by that human
step. `D-BR0826-1` fixed that constraint before this Epic opened; it is not a mitigation invented
here to justify the tier.

⚠ **What this tier costs, stated so nobody has to reconstruct it.** `security_audit: basic`
(OWASP Top 10 checklist rather than the 15-phase audit) and `review_depth: quality-only` mean the
proposed rules get a code-review pass, not a security specialist's pass. If the generated `deny`
list grows past a handful of obvious entries, or if the command ever gains a write path,
`/sig:escalate` **upward** is the correct response and this note is the trigger for it.

**Consequence for DISCUSS.** FEATURE keeps `gate_strictness: light`, so confirmation is once per
phase rather than per decision. The FULL-only NFR prompt (health probes, graceful shutdown,
structured request logging, security headers, rate limiting) does **not** run — for a command that
emits a markdown proposal it would produce a five-line `N/A` block, which is the present-but-vacuous
failure `M5.E10` shipped a check against. The FEATURE NFR prompt (error handling at boundaries,
failure logging, input validation) **does** run, and so do the blast-radius and outcome-oracle
prompts, which are asked at FULL **and** FEATURE.
