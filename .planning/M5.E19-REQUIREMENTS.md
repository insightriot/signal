# M5.E19 — Requirements: the closure-gated archive command

**Tier:** FEATURE (Epic-scoped — see [`M5.E19-PROFILE.md`](M5.E19-PROFILE.md); project default is
FULL). `nyquist_enforcement: strict`, so **every acceptance criterion below maps to a test**.

**One sentence:** M5.E18 built a library that can decide what is closed and where it should go, and
wired none of it to a command — this Epic is that wiring, plus the defect (`B82`) that would
otherwise ship a half-archived unit.

---

## Why now — the trigger, and the bar

**Trigger FIRED 2026-08-04.** `curator` was removed from the machine. `eval-project-A` and
`eval-project-D` archive by hand-written runbook **today**. This is the only item on the backlog
with users waiting.

**The bar is set by how the thing it replaces failed.** `curator` matched filenames and never
checked whether the work was finished; its only protection was a hand-maintained list you had to
update *before* writing a file. It proposed archiving the same four **live** units twice. The
2026-08-01 remedy was a printed warning, and it failed the way warnings fail.

> **A warning asks; a gate refuses.** Every requirement below is downstream of that sentence.

## Functional requirements

### FR1 — A new `/sig:archive` command (not a flag on `/sig:migrate-memory`)

`/sig:migrate-memory` is a layout *reorganizer* keyed to `docs_layout_version`. Archiving closed
work is a different question on a different cadence (every Epic close, not every layout bump).
Folding them together makes one command with two unrelated triggers.

- **AC1.1** — `commands/archive.md` exists and is registered in the command roster.
- **AC1.2** — The command is **not** phase-gated (same class as `/sig:sweep`, `/sig:index`): it
  runs at any phase, in Epic mode or linear mode.
- **AC1.3** — Running it on a project with no `.planning/` exits cleanly with a named reason, not
  a stack trace.

### FR2 — Closure is a gate, not a report

Only units `resolveClosures` reports as **closed** are eligible to move.

- **AC2.1** — A unit with status `open` is **never** included in the move plan.
- **AC2.2** — A unit with status `cannotDetermine` is **never** included in the move plan.
- **AC2.3** — The run **completes** when units are refused; it does not abort. *Rationale, from
  the corpus:* 9 of 30 terminal artifacts (30%) carry no readable verdict, and `eval-project-B`
  throws on `readState`, which makes **every** unit `cannotDetermine`. An abort would let one
  unreadable project block archiving everywhere.
- **AC2.4** — Every refusal is reported with the `reason` string `resolveClosures` already
  produces. A refusal with no reason is a warning wearing a gate's clothes.
- **AC2.5** — A **stub** retrospective (still holding `[FILL IN]`) does not read as closed. This
  is `B64`, which was fixed at five decision sites in M5.E18; the command must not become a sixth
  site that re-opens it.

### FR3 — ~~One source of truth for unit membership (`B82`)~~ · **SHIPPED SEPARATELY, out of scope**

**`B82` was fixed in the fix lane on 2026-08-07 and merged to `main` (#98) — it is not this Epic's
work.** Split out on the reasoning that a live data-integrity defect hurting two real projects
should not wait on a six-phase Epic for a feature nobody is blocked by.

**What shipped, and how it differs from `D-M5E19-4`.** The decision said *the closure record carries
its files*. The fix took a **different shape**: `planArchiveMoves` calls `deriveUnits` directly, and
the suffix rule was exported as `suffixOf` from `work-units.js` so the mover could preserve
lifecycle ordering without re-deriving it. Same principle — one implementation of unit membership —
reached at a different seam, because `resolveClosures` was not the caller that needed changing.

Measured before → after, across all 12 local projects: **3 split units / 6 stranded files → 0 / 0.**
Full detail in `CHANGELOG.md` `[Unreleased]` and the `B82` row.

### FR4 — Dry-run by default

Same posture as `/sig:migrate-memory`, and the correct default for a tool replacing one that moved
things it shouldn't have.

- **AC4.1** — With no write flag, **zero** files are moved and **zero** bytes written under
  `.planning/`. Asserted by comparing a full mtime+content snapshot before and after.
- **AC4.2** — The dry-run output names every file that *would* move, with its destination.
- **AC4.3** — Writes require an explicit flag; the moves are `git mv`-equivalent and reversible.

### FR5 — The ungrouped set is reported, never silently dropped

Required by `D-M5E18-2`. Signal's own tree carries **57 ungrouped files against 13 units**.

- **AC5.1** — The report states the ungrouped count unconditionally, including when it is **0** —
  an empty collection must stay distinguishable from one that was never computed (`B39`).
- **AC5.2** — A run that archives N units and says nothing about the ungrouped files fails this
  requirement even if every move is correct.

### FR6 — "Checked and clean" is distinguishable from "could not check"

The M5.E16 lesson, applied here.

- **AC6.1** — The report distinguishes *no closed units found* from *closure could not be
  evaluated*, in its own words, not by printing nothing.
- **AC6.2** — When `stateReadable` is false, the report says so once at the top rather than
  repeating an identical per-unit reason 13 times.

## Non-functional requirements

### NFR1 — Path confinement (`security_audit: basic`)

- **AC-N1.1** — A unit name failing `isSafeUnitName` is **dropped, not thrown on** (NFR4 of
  M5.E18: one hostile name must not deny the whole plan), and appears in the `dropped` list with
  its reason.
- **AC-N1.2** — No planned destination resolves outside `.planning/archive/`. Asserted against
  `..`, absolute paths, and separator-bearing names.

### NFR2 — Idempotency

- **AC-N2.1** — Running the command twice with writes enabled produces no moves on the second run.
- **AC-N2.2** — Files already under `archive/` are excluded from move-planning input.

### NFR3 — Boundary hygiene (the FEATURE-tier NFR prompt, answered explicitly)

| Prompt | Disposition |
|---|---|
| Error handling at boundaries | **In scope** — `readdir`, `readState`, and per-file `rename` each fail to a named reason; a single file's failure does not abandon the run mid-plan. |
| Log lines for failures | **In scope** — every refusal, drop, and write error is reported. Covered by AC2.4 / AC-N1.1. |
| Basic input validation | **In scope** — `isSafeUnitName` on every unit before a path is built (AC-N1.1). |

### NFR4 — Deterministic and offline

- **AC-N4.1** — No network. Same output for the same tree, independent of file-read order.

## Explicitly out of scope

- **Link rewriting** via `senseArchiveTree` — deferred to PLAN to decide whether it lands here or
  in a follow-up. Archived files' inbound references are a real problem, but the move is the
  wiring this Epic promised.
- **`--heal` / auto-repair.** `/sig:sweep` detects and never heals (`D-M5E16-1`); nothing here
  changes that boundary.
- **The full tracker integration** (`M5.E14`). Its trigger is unmet and it is Epic-shaped.

## Assumptions to validate during EXECUTE

1. **`resolveClosures`' record can carry `files` without breaking its two existing callers.**
   `grep` shows `closure.js` consumed at `state-drift.js:496` and in M5.E18's tests; an additive
   field should be safe, but "should be" is the assumption.
2. **`git mv` is the right move primitive** rather than `fs.rename` — it keeps history and makes
   the operation revertible, which is the stated safety property. Unverified against a project
   whose `.planning/` is untracked (memory: `.planning/` is always tracked, but that is Signal's
   norm, not a guarantee for every project the command will run in).

## Open question carried into PLAN

`deriveUnits`' conservative fold is what makes `PLAN-SLICE-SSO-RESEARCH.md` belong to `SLICE-SSO`.
The fold is single-hop by construction. Whether the **archive destination** for a folded-in file
should be the target unit's directory (current behaviour once FR3 lands) or its own is a real
question the corpus can answer — check it before assuming.
