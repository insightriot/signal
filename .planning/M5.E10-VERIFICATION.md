**1. That the checks find anything on projects that are not this one.** `NFR5` measures
*applicability*, not correctness, and the numbers are not flattering: FR1 evaluates **2 of 12**
corpus projects, FR9 evaluates **1 of 12** — and the one is this repository. **FR9 cannot evaluate
`eval-project-A`, the project `B94` was filed from.** A green run here is evidence about a
minority-shape corpus. Nothing in this phase establishes behaviour on the ten-to-eleven projects each
check declines to look at; it establishes that they are *declined* rather than silently passed.

**2. That a filled template means a true report.** Stated in the template itself and repeated here
because this file is subject to it: every heading can be present, every body substantive, every
requirement id named — and the report still wrong about what its evidence establishes. The
**semantic backstop does not exist** (`AC0.1`, deferred by `D-M5E10-1`). A row above reading
*"verified by `tests/x.test.js` (18)"* was checked for the file's existence and its passing count;
**no mechanism confirms that those 18 tests assert what the criterion says.** For most rows my
evidence is that the test file exists, passes, and is named for the criterion — which is weaker than
having read all 176 new assertions, and I did not.

**3. Strict Nyquist, for the majority of criteria.** See the (b) list above: 24 criteria rest on
attestation rather than an isolated red commit. That is permitted by `tier-definitions.md`, and it is
weaker evidence than form (a). It is written here rather than left to be inferred.

**4. `AC1.5`'s literal wording — the amended pair does not pass, and the AC was scoped rather than
met.** `AC1.5` reads *"the amended pair passes."* On the real field data it does not: the amendment
fixed `NFR-9.2` and left eight `AC-16.*` requirements unmentioned, which looks like a genuine open
gap in the source project. The honest contrast shipped is scoped to the defect the amendment
addressed, and a test pins the `AC-16` gap in **both** copies so the claim cannot quietly go false.
**Recorded as a scoped AC, not a met one.**

**5. `B95` — the retro-index freshness signal is currently uninformative, and this run did not fix
it.** `RETROSPECTIVES.md` sorts by `stat().mtime`, which git does not store, so a clone or checkout
reorders it and FR7 reports `structural` drift with every row present and unchanged. Found by running
this Epic's own check against this repository. **Filed as `B95` (P2), deliberately not fixed here** —
it is an `M4.5.E9` defect and the fix is a design call (sort by Epic id, or by a date parsed from the
retro's own `**Closed:**` line). The consequence for *this* report: the `/sig:sweep` structural
finding above is not a real hygiene failure, and `ship.md` §6's regen will rewrite the file to an
arbitrary order at ship.

because `/sig:verify` was actually invoked — `B87` (a phase that ran and never entered the ledger)
