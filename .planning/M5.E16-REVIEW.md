## Critical

### C1 — Check `(c)` reports "checked, clean" on a project it structurally cannot see

**`tools/lib/state-drift.js:433`** — `checkEpicWithoutRetro`

```js
applicability: () => APPLICABILITY.EVAL,      // unconditional
```

…while its detection is keyed to a **strict** Epic-ID filename:

```js
const EPIC_ID_IN_FILENAME = /^(M\d+(?:\.\d+)?\.E\d+)-(PLAN|PROGRESS|VERIFICATION|REVIEW)\.md$/;
```

**Measured on a real project.** `traction-engine` names its artifacts `PHASE10-PLAN.md`,
`PHASE10-REVIEW.md`, `PHASE11-VERIFICATION.md` — a non-strict prefix convention. It has:

- **19** phase artifacts matching `PHASE{n}-(PLAN|PROGRESS|VERIFICATION|REVIEW).md`
- **0** retrospectives, of any name

The regex matches none of them, `run` returns `[]`, and the harness reports **`clean`**.

**This is the exact failure the Epic exists to prevent, inside one of the Epic's own checks.** The
module's own header states the contract in words:

> `clean` and `cannot-evaluate` collapsing into one another is the bug this module is built to make
> impossible.

Check `(c)` collapses them. A `traction-engine` user running `/sig:sweep` is told this check is
**clean** when it could not see a single one of their artifacts. That is `B39`'s shape and `B54`'s —
and it is the *fourth* recurrence of the class this Epic was written to end.

**Root cause is the same one check `(h)` reports: non-strict Epic IDs.** `(a)` and `(b)` handle this
correctly — they return `BLIND` with a reason that points at `(h)`. `(c)` was written before that
pattern existed and never revisited, so **three of four Epic-shaped checks got it right and one did
not**, which is why reading them together is what surfaced it.

**Severity: Critical, not Important.** It produces a *confident wrong answer* in shipped code, on the
one project shape the Epic's own research identified as most divergent. Precedent: M5.E9's REVIEW
Critical was a sweep check telling every healthy project its history had been destroyed — **removed
rather than re-tuned**, because a false reassurance is worse than no check.

**Why it does NOT qualify for PASS-WITH-FIXES.** The four conditions are conjunctive, and the fix
fails two of the disqualifiers named in `commands/review.md:125`:

| Condition | Met? |
|---|---|
| Discovered and closed inside REVIEW | would be |
| ≤ 50 LOC | yes, ~15 |
| Tests still green | yes |
| No design impact | **no — it changes `(c)`'s applicability model** |
| *(disqualifier)* requires new tests | **yes — a non-strict-prefix fixture, red-first** |
| *(disqualifier)* requires re-validation | **yes — FR2.1 requires re-measuring the 13-project corpus** |

`D-M5E17-1` records the counter-argument explicitly: *"'the diff was small' is exactly how a Critical

Taking the small-diff exit here would be the first use of that loophole, in the Epic about guards

**Proposed fix, for EXECUTE:**

   telling them their process is wrong. **This is a structural narrowing (a categorical property of
   the project), not a threshold** — FR2.2 forbids the latter.
3. Re-measure the full 13-project corpus and record the new precision numbers.

## Suggestions

### S1 — Dead code in `changelogBetween`'s title extraction

**`tools/lib/update.js`** — the first operand is always the empty string:

```js
title: s.heading.replace(CHANGELOG_HEADING, '').trim() ||   // <- always ''
  s.heading.replace(/^##\s*\[[^\]]+\]\s*[—-]?\s*/, '').trim(),
```

`CHANGELOG_HEADING` is `/^##\s*\[([^\]]+)\][^\n]*$/` — fully anchored, so it matches the entire
heading line and replacing it with `''` yields `''`. The `||` fallback therefore runs **every
time**, and the first branch is unreachable.

Measured, not inferred:

```
first operand  => ""
fallback       => "2026-08-02 — STATE-vs-world drift detection (M5.E16)"
```

Harmless today — the fallback is the correct expression — but it reads as a deliberate two-strategy
lookup when only one strategy exists. Delete the first operand. **Not a correctness bug; grouped as a
Suggestion rather than inflated.**

### S2 — `renderUpdateReport` normalises blank lines in changelog bodies

The closing `.replace(/\n{3,}/g, '\n\n')` collapses runs of blank lines anywhere in the output,
including inside a quoted CHANGELOG body. The rendered delta is therefore not byte-faithful to the
source. Cosmetic, and arguably desirable, but it is an undocumented transformation of someone else's
text. Worth a comment saying so, or scoping the collapse to the frame rather than the content.
