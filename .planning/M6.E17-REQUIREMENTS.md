# M6.E17 — Requirements: the REVIEW fix loop becomes a mechanism

**Label:** *"Make the REVIEW fix loop a mechanism, not a habit"*. Priority 1 of
[`BACKLOG-REVIEW-2026-10-14.md`](BACKLOG-REVIEW-2026-10-14.md), picked by Brett. Covers `SIG-303`,
`SIG-139`, and three pieces of unfiled work named by the M6.E14 and M6.E16 retrospectives. Tier:
project FULL (no per-Epic profile), `attention: checkpointed`. Decisions `D-M6E17-1` … `D-M6E17-6` in
[`DECISIONS.md`](DECISIONS.md).

## Why now

Measured from the last four Epics' records:

- M6.E16's REVIEW ran four full passes and a narrow one. `loopStatusFor(state, 'REVIEW')` read **0**
  throughout, because `completed_phases` records a phase when it is left and REVIEW was never left
  ([`M6.E16-RETROSPECTIVE.md`](M6.E16-RETROSPECTIVE.md) § What to feed back). The ceiling held only
  because the report said so in prose; `/sig:drive` reads the same count and would have looped.
- *"Fixes to fixes get their own fresh reader"* found the worst defect in M6.E14 and paid off four
  Epics running, and is still not a step ([`M6.E14-RETROSPECTIVE.md`](M6.E14-RETROSPECTIVE.md) § What
  to feed back). `review.md`'s PASS-WITH-FIXES caps a fix at 50 lines and says nothing about who reads it.
- M6.E16 pass 2 shipped four hollow tests that a "fails with the guard removed" check would have caught
  a day earlier. M6.E14's AC7.2 proved nothing on its own, found only by running it on the parent.
- Three timing tests fail under load (`SIG-303`) and heavy git tests time out under local parallelism
  (`SIG-139`). Each false failure costs a re-run and teaches people to ignore failures.

## Functional requirements

Every FR starts with a test that fails on `main` before the change (FULL, strict TDD).

### FR1 — A pass is recorded when it ends (`D-M6E17-1`, `-5`, `-6`)
- AC1.1 One function records a VERIFY or REVIEW pass with its verdict (PASS / PASS-WITH-FIXES / FAIL)
  and date in `STATE.md`. It refuses any other phase.
- AC1.2 `loopStatusFor` counts the larger of the recorded passes and the phase exits for that phase.
  A STATE with four recorded REVIEW passes and no REVIEW exit reads count 4, at the ceiling.
- AC1.3 The records are per Epic: an Epic roll (`setCurrentEpic`) clears them, as it clears
  `completed_phases`.
- AC1.4 A pass record that does not parse makes `loopStatusFor` return `null`, so `/sig:drive` halts
  with `loop-unknown`. It is never read as zero.
- AC1.5 A STATE with no pass records reads exactly as it does today (projects that have not run a
  recorded pass are unchanged).
- AC1.6 `review.md` and `verify.md` call the recording function at the end of every pass, before the
  loop-back ask; `references/state-schema.md` documents the field.
- AC1.7 `/sig:drive` halts at the third REVIEW pass of a unit whose passes never left REVIEW — shown
  by a test that replays M6.E16's shape.

### FR2 — A fresh read of every fix round, with a stop (`D-M6E17-2`)
- AC2.1 `review.md` has a numbered step: after any FAIL loop or in-phase fix, one fresh-context
  reviewer reads only that round's diff (the commits since the pass that found the issues), given the
  diff and the requirements and nothing else, under the existing omission rules.
- AC2.2 The stop is stated: the chain ends when a fresh read of a round finds 0 Critical and 0
  Important, or when the loop ceiling is reached, whichever comes first.
- AC2.3 The REVIEW report records each fresh read: the diff range read, the findings count by severity,
  and whether the stop was reached. A PASS or PASS-WITH-FIXES verdict after a fix round without that
  line is refused by the report check. *(Amended at PLAN: no check reads a REVIEW report's rounds
  today, so it is new — `checkFixRounds`, `plugin/tools/lib/review-rounds.js`.)*

### FR3 — "Fails without the fix" is proven by a tool (`D-M6E17-3`)
- AC3.1 A tool takes a list of test files and a base commit (*amended at PLAN:* stated explicitly, or
  `--of <commit>` for its parent), runs those tests against the base in a temporary git worktree, and reports, per test file, whether it failed there. It removes the
  worktree on every exit path, error paths included.
- AC3.2 It separates "failed on the base" from "could not run on the base". The second is never
  reported as proof. *(Amended at PLAN: under strict TDD the new test is absent on the base by
  definition, so the tool copies the named tests onto the base; "could not run" is a git failure, no
  worktree, no matching result, or a load/import error.)*
- AC3.3 A REVIEW fix round's record and an EXECUTE slice's record carry the tool's result. REVIEW's
  verdict step and EXECUTE's slice close name the result; a missing result is a stated gap, not a pass.
- AC3.4 A standard brief for a fixer or executor sub-agent states that it must run the tool and report
  its output verbatim; `executor.md` and the REVIEW fix-round step point at that brief.

### FR4 — Timing tests stop failing for reasons other than slowness (`D-M6E17-4`)
- AC4.1 The wall-clock tests named in `SIG-303` run in a separate, serial perf run
  (`npm run test:perf`), not in `npm test`. Their budgets are unchanged. *(Amended at PLAN: two
  tests, not three — `tests/planning-index.test.js` asserts no budget; it is covered by AC4.3.)*
- AC4.2 CI runs the perf run as its own step.
- AC4.3 Local `npm test` caps parallel workers so the git-heavy tests named in `SIG-139` do not reach
  the 15 s timeout. Evidence: five consecutive full local runs green, with machine load recorded.
- AC4.4 A test fails if a test outside the perf run asserts a wall-clock budget, so the next timing
  test lands in the right place. *(Amended at PLAN: the ~15 files that already do are on a grandfather
  list with a reason each; the list may shrink, not grow.)*

## Non-functional requirements (FULL prompt, answered)

- Health probe, graceful shutdown, request logging, security headers, rate limiting: **not applicable** —
  Signal is a local CLI plugin with no server or network surface.
- The worktree tool runs project test commands. It runs only the tests named to it, from the project
  root, and adds no network access. It never runs against a production project (house rule).
- Errors at the edges: the recording function and the worktree tool fail with a named reason, never
  silently; an unreadable state stops the driver (AC1.4).

## Blast radius — what this touches that we are not changing

- **`/sig:drive`**: reads `loopStatusFor` through `canProceedUnattended`. It will now halt where it
  used to loop. That is the intended change, and it applies to every project on the next update.
- **`STATE.md` in every project**: gains an optional field. Absent means today's behaviour (AC1.5).
  `schema_version` stays 1 unless PLAN finds the reader rejects unknown keys.
- **`commands/*.md`** edits may move the adherence directive-line ceiling; if `ADHERENCE-LOG.md` is
  regenerated, the PR merges with `--merge` (already the only method on `main`).
- **CI**: one more step; total wall clock grows by the perf run's duration.
- **Not changed**: the ceiling value (3), PASS-WITH-FIXES's 50-line rule, the three REVIEW agents.

## Outcome

**How we will know it worked:** the next Epic whose REVIEW loops reaches pass 3 and stops because
`loopStatusFor` returned `atCeiling: true` from recorded passes, not because the report said so; its
REVIEW report carries a fresh-read line and a parent-run result for every fix round; and the local
suite runs green five times in a row on this machine. Checked at that Epic's REVIEW and in its
retrospective.
