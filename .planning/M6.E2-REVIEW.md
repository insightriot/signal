## Critical Issues

**C1 — `rewriteBugTally` silently no-ops on an unbolded total marker. FIXED in-phase.**
`plugin/tools/lib/add.js`

`readPublishedTally` accepts `(9 total)` as readily as `(**9 total**)`, and the splice regex matched
only the bolded form. On such a file `String.replace` did nothing, the count stayed wrong, and the
capture reported success.

**A silent no-op inside the fix for silently wrong published counts.** This Epic's own defect class,
in this Epic's own code, and it would have passed every test written for S2 because every S2 fixture
used the bolded shape — Signal's own. The same blind spot `B82` was: fixtures drawn from the one
project whose conventions the author already had in mind.

Found by **running** it against a hand-built variant, not by reading it. Fix: the marker's asterisks
are now optional in the pattern. Coverage: two tests, one on `rewriteBugTally` directly and one
end-to-end through `captureToBugs`.

## Suggestions

**S1 — `BUGS.md` is read twice per sweep** (once in `applicability`, once in `run`), against
`buildContext`'s stated intent that checks not each re-read the same files. **Deferred, with the
measurement rather than a shrug:** `BUGS.md` is 270 KB here and one extra read costs **~0.44 ms**.
The available fixes are a module-level cache (introduces cross-run staleness in a module whose whole
subject is stale published state) or widening `ctx` (a `state-drift.js` contract change for 0.44 ms).
Neither trade is worth it; recorded so the next reader does not re-derive the same conclusion.

**S2 — `checkFactsAttribution` hardcodes `plugin/references/facts.md`.** Correct for this repository
and returns `NOT_APPLICABLE` elsewhere, which is honest and matches its published 1-of-12 reach. Left
as-is; generalising a path for a check that evaluates one project would be speculative.

## Security Findings

The applicable surface is small and was audited rather than waved through.

- **Dependencies:** unchanged — `yaml` remains the single runtime dependency. No package added.
- **Network:** `tools/audit-network-calls.js` reports nothing. Every check is local-file-only; no
  fetch, no subprocess.
- **Input validation at the one boundary that exists:** every check reads **untrusted document
  content from disk** — a malformed, truncated, or hostile `BUGS.md` / `CHANGELOG.md` / milestone
  file. This is covered by `NFR2`'s fail-open tests: an unreadable file, a directory where a file is
  expected, and a throwing check each degrade to `CANNOT_EVALUATE` with a reason rather than taking
  down `/sig:sweep` or `/sig:resume` (`B70` is why that matters).
- **Writes:** exactly one path writes — `captureToBugs`, through the pre-existing lock +
  `atomicWrite` substrate, unchanged by this Epic. The five checks are read-only by construction.
- **Regex input:** bug ids are interpolated into a `RegExp` in `checkBugStatusVsChangelog`. They come
  from `walkBugEntries`, which matches `B\d+` — digits only, so no metacharacter reaches the
  constructor. Noted because "it happens to be safe today" is worth writing down.
- **OWASP Top 10:** no web surface, no authn/authz, no serialization of user input, no injection sink.
  The categories do not apply to a local read-only CLI check; saying so explicitly rather than
  rendering an empty checklist.

## Performance Findings

- **No N+1, no unbounded fetch, no pagination surface** — there is no data layer.
- **Full sweep with 13 checks** completes in the same order of magnitude as the 8-check version; the
  five additions are file reads of documents already on disk.
- **The one measured cost is S1's double read at 0.44 ms**, deferred above with its number.
- **`/sig:resume`'s briefing budget** is the real performance concern and it is a *rendering* one:
  `AC5.3` keeps not-applicable checks as a count and the reach caveat to one grouped line, so five
  new checks add at most one line to a healthy project's briefing.

## Simplification Opportunities

- **No dead code.** `describeReach` and `REACH` both have callers; `ALL_DRIFT_CHECKS` has two.
- **No redundant abstraction.** The Epic reuses `defineCheck` rather than writing a second harness,
  and reuses `bugs-tally.js` rather than reimplementing derivation — `B82`'s lesson applied
  deliberately.
- **`readIf` is a small local helper** duplicating a pattern that exists informally in `sweep.js`.
  Left local: hoisting a three-line try/catch into a shared module for two consumers is the kind of
  premature extraction that makes call sites harder to read.
- **Naming:** `ALL_DRIFT_CHECKS` living in `published-facts.js` reads slightly off — it is there
  because the reverse import would be a cycle, and the docblock says so. Considered and kept.
