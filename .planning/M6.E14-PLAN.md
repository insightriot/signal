# M6.E14 — Plan: harden the work store

**Phase goal:** fix the eight known work-store defects so the store refuses, deduplicates and reports
correctly before other projects move onto it (priority 2).

Requirements: [`M6.E14-REQUIREMENTS.md`](M6.E14-REQUIREMENTS.md). Research:
[`M6.E14-RESEARCH.md`](M6.E14-RESEARCH.md). Tests: [`M6.E14-VALIDATION.md`](M6.E14-VALIDATION.md).
Node 22+ assumed; dev machine Node 22.13.0. TDD throughout: each task's first commit is a test that
fails on this branch before the fix.

## What this Epic does for the first time — wave 1

- **A project shape never tried:** a `.planning/` that is a symbolic link to a folder inside the
  repository, with the work store on. No test or project has run a store write through one; today
  it refuses every change (`SIG-279`).
- **A code path never taken:** `promoteToBacklog`/`promoteToBugs` with the store on, called twice at
  once. The only caller refuses with the store on, so the store-on promote has run only in unit tests,
  never concurrently.

**Therefore S1 is wave 1**, and S3's concurrency test is written before S3's fix. If either shape
breaks in a way the research did not predict, it breaks before the narrower fixes are built on it.

### S2 — Record writes land fully or refuse up front (FR4, `SIG-280` (6)) · wave 2 · M
- **t2.1 (RED)** For each refusal cause — hand-kept view, linked `WATCHLIST.md`, bad archived Epic

- **t2.2** `checkViewsWritable(baseDir)` in `work-views.js`: everything `regenerateViews` checks,

- **t2.4** `regenerateAfter`'s message: keeps "was written", adds the rebuild step (AC4.2). There is

  invent a command.
- **Files:** `work-views.js`, `work-records.js`, new `tests/work-records-views-preflight.test.js`;

- **t2.5 (measure)** Generate a 10,000-record v2 store in a temp dir; time `checkViewsWritable` and a

- **Also run:** `tests/work-records-inventory.test.js`, which enforces how writers take the lock

- **Out of scope:** changing what `regenerateViews` refuses; a history-year file that the write itself

  `regenerateViews`, `archive-tree.js:677` and `work-ops.js:140` (plan-checker M3).

### S3 — Promote dedupe inside the lock (FR1, `SIG-277`) · wave 3 · M
- **t3.0** Add a test seam to `promoteInStore`, `_beforeWrite` (awaited just before `newItem`), modelled
  on `acquireLock`'s `_beforeTakeover` (`file-lock.js:101`). Exemplar for S3 and t7.4.
- **t3.1 (RED)** One process, deterministic (plan-checker I1: `acquireLock` never waits, so two truly
  overlapping writers give one record + one `LOCKED`, which passes on `main`). Promote A with a
  `_beforeWrite` that runs promote B of the same block to completion. On `main`: A's unlocked check
  already passed, B writes, then A writes a twin → two records. Assert: exactly one record with that
  `source_ref`, one call `written`, the other `deduped`, neither `LOCKED`, and the seam ran (AC1.3).
- **t3.2** `newItems(..., { dedupeBy: 'source_ref' })`: inside the lock, before `planNew`, a spec whose
  `source_ref` matches an existing record returns that record's entry with `deduped: true` and writes
  nothing for it (AC1.1).
- **t3.3** `promoteInStore` uses it; the unlocked lookup goes (AC1.2). Return shape unchanged
  (`{written: false, deduped: true, ...}`).
- **Files:** `work-records.js`, `backlog.js`, new `tests/backlog-promote-concurrent.test.js`.
- **Out of scope:** enabling the drain with the store on.

### S5 — A proof hash must name one commit (FR6, `SIG-276`) · wave 4 · S
- **t5.1 (RED)** Unit test through `ancestryFailure`'s injected `execFn` (plan-checker I4: a real
  7-hex commit collision needs ~20k commits). The fake answers `rev-parse --disambiguate=<p>` with two
  commit ids and resolves `<p>^{commit}` to the one of them a same-named branch points at — so `main`
  returns null (confirmable). Assert `ambiguous-proof`, nothing confirmed (AC6.1); one commit line →
  unchanged behaviour. A real-repo case only with a precomputed colliding pair (`commit-tree`, fixed
  dates), optional.
- **t5.2** `ancestryFailure`: for a proof under 40 hex, `rev-parse --disambiguate`; more than one
  commit → `ambiguous-proof`. Fix the comment (AC6.2). Best-effort check in `requestClose(s)` when
  inside a git repo.
- **Files:** `work-records.js`, `tests/work-records-proof-refs.test.js`.
- **Out of scope:** full-length (40-hex) proofs, which cannot be ambiguous; changing `COMMIT_RE`.

### S6 — Lock message and stat race (FR7, `SIG-251`, `SIG-252`) · wave 4 · S

- **Files:** `file-lock.js`, `tests/file-lock.test.js`. Run every lock test file.
- **Out of scope:** the PID-namespace limit of the dead-pid shortcut (M6.E11 retro).
