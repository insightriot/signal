| Phase | Outcome |

**The deliverable, both halves:**

- **The ceiling (FR5).** Of **407 directive lines** across 18 `commands/*.md`, **91 (22.4%) are
  trace-measurable; 316 (77.6%) are not.** Published in `ADHERENCE-LOG.md`, computed by a classifier
  whose split rule is written out in full so a reader can disagree with it line by line. **The
  unmeasured remainder is unmeasured, not passing** — pinned by a wording test.
- **The verdict.** `B41-phase-entry`: **3/3 as-written, 0/3 with the instruction deleted, zero
  failed runs → OBEYED.** M5.E9's phase-entry fix works. It shipped in v0.1.12 unverified — M5.E9
  said so in its own test header, and that admission is what opened this Epic.

## What changed mid-flight

1. **The seam.** `CLAUDE_PLUGIN_ROOT` does not redirect command *resolution*; `claude --plugin-dir`
   does. Caught before building on it, on evidence available in the session itself.
2. **The fixture.** It shipped a PROFILE and a STATE and nothing else, so `/sig:execute` halted on
   real preconditions before the instruction applied. Now ships PLAN + VALIDATION + a git repo.
3. **The control arm.** Line-level deletion → section-level deletion. See below; this was the one
   that mattered.
4. **Transcript retention** became unconditional, and **arms became independently runnable**
   (`--arm` / `--combine`) after a 40-minute run was killed mid-flight.
5. **Timeout 300s → 900s** — recorded explicitly as an *instrument* setting, **not** the verdict
   threshold, which has never moved.

## What assumptions broke

**R1's ceiling estimate, and the inference riding on it.** Research computed 22/202 = **10.9%**. The
built classifier measures **22.4%**. More importantly, R1 claimed `execute.md`, `verify.md`,
`review.md` and `calibrate.md` name **zero** library calls — therefore *"the phases doing the most
work are the least measurable."* They name **4 / 3 / 3 / 0**, including `transitionPhase`, this
Epic's own canary. **The inference is false**, and the estimate was left verbatim under a
superseded-by-measurement block rather than rewritten, because the plan was built on it.

**That a fixture is scaffolding.** It is an experimental control. Both invalidated runs failed there.

**That `tools/` copies are self-contained.** The plugin copy needed `.claude-plugin/plugin.json` and
the `yaml` dependency, or it could neither load as a plugin nor execute what a canary measures.

## What surprised us

**Every defect this Epic found was in the measuring instrument, and every one produced a
plausible-looking result rather than an error.**

| Defect | What it produced | Would a reader have doubted it? |
|---|---|---|
| Unreachable fixture | `ABSENT` 0/3, 0/3 | No — reads as "the instruction is ignored" |
| Broken seam | would have been `INERT` | No — reads as "the fix does nothing" |
| Incomplete deletion | near-miss `INERT` (control 1/3 trace=YES) | No |
| Commit captured post-run | a valid-looking paired verdict | No |

**An agent refused a Signal instruction, correctly, and explained why.** Against a fixture with no
plan, it declined the phase-entry write because calling `transitionPhase` on a halted phase writes a
false record into the ledger M5.E9 had just made honest. `execute.md` states the instruction
unconditionally. **That conflict is now `B48`, and it is live in shipped v0.1.12.**

**It came from a transcript, not a verdict.** The run whose headline output was useless produced the
Epic's most valuable finding. That is why retention is now unconditional.

## What we'd do differently

1. **Prove the seam before planning around it.** R3 justified a mechanism from adjacent evidence
   (command files *mention* `${CLAUDE_PLUGIN_ROOT}`) without checking the mechanism itself. A
   two-call probe settled it. **Any plan resting on an unverified external behaviour should carry a
   probe as a first slice.**
2. **Design the fixture as a control, in PLAN.** "Can this fixture reach the instruction?" is a
   validation question and was never asked. It cost two invalidated runs.
3. **Ask what the mutation leaves behind, not just what it removes.** Signal's command files are
   uniformly instruction → rationale → timing rule. Line-level deletion was wrong for *every*
   future canary, not just this one.
4. **Generate scope, never remember it.** The `OBEYED` record shipped without caveats and needed an
   appended correction. `buildCaveats()` now derives them from the run's parameters.

## What to feed back into Signal

**1. A class Signal keeps re-committing: a guard that is written, shipped, and never called.**
Three instances now, and the third was found inside the Epic reviewing the other two:

- **`B39`** — a trigger watchlist written down and never walked.
- **`B46`** — 45 dispositions written where nothing reads them back.
- **`I2` (this Epic)** — `adherence-ceiling.js --check` did the correct staleness comparison, and
  **nothing ever invoked it**, while the test that was supposed to guard the number was a substring
  match that could not fail.

**This is one defect class, not three bugs, and it deserves a mechanism rather than three fixes.**
Candidate: a hygiene check asserting every `--check`-style guard in `tools/` has a caller.
`B48`'s home Epic is the natural place.

**2. Pre-committing to an acceptable outcome creates a blind spot.** The plan named `inert` as the
expected worst case, in writing, so a null result would not be treated as a crisis and tuned away.
That is good discipline and **it is exactly what would have carried a broken control arm into the
published log.** A false `inert` is indistinguishable from a real one by inspection of the number.
**The lesson is not to stop pre-committing — it is that a pre-committed outcome needs a
pre-committed way to tell the real thing from its impostor.** Which is what the impostor table in
`M5.E8-REVIEW.md` now is.

**3. Verdicts should carry their own scope.** `OBEYED` alone reads as *"the instruction is
followed"* — which this Epic's own evidence contradicts via `B48`. Records now generate their scope
boundaries.

**4. The measurement is available to the whole flow now.** `/sig:ship`'s checklist prompts a re-run
when a measured instruction's wording changes. **Presence only** — it cannot prove a maintainer acts
on it, and that limit is labelled where the test lives.

## Anti-rationalization moment

**The temptation: accept the near-miss `INERT` and publish it.**

The control arm's first live run returned `control 1/3 trace=YES` and was heading for a unanimous
`INERT` — *"M5.E9's phase-entry fix does nothing."* Every condition for accepting it was in place:
the seam probe had passed four times, the fixture had just been fixed, the suite was green, and
**the plan had pre-authorised `inert` in writing as the desired worst case** so that nobody would
treat it as a crisis. It would have been a striking, publishable finding.

It was false. The deletion removed one line from a section that stated the same instruction three
more times — the heading, the rationale naming `transitionPhase`, and the timing rule. The control
arm still contained the instruction.

**What caught it was not the number.** The number looked fine. It was asking *what does this
mutation actually leave in the file?* — and reading the file.

**A second temptation, resisted the same day:** when the 300s timeout forced `INDETERMINATE` after
the trace had already fired, the tempting fix was to rule that a timeout *after* an entry-time trace
does not count as a failed run. That is changing a pre-declared verdict rule after seeing results.
**The timeout moved instead; the rule did not**, and the distinction is recorded in the commit so it
cannot later be blurred.
