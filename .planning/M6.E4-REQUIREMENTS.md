# M6.E4 — Requirements

**Epic goal:** a plan carries what the builder needs, and its own numbers hold up.

Three backlog rows batched by **subject** rather than size (`D-BR0823-1`). All three land on
`commands/plan.md`, the plan-validation pass, or the drain contract `plan.md` consumes.

---

## S1 — Spec-internal consistency: a plan that contradicts itself

**The defect:** `M4.5.E9` shipped a task whose stated threshold formula could not satisfy the
acceptance criterion stated in the same task. The 8-dimension pass audits goal alignment,
completeness, dependency, testability, scope, context, risk and vertical slicing — **none of which
compares a plan's stated formula against a plan's stated criterion.**

### FR1.1 — A deterministic detector for quantitative tasks

A JS check walks a PLAN artifact and returns every task carrying **both** a numeric value and an
acceptance criterion. Token-level only; it never judges satisfaction.

- **AC1.1a** — Given the `M4.5.E9` task that motivated this row, the detector returns it.
- **AC1.1b** — Given a plan whose tasks contain no numbers, the detector returns an empty list and
  reports `clean`, not `cannot-evaluate`.
- **AC1.1c** — The detector distinguishes **"checked and found nothing"** from **"could not
  read the plan"** (`B39`). An unreadable or absent PLAN renders `cannot-check`, never `clean`.
- **AC1.1d** — Reach is **published next to the clean count**, measured across the eval corpus
  (`M6.E2`'s rule): the report states how many corpus projects the check could evaluate.

### FR1.2 — The detector creates a non-optional obligation for the prompt

`agents/verifiers/plan-checker.md` must address **each flagged task by name** under the
`testability` dimension.

- **AC1.2a** — `plan-checker.md` names the detector and states that each flagged task is addressed
  individually.
- **AC1.2b** — The obligation folds into **`testability`** (a `core` dimension), so it runs at
  FEATURE. No 9th dimension is added; the count stays 8 (`D-M6E4-3`).
- **AC1.2c** — ⚠ **Stated limit, not a claim of enforcement:** nothing fails if the prompt ignores
  the list. This is `B75`'s open shape, deliberately reproduced at a smaller radius, and it is
  written down at the point of use rather than discovered later.

## S2 — Standing inbox entries counted as undecided

**The defect, restated from measurement** (`D-M6E4-1`): the inbox holds 6 entries, 5 dispositioned,
**1 live candidate — and that candidate is the permanent trigger-watchlist entry.** The live count
therefore **can never reach zero**; the inbox cannot report itself clear.

⚠ The row's second instance does not exist: its quoted *"do not close this entry"* is absent from
the repo and from all git history.

### FR2.1 — An explicit standing marker

A `<!-- standing -->` HTML comment in an entry's header region marks it permanently open.

- **AC2.1a** — `parseEntries` returns `standing: true` for a marked entry.
- **AC2.1b** — The marker is read **fence-aware and header-scoped**, matching how `parseEntries`
  already finds the Status line — a marker quoted deeper in a body does not mark the entry.
- **AC2.1c** — `parseTriggerWatchlist` is **unchanged** (`D-M6E4-4`); no second mechanism ships.

### FR2.2 — Standing entries are reported separately and excluded from the live count

- **AC2.2a** — `listDrainCandidates` **excludes** standing entries.
- **AC2.2b** — Standing entries are retrievable as their own category — a value on the record, not
  a rendering choice (`M5.E18`'s `cannotDetermine` precedent).
- **AC2.2c** — **The measurable outcome:** on this repo the drain reports **0 live candidates and
  1 standing**, where it reports 1 live today.
- **AC2.2d** — A project with no marked entries behaves **byte-identically** to today.
- **AC2.2e** — No `/sig:add --standing` flag is added (`D-M6E4-5`).

## S3 — Task-handoff completeness: the research never reaches the builder

**Three leaks in one seam, all re-verified on disk 2026-08-23:**

1. `agents/executors/executor.md` `## Inputs` declares the PLAN task, `CONTEXT.md` and
   `{phase}-VALIDATION.md`. **`RESEARCH.md` is not among them**, and `commands/execute.md`'s
   dispatch reads PLAN + VALIDATION only.
2. `skills/plan/planning-and-task-breakdown/SKILL.md:99` has a **Files likely touched** field;
   `commands/plan.md`'s required-contents list omits it. Skill and command disagree.
3. **No per-task out-of-scope field exists anywhere.**

### FR3.1 — RESEARCH.md reaches the executor, by both routes

- **AC3.1a** — `executor.md` `## Inputs` declares `{phase}-RESEARCH.md`.
- **AC3.1b** — A plan task may name a **specific exemplar** from research; the executor follows it
  rather than re-deriving the pattern.
- **AC3.1c** — The whole RESEARCH document is **not** bulk-injected into every task's context
  (`D-M6E4-6` — context budget is the project's stated highest risk).

### FR3.2 — The two missing plan fields

- **AC3.2a** — `commands/plan.md`'s required-contents list carries **Files likely touched**,
  reconciling it with the planning skill.
- **AC3.2b** — A per-task **Out of scope** field exists and is named in the same list.
- **AC3.2c** — The requirement folds into **`completeness`** (a `core` dimension), so it runs at
  FEATURE (`D-M6E4-3`).
- **AC3.2d** — ⚠ **Advisory first** (`D-M6E4-7`): a plan lacking the fields is **reported**, not
  failed. Corpus plans predate the fields and were correct when written.

## Non-functional requirements (FEATURE prompt — `discuss.md` §6)

- **NFR1 — Error handling at boundaries.** Every new check is **fail-open for reporting**: a check
  that cannot read its input renders `cannot-check` and the surrounding command continues (`B39`).
  *(Distinct from `/sig:drive`'s fail-closed posture, which governs an **actor**, not a detector.)*
- **NFR2 — Input validation.** Marker and detector parsing tolerate malformed markdown without
  throwing; a dangling fence must not silently swallow entries (`listDrainCandidatesWithRecovery`'s
  existing contract is preserved).
- **NFR3 — Log lines for failures.** Any `cannot-check` states **which** input it could not read.
- **NFR4 — No new dependencies.** Deterministic, offline, no network.

## Blast radius (`D-M6E4-7`)

**Touched but not changed:** every downstream consumer of `{phase}-PLAN.md` — `plan-checker`,
`execute.md`'s dispatch, the executor. Every consumer of `parseEntries` — `listDrainCandidates`,
`listDrainCandidatesWithRecovery`, `commands/plan.md`'s drain step, and the drain tests.

**Not touched:** `BUGS.md`, `BACKLOG.md`, archive paths, STATE schema, the plugin payload.

**Rollback:** revert the commit. No stored data, no published artifact, no migration.
