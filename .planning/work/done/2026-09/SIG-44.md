| B44 | `fixed` | **P2** | **`transitionPhase`'s dedupe assumes a ≤7-entry per-Epic ledger — nothing enforces that invariant, so the first programmatic call on a long linear-mode history silently collapses it.** `state.js:388-395` keys `completed_phases` by phase name in a `Map` (most-recent wins) — **specified**, not accidental: the docstring says *"dedupes by phase name … so recovery re-transitions don't accumulate duplicates"* and `references/state-schema.md:128` documents *"Dedupe by phase name on re-transition."* The dedupe is correct **for the scope it was designed against** — an Epic, where the list holds at most one entry per phase and B9's `setCurrentEpic` reset clears it on every roll. **Linear mode has no such reset** (B9's fix fires only on an Epic roll), so `completed_phases` is the project's whole multi-slice history — and the collapse is unbounded, silent, and unwarned. **Live instance 2026-07-26 (`eval-project-A`):** a hand-maintained 53-entry history was rewritten to 8 by one `transitionPhase` call; caught before commit, by hand. **The two preconditions are both Signal's:** the ≤7 invariant is undocumented and unasserted, and the history could only have been hand-built in the first place **because of B41** (the middle commands never call `transitionPhase`, so a linear project maintains the field manually). Fix B41 alone and this gets *worse*, not better — every newly-wired phase command becomes another collapse site. **The precise framing (Brett, 2026-07-26): set semantics applied to log data.** The `Map` is keyed on the first whitespace token and JS `Map` is last-write-wins per key, so the operation is only coherent if `completed_phases` means *"which phases has this project ever reached."* Used as an append-only chronological log — which is what a multi-slice project's STATE is, and what `STATE-HISTORY.md` treats it as — **every prior slice's history is destroyed on the first call.** *Scope correction: this is not linear-mode-only. **Any** project past its first unit hits it; Epic mode is spared only because `setCurrentEpic` (`state.js:614-616`, the B9 fix) deliberately zeroes `completed_phases` on every roll, so the list never gets long enough to notice. Linear mode has no roll and therefore no reset.* **What made it dangerous rather than merely wrong is the silence:** `writeStateFrontmatter` (`state.js:478-483`) re-serializes the whole frontmatter atomically — no diff, no warning, no dropped-entry count. Caught in `eval-project-A` only because a `git diff` was run before committing a file expected to carry two edits. **Fix shape (decide, don't assume):** if it's a log, **drop the `Map` entirely** — a one-line fix; if it is genuinely a set, then **entries must not carry dates**, because a date on a last-write-wins entry looks like *"when this happened"* and means *"most recent write,"* which is exactly how it misled here. Either way **write the invariant down in `references/state-schema.md:128` and assert it** — that line currently specifies the dedupe without ever stating the ≤7 scope it depends on. Sequence **before or with B41** (same state-mutation core, M5.E9): fixing B41 first turns four more commands into collapse sites. **Writer audit (done 2026-07-26, answering "is this class waiting in the other frontmatter writers?" — no):** every other mutator spreads the parsed state via `stripStateMeta` and **patches named fields** — `markFresh` two scalars (`state.js:1384-1389`), `setCurrentTask` a pure append (`:516`), `clearCurrentTask` a filter on an explicit id, `addBlocker`/`clearBlocker`/`touchDecisionTimestamp` likewise. `transitionPhase` is the **only** writer that rebuilds an array by derivation. Two residual notes, neither a truncation: `setCurrentEpic` wipes `completed_phases` by design (B9) with no archival step, and because every write round-trips the frontmatter through the YAML serializer, **comments and hand formatting inside the frontmatter block are dropped by any writer** (data keys survive). **→ Status reconciled 2026-08-02** (fix lane, BUGS.md status-vs-code sweep): fixed in **M5.E9 (D-M5E9-5)** and never flipped. The set-vs-log question was decided in favour of **log**: `transitionPhase` is now append-only with no dedupe (`tools/lib/state.js:425`), so a long linear-mode history can no longer be collapsed by a single call. `references/state-schema.md` was updated with it. Asserted in `tests/state.test.js`, `tests/phase-recording.test.js` and `tests/adherence-append-only.test.js`. |
