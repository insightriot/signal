| B103 | `fixed` | **P1** | **`/sig:doctor --fix` generated `rm -rf` for cache copies that *running* sessions had resolved.** `detectP2OrphanCacheEntry` treats "not the manifest's current version" as sufficient grounds for deletion, and `buildFixScript` never looked at process state — so the generated script offered to delete a directory a live session was executing out of. Claude Code resolves a plugin path once at session start and holds it for the life of the process; that is **`B52`**, and `v0.1.20` shipped a *detector* for it that this path never consulted. `UNREACHED-MECHANISM-ANALYSIS.md`'s class: the capability existed and nothing reached for it. The per-step `[y/N]` is not mitigation — it reads as a formality, so the reflexive answer is the destructive one. **Found by running `--fix` on this machine 2026-08-18, not by reading code:** three `claude` processes were live and two of them (pids 29938, 78473) had resolved `sig/0.1.25`, which the script listed for deletion; the step was declined by hand, and nothing in Signal would have declined it. **Fixed in `v0.1.28`:** `parseClaudeProcesses` + `detectLiveBindings` (pure) infer each session's copy as the newest cache dir that existed when the process started, `readLiveBindings` does the I/O and never throws, and both script builders emit a guard that **re-checks at script-run time** — not at generation time, because a session can start in the gap and `~/.claude/sig-doctor.sh` survives to be re-run days later. The guard calls back into the same module rather than reimplementing the inference in bash (`B82`'s shape). Held directories are skipped outright, never prompted. ⚠ **The inference is a heuristic and is labeled one:** there is no API that reports another session's resolved path, so a downgrade or a hand-moved cache dir can mis-attribute — it errs toward holding, since a false hold costs disk and a false delete costs someone's session. `ps` unavailable / an unreadable dir / no `node` are `cannotDetermine`, and those steps render `[UNVERIFIED]` rather than prompting as though the check had run (`B39`). Verified end-to-end: answering `y` to every prompt now deletes nothing while a session holds the copy. |
