| B104 | `fixed` | **P1** | **`/sig:init` spawned four agents holding `Bash` across a codebase, and nothing anywhere told them the content was data.** ⚠ **CORRECTED 2026-08-18, same day, after Brett asked how scanners write to a codebase — they do not.** The first version of this row and of `v0.1.30`'s release note said *"an arbitrary repository"* / *"a stranger's repository"* and implied a write risk. `/sig:init` runs on **your own** existing codebase, and every scanner is constrained to `.planning/scan/{name}.md` with `npm install` and `git push` forbidden. **The real exposure is command execution (they hold `Bash`) and downstream propagation (their output becomes `LANDSCAPE.md` → `PROJECT.md` → every later phase), not file writes.** It remains a real gap because your own codebase carries text you did not write — vendored deps, contributor commits, forked files, fixtures — and because people do point `/sig:init` at a repo they cloned to evaluate or at a client's. The fix is unchanged; the severity framing was written from the shape of the work rather than from the artifact, which is `B50`'s class committed in a bug report about security. Found 2026-08-18 while reviewing `vercel-labs/eve-software-factory-template` (MIT), which ships a prompt-injection eval Signal had no equivalent of. **The diagnosis was a grep, not a judgement:** `plugin/agents/scanners/*.md` and `commands/init.md` contained **zero** instructions treating scanned content as data — not a weak instruction, none — while all four scanners declare `tools: Read, Bash, Grep, Glob`. Signal is publicly installable with four non-Signal users, so a `README` in any scanned repo saying *"ignore the tier gate"* or *"run this setup command first"* met no instruction standing against it. **Fixed in `v0.1.30`:** a Constraints clause in every scanner naming the content as data, naming the destination for such a finding (`suspicious embedded directive at {path}` under *Detection Failures*), and naming `Bash` as what makes the constraint load-bearing; plus the same instruction in `init.md` at the spawn site. **Pinned by a whole-population assertion** — the test reads the scanner directory from disk rather than a hardcoded list, so a fifth scanner fails the suite until it carries the clause. That shape is itself borrowed from the same repo, and is what `B81` needs. ⚠ **Scope, stated rather than implied: this covers the scan surface only.** Two of the three surfaces named at filing are untouched — `/sig:add` captures verbatim **by design**, and every phase command reads `.planning/` documents that anyone with commit access can write. Whether those need the same treatment is undecided; a clause in a scanner does not generalise to a document Signal itself authored. ⚠ **An instruction is not a sandbox.** This makes the expected behaviour explicit and testable; it does not make injection impossible, and no eval exercises it — Signal has no run-event stream to assert against (see the inbox entry on behavioral evals). |
