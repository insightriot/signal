The briefing renders in full and **names the problem** — phase unrecognized, a one-line elided excerpt of what STATE.md holds, and the seven valid values. Rendering nothing was rejected as `B39`'s shape. 16 tests in `tests/noncanonical-phase.test.js`, RED-first, keyed to `eval-project-C`'s real five-paragraph `phase` value; verified end-to-end against that project, the one of three locally-reachable projects that reproduced the throw. **Original report:** **`/sig:status` and `/sig:resume` throw outright on a project whose `phase` is not one of the seven canonical names — 5 of 12 real projects, measured.** `nextActionForPhase` throws `unknown currentPhase "…"` on anything outside `PHASES` (`tools/lib/status.js:46-50`). **Neither command carries a fail-open instruction for it, and every neighbouring optional read does** — verified by reading both files: `isStaleVsOrigin`, `readLayoutBanner`, `readStateSizeForTier` and `readEffectiveProfile` are each marked *fail-open* or *advisory* in `resume.md` and `status.md`; `nextActionForPhase` is the one call nobody marked safe. In `resume.md:128` it sits **inside the argument list of `renderResumeBriefing`**, so a literal execution throws before the render is entered; `status.md:175` computes it at §2.6. **Scope of the evidence, stated rather than blurred:** the throw is **measured**; the user-facing consequence is **read, not run** — these are agent-executed prose files, and what a given agent does when an instruction throws is not determined by the file (M5.E8's exact subject). So the defensible claim is *the orientation commands lose their next-action step, and nothing in either file tells the agent to continue without it* — not *the user is guaranteed to see nothing*. **Nothing upstream stops the bad value getting there:** `readState` returns `phase` verbatim without validating it against `PHASES`, and the `PreToolUse` frontmatter-shape guard only ever inspects `completed_phases` — `checkStateFrontmatterShape` calls `sectionLines('completed_phases')` and nothing else, and `sectionLines` returns `null` for any **inlined** scalar (`tools/lib/retrospective.js`), so a multi-line prose `phase:` is invisible to it by construction. That is `B8`'s vector-1 class on a field the de-prose work never covered. **Measured 2026-08-02, not cited** — every `/Users/macstudio/dev-biz/*/.planning/STATE.md` read through `readState`, then `nextActionForPhase(state.phase, [])`: **7 ok · 5 crash · 1 `readState` throws** (13 total, one of them Signal). Crashing: `eval-project-C`, `operator-os`, `eval-project-K`, `eval-project-J`, `eval-project-E` — every one of them a hand-maintained linear project that parked narrative in the `phase` scalar. `eval-project-B` never gets that far (`readState` throws). So **6 of 13 real projects cannot run the two orientation commands**, and M5.E16's corpus table already recorded the input (*"Canonical `phase`: 7 of 12"*, `M5.E16-RESEARCH.md:54`) without anyone executing the consequence. **`P1`, matching `B42`'s precedent:** not degraded behaviour — two documented commands refusing to run at all against the majority mode. **Fix shape (decide, do not assume):** the cheap half is for both commands to tolerate a non-canonical `phase` — render the raw value and say *"not a recognised phase, so there is no next action"* rather than throw; the real question is whether `readState` should quarantine an off-enum `phase` the way `partitionCompletedPhases` (the `B45` fix) already quarantines an off-enum ledger entry, which would give one answer for both fields. **Sequencing: M5.E18.** It is the same population — the 8-of-12 linear projects the archive half does not reach — and fixing the archive for projects whose `/sig:resume` throws would be shipping the second half of a door. |
