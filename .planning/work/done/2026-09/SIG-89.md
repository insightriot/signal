| B89 | `fixed` | **P2** | **`/sig:plan` grants permission to skip the drain and forbids skipping the drain, in the same file.** `commands/plan.md:66` (Step 1b): *"This step is **advisory and fully skippable** — if you'd rather not triage now, skip the whole step and planning proceeds unchanged."* `commands/plan.md:210` (the Anti-Rationalization table): *"The plan's decided — skip the FUTURE-IDEAS drain"* → *"**No.** … the PLAN drain (Step 1b) **IS** the promotion step. Skip it and captures rot in a write-only file."* **The table names skipping as a rationalization to refuse; the step grants it as an option.** An agent that skips is simultaneously obeying Step 1b and committing the exact rationalization the same file forbids, and neither instruction is wrong on its own terms. **This is `M5.E17`'s class** (*instructions that contradict other instructions*) — but **inside one file**, where the cross-document tests M5.E17 shipped do not look. **Live, and I am the evidence:** during `M5.E19` PLAN on 2026-08-07 the drain was skipped, citing Step 1b's permission, with **52 candidates** in the inbox (the oldest dating to 2026-05) — the precise outcome the table exists to prevent. The skip was declared out loud, which is the only reason it is visible at all. **Consequence beyond the contradiction:** the drain is Signal's *only* culling mechanism for `/sig:add` captures, and it runs **only at PLAN**, so a permission to skip it is a permission for the inbox to grow without bound. `evictTerminalToLedger` makes the inbox *converge* once entries are dispositioned — nothing makes them get dispositioned. **The fix is a product call, not a wording tidy:** either (a) the step is genuinely optional and the anti-rationalization row is deleted, or (b) the drain is mandatory and Step 1b's escape becomes a bounded one — e.g. *defer-all* (which stamps every entry and is one action) rather than *skip*, so the inbox always advances even when the operator does not want to triage. **(b) is the one that matches the table's stated intent**, and `applyDispositions` already supports the batch. **Found 2026-08-08** by reading Step 1b against the table in the same file, prompted by a question about how the roadmap is culled. **FIXED 2026-08-08 — resolved toward (b), required-with-a-bounded-escape**, on Brett's call and for the asymmetry the entry itself names: the drain is the only culling mechanism and runs only at PLAN, so a permission to skip is a permission for the inbox to grow without bound. Step 1b is now **required**; *"defer all remaining"* is the escape and is offered **unconditionally** rather than *"on a large first run"* — an escape that appears only above an unstated size threshold is not one a required step can rely on. `applyDispositions` already supported the batch, so this is wiring and wording, not new machinery. The anti-rationalization row survives, now naming the permitted move (a refusal with no alternative is what made the contradiction survivable) and no longer naming the retired `FUTURE-IDEAS` filename. **`tests/intra-file-consistency.test.js` guards the class**: M5.E17 shipped cross-document tests, so nothing ever compared a file against **itself** — an anti-rationalization table is by construction a list of what the file forbids, and its own steps a list of what it permits, and those two lists had never been read against each other in any command. **Two things the fix found.** The general check was first written as *"strip blockquotes"* — wrong, and measured so: `add.md` and `migrate-memory.md` both carry **live directives** inside `>` blocks, so that shortcut would have blinded the check to real instructions. It keys on an explicit `[RETIRED]` marker instead, which is the BACKLOG corollary *"retract at the granularity people search at"* applied to a retired instruction rather than a false claim — the old wording is **kept, quoted, and marked**, because deleting it would pass every check while losing the only in-file record of why the rule changed. 2361 → **2366 tests**. |
