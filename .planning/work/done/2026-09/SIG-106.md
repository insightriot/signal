| B106 | `fixed` | P3 | **`cut-release.js` updated the published test count and left the sentence naming the release that produced it — so every cut published a fresh figure attributed to the PREVIOUS version.** `plugin/references/facts.md` carries `- **Test count:** N` followed by *"Set at each release … most recently **vX.Y.Z (date)**"*. `setFactsTestCount` rewrote the number; **nothing rewrote the attribution**, which is a release-time fact for exactly the same reason the count is (`B56`) — only knowable at the cut, and unre-derivable between cuts. **Found 2026-08-21 by cutting `v0.1.31`**, not by reading the file: `facts.md` correctly read `2786` while the line beneath it still said *most recently v0.1.30 (2026-08-18)*. ⚠ **The detector worked and the tool did not.** `M6.E2`'s `facts-attribution` check exists for precisely this condition and **fired on the cut** — so this is not a gap in detection, it is `UNREACHED-MECHANISM-ANALYSIS.md`'s class one layer over: the check names the situation, and the tool that *creates* the situation every single release was never taught to fix it. Left alone, it re-fires at every future cut and trains the operator to clear it by hand. **Fixed 2026-08-21:** new `setFactsAttribution(source, version, date)` mirroring `setFactsTestCount`, composed into the same `releaseEdits` entry so the count and its attribution are written **by one edit** and cannot diverge. It **throws rather than silently no-opping** when the attribution is absent — `rewriteBugTally`'s lesson (a replace matching nothing returns the input unchanged and the caller reports success on a file it never fixed). **Pinned by a cross-file assertion, not a literal:** a test reads `FACTS_REL` **out of `published-facts.js` source** and parses this function's output with it, so if the writer and the reader drift the suite fails — pinning the literal string in the test would have recreated the bug inside the test (`B85`'s lesson). ⚠ **What this does not do:** it asserts the figures were re-derived *at that release*, not that they are *correct* — the check's own stated limit, unchanged. |
