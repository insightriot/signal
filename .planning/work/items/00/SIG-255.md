Found 2026-10-01 in the same /sig:docs-migrate dry run. The project keeps a hand-written keep-live list in .curator.yml (keep_live: six SSO files, with the reason: merged but DORMANT, gate off until a customer go-live). Signal's archive paths (archive-tree.js, archive-command.js) read no such list: closure comes only from resolveClosures (terminal artifact + verdict), so a slice that PASSED review reads closed and is proposed for archive.

Signal has no way for a project to say "closed, but keep it live". Options, none chosen: (a) honour .curator.yml keep_live / never_move_or_rename when present (it is another plugin's file, read-only); (b) a Signal-native hold, e.g. a frontmatter or PROFILE field, or a hold marker the closure resolver treats as open; (c) both. Either way the dry run must name a held unit as held, not silently skip it.

Also seen in that run and NOT a bug: one unit (RBAC1-UNIT5) was reported as cannot-determine because its VERIFICATION states no readable verdict. That is the resolver being honest.
