Found 2026-10-29 by a fresh read of the execute rewrite (PR #322), not fixed there (the fix loop was at its ceiling). (1) A loop back from VERIFY or REVIEW runs the fixes in that phase's report as tasks. If the session is interrupted, the re-run finds phase already EXECUTE, so it is treated as an ordinary resume: the task list goes back to the plan's tasks (all marked done), only the fix still in current_tasks is resumed, and fixes not yet started are dropped while Finish runs as if all were done. Nothing records that the run is a loop back. (2) In a project without Epics, last_completed_task is reset only by setCurrentEpic (state.js), so if the first task of a new run is interrupted and resumed, execute.md step 5.2 takes the previous run's last commit as its start, and the parent-run check is weaker than it reads. Both are rare; both are silent.
