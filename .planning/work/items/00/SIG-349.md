From the fresh read of PR #304's second ceiling round (M6.E17 SHIP, 2026-10-19). `loopStatusFor` does not hold a phase while it is the current phase and the LAST entry of `phase_passes` is its own PASS or PASS-WITH-FIXES. STATE cannot say whether that entry was written in the current visit, so when a later visit ends without `recordPass` (crash, interrupted session, skipped step), an earlier PASS keeps lifting the phase's ceiling at every count. Probe: `phase_passes: [VERIFY FAIL, VERIFY PASS]`, two later VERIFY and REVIEW exits, `phase: VERIFY` → count 2, not held. Bounded: REVIEW's exits still raise its count and hold the cycle. Fix: a visit marker written on phase entry (for example the index into `phase_passes` at entry), and lift only for a record written after it, with tests for a visit that left no record. Also seen: drive checks the ceiling after a phase runs and `describeNextAction` ignores the verdict, so the ceiling bounds loops only if each FAIL's loop-back goes backwards (drive.md).
