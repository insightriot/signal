**`claude plugin update` exits 0 on failure.** Non-bug (triaged 2026-08-06, in the same session that surfaced it). Reported to the user as a second finding alongside `B85`, on the strength of an `EXIT=0` printed after **both** the failing and the succeeding invocation. That number was produced by `echo "EXIT=${PIPESTATUS[1]:-$?}"` following a pipe into `tail`: `PIPESTATUS` is bash's spelling and is unset in zsh, so the `:-` fallback read **`tail`'s** exit status, not `claude`'s. Re-measured without a pipe — `out=$(claude plugin update sig 2>&1); rc=$?` — gives **`rc=1`** on the failing form. The CLI's exit code is correct, and `B85` therefore cannot cause a silent false-success. **Recorded rather than dropped** for two reasons: the claim reached the user before it was verified, and the trap is reusable — an exit code read through a pipe in zsh is not the exit code of the command you care about, so any future finding of this shape must be re-measured unpiped before it is filed. Same discipline as `B1`: surfaced from unverified surface behavior, dismissed by measuring properly.
