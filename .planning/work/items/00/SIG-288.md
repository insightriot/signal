Found while fixing SIG-286 (M6.E15 S6). Decision: D-M6E15-21 fixed it on the /sig:docs-migrate path only and filed this.

`senseArchiveTree`'s default closed-set (`plugin/tools/lib/archive-tree.js:506-518`) is the union of Epics with a non-stub retrospective and units `resolveClosures` marks closed. The retrospective half has no current-unit check and no verdict check. `/sig:docs-archive` takes its moves from that default (`plugin/tools/lib/archive-command.js:68`); it differs only in refusing everything when STATE.md is unreadable (`archive-command.js:90-105`).

So on /sig:docs-archive a filled-in retrospective alone can still move an unfinished Epic's files, including the current Epic's. /sig:docs-migrate now passes `closedUnits` from `resolveMigrateClosedUnits` (`plugin/tools/lib/migrate-memory.js`) instead.

Changing the shared default flips pinned /sig:docs-archive behaviour (`tests/archive-destination.test.js:219-275` and others), which is why it was out of scope for M6.E15.
