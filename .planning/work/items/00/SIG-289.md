Measured during M6.E15 S6 (SIG-286 fix). A consequence of D-M6E15-21.

/sig:docs-migrate now evicts a closed Epic's STATE narrative only when `resolveClosures` says the Epic is closed. `resolveClosures` lists only the top-level `.planning/` folder (`plugin/tools/lib/closure.js:249`). If the Epic's VERIFICATION.md was already moved into `.planning/archive/` (for example by /sig:docs-archive), the Epic resolves as open, so:

- its `## M…` narrative section in STATE.md is not evicted, and the dry run flags it `not-closed`;
- `isV3Conformant` returns true, so the project is stamped v3 with closed narrative still inline.

Reproduced with a scratch fixture: retro in root, `archive/M5/E1/M5.E1-VERIFICATION.md` with `**Verdict:** PASS`, STATE with an inline `## M5.E1` section and a different current_epic → 0 evicts, isV3Conformant true. Before SIG-286, the retrospective alone drove that eviction.

It fails safe (the narrative is kept, nothing is lost), but closure.js needs to look in archive/ for an archived Epic's terminal artifacts.
