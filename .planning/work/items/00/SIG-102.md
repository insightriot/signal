**Signal's own migration instructions uninstall the plugin and then tell you they didn't.** Shipped in `v0.1.26` (`M6.E1`), found 2026-08-18 when Brett asked whether `/sig:update` could perform the migration and the sequence was **run** for the first time. `claude plugin marketplace remove signal` **uninstalls the plugin** — measured in an isolated config, `claude plugin list` reports *"No plugins installed"* immediately after. `marketplace add <url>` does **not** restore it; a third command, `plugin install sig@signal`, is required. **All three surfaces prescribe only two commands** — `plugin/commands/doctor.md`'s `P6` block, `docs/map/install/index.html`'s existing-user section, and `README.md`'s migration note — so a user who follows them lands with **Signal uninstalled**. **Two of the three additionally assert *"Your installed plugin and its settings are untouched by this"*, which is false in its first half**: settings survive (`enabledPlugins` came through intact), the plugin does not. **This is the `CLAIM-INTEGRITY-ANALYSIS.md` class, committed in the release whose own Epic filed `B100` and `B101` about the same thing** — the sentence was written from the *shape* of the operation rather than from running it, by the author of `AC0.1`'s warning, three days after writing it. **`P6` is info-only and the old path keeps working, so nobody is broken by inaction — the damage is only to users who *follow the advice*.** *Fix:* all three surfaces prescribe the **three**-command sequence and drop the false clause, replacing it with what is actually true (*your settings and projects are untouched; the plugin is removed and reinstalled*). Pinned by a test asserting that any surface prescribing `marketplace remove` also prescribes `plugin install` — derived, so a fourth surface cannot drift. **Not automatable in `/sig:update`, decided the same day:** step 1 deletes the plugin that is running the command, so a failure at step 2 or 3 strands the user with no Signal and no `/sig:` command to recover with.
