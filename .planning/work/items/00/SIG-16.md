**A failed/rolled-back `--apply` in git mode now leaves a lingering `pre-migrate-memory-<stamp>` tag.** Introduced by the C1 rollback fix (`50ad065`): the pre-apply tag is hoisted to run *before* the mechanical phase so non-git modes have a recovery pointer. On a successful apply the tag is the intended revert pointer (correct, printed in `revertLine`). But on a **rolled-back** apply the tag now persists (pointing at the restored pre-apply state) — harmless, but it accumulates across retries in a stranger repo. **Fix:** clean up the tag in the rollback catch (or make it idempotent per-run).
