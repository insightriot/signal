## `transitionPhase` regenerates INDEX.md at phase ENTRY, so INDEX never holds the current phase's own artifact


`transitionPhase` regenerates `.planning/INDEX.md` as part of recording phase entry — which every phase command calls *before* it writes anything. So the index of the corpus is, structurally, always exactly one artifact behind: the phase's own output does not exist yet when the index that is supposed to list it is built. Found 2026-09-04 during `M6.E6` REVIEW: `transitionPhase(base, 'REVIEW')` reported `docCount: 311` and wrote INDEX; `M6.E6-REVIEW.md` was written minutes later; `grep -c 'M6.E6-REVIEW' .planning/INDEX.md` returned **0**. Regenerating by hand afterwards gave 312. This is not specific to REVIEW or to this Epic — it holds for every phase of every Epic, and the gap closes only incidentally, when some *later* transition or a manual `/sig:docs-index` sweeps it up. Cost: INDEX is the corpus map, and `/sig:docs-sweep`'s orphan detection reads it, so a freshly written artifact is briefly indistinguishable from an orphan. Fix candidates: (a) regenerate at phase *close* in addition to entry — cheapest, keeps the entry-time write that makes the position true while the phase runs; (b) trigger regeneration from the artifact write itself, which is more precise and touches more call sites; (c) leave entry-only and have `/sig:ship` regenerate as a pre-PR step, which fixes the published state but leaves every mid-Epic read stale. Note (a) and (c) are not exclusive.
