## /sig:discuss --epic picks an Epic number the milestone file already plans for another Epic

Measured 2026-10-28 on the test project (a fresh session running the rewritten `/sig:discuss` on a copy). `deriveNextEpicId` (`plugin/tools/lib/milestones.js`) counts Epics from files, folders and unit records. It does not read the milestone file. The test project's `MILESTONE-M3.0.md` plans E3 and E4 by name, but neither has a file or a record yet, so the next ID came out as `M3.0.E3`. That is the planned Epic's number, and it is being built on another branch.

The session noticed and asked before opening anything, which was the right call. But it noticed only because it happened to read the milestone file. A run that trusted the derived ID would have taken the planned Epic's number, and the two would have collided when the branches met.

**Fix:** count the Epic numbers a milestone file plans (`MILESTONE-M{N}.md` / `MILESTONE-{N}.md`, rows or headings naming `E{n}` or `M{N}.E{n}`) as taken, the same way records and folders already are.
