The bare `git` row in `plugin/tools/lib/permissions-scan.js` is propose-allow, so every git subcommand a prompt file names falls through to a proposed rule. Some of those run a command with the right flags: `git fetch`/`git pull --upload-pack=<cmd>`, `git push --receive-pack=<cmd>`, `git grep -O<cmd>` (ran by the r6.5 confirm reader). `git bisect`, `git clone` and `git config` were made never-propose in r6.5; the rest were left because changing the fall-through changes most of the proposal. `plugin/commands/permissions.md` now warns about it. Also noted there: `Bash(claude plugin:*)` permits `claude plugin install <anything>`; the `git push --force` deny does not match `-f`, `+ref`, `--mirror`, `--delete`. Fix: make bare `git` never-propose and offer only named subcommands, with deny rules for the flag forms.
