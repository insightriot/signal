| B121 | `confirmed` | P2 | **`parseBacklogRows` returns ZERO rows for a CRLF `BACKLOG.md`, and `/sig:advise` then writes an advisory saying *"Nothing. No live row survived the ranking inputs."*** `headingRe` is `/^(#{2,4})\s+(.*)$/` with **no `m` flag**, so `$` matches only at end of input and `.` excludes `\r`: a heading line ending in `\r` never matches. Measured: the same file at LF yields 2 rows, at CRLF **0**. A Windows checkout with `core.autocrlf=true` produces exactly this file. **The consequence reaches the citation gate:** zero rows means zero claims, `verifyCitations` returns `ok` over nothing, `0 >= 0` passes, and the artifact is written. `advise.js`'s own docblock reasons that *"`claims === 0` implies `rows.length === 0`, and with no live rows there is genuinely nothing to cite"* — **false for this input: 52 rows exist and 0 were parsed.** `walkBugEntries` DOES parse CRLF, so the same artifact still claims `BUGS.md` was consulted. Found by the `M6.E8` REVIEW pass-3 security audit, reproduced. Fix: split on `/\r?\n/` (or strip a trailing `\r`) in `parseBacklogRows`, and have `readCorpus` report cannot-check when the file has bytes but zero headings at any depth. |
