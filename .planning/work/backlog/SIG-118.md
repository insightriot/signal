| B118 | `confirmed` | P2 | **`/sig:drive` chooses what to work on by reading the checked-out branch's `STATE.md` and no other, so an Epic in flight on an unmerged branch is invisible and the "resuming beats starting new" rule silently does not fire.** Found 2026-09-08 **by running the command** on `main`, one step after `B115`'s binding halt passed clean. `proposeEpicCandidates` (`drive.js:327`) opens with `readState(baseDir)`, and `readState` (`state.js`) resolves exactly one path — `join(baseDir, PLANNING_DIR, 'STATE.md')` — from the working tree. One file, one branch. **Measured, not reasoned:** `M6.E8` was open at `phase: DISCUSS` / `current_epic: M6.E8` on `feat/m6.e8-advisor-ranking-inputs` (4 commits ahead of `main`, 16 behind, no open PR, `M6.E8-REQUIREMENTS.md` complete at 176 lines with **0** unfilled markers). The run stood on `main`, read `M6.E7` with `SHIP (2026-09-06)` in `completed_phases`, emitted **no** open-Epic candidate, and presented **51** backlog rows as the full set of things one could start. ⚠ **`cannotCheck` came back EMPTY, and that is correct for the code as written** — the read succeeded, the file parsed, nothing was unreadable. **This is `B94`'s shape, not a never-called guard: the guard ran; its scope is narrower than the guarantee its output implies.** `drive.md` states the rule as *"an already-open Epic comes first, because resuming beats starting new"* — an unqualified claim about the repository, answered from one branch, with no note that the answer is branch-scoped. "No open Epic" must mean no open Epic, never "none on the branch I happen to be standing on". ⚠ **The failure is silent in the direction of MORE work, which is the expensive direction.** The maintainer was shown a clean queue, picked new work from it, and `M6.E8` would have been left drifting further behind `main` with nothing on `main` recording that it exists. It was caught by a person running `git branch -a`, not by the command — and only because the run happened to print the branch list for an unrelated reason. **Second harm, same root:** `main`'s `CLAUDE.md` read *"**Active: nothing in flight.**"*, which is true of `main` and false of the repository, and that line is loaded at **every** session start. `B93`'s row already recorded the branch/`main` split and rationalised it — *"`main`'s still reads `M6.E7` and `CLAUDE.md` still says nothing is in flight, **both correct for `main`**"*. Correct for the file; wrong as the input to a repo-wide question, which is the use it actually gets. **Not fixed in this pass, and the reason is specific:** `resolveStartPhase` (`drive.js:580`) detects the resume path with `candidate?.source?.includes('STATE.md')`, so a cross-branch candidate fed through it would resume an Epic **on the wrong branch** — the fix has to decide whether `/sig:drive` may check out a branch, which is a design call and not a papercut. **Fix shapes, none chosen:** (a) enumerate `refs/remotes/origin/*`, read each `STATE.md`, surface any unshipped `current_epic` differing from the local one as a candidate **carrying its branch name**, and make `resolveStartPhase` refuse rather than resume when the candidate's branch is not the current one; (b) the minimum honest version, which costs almost nothing and can ship first — push `{source: 'STATE.md on other branches', reason: 'N remote branches carry a STATE.md this reader did not open'}` into `cannotCheck`, so the empty-and-clean read stops being indistinguishable from a complete one. **(b) alone would have surfaced this**, and `drive.md` already forbids presenting an unread source as an empty result. ⚠ **WIDER THAN FILED: `/sig:advise` has the same blindness, and the PR reviewer on `#248` found it — in the fix for this very row.** `readCorpus` (`advise-corpus.js`) resolves every one of its five sources as `join(baseDir, …)`; it makes **no** git call and enumerates **no** branch, so all five are read from whichever branch is checked out. The reviewer's route in was not the code but the prose: this PR's own `CLAUDE.md` paragraph established that `M6.E8` is invisible to tooling and then **closed by telling the reader to run `/sig:advise`, which exists to answer that** — pointing at the failure mode two sentences after describing it. **So the fix does not belong in `drive.js`.** Both commands answer *"what should I work on"* from a one-branch read, and shape (b) has to land in the shared corpus layer or it fixes one caller and leaves the other. That also means the blast radius is every consumer of `readCorpus`, not just the driver. **Fresh sighting 2026-09-14 (`M6.E8` VERIFY):** the Epic's own Outcome procedure — *"diff the next advisory against `BACKLOG-REVIEW-2026-09-13.md`"* — is invalid **because of this bug**. The baseline was generated on `main` (`46e6e44`) and lacks the row this branch promoted at DISCUSS (`7e9c288`), so the diff measures corpus drift plus ranking change and cannot separate them; run literally it shows the recommended five changing, which is false. A controlled experiment on one corpus gives an identical top five. **So this bug does not only pick the wrong work — it silently invalidates advisory-to-advisory comparison**, which is the only outcome instrument the corpus offers. |
