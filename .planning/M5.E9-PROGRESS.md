4. **FR2 was redesigned at Wave 2 entry — requirements rewritten before any code.** Drafts 1

### Deviations, surfaced not absorbed

7. **The `/sig:migrate-memory` predicate widening was tried and REVERTED — its own idempotence
   test killed it.** Widening vector-1 from *prose/oversized* to *anything not `PHASE (date)`*
   re-flags **the residue vector-1 itself leaves**: by B12's deliberate design that residue is a
   meaningful short *label*, not a `PHASE (date)` scalar. So a second `applyDeproseVector1` run
   found work forever and the migrate stopped converging. **Junk and already-repaired are
   indistinguishable at that layer.** The repair moved to the **write seam**
   (`partitionCompletedPhases`), where it is automatic, idempotent, and cannot make the migrate
   non-convergent. `/sig:sweep`'s message was corrected to match — it now describes what
   actually happens rather than pointing at a command that would not fix it. *`R3`'s "the repair
   machinery already exists" research finding was right about the machinery and wrong about
   where to attach it.*
8. **A gap in my own FR4 implementation, found while fixing 7.** `partitionCompletedPhases`
   dropped malformed entries from the live list and merely **returned** them — so a caller that
   ignored the return value destroyed them silently. That is a smaller copy of the exact bug
   this Epic exists to fix, and it violated NFR2. Quarantined entries are now **archived
   verbatim before the write**, with a test asserting they land in `STATE-HISTORY.md`.
9. **`export const PHASES` broke the hook with a duplicate export** — `PHASES` was already
   exported at the foot of `state.js`. Caught only by the **spawn** tests (`vitest`'s transform
   tolerated it; `node` did not). Reverted. *Worth noting for the record: the in-process suite
   was green while the shipped hook was crashing — a real gap between how tests load modules and
   how the runtime does.*

### What FR6's tests do NOT prove

`tests/phase-recording.test.js` has two kinds of test, labelled as such in the file header. The
mechanism test proves the sequence produces a correct ledger. The presence test proves the
instruction is **in** the command file. **Neither proves an agent reading that file executes
it** — that is M5.E7's headline finding and **M5.E8's job**. Stated here because a presence
check described as an obedience check is test theater with a good disguise.
