### What wave 1 was for, and what it found

Wave 1 exists because of M5.E17's first-use rule: *name the thing this Epic will run for the first
time, and schedule it first.* Here that was `readProfileFromPath` and the artifact resolvers used as
**drift oracles** over foreign `.planning/` trees — machinery built to *resolve* being asked, for the
first time, whether what a file claims is true.

Running it at PLAN already produced `B59` (Signal's own Epic profile was unloadable, so the Epic
declaring FEATURE ran DISCUSS at FULL) and check **(h)** (not in the requirements; found only by
measuring). Wave 1 finished the job:

**The `cannot-evaluate` branch is not defensive programming — it is the deliverable.** `readState`
**throws** on `eval-project-B` (*"has frontmatter but no schema_version key"*). Before this slice,
that was a crash or a silent skip; a silent skip would have reported the project **clean** when
nothing looked at it. `tools/lib/state-drift.js` now reports it, with the reason, under a heading
that says in words *"these checks could not look. This is NOT the same as clean."*

**The probe reproduces the plan's numbers exactly**, so they are re-derivable rather than asserted:

```
readable STATE.md ........ 12/13
canonical phase .......... 7/12
Epic mode ................  4/12
...of those, strict ID ...  2/4
non-empty blockers[] .....  0/12
```

That last row is why check **(f)** was dropped: **no real project has a blocker**, so FR2.1's
"validate against a real non-Signal project" cannot be satisfied for it even in principle.

### Two design points that came out of building it, not planning it

1. **`healMechanism` is required for categories 1 and 2, enforced by the constructor.** Categories 1
   and 2 make a *promise* — "this clears on its own", "Signal fixed it". A promise whose mechanism
   cannot be named is unfalsifiable, and an unfalsifiable reassurance is worse than a finding. This
   is the generalised form of the defect caught in the plan itself, where **(d)** declared category 2
   while nothing healed it.
2. **The category-1 heading is tier-independent by construction.** *"Clears the next time Signal
   writes STATE here"* is true whether the next write is a phase-close `markFresh`
   (FEATURE/SPIKE/FULL) or a manual `/sig:checkpoint` (SKETCH, where four command files skip
   `markFresh`). The obvious wording — *"heals on next phase command"* — would be **false at
   SKETCH**, which is `B42`'s shape: a rule that silently mis-serves one tier.

**The registry ships empty at S1, and that emptiness is asserted, not assumed.** A test pins that the
category-2 bucket holds nothing, so the day a "Signal runs it" check is registered without
`/sig:sweep --heal` existing to run it, the suite fails rather than the user receiving a promise
nothing keeps.

## S5 — `INDEX.md` at every phase transition (FR5)

- [x] **S5.t1** — regeneration fires on phase transition (AC5.1)
- [x] **S5.t2** — an unchanged doc set still writes nothing (AC5.2)
- [x] **S5.t3** — no hook gains write capability (AC5.3)

**Tests:** 1904 → **1911** (+7).

**Hooked to `transitionPhase`, not to the command files.** `regeneratePlanningIndex` was called from
`/sig:ship` §8 and `/sig:index` and nowhere else, so the docs map was accurate at exactly the moment
an Epic *finished* and drifted through the whole span of work — the span when someone is actually
re-orienting from it. Putting the call in ten command files would have been **`B60`'s shape**: an
instruction stated in some files and silent in others. In `transitionPhase` it cannot be forgotten.

Three constraints, each load-bearing:
1. **The lock-free Core.** `regeneratePlanningIndex` self-locks on the same `.state.lock`
   `transitionPhase` already holds — calling it would deadlock. Same discipline
   `/sig:migrate-memory` follows with `evictEpicNarrative`.
2. **Dynamic import.** `planning-index.js` imports `withStateLock` from `state.js`; a static import
   back would be a cycle.
3. **Never throws.** The phase record is load-bearing; the docs map is not. A docs problem must not
   become a state-corruption problem — asserted by a test that makes `INDEX.md` a *directory* so
   every write to that path fails, and checks the transition still records.

**AC5.3 passed before it was written**, and it is a lock rather than a fix: FR5 rejected session-start
regeneration because no Signal hook writes anything, and a hook that edits files before the user has
asked for anything crosses a line the design holds deliberately. The test asserts that line — no
write call and no index import in any hook — so it now takes a failing suite to cross it.

**The `B48` guard fired on this slice's own fixture** — the first test project had a PLAN but no
REQUIREMENTS, and `transitionPhase` correctly refused to record DISCUSS as complete. The fixture was
wrong, not the guard.

**Parsing is the fragile part, and it is treated as fragile.** `claude plugin list` has **no
`--json` flag** — confirmed by running it, not by reading docs — so the command prefers the
structured `plugin.json` and treats the text format as a fallback that may break. When it does not

guesses**, because a plausible wrong version number is exactly what `B58` was for two releases:
*"sig is already at the latest version (0.1.13)"* was truthful and wrong at the same time.

`compareVersions` compares **numerically**. String comparison puts `0.1.9` after `0.1.13`, and
Signal has shipped 0.1.9 through 0.1.16 — the precise range where the naive version is wrong.

**The restart notice is a statement, never an action** (`B52`). Brett asked for the timing to be
his. The constraint is not theoretical: **the session that built this command ran bound to v0.1.13
while the repo was at v0.1.15**, with the v0.1.15 payload already sitting in the cache — two
releases of command text on disk and unreachable for the life of that session.

**Tests:** 1933 → **1938**.

### C1 — check `(c)` reported "clean" on a project it could not see

`applicability: () => APPLICABILITY.EVAL` unconditionally, while detection was keyed to a strict
`M{n}.E{n}` filename. `eval-project-C` names artifacts `PHASE10-PLAN.md`: **19 phase artifacts, 0
retrospectives, verdict `clean`.**

**Fixed in two parts, both structural:**
1. **Prefix broadened to any token**, so the check can *see* non-strict projects at all.
2. **`NA` when the project has no retrospectives anywhere** — a project that does not use them has a
   different convention, not drift. Flagging all 19 would be telling its author their process is
   wrong. Categorical (a property of the project), **not a threshold**, which FR2.2 forbids.

### The re-measurement caught a false positive the fix introduced

FR2.1 requires re-validating the corpus after changing a check, and it earned its keep immediately:
broadening the prefix made **`eval-project-F`'s `EXECUTE-PROGRESS.md`** read as an un-retrospected unit
named *"EXECUTE"*. That is `resolveArtifactPath` **pattern 3** — the literal-substitution form
`{PHASE}-{ARTIFACT}.md` — so the prefix is a phase name, not a unit.

Narrowed by **excluding the seven phase names**: a closed, enumerated set, so categorical rather
than tuned. **Found by re-measuring, not by reasoning.**
