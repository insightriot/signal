### What wave 1 was for, and what it found

Wave 1 exists because of M5.E17's first-use rule: *name the thing this Epic will run for the first
time, and schedule it first.* Here that was `readProfileFromPath` and the artifact resolvers used as
**drift oracles** over foreign `.planning/` trees — machinery built to *resolve* being asked, for the
first time, whether what a file claims is true.

Running it at PLAN already produced `B59` (Signal's own Epic profile was unloadable, so the Epic
declaring FEATURE ran DISCUSS at FULL) and check **(h)** (not in the requirements; found only by
measuring). Wave 1 finished the job:

**The `cannot-evaluate` branch is not defensive programming — it is the deliverable.** `readState`
**throws** on `affiliate-mojo` (*"has frontmatter but no schema_version key"*). Before this slice,
that was a crash or a silent skip; a silent skip would have reported the project **clean** when
nothing looked at it. `tools/lib/state-drift.js` now reports it, with the reason, under a heading
that says in words *"these checks could not look. This is NOT the same as clean."*

**The probe reproduces the plan's numbers exactly**, so they are re-derivable rather than asserted:

```
readable STATE.md ........ 12/13
canonical phase .......... 7/12
Epic mode ................  4/12
...of those, strict ID ...  2/4
non-empty blockers[] .....  0/12
```

That last row is why check **(f)** was dropped: **no real project has a blocker**, so FR2.1's
"validate against a real non-Signal project" cannot be satisfied for it even in principle.

### Two design points that came out of building it, not planning it

1. **`healMechanism` is required for categories 1 and 2, enforced by the constructor.** Categories 1
   and 2 make a *promise* — "this clears on its own", "Signal fixed it". A promise whose mechanism
   cannot be named is unfalsifiable, and an unfalsifiable reassurance is worse than a finding. This
   is the generalised form of the defect caught in the plan itself, where **(d)** declared category 2
   while nothing healed it.
2. **The category-1 heading is tier-independent by construction.** *"Clears the next time Signal
   writes STATE here"* is true whether the next write is a phase-close `markFresh`
   (FEATURE/SPIKE/FULL) or a manual `/sig:checkpoint` (SKETCH, where four command files skip
   `markFresh`). The obvious wording — *"heals on next phase command"* — would be **false at
   SKETCH**, which is `B42`'s shape: a rule that silently mis-serves one tier.

**The registry ships empty at S1, and that emptiness is asserted, not assumed.** A test pins that the
category-2 bucket holds nothing, so the day a "Signal runs it" check is registered without
`/sig:sweep --heal` existing to run it, the suite fails rather than the user receiving a promise
nothing keeps.
