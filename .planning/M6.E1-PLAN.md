# M6.E1 — PLAN

**Phase goal:** make an install carry the plugin (~2 MB) instead of the repository (58 MB), without
breaking existing installs and without pinning users off `main`.

**Tier:** FULL · `plan_validation_dims: all` · `nyquist_enforcement: strict` · `gate_strictness: strict`
**Reads:** `M6.E1-REQUIREMENTS.md`, `M6.E1-RESEARCH.md`, `MILESTONE-6.md`, `B99`, `D-M6E1-1 … 6`.

---

## What this Epic does for the first time — and it is scheduled in wave 1

**Two shipped path expressions have never run at a tree depth other than the one they were written
at.** `tools/lib/plugin-binding.js:56` and `tools/lib/roster.js:22` both derive the **plugin root from
their own module path**, and both are correct today only because the plugin root and the repo root are
the same directory. This Epic makes them different for the first time in Signal's history.

**`plugin-binding.js` is `B52`'s mechanism** — *which copy of Signal is actually running*. Its
failure mode is silent and documented: one earlier sighting *"silently discarded M5.E8's six-phase
ledger."* A move that quietly breaks it produces a Signal that reports the wrong version of itself,
which is the condition under which every other verdict in this Epic becomes untrustworthy.

**Neither expression is new code.** That is the point (`M5.E17` FR1): the risk lives in machinery that
already exists, was built for a purpose, and has never been run under the shape about to be created.

**Therefore S1 is wave 1** — prove the two expressions under the new depth **before a single file
moves**, using a throwaway fixture tree. If the geometry is wrong, it is wrong against a fixture
rather than against 147 relocated files and a rewritten test suite.

**Second first, scheduled in S5 where it belongs:** Signal has never been fetched through a
URL-hosted marketplace, and `git-subdir` has never been used for it. That path is exercised for real
in S5, against the live domain, before the install page tells anyone to use it.

## Dependencies

```
S1 ──▶ S2 ──▶ S3 ──▶ S4 ──▶ S5 ──▶ S6
```

Strictly linear, and deliberately so. S2 is the only large slice and everything downstream depends on
the tree being settled; parallelising S3/S4 against a moving tree would buy hours and cost the ability
to bisect. **S1 gates S2 absolutely** — if the geometry does not hold, the Epic's approach changes
rather than its schedule.

## Environment

Node **22.13.0**; plugin targets Node 22+. No drift, no native modules, **no new dependency
introduced** — `yaml@2.8.3` is already resolved and merely re-declared. `npm ci --ignore-scripts`
needs no compiler toolchain.

## Rollback

Every slice is a revert. The **old install path keeps working throughout** (`AC5.1`), so a stop at any
boundary leaves users unaffected — including a stop after S2, when the repo is reorganised but the
catalogs still point the old way.
