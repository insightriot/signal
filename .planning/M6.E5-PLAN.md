set for this project, which the user installs.

**Tier FEATURE** (`M6.E5-PROFILE.md`): `plan_validation_dims: core`, `research_parallelism: 2`,

## What this Epic does for the first time — WAVE 1, ahead of everything

**`detectProjectKind` has never been called to let a command proceed.** Since `M4.5` its only
production caller has been `buildMissingPlanningError` (`add.js:217`), which uses it to pick *which
refusal to print*.

> ### ⚠ AMENDED 2026-08-27 by the probe this section scheduled — and this is the point of it
>
> The claim above is true. The **inference** — that `FR5.3` would therefore be the code path to call
> it — did not survive first contact. `detectProjectKind` returns `greenfield` for **any** directory
> without a `.git`, so a full codebase and an empty directory are indistinguishable (**`B112`**,
> filed with a control arm). **`FR5.3` uses `.planning/` presence instead**, which is one
> `existsSync` and carries none of the ambiguity.
>
> `AC-S1.t0-b` said to re-plan rather than work around it in the report layer. Re-planned — see
> `S4.t3` below. The probe changed the plan on the Epic's **first** task instead of its last, which
> is the `B55` outcome the wave-1 rule exists to buy. Full results: `M6.E5-RESEARCH.md` § Addendum.

**Second, same slice:** the prescribed-CLI extraction has only ever run over `plugin/commands` for
one verb (`prescribed-cli.test.js`). Reading `agents/`, `skills/` and `references/` for **every**
binary has never executed — and the `rm` finding already shows its output is not what a reader
predicts.

**So `S1.t0` runs both against real directories before anything is built on them.** If the scan's
reach or `detectProjectKind`'s verdict differs from what this plan assumes, it fails against a probe
rather than against a finished report. Full reasoning: `M6.E5-RESEARCH.md`.

## S1 — The scan and its classification · **wave 1** · **M**

*Vertical slice: after S1, `node -e` over the new module prints a classified candidate list for this
repo. Nothing else needs to exist.*

**Files:** `plugin/tools/lib/permissions-scan.js`, `tests/permissions-scan.test.js`

### `S1.t0` — FIRST EXECUTION PROBE (do this before writing S1's implementation) · **S**

Run, and write the results into `M6.E5-RESEARCH.md` as an addendum:

1. `detectProjectKind` against three real directories — this repo, `examples/url-shortener`
   (has `.planning/`), and a scratch directory with a `.git` and no `.planning/`.
2. A throwaway extraction over all four payload directories, printing the binary set.

- **AC-S1.t0-a** — The probe's actual output is recorded, including anything that contradicts this
  plan. A probe that only confirms is a probe nobody read.
- **AC-S1.t0-b** — If `detectProjectKind` returns something `FR5.3` cannot use, **stop and re-plan
  `S5`** rather than working around it in the report layer.

⚠ **Do not skip on the grounds that `S1.t1` will cover it.** `B55` was `M5.E13`'s largest finding
and surfaced on that Epic's *last* task, because that is when the machinery was first used for real.

### `S1.t1` — The two-layer scan · **M**

Implements `FR1.1`. Deterministic layer (`execFileSync`/`exec` call sites in `tools/`, `hooks/`) and
prompt layer (backticked strings in `commands/`, `agents/`, `skills/`, `references/`), returned as
**separately labelled** sources, each entry carrying its file and line.

- Satisfies `AC1.1a`, `AC1.1b`, `AC1.1c`, `AC1.1d`.
- **Reads the payload from disk** (`AC1.1d`) — never a committed file list.
- ⚠ **The four-directory reach is now measured, not assumed** (probe 2, 2026-08-27): **11 distinct
  binaries are reachable ONLY outside `plugin/commands`** — `cp`, `eslint`, `go`, `grep`, `npx`,
  `pip`, `pnpm`, `prettier`, `pytest`, `vitest`, `yarn`. A `commands`-only scan, which is the
  existing precedent's reach, would miss more than half the set.
- **Test strategy (TDD):** write the failing test first against a fixture tree with a known binary
  set; then a test asserting the live repo scan returns at least the pairs measured at DISCUSS; then
  an unreadable-directory test asserting `cannot-check`, **not** an empty clean result.

### `S1.t2` — The classification and its whole-population test · **M**

Implements `FR1.2`. One committed table, three verdicts (`propose-allow` / `propose-deny` /
`never-propose`), read by both the generator and the test (`AC1.2d` — two copies is `B82`).

- Satisfies `AC1.2a`, `AC1.2b`, `AC1.2c`, `AC1.2d`.
- ⚠ **New requirement from probe 2: provenance is part of the classification input, not just the
  binary name.** `plugin/agents` contributes 12 binaries and is where every language-ecosystem tool
  enters (`pytest`, `cargo`, `go`, `pip`, `pnpm`, `yarn`) — precisely the ones most likely to be
  *descriptions of other people's stacks* rather than prescriptions for this flow. A binary seen
  only in `agents/` is weaker evidence than one in `commands/`, and the classification must be able
  to say so.
- **Test strategy (TDD):** the load-bearing test is `AC1.2c` — feed it the **live** scan output and
  assert every returned binary is classified, so a new command prescribing a new tool fails the
  suite. Write it before the table, confirm it fails naming the unclassified binaries, then fill the
  table until it passes. **A test written against a fixture list would recreate the bug inside the
  test** — the mistake `prescribed-cli.test.js` explicitly avoided by deriving the identity.
- Separate assertions pin `rm` → `never-propose` (`AC1.2a`) and the history-rewriting git
  subcommands out of `propose-allow` (`AC1.2b`).

**Depends on:** `S1.t0`, `S1.t1`.

## S2 — Settings state and the delta · **wave 2** · **M**

*Vertical slice: reports what this project already grants, and what is missing, with no proposal
attached.*

**Files:** `plugin/tools/lib/permissions-state.js`, `tests/permissions-state.test.js`

### `S2.t1` — Read three scopes, three outcomes · **M**

Implements `FR2.1`. User / project / local, each **absent**, **readable**, or **`cannot-check`**.

- Satisfies `AC2.1a`, `AC2.1b`, `AC2.1c`.
- **Test strategy (TDD):** the discriminating tests are the ones that must not collapse — a
  **malformed** settings file and an **absent** one must produce *different* outcomes, and neither
  may render as "no rules". Write both before the reader. Delta suppression is tested against a
  fixture where a proposed rule is already granted **in a different scope** than the one being
  proposed into.

### `S2.t2` — The stated limit, rendered with the read · **S**

Implements `FR2.2`. The approximation warning (`PreToolUse` hooks; two unreadable scopes; five-scope
precedence) renders **whenever the read renders**.

- Satisfies `AC2.2a`, `AC2.2b`.
- **Test strategy:** assert the limit text is present in the rendered output for every read outcome,
  including the all-clean one. **The clean path is the one that would drop it**, and a limit that
  appears only on failure is the reassurance-shaped bug this Epic is supposed to avoid.

*Vertical slice: names the host project's stack and the rules it implies, independent of everything

**Files:** `plugin/tools/lib/stack-detect.js`, `tests/stack-detect.test.js`

Implements `FR3.1`. Presence plus **shallow** parse of `package.json`, `pyproject.toml`, `setup.py`,
`Cargo.toml`, `go.mod`, `Gemfile`, `composer.json`. **No new dependency** — `JSON.parse` for JSON,

Implements `FR3.2`. A docblock and a docs line stating this is a **new detector, not a reuse** —

- Satisfies `AC3.2a`, `AC3.2b`.
- **Test strategy:** a doc-integrity assertion that the module names the relationship. ⚠ **Stated

## S4 — The report, the proposal, the deny list · **wave 3** · **L**

*Vertical slice: the full rendered output, from a real repo, before any command file exists.*

**Files:** `plugin/tools/lib/permissions-report.js`, `tests/permissions-report.test.js`

### `S4.t1` — Render the report · **M**

Composes `S1`–`S3`. Flow-derived and stack-derived rules labelled separately (`AC3.1d`); suppressed
already-granted rules counted (`AC2.1c`); every `cannot-check` visible as a line the user sees
(`NFR2`).

- Satisfies `AC5.1c` (renders when nothing is proposable, saying so), `NFR1`, `NFR2`, `NFR4`.
- **Test strategy (TDD):** golden-output tests over fixture trees. Includes the empty case — a repo
  where everything is already granted **still renders a report**.
- **`NFR4` — offline and deterministic, and this needs its own two tests, not an assertion in a
  docblock.** (a) **Determinism:** render twice over an unchanged fixture and assert the two outputs
  are **byte-identical**, which catches the ordinary causes — `readdirSync` order, `Set`/`Object`
  iteration, an unsorted merge — none of which a reviewer reliably spots. (b) **Offline:** assert no
  network call is reachable from the render path. ⚠ *Added at plan validation, not at authoring:
  the completeness pass found `NFR4` covered by no task while all 10 FRs and 34 ACs were covered —
  the requirement most likely to be quietly skipped is the one nobody wrote a task against.*

### `S4.t2` — The deny proposal · **S**

Implements `FR4.1`. Short, each entry naming why; the absoluteness warning at the list; the three
platform mode names and **no fourth**.

- Satisfies `AC4.1a`, `AC4.1b`, `AC4.1c`, `AC4.1d`.
- **Test strategy:** assert the deny set is bounded (a hard cap the test enforces, so it cannot grow
  by accretion into the work-stopping shape `AC4.1b` warns about); assert `B75`'s no-fourth-dial
  rule by checking the output introduces no Signal-invented mode name.

### `S4.t3` — Write the tracked artifact · **M**

Implements `FR5.1`, `FR5.2`, `FR5.3`.

- Satisfies `AC5.1a`, `AC5.1b`, `AC5.2a`, `AC5.2b`, `AC5.2c`, `AC5.2d`, `AC5.3a`, `AC5.3b`,
  `AC5.3c`, `AC5.3d`.
- **Test strategy (TDD), and two tests here are the Epic's real safety net:**
  - `AC5.1a` — a test asserting **no write path touches `.claude/` or `~/.claude/`**. Assert over
    the module's actual write calls, not over a reviewer's reading.
  - `AC5.3a`/`AC5.3b` — run the whole report in a fixture repo with **no `.planning/`**: it renders
    in full, and the artifact step reports **skipped with its reason**. `AC5.3c` asserts
    `.planning/` was **not created** — check the directory afterwards, since "we didn't mean to" is
    not evidence.
  - ⚠ **RE-PLANNED 2026-08-27 (`AC-S1.t0-b`): detect `.planning/` with `existsSync`, NOT with
    `detectProjectKind`.** The probe found `detectProjectKind` returns `greenfield` for any
    directory lacking a `.git`, so it cannot distinguish a full codebase from an empty one
    (`B112`). It also answers a different question — *which refusal to print* — and `FR5.3` is not
    printing a refusal. **Do not import it here**, and do not "improve" it from this Epic: it is
    `/sig:add`'s path, and `B112` is filed for whoever takes it.
  - `AC5.2c` — idempotence: two runs on an unchanged tree leave the file's mtime untouched.
