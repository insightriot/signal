# M6.E15 — Plan: move other projects onto the work store

**Phase goal:** `/sig:docs-migrate --work-store` turns the store on for any project and moves
corpus project 1's hand-kept lists into records with nothing lost, and docs-migrate stops archiving
units that are not closed (`SIG-286`).

Requirements: [`M6.E15-REQUIREMENTS.md`](M6.E15-REQUIREMENTS.md). Research:
[`M6.E15-RESEARCH.md`](M6.E15-RESEARCH.md). Tests: [`M6.E15-VALIDATION.md`](M6.E15-VALIDATION.md).
Decisions `D-M6E15-1` … `-22`. Node 22+ assumed; dev machine Node 22.13.0. TDD throughout: each task's
first commit is a test that fails on this branch before the change.

## What this Epic does for the first time — wave 1

- **A project shape never tried:** the store turned on in a repository that is not Signal. Every store
  write, view and hook has only ever run against Signal's own `.planning/` (`SIG-274`).
- **A tool used on input it was not built for:** the segmenters, run on corpus project 1's lists,
  throw on the first bug and produce no correct question (RESEARCH §1). That was found by running
  them at PLAN; the remaining unknown is whether records built from those lists pass `validateRecord`
  / `checkEvents` and render views.

**Therefore S1 is wave 1** (the on-switch in a non-Signal temp repo, end to end), and S2's first task
writes the corpus-shape fixtures and runs them through the current segmenters before anything changes.
