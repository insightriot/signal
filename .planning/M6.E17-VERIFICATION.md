## Verdict

**FAIL — three Important defects, each reproduced. 18 of 18 acceptance criteria are met as written,
12 fully and 6 with a limit. None is unmet.** The suite, perf run, lint, build and plugin validation
are all clean.

It fails because two of the defects defeat the purpose of the Epic in practice, even though every
criterion's wording holds:

- **D1 — a linear project carries pass records from one run into the next.** `completePhase('SHIP')`
  in linear mode (`plugin/tools/lib/state.js:743-763`) archives and clears `completed_phases` but
  leaves `phase_passes`. The verifier's demo: record two REVIEW passes, then complete SHIP. Afterwards
  `completed_phases` is `[]`, `phase_passes` still holds both, and `loopStatusFor` reads
  `count 2, atCeiling true`. On the next run, the first REVIEW halts `/sig:drive` with `loop-ceiling`
  before any pass of that run. This hits every linear project after the update. AC1.3 names only the
  Epic roll, so the criterion is met; the intent ("the records are per unit of work") is not.
- **D2 — the report check cannot see a fix round that was never written down.**
  `checkFixRounds('# Review pass 2 after FAIL loop-back\nAll fixed.\n', 'PASS')` returns
  `{ok: true, rounds: []}` (reproduced). A PASS after an earlier REVIEW FAIL is exactly the case
  AC2.3 exists for, and the check takes no state, so it cannot know the FAIL happened. The record
  that would tell it is `phase_passes`, which this Epic added.
- **D3 — `parent-run.js` exits 0 with no output when its path is reached through a symlink or
  contains a space.** The main-module check at `plugin/tools/lib/parent-run.js:299` compares
  `import.meta.url` against `` `file://${process.argv[1]}` `` without resolving or encoding it.
  Reproduced: `node <symlink>/tools/lib/parent-run.js --bogus` gives exit 0 and no output; the same
  call on the real path gives exit 2. **Exit 0 is the tool's "every file failed on the base" answer,
  which is proof.** A silent run that reads as proof is the failure FR3 exists to stop.

  decides how often D3 fires. The cache folders on this machine are plain directories with no space.
  The fix does not depend on the answer.
- **Where an executor gets "the commit the task started from" for `--base`.** Nothing in `state.js`
  records it at `setCurrentTask`, so `execute.md` and `executor.md` leave the agent to work it out. It
  was correct in this Epic because it was done by hand.
- **Whether `/sig:drive` checks the count between passes when one `/sig:review` run makes several
  passes.** The driver checks once per command (`drive.md` § 3, step 2). Not exercised.
- **Being killed mid-run.** `parent-run.js` cleans up in `finally`. A kill signal during the blocking
  vitest run skips it, and the temp folder survives. A later `git worktree prune` clears the worktree
  entry, but not the folder.

  `toBeLessThan`. It does not detect `new Date()` arithmetic or `expect(elapsed < n).toBe(true)`. Its
  "never grow" check is a count, so swapping a file on and off the list, or adding a second budget to
  a file already on it, passes.
- **The Outcome** (REQUIREMENTS § Outcome) is checked at the next Epic whose REVIEW loops, not here.
- **This report checks claims against code by reading.** No mutation run was done beyond the
  parent-run results.
