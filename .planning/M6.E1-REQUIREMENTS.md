## Functional requirements

### FR1 — The plugin payload lives under `plugin/`

`commands/`, `agents/`, `skills/`, `references/`, `hooks/`, `tools/lib/` and
`.claude-plugin/plugin.json` move to `plugin/`. `tests/`, `.planning/`, `analysis/`, `docs/`,
`examples/`, the nine `tools/*.js` maintainer scripts, and the root `package.json` stay put.

- **AC1.1** — `plugin/` contains every file a `/sig:*` command reads at runtime, and no file outside
  `plugin/` is required for any command to run.
- **AC1.2** — **No file under `plugin/` imports, reads, or references a path outside `plugin/`.**
  Enforced by a test, not by review: the failure mode is invisible locally (the file exists in the
  repo) and only appears after installation. Includes `${CLAUDE_PLUGIN_ROOT}`-relative paths in
  `commands/*.md`, `hooks/*`, and `tools/lib/*.js`.
- **AC1.2a — the outward-reference test must declare its detected population and what it misses.**
  A grep for `../` catches the easy cases and misses the ones that matter: `${CLAUDE_PLUGIN_ROOT}/../x`,
  a command file naming a repo path in prose, a `join(__dirname, '..', '..')` in `tools/lib`. **This is
  `B81`'s shape** — a population-of-one assertion passing while governing almost nothing — arriving on
  this Epic's single most important invariant. PLAN must state what the detector's population **is**
  and what it demonstrably does **not** reach; a bare "no matches found" is a false green here.
- **AC1.2b — absolute user-config paths are out of AC1.2's scope, stated once.** `/sig:doctor` reads
  `~/.claude/plugins/known_marketplaces.json` (`AC5.2`). That is an absolute path in the user's home,
  not a repo-relative traversal, and it is **not** a violation. Written down so a reviewer applying
  AC1.2 mechanically does not flag it and re-argue it.
- **AC1.3** — the full suite passes with imports repointed (138 test files import `tools/lib`).
- **AC1.4** — `npm run build`, `npm run lint`, `npm run validate` and the vitest `include` globs all
  resolve post-move.
- **AC1.5** — `validate-plugin.js` validates the plugin at its new root (its `ROOT` is
  `join(__dirname, '..')`, which changes meaning when `tools/lib` moves and the script does not).

### FR2 — No command file cites a path that will not exist in an install

- **AC2.1** — a grep (**not** a recollection — `D-M6E1-2`) over `commands/**` and `agents/**` for
  every `tools/…`, `references/…`, `skills/…` and `${CLAUDE_PLUGIN_ROOT}/…` path, checked against
  what ships. Every hit either resolves inside `plugin/` or is amended.
- **AC2.2** — `ship.md`'s `node tools/adherence-run.js` line is amended to name itself a
  Signal-repository step, since the script deliberately does not ship (`D-M6E1-2`).

### FR3 — The plugin declares `yaml` and nothing else

- **AC3.1** — `plugin/package.json` declares exactly one dependency, `yaml`, and no
  `devDependencies`; a lockfile sits beside it so Claude Code's install is triggered and frozen.
- **AC3.2** — a fresh cached install contains `node_modules` **≤ 3 MB** and contains no `vitest`,
  `eslint` or `esbuild`.
- **AC3.3** — a test asserts `plugin/package.json`'s `yaml` version matches the root
  `package.json`'s, so the two manifests cannot drift (`D-M6E1-3`'s stated cost).
- **AC3.4 — the failed-install path is specified, not assumed.** The documented install is
  `npm ci --ignore-scripts`, which needs a reachable registry **at install time**, and a failed
  install *"never blocks the plugin"*. So a restricted-network user can receive a plugin whose two
  most load-bearing files fail to import. This AC requires that outcome be characterised and made
  legible — not that it be prevented.
- **AC3.5 — PLAN must evaluate vendoring before the manifest is built.** A third option was **not**
  enumerated at DISCUSS and must be weighed in PLAN: vendor `yaml`'s files into `plugin/vendor/` with
  a rewritten import. It keeps `tools/lib/*.js` as **source** — the stated reason the esbuild bundle
  was rejected (`D-M6E1-3`) — needs **no manifest**, and **never triggers the install**, which
  dissolves `AC3.4` entirely rather than documenting it. Cost: a vendored dependency to update by
  hand, and `yaml`'s own license and file layout to respect. **If vendoring wins, `D-M6E1-3` is
  superseded and `FR3` is rewritten** — recorded here so that outcome is a decision, not a drift.

### FR4 — Two catalogs, both honest

- **AC4.1** — `.claude-plugin/marketplace.json` carries `"source": "./plugin"` — the relative
  **string** form. `install-contract.test.js`'s assertion moves `.` → `./plugin` and **keeps** its
  string-form and no-sha checks (`B58`).
- **AC4.2** — `docs/map/install/marketplace.json` carries a `git-subdir` source (`url` = this repo,
  `path` = `plugin`) and **no `ref` and no `sha`**.
- **AC4.3** — a test pins the invariant rather than byte-equality (`D-M6E1-4`): both catalogs name the
  same plugin `name`, and **neither** carries a `ref` or `sha`. A byte-equality test would be wrong
  and would break one of the two fetch paths.
- **AC4.4** — `https://signal.insightriot.com/install/marketplace.json` returns the published catalog
  over HTTPS, and `claude plugin marketplace add` against that URL installs a working plugin.

### FR5 — Existing installs keep working, and Signal says so

- **AC5.1** — `/plugin marketplace add insightriot/signal` still installs a **working** plugin after
  this Epic. Nobody is stranded (`D-M6E1-5`).
- **AC5.2** — `/sig:doctor` detects a `github`-sourced `signal` marketplace in
  `~/.claude/plugins/known_marketplaces.json` and prints the one-line switch to the URL form.
  Read-only and fail-open: an unreadable or absent file reports *could not check*, never *clean*
  (`B39`).
- **AC5.3** — the check is **absent-safe in both directions**: a user already on the URL form gets no
  nag, and a machine with no Signal marketplace at all does not error.

### FR6 — The install page carries the migration

- **AC6.1** — `signal.insightriot.com/install` gains an existing-user section whose first snippet is
  the URL-form `marketplace add`.
- **AC6.2** — the section **does not** tell users to delete plugin version directories. Measured:
  11 of 13 cached versions are inside the documented ~14-day orphan sweep and clear themselves
  (`B99`). It **does** cover the marketplace clone, which does not self-clean and is orphaned by this
  change.
- **AC6.3** — the page's primary install snippet becomes the URL form.

## Non-functional requirements

- **NFR1 — Reversibility.** Every step is a git revert away, and the old install path keeps working
  throughout (`AC5.1`), so a mid-Epic stop leaves users unaffected. **Blast radius:** 138 test files,
  4 build/config entry points, ~20 command files, and the public install path.
- **NFR2 — Supply integrity.** The published catalog is served over HTTPS from a domain we control
  and carries no `ref`/`sha`, so there is no pin to a commit to compromise (`D-M6E1-6`).
- **NFR3 — Boundary failure is legible.** If the dependency install fails, the documented behaviour is
  that it *never blocks the plugin* — so a missing `yaml` must surface as a clear error from
  `profile.js`/`state.js`, not as an unexplained failure three commands later.
- **NFR4 — N/A by shape, recorded rather than skipped** (`D-M6E1-6`): health/liveness probes, graceful
  shutdown, structured request logging, security headers, rate limiting. This Epic ships no service
  and opens no port.

## Out of scope

- **Whether `.planning/` should be public at all.** This Epic stops it being *copied to users*.
  Keeping it in a public repo is a separate, deliberately deferred decision (`B99`).
- **The 728 MB / 13-version local cache.** Mostly self-clearing; not this Epic's to fix.
- **Renaming `migrate-memory` → `migrate`** (`D-BR0809-3`) — a breaking window, unrelated to payload.

## Done when

A fresh install carries only the plugin payload; `.planning/` and `tests/` reach no user by **either**
fetch; `node_modules` in the cache is ~1.2 MB rather than 47 MB; users still track `main` with nothing
pinned; existing installs still work and are told how to move; the suite is green.
