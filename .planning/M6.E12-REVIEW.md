## Important Issues (should fix)

1. **A priority can cover a row the same artifact lists as dropped** (code-reviewer I1, test-engineer
   I2). `validatePriorities` checks covers against every parsed row, not the rows `classifyRows`
   keeps live (`advise-priorities.js:63`). A covered `Parked` row renders under the priority *and*
   under *Dropped*. Contradicts the refusal message, `advise.md` step 3, AC2.3 and the judgment line.
2. **The citation count gate has slack** (code-reviewer I2). `claims` counts one per priority while
   `resolved` counts one per evidence token, and the gate is `>=`; extra evidence tokens hide missing
   appendix citations (`advise.js:803,813`). AC2.4 is not met as stated.
3. **A `## Picked by you` substring anywhere blocks every pick** (security 3, code-reviewer I3). Both
   `nextArtifactName` and `recordChoice` use `includes`; a backlog row or a model title quoting the
   heading makes every fresh advisory read as picked, and runs climb `-2 … -999`.
4. **The digest cap is not a bound** (security 4, code-reviewer I4, test-engineer I1). High-priority
   bugs, milestone rows, open Epics and vision are never trimmed: 3,000 P1 bugs → 563,616 characters
   against 24,000, with an innocent group cut to zero and no note that it still did not fit. **AC1.4 was
   recorded as verified in VERIFY and is not met** — the tests grew only trimmable groups.
5. **Digest reads follow symlinks out of the project** (security 1). Five new sources use plain
   `readFile`; a cloned repo's symlinked `MILESTONE-*.md` put an outside secret into the digest.
   `readFileConfined` exists for exactly this (`path-confine.js`, M6.E3). The corpus's BACKLOG/BUGS
   reads have the same exposure, pre-existing.
6. **`recordChoice` writes `at` unescaped** (security 2, code-reviewer nit). A newline in `at` forged a
   `## Priorities` heading and a priority after the gate had run.
7. **Oversized or cyclic proposals are processed exponentially** (security 5, code-reviewer S4). The count
   refusal does not return; the cycle walk has no memo — 24 priorities with dense `dependsOn` took 822 ms,
   doubling per priority. Model output, so it is untrusted input.
8. **`drive.md` step 0a misdescribes the backlog order** (code-reviewer I5). It says "the rest in file
   order" and "age has never been an input"; `rankBacklogRow` floats id- and tag-led rows, then ties on
   line number, which this Epic's own REQUIREMENTS call close to oldest-first. AC5.3 is not met as written.
9. **Digest tests check range, not content, and miss whole sources** (test-engineer I3, I5). Shifting
   cited lines by +1 went uncaught (4 of 4); removing local open Epics, other-branch Epics, milestone rows,
   the newest-three limit or the retro order went uncaught. The appendix half of the stale guard is
   untested when covers are bugs only (I4).

## Suggestions (optional improvements)

- Bug stale probe matches `B1` inside `B12` — use a word-bounded match (code-reviewer S1).
- Whole-file evidence (`path` with no line) passes while AC2.3 says `path:line` — the doc allows it; decide and align (S2). **Decision: allow it** — a whole file is legitimate evidence (the first real proposal cited `work-migrate.js`); amend AC2.3 and the refusal text.
- `recordChoice` takes a number only; a re-run while asking can record N against a different list — accept the expected title (S3).
- The same row twice in one priority is accepted and counted twice (S5, test-engineer nit).
- `bugPriority` hard-codes column 3 (S6) — unverified against corpus shapes; leave, note.
- The artifact's "Digest read" describes a re-read at write time (S7) — say so in the label.
- `formatDigest` rebuilds per trimmed entry, quadratic (security 6, test-engineer, in-session) — compute cuts from lengths, build once.
- The user's words should reach `recordChoice` through a scratch file, like the proposal (security 7).
- Untested caps and reasons: retro clip, question cap, unreadable-vs-absent for 7 of 8 sources; AC1.3 assertion is loose (test-engineer).
