## What shipped

Five checks for one defect class — **a document states a fact about the project and nothing derives
it from the artifact it summarises** — plus the write-path fix that stops `/sig:add --bug`
falsifying the file it writes to.

- `plugin/tools/lib/published-facts.js` — a registry built on `state-drift.js`'s existing
  `defineCheck` harness, exporting its own frozen set rather than being appended to
  `STATE_DRIFT_CHECKS` (`D-M6E2-3`).
- `ALL_DRIFT_CHECKS` composed into `/sig:sweep` and `/sig:resume` — the two commands that already run
  drift checks in any project.
- `insertBugsEntry` + `rewriteBugTally` in `add.js` — a capture now lands **above** `BUGS.md`'s tally
  and the counts are **re-derived**, never incremented.
- `tools/measure-published-facts.js` — the read-only corpus probe that decided the Epic's scope.

## The finding that mattered most: reach

The Epic was pitched on **five instances found in five files of this repository**, with an implied
generality nobody had checked. The corpus run, taken **before scope was locked**, found:

| Published fact | With Signal | Excluding Signal |
|---|---|---|
| `BUGS.md` tally | 1 / 12 | **0 / 11** |
| Milestone Epic-status rows | 1 / 12 | **0 / 11** |
| `[Unreleased]` heading | 4 / 12 | 4 / 11 |

**Three of the five reach only this repository.** Brett ruled *no trimming* (`D-M6E2-1`), on the
`M5.E10` precedent that narrow reach has never been the disqualifying property here — claiming
generality you do not have is. So the scope decision created an obligation of **disclosure**, which
`S4` discharged: `renderDriftReport` now prints one grouped line naming every narrow check with its
fraction, placed with the clean count it qualifies.

## What went wrong, in order

**1. The requirements were wrong about their own foundation.** `FR1` said the inbox path "already
solves this" with `insertAboveFooter` + `rewriteFooter`. It does not: `FUTURE_IDEAS_FOOTER_RE`
requires a line beginning `*Last updated:` with no interior asterisk, and `BUGS.md`'s footer begins
with the tally and carries bold spans. The *pattern* transfers; the helpers do not. **Caught at PLAN**
by the "what does this Epic run for the first time" step, which sent us to run the regex against the
real file.

**2. The plan wrote acceptance criteria as en-dash ranges.** `diffRequirementCoverage` returned three
missing (`AC1.2`–`AC1.4`) because an id inside a range is invisible to it. **That is `M5.E10`'s exact
finding, reproduced by the Epic about published facts being wrong, while writing its own plan.**

**3. The first applicability rule flattened an unknown into an exemption.** `S1.t1` originally
returned `NA` for a `BUGS.md` publishing no tally. `compareBugTally` already refuses that case on the
stated grounds that *silence must not read as clean* — and it is **the only non-Signal case the check
can see**, since all three non-Signal projects with a `BUGS.md` are in it. Caught at PLAN review,
before code.

**4. `AC3.2` could not be made precise, and the measurement said so.** Three rules, measured over 28
`confirmed` rows: any mention → 13 flags / 1 real; mention + fix-language → 3 / 1; headline → 2 / 1.
The natural rule fails on *"`B81` remains open (filed not fixed)"* — the word is present, the meaning
inverted. **This Epic's own out-of-scope boundary (`D-M6E2-7`) appearing inside it.** Shipped as the
best of three with its precision printed in the check's `describe` and in every finding.

**5. A silent no-op inside the fix for silent falsification.** `rewriteBugTally` spliced only the
**bolded** total marker while `readPublishedTally` accepts the unbolded form — so on such a file the
replace did nothing, the count stayed wrong, and the capture reported success. Every S2 fixture used
the bolded shape because that is Signal's own. **`B82`'s blind spot exactly**, and it took a REVIEW
probe against a hand-built variant to find it.

**6. The report heading stopped being true.** `## STATE vs. world` while the section had grown
published-fact checks. Renamed at REVIEW.

**7. Two wrong numbers in this Epic's own artifacts.** A commit sha in `PROGRESS.md` that does not
exist, and a test count in `REVIEW.md` that was 2 too high. Both caught by reading the documents back
against the tools. Both are the class.

## What changed mid-flight

- **Scope did not shrink when the evidence weakened it.** The measurement showed three of five
  instances were Signal-only; the recommendation offered a trim to fix-lane. Brett chose all five
  with reach published (`D-M6E2-1`), which converted the Epic from *"a general defect class"* to
  *"one general check, one command bug, and three hygiene checks that share a mechanism"* — a smaller
  claim about the same work.
- **`AC3.2`'s matching rule changed twice** — loose, then fix-language, then headline — each time
  against a measurement rather than an argument.
- **The `/sig:add` implementation moved home**, from `add.js`'s inbox helpers to `bugs-tally.js`'s
  primitives, once the footer shapes were compared.

## What assumptions broke

1. **"The inbox path already solves this."** It does not — different footer shape, different regex.
2. **"These are registry entries, not a new mechanism."** This one **held**, but only because it was
   checked: `defineCheck`'s contract is general, verified by reading it rather than inferred from a
   registry whose eight entries are all STATE-shaped. Had it been wrong the Epic was materially bigger.
3. **"A `BUGS.md` without a tally is not applicable."** It is an *unknown*, and it is the only
   non-Signal case the check can see.
4. **"A CHANGELOG naming a bug id means the bug shipped."** Measured at 1-in-13.

## What surprised us

- **The Epic's own artifacts kept committing its defect.** A non-existent commit sha in `PROGRESS.md`;
  a test count 2 too high in `REVIEW.md`; acceptance criteria hidden inside en-dash ranges; a report
  heading that stopped being true. Four instances of *"a document asserting something nothing
  derives"* produced **while building the checks for exactly that**.
- **The first real sweep found a defect the new check did not catch.** `body-omits-current-epic` — an
  existing check — fired on `STATE.md` one hour in. The value came from *running the registry here for
  the first time*, not from the thing being built.
- **`B75` is a false positive the design cannot remove.** Pinning it as a passing test felt wrong and
  is right: the test asserts documented behaviour, not good behaviour.

## What we'd do differently

- **Measure reach at DISCUSS, not at PLAN-adjacent research.** The corpus probe should be the first
  action of any Epic proposing a detector. It changed this Epic's central claim and cost twenty
  minutes.
- **Write acceptance criteria through the coverage tool from the first draft.** Running
  `diffRequirementCoverage` against the requirements *while writing them* would have caught the
  en-dash ranges before they reached a plan.
- **Build fixtures from a shape the author did not choose.** Every S2 fixture used Signal's bolded
  tally, which is why the unbolded no-op survived to REVIEW.
- **Get an independent read.** Two of this Epic's defects were found by running tools against the
  work. None were found by re-reading it.

## What to feed back into Signal

- **A reach measurement belongs in the DISCUSS gate** for any Epic that ships a detector, the way the
  inbox drain belongs in PLAN. Candidate for `BACKLOG.md`.
- **`diffRequirementCoverage` should run at PLAN, not only at VERIFY.** It caught three missing ids
  here only because it was invoked by hand.
- **`checkValidationConsistency` returned `cannot-evaluate` on a well-formed VALIDATION** because the
  completeness dimension named no ids. Worth a template note so the check is fed by default.
- **The retro template's FULL headings were discovered by failing the gate**, not by reading the
  template first. A pointer in `ship.md` §0.5 would save the round-trip.

## Anti-rationalization moment

*"The `AC3.2` check is noisy — 13 findings, mostly wrong. Ship it anyway; a person can filter."*

Rejected. Thirteen findings on a first run is how a check earns a mute, and a muted check is the
exact defect this Epic exists to end — building a mechanism nothing reaches. The alternative
temptation, *"cut it, it doesn't work"*, was also wrong: Brett had ruled no trimming.

What survived both was **measuring three rules and publishing the winner's precision in the check's
own output**. That is neither shipping noise nor hiding a weakness; it is letting the reader price
the finding. The second temptation — *"the `remains open` false positive is embarrassing, quietly
tighten the rule"* — was rejected the same way: the tightened rule measured **worse**, and the test
that pins the false positive exists to stop a future reader making that exact improvement.

## What worked

- **Measuring before deciding.** The corpus probe cost twenty minutes and changed what the Epic
  claims about itself. Without it this would have shipped as *"five instances of a general class."*
- **Wave 1 = what runs for the first time.** It paid twice before any code: the `insertAboveFooter`
  finding, and — one hour in — the composed registry's first real sweep catching `STATE.md`'s own
  narrative saying *"Milestone 6 is not opened"* while its frontmatter said `M6.E2`.
- **Leaving evidence broken on purpose.** `B102`'s row was left reading `confirmed` until a check
  found it (`D-M6E2-5`). It was then corrected *by the check*, and the tally re-derived by
  `rewriteBugTally` on real data for the first time. Fixing the evidence first would have shipped
  both untested against the only real instances available.
- **Asserting the write path through the detector.** `AC1.2` requires `compareBugTally(after).ok`
  after a capture. The two cannot drift apart without a test going red.

## Carried forward

- **`bug-status-vs-changelog` ships at 1-in-2 measured precision.** If it earns a mute, that is the
  signal to cut it — and the honest fix is semantic comparison, which stays out of scope.
- **Two real findings left open deliberately:** the dated `[Unreleased]` heading needs a product call
  (`OPEN-QUESTIONS.md`), and `facts.md`'s attribution belongs to `cut-release.js`.
- **No independent review.** Research, planning and review all ran single-context; the second reader
  was a stronger model on the same transcript, not a fresh-context agent on the diff. This Epic found
  two defects by *running* tools rather than reading, which is the argument for the independent pass
  it did not get.
- **The semantic half remains unbuilt** (`D-M6E2-7`). Everything here compares tokens.
