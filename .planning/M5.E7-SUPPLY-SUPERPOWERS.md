## 2. The five-round breaker — the actual portable mechanism

Lives in `skills/subagent-driven-development/SKILL.md` (503 lines) plus three prompt
templates and three bash scripts. This is a **specified, sized, artifact-backed control
loop** — the opposite of `<HARD-GATE>`. Everything below is from the tree at `3dcbd5c`.

**Dating: this is two days old.** `RELEASE-NOTES.md:10`, under `## v6.2.0 (2026-07-23)`:
"The lifecycle restructure gives fix rounds resume-the-implementer semantics instead of fresh
dispatches, adds a scoped re-review prompt (`re-review-prompt.md`) … and **installs a
five-round circuit breaker with controller adjudication when it trips.**" The ledger and
file-based reports are older — `RELEASE-NOTES.md:116` under `## v6.0.0 (2026-06-16)`.
Anyone sizing a port should know the loop's current shape has ~2 days of field exposure.

### 2.1 Roles

Three roles, each a separate dispatch with its own context:

- **Controller** — the session. Never writes code. `SKILL.md:355`: "Never fix findings
  yourself in the controller session — your context stays clean for coordination, and
  controller fixes skip review."
- **Implementer** — one fresh subagent per task (`implementer-prompt.md`).
- **Reviewer** — task reviewer (`task-reviewer-prompt.md`), then scoped re-reviewer
  (`re-review-prompt.md`), then a whole-branch final reviewer
  (`../requesting-code-review/code-reviewer.md`).

`SKILL.md:230`: "**Never dispatch multiple implementation subagents in parallel
(conflicts).**" The loop is strictly sequential per task.

### 2.2 The loop, concretely

**Setup** (`SKILL.md:110-155`):
- Worktree via `superpowers:using-git-worktrees`; never start on main without consent
  (`:112-115`).
- `scripts/sdd-workspace PLAN_FILE` prints a per-plan git-ignored directory,
  `<repo-root>/.superpowers/sdd/<plan-basename>/` (`:122-125`, script lines 31-40). It writes
  a self-ignoring `.gitignore` (`sdd-workspace:39`).
- Ledger at `<workspace>/progress.md`, first line `# SDD ledger — plan: <plan file path>`
  (`:134-135`). Resume rule (`:126-133`): tasks with a `Task <N>: complete` line are done;
  a task whose last line is a fix round is mid-loop, resume at the next round; a ledger
  naming a different plan is left alone.
- Rationale, verbatim (`:117-120`): "Conversation memory does not survive compaction. In real
  sessions, controllers that lost their place have re-dispatched entire completed task
  sequences — the single most expensive failure observed."
- **Pre-flight conflict scan** (`:145-155`): before Task 1, scan the plan for tasks that
  contradict each other or the Global Constraints, and for anything the plan mandates that
  the review rubric treats as a defect. Present as **one batched question**, not one
  interrupt per discovery.

**Per task** (`SKILL.md:200-389`):
1. Record `BASE` = `git rev-parse HEAD` (`:202-203`). Run `scripts/task-brief PLAN_FILE N`
   → writes `task-N-brief.md`, prints the path (`:206-216`). The brief is the single source
   of requirements; exact values appear only there; "Never make a subagent read the whole
   plan file" (`:216`).
2. Implementer writes a full report to `task-N-report.md` and returns **under 15 lines**
   (`implementer-prompt.md:128-135`): status, commits, one-line test summary, concerns,
   report path.
3. Status enum, four values (`implementer-prompt.md:130`): `DONE | DONE_WITH_CONCERNS |
   BLOCKED | NEEDS_CONTEXT`. Controller handling at `SKILL.md:236-254`.
4. `scripts/review-package PLAN_FILE BASE HEAD` writes commit list + `--stat` + `git diff
   -U10` to one file and prints the path (`review-package:32-46`). Explicit warning against
   `HEAD~1`, which "silently drops all but the last commit of a multi-commit task"
   (`SKILL.md:238`).
5. Task reviewer returns **two verdicts in one dispatch** — spec compliance and task quality
   (`task-reviewer-prompt.md:139-165`), plus a `⚠️ Cannot verify from diff` channel for
   requirements living in unchanged code (`:145-147`). The controller must resolve each ⚠️
   itself; a confirmed gap "enters the fix loop with the other findings" (`SKILL.md:293-298`).

**Two exits before the loop** (`SKILL.md:307-318`):
- **Minor findings never enter the loop.** Ledgered as `Task <N>: minor (deferred): <one-liner>`
  and handed to the final review. "A roll-up nobody reads is a silent discard."
- **Plan-mandated findings go to the human**, not the loop: present the finding beside the
  plan text, ask which governs.

**A round** = one fix dispatch + one scoped re-review (`SKILL.md:319-320`). Max five.

### 2.3 What trips the breaker

Two conditions, in order (`SKILL.md:94-96`, `:358-359`):

1. Round counter reaches **R = 5** — the dot-graph diamond is literally `"R = 5?"`
   (`SKILL.md:64`, edge label `"yes - breaker trips"` at `:96`).
2. **AND** round 5's scoped re-review still leaves findings open.

`SKILL.md:358`: "When round 5's re-review still leaves findings open, stop dispatching."

**Escalation inside the loop, before the cap** (`SKILL.md:322-333`):
- Rounds **1-3**: resume the *original* implementer, sending open findings verbatim — its
  context is intact. Fallback if the harness cannot message a live subagent: fresh
  implementer carrying the brief path, report-file path, and findings.
- Rounds **4-5**: fresh implementer on a **more capable model**, framed "A prior implementer
  attempted this task [N] times; you own it now. Read the report file for what was tried."
  Rationale at `:332-333`: "A loop that survives three resumes usually means the implementer
  cannot see its own problem — fresh eyes and a capability bump in one move."

**Round gating** (`SKILL.md:335-341`): before re-dispatching the reviewer, the controller
confirms the fix report contains the covering tests, the command run, and the output. All
three present, or no re-review.

**Anti-early-adjudication rule** (`SKILL.md:373-375`): "Adjudicate only at the cap.
Adjudicating earlier to end a loop is pre-judging with a different name. Every adjudication is
a ledger entry — a silent discard is forbidden."

### 2.4 The three-way adjudication at the cap

`SKILL.md:360-371` — the controller rules on each still-open finding:

| Ruling | Condition | Action |
|---|---|---|
| Park (contestable) | "The reviewer is wrong, or the point is contestable" | `Task <N>: parked — <finding> — ruling: <why the code stands>`; final review sees both sides |
| Park (deferred) | "Real, but nothing downstream builds on it" | same form, ruling says real-and-deferred |
| **BLOCKED** | "Real and load-bearing — a later task builds on it, or it reveals a plan defect" | **STOP**; append `Task <N>: BLOCKED — <reason>`; report to human |

The stated reason BLOCKED is not optional (`SKILL.md:371`): "Parking a structural failure lets
every dependent task build on it and hands the final review a problem it cannot fix either."

### 2.5 `BLOCKED` propagation — two distinct things, do not conflate

A planner sizing this needs both:

**(a) Implementer → controller.** `BLOCKED` is one of four report statuses
(`implementer-prompt.md:130`). The implementer is explicitly licensed to use it
(`implementer-prompt.md:63-78`): "It is always OK to stop and say 'this is too hard for me.'
Bad work is worse than no work. You will not be penalized for escalating." Controller handling
(`SKILL.md:244-250`) is a four-branch decision: more context → re-dispatch same model; more
reasoning needed → more capable model; too large → split; plan is wrong → escalate to human.
Hard rule at `:250`: "**Never** ignore an escalation or force the same model to retry without
changes."

**(b) Controller → human.** Reached only at the cap, only for a load-bearing finding
(`SKILL.md:98`, `:368-371`). This is the only automatic stop-the-line in the loop.

### 2.6 What the human actually sees

Four interrupt points, and only four:

| # | When | What they see | Cite |
|---|---|---|---|
| 1 | Before Task 1 | One batched list of plan-internal conflicts, each finding beside the plan text that mandates it, asking which governs. Silent if the scan is clean. | `SKILL.md:145-155` |
| 2 | Mid-loop, any round | A finding that conflicts with plan text: the finding + the plan text + "which governs?" | `SKILL.md:314-318` |
| 3 | At the cap, load-bearing only | BLOCKED report: the finding, the plan text it collides with, and the fix history | `SKILL.md:368-370` |
| 4 | End of branch | `finishing-a-development-branch` menu, incl. any residual load-bearing findings from the final review | `SKILL.md:411-414`, `:423` |

Between those, nothing. `SKILL.md:17`: "**Continuous execution:** Do not pause to check in
with your human partner between tasks … 'Should I continue?' prompts and progress summaries
waste their time — they asked you to execute the plan, so execute it." And `:14-15`: "between
tool calls, narrate at most one short line — the ledger and the tool results carry the record."

### 2.7 Final review — a fixed one-wave budget

`SKILL.md:391-414`. Whole-branch package from `merge-base`, dispatched on the most capable
model, pointed at the ledger's deferred-minor and parked lines. If it returns findings:
**ONE** fix subagent with the complete findings list, then **exactly one** scoped re-review,
then adjudicate residuals as in the task breaker. `:412`: "There is no second fix wave."
Rationale at `:406-407`: "a real session's final-review fix wave cost more than all its tasks
combined."

### 2.8 Anti-rationalization table

`SKILL.md:425-436`, 8 rows — the same format as TDD's. Notable rows: "One more round will
converge" → "Past the cap, rounds don't converge — the failure is structural"; "This finding is
obviously wrong, I'll drop it" → "You adjudicate only at the cap … Silent discards are
forbidden"; "Ledger bookkeeping is overhead" → "The ledger is what survives compaction."

### 2.10 The cost discipline wrapped around it

Not the breaker, but shipped with it and materially load-bearing (`SKILL.md:157-192`):
per-role model tiering; "**Always specify the model explicitly when dispatching a subagent.**
An omitted model inherits your session's model — often the most capable and most expensive —
which silently defeats this section" (`:177-179`); and a counter-intuitive correction at
`:181-187`: "**Turn count beats token price.** … the cheapest models routinely take 2-3× the
turns on multi-step work — costing more overall. Use a mid-tier model as the floor for
reviewers and for implementers working from prose descriptions."

Paired with a hard context rule (`SKILL.md:196-198`): "Everything you paste into a dispatch
prompt — and everything a subagent prints back — stays resident in your context for the rest
of the session and is re-read on every later turn. **Hand artifacts over as files.**" With a
measured failure at `:224-225`: "a real session's dispatch hit 42k chars of which 99% was
pasted history."

### The anti-rationalization table's structure

Not one table — a **four-part apparatus**, all in `test-driven-development/SKILL.md`:

**(a) `## Good Tests` — a quality table** (`:198-204`). Three rows, three columns
(Quality | Good | Bad): Minimal / Clear / Shows intent. Diagnostic, not defensive.

**(b) `## Common Rationalizations` — the anti-rationalization table** (`:212-226`). Two
columns, `| Excuse | Reality |`, **11 rows**. Left column is a verbatim excuse in quotes;
right column is a rebuttal that *concedes nothing*. Two distinct row lengths:

- Terse (`:216`): `| "Too simple to test" | Simple code breaks. Test takes 30 seconds. |`
- Argued (`:217`): `| "I'll test after" | Tests written after pass immediately — which proves
  nothing. They may test the wrong thing, test the implementation instead of the behavior, or
  miss the edge case you forgot. You never watched it fail, so you never proved it can catch
  the bug. Test-first forces that failure. |`

The long rows are the ones covering excuses a smart agent can defend. `:218` ("Tests after
achieve same goals (spirit not ritual)"), `:219` ("Already manually tested"), `:220` ("Deleting
X hours is wasteful" → answered by naming the sunk-cost fallacy), and `:224` ("TDD will slow me
down") all get full paragraphs. Cheap excuses get one line.

**(c) `## Red Flags - STOP and Start Over`** (`:228-244`). 13 bullets, no table — a
self-check list mixing observable states ("Code before test", "Test passes immediately") with
*internal monologue* ("Rationalizing 'just this once'", "'It's about spirit not ritual'",
"'This is different because…'"). Closes `:244`: "**All of these mean: Delete code. Start over
with TDD.**"

**(d) `## When Stuck`** (`:298-306`). A 4-row `| Problem | Solution |` table that routes
difficulty back into design feedback: "Test too complicated" → "Design too complicated.
Simplify interface"; "Must mock everything" → "Code too coupled. Use dependency injection."

**Plus**: a `## Verification Checklist` of 8 boxes (`:283-296`) ending "Can't check all boxes?
You skipped TDD. Start over."; and a `## Final Rule` (`:313-320`) — "Production code → test
exists and failed first / Otherwise → not TDD / No exceptions without your human partner's
permission."

**Where the exceptions live** (`:24-29`): throwaway prototypes, generated code, config files —
and all three are gated on *asking the human*, not on agent judgment. Immediately followed by:
"Thinking 'skip TDD just this once'? Stop. That's rationalization."

**Companion**: `writing-good-tests.md` (198 lines), invoked at `:206` for every test written or

Four pieces:

**(a) The premise** (`writing-skills/SKILL.md:10`): "**Writing skills IS Test-Driven

**(b) The test method** (`testing-skills-with-subagents.md`). RED = run a subagent on a

**(c) `## Match the Form to the Failure`** (`SKILL.md:459-474`) — the most surprising content

→ wrong form:

| Baseline failure | Right form | Wrong form |
|---|---|---|
| Skips/violates a rule under pressure | Prohibition + rationalization table + red flags | Soft guidance |
| Complies, but output has the wrong shape | Positive recipe/contract: state what the output IS | Prohibition list |
| Omits a required element | Structural: REQUIRED slot in the template | Prose reminders |
| Behavior should depend on a condition | Conditional on an observable predicate | Unconditional rule + exemptions |

With a measured result (`:470`): "In head-to-head wording tests on dispatch-prompt guidance,
the prohibition arm produced clearly more of the unwanted content than the recipe arm (fully
separated distributions), and trended worse than even the no-guidance control." And two
follow-on rules at `:473-474`: "**No nuance clauses.** 'Don't X unless it matters' reopens the
negotiation — appending a single nuance clause to a winning recipe degraded it from consistent
to noisy"; "**Exemption clauses don't scope.** 'This limit doesn't apply to code blocks' still
suppresses code blocks."

This says the anti-rationalization table — the pattern Signal's April doc records as a general
convention — is scoped: it is the right form for *discipline* failures and the documented wrong
form for *shaping* failures. `:480` restates the scope explicitly.

**(e) Token-budget guidance** (`SKILL.md:213-266`), including concrete targets: "getting-started

falls past the heredoc to `:42-46` and `exec bash` the named script. Comment at `:7-9`
explains why hook scripts are extensionless: "Claude Code's Windows auto-detection — which
prepends 'bash' to any command containing .sh — doesn't interfere."
