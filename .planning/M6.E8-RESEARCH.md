## Finding 1 — FR2's phrase hits exactly one row, and it is the gate itself

`FR2` says `BLOCKED_RE` gains *"entry price for"* and that *"four rows currently reading
`blocked: false` are gated on `B75` and should read `blocked: true`."* Measured:

- **"entry price for" occurs in one live row's text or body: the row headed *"The entry price for
  any Phase A autonomy work: `B73`–`B76`"*.** That row is the gate. Widening `BLOCKED_RE` with the
  phrase demotes the row that says *do these first* — a false positive on the only row it hits.
- **The four rows `D-M6E8-2` called "gated on `B75`" cite `B75` as a measurement, not as a gate.**
  Their `B75` mentions, verbatim: *"a fourth knob beside `tier` / `gate_strictness` / `attention` is
  `B75`"* (the bug's *shape*); *"`B75` measured that ceiling"*; *"the remedy `B75` measured the
  ceiling on"*; *"`B75` already measured that ceiling"*. None says the row waits on `B75`. One of
  the four already reads `blocked: true` for an unrelated phrase.
- **Sibling search — twelve gate-shaped phrases over all 48 live rows** (`precondition`,
  `prerequisite`, `blocked by`, `gated by`, `waiting on`, `needs … first`, `until … ships|lands`,
  `after … ships|lands`, `stuck behind`, `sequenced behind|after`, `can't … until`, and the phrase
  above): **zero correct hits.** `precondition` hits the gate row again and one prose use; `needs …
  first` hits *"needs the measure-first treatment"* and a row already blocked. Nothing in the file
  expresses an unmet gate that `BLOCKED_RE` misses.

**Consequence:** `AC2.1` cannot be satisfied by any heading or body vocabulary that exists in the
file. The only mechanism that would flip those four rows is *"body names a confirmed bug → blocked"*
— which is the body-scanning heuristic `D-M6E8-2` itself rejected and `M6.E7` bought a bug learning
not to write, and it would also demote **9** rows including this Epic's own. The plan does **not**
widen `BLOCKED_RE`; the zero is recorded next to the pattern (`NFR6`). This is a DISCUSS claim
written from the shape of the work — *"the backlog calls `B75` the entry price; these rows cite
`B75`; therefore they are stuck behind it"* — in the Epic that exists because of that class.
Recorded as `D-M6E8-7`; disposition confirmed at the PLAN gate because it changes the Epic's stated
outcome.

## Finding 2 — FR3 is already live: input 3 is the closed-Epic drop

`FR3` asks for *"a live row whose own leading Epic ID resolves to `closed` via `resolveClosures`
drops out with a reason."* `backlogDischargeStatus` (`plugin/tools/lib/backlog.js`) already does
exactly that: it takes every live row with a `leadingId`, resolves unit ids through
`readClosureSources` → `resolveClosures` and bug ids through `BUGS.md`, and pushes a row whose
verdict is `closed` into `stale[]`. `runAdvise` hands `stale` to `rankRows`, which drops any row
whose `leadingId` is in it — that is ranking **input 3, discharge**. Building `FR3` as a new input
is the second definition of "closed" that `NFR2` forbids.

What is genuinely missing is smaller than an input:

- **The reason does not say which source closed the row.** `declineReason` renders *"its work
  already reads as closed"* with no source and no evidence, while `stale[]` entries carry the
  `evidence` string and the id's family says which source answered. `AC3.1` — *"a reason naming the
  closure input"* — is a labelling task.
- **One real gap, already filed:** `backlogDischargeStatus` parses at the default `maxDepth: 3` while
  the advisor reads at 4, so a `####` row led by a closed unit is invisible to input 3 unless an
  `###` row shares its id. Untriaged in `BUGS.md` as *"dischargeBacklogRows is blind to rows nested
  below h3"*. Live effect today: **0** either way (`stale` is empty at depth 3; `leadingId ∈ closed`
  is 0 at depth 4). Fixing it there fixes the sweep and the advisor together; fixing it here would be
  a second walk.
- **The loose predicate is now worse than DISCUSS measured.** *"Heading mentions a closed unit"*
  hits **3** live rows, all false: the `M5.E6` PARTIALLY-SHIPPED row, the `M5.E16` renumbered-from
  note, and **this Epic's own row**, which names `M6.E7` as the REVIEW it was filed from. `M6.E7`
  closed on 2026-09-06. `AC3.2` gains a third fixture.

Recorded as `D-M6E8-8`.

## Finding 3 — the "Consulted by the ranking" line was wrong in the other direction

`FR7` assumes the shipped line *"`BACKLOG.md` only"* over-claimed nothing and under-claimed
nothing. Finding 2 shows input 3 reads **`BUGS.md` and STATE/closure** through
`readClosureSources` — independently of `readCorpus`, so a source can be readable to one and not
the other. The ranking has consulted three sources since `M6.E7` shipped; the line said one.
**"Consulted"** therefore needs a definition, not a longer literal: *the `ADVISOR_SOURCES` entries
any ranking input read on this run*, derived from what `rankRows` was actually given —
`BACKLOG.md` always; `BUGS.md` and `STATE/closure` when the discharge status was evaluable (input 3
read both) or when a confirmed-bug set was supplied (input 6); `milestone rows` never, and the line
says so with `FR6`'s reason. Recorded as `D-M6E8-9`.

## Finding 4 — the fold vocabulary, measured

Heading-only, on the 48 live rows: `FOLDED INTO` ×1, `absorbed into` ×3, `re-homed` ×1 — **5
headings**. `KEPT` ×2, both uppercase, and both are among the five. **Without `re-homed` the
override preserves one row, not two**, so `AC4.3`'s *"exactly 2 preserved"* fixes the vocabulary:
all three phrases are in. Case-insensitive matching changes no count (any-case 5 / exact 5; `kept`
any-case 2 / `KEPT` 2). One row mentions a fold phrase in its **body** only (the `M5.E14`
obligation-tracker row) — the false positive heading-only avoids.

**All five rows sit in the 2026-09-13 advisory's declined pool.** Three change from *"demoted by
trigger-met and age"* to *"dropped by the fold input"*; two are explicitly preserved. **The
recommended five do not change composition from this input.**

## Finding 5 — the bug-discharge vocabulary, measured

Heading-only. Two live headings name a bug id at all (`B87`, `B90`; `B73`, `B76`) and all four ids
read `fixed` — **0** headings name a `confirmed` bug. One heading carries a discharge word:
*"open/closed work"* — ordinary English, the `DONE_WORD_RE` lesson again, so the verb must sit
**adjacent to the id** (`fixes B75`, `B75 — fixed`), not anywhere in the heading. **9** live rows
name a confirmed bug in their **body** (`B75` in five of them, the promoted row included): the
population a body-reading version would wrongly promote, and `AC1.2`'s fixture.
