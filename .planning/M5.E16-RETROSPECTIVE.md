## What surprised us

**The Epic's tier was a lie for the whole of DISCUSS, and the first line of PLAN found it.**
`M5.E16-PROFILE.md` carried two values outside their enums — `stakes: moderate` (valid only for
`reversibility`) and `reversibility: easy` (valid nowhere). `readEffectiveProfile` **threw**, and
because `/sig:resume` fails open, the Epic that declares FEATURE ran DISCUSS at the project's FULL.
Written by hand in the *same commit* as the DISCUSS it was meant to govern, and unread until code
touched it (`B59`). Two bad values, not one — validation short-circuits, so fixing what the error
message named would have left the file still unloadable.

**Signal's own project shape is the minority shape, by a wide margin.** Measured across 13 real
`.planning/` trees on this machine: **4 of 12** readable projects are Epic-mode, **7 of 12** have a
canonical `phase`, and `readState` **throws** on one outright. The two checks aimed squarely at the
incident that opened this Epic can evaluate **2 of 13** projects. That number reshaped the entire
plan — it is why the harness makes *"could not check"* a first-class outcome instead of a footnote.

**Measuring produced a check nobody had thought of.** `(h)` — `current_epic` set but not a strict
Epic ID — is not in the requirements. It exists because the probe found `eval-project-I` carrying
`"M1"` and `eval-project-C` carrying `"PHASE12"`, both of which make every resolver fall open to
linear mode while the project believes it is running Epics. That is **`B53`'s class, live in the
field**, on half the Epic-mode corpus, after being fixed as a Signal-side bug in v0.1.14. And it
turned out to be structurally elegant: the two projects where `(h)` fires are exactly the two where
`(a)` and `(b)` go blind, so `(h)` is the check that reports *why* the others cannot see.

**REVIEW found a Critical that 1933 passing tests, a green validator, a clean lint, a clean network
audit and a full VERIFY had all missed** — because it was a *wrong answer*, not a broken build.
Check `(c)` declared itself unconditionally evaluable while keying detection to a strict filename,
so `eval-project-C` (19 phase artifacts, 0 retrospectives) reported **`clean`**. The module's own
header states the contract it violated: *"`clean` and `cannot-evaluate` collapsing into one another
is the bug this module is built to make impossible."* Caught by reading four sibling checks against
each other and noticing three handled non-strict IDs and one did not.

**The fix for the false-clean introduced a false-positive, and the process caught it inside the same
loop.** Broadening the prefix made `eval-project-F`'s `EXECUTE-PROGRESS.md` read as an un-retrospected
unit named *"EXECUTE"*. FR2.1's re-measure requirement is the only reason that did not ship.

**One diagnosis was wrong and had to be retracted mid-investigation.** A ~1-in-10 suite flake traced
to `last_updated_commit` being YAML-coerced (`0012345` → `12345`, `1e23456` → `Infinity`). The first
conclusion was *product bug*; measuring the writer disproved it — the `yaml` package quotes
numeric-looking strings, so every Signal writer is safe and only the hand-written **test fixture**
was wrong. Filed accurately as `B61` (P3) instead of as the P2 it first looked like.

**Check `(a)` fired in the field for the first time, and this Epic's own process caused it.** VERIFY
had recorded it as fixture-only evidence — zero live hits, a corpus that could not tell *precise*
from *inert*. Then the REVIEW→EXECUTE loop-back moved the recorded phase backwards past an artifact
that already existed, and `(a)` reported it correctly.

## What we'd do differently

**Validate the Epic profile at the moment it is written, not at the next command that reads it.**
`B59` cost nothing here because PLAN caught it, but DISCUSS ran an entire phase at the wrong tier.
`/sig:calibrate` writes these files; a hand-written one has no writer to validate it. The generalised
form now ships as check `(g)`, and Signal's own repo is pinned by
`tests/own-profiles-parse.test.js` — but the *ordering* lesson stands: **a document that governs a
phase should be parsed before the phase runs, not during the next one.**

**Run the corpus probe at DISCUSS, not at PLAN.** Every structural decision in this Epic traces to
the 13-project measurement: which checks ship, which are dropped, why the harness has four statuses
instead of two, and the existence of `(h)`. DISCUSS wrote six FRs and three open questions from the
bug catalogue alone; two of the six needed rewriting once the corpus was measured. **The evidence was
one script away the whole time.**

**Do not put an absence assertion and its positive sibling in the same undifferentiated pile.**
Nyquist strict surfaced that 10 of 93 new tests passed against their own pre-implementation
baseline. Five were absence assertions (*"X does not appear"*), which are vacuous before X exists —
structural, not careless. But they were only distinguishable *after* measuring; had the evidence been
an attestation, all 93 would have been claimed red-first and been technically true. **Mark absence
assertions as such when writing them.**

**Read sibling implementations against each other as a deliberate step, not by luck.** `C1` was
found that way. So was `B59`. So was the FR4-vs-NFR2 contradiction. Three of this Epic's four
biggest findings came from putting two documents or two functions side by side — and none of them
came from a mechanism.

## What to feed back into Signal

**`review_depth` silently overrides `simplification_pass`, and nothing says so at the profile.**
(`O1`, found at REVIEW.) `M5.E16-PROFILE.md`'s prose states *"`simplification_pass: true` stays on"*
while `commands/review.md`'s master-switch rule disables Step 4 whenever `review_depth:
quality-only`. **The profile asserted rigor it did not receive for the entire Epic.** This is `B59`'s
shape one level up: `B59` was a profile the code could not *parse*; this is one the code parses and
then silently overrides. **Candidate check: a profile whose prose claims a dial the precedence rules
disable.** Genuinely hard — it is a prose-vs-precedence comparison, which is M5.E10's semantic
territory rather than this Epic's deterministic one.

**The FR1 retrospective gate and check `(c)` should know about each other.** `(c)` flagged `M5.E17`
as worked-without-a-retrospective for this Epic's entire duration, from a *different* command
(`/sig:sweep`) than the one that enforces retros (`/sig:ship`). The gate is Epic-close-only and
fires at ship; the check is continuous and fires anywhere. That is a good pairing nobody designed —
worth making explicit.

**`/sig:plan`'s inbox drain has a trap worth documenting.** Batch-deferring stamps entries as
dispositioned, which **removes them from future drain candidates**. With 48 entries owned by M5.E14
(`D-M5E17-3`), deferring them would have hidden them from the Epic chartered to triage them. The
drain step should say so where the batch-defer offer is made.

**The published adherence share moves for reasons unrelated to adherence, and now has four
instances.** Clarifying an instruction lowers it (three times); adding a step that names a real
library call raises it (this Epic, 20.8% → 21.0%). `ADHERENCE-LOG.md` now says this above the table
in both directions. **The number should never be quoted release-to-release without that paragraph.**

**FR4's middle bucket shipped empty, and that is the honest outcome of `D-M5E16-1`.** FR4 called
itself load-bearing and said *"Signal runs it"*; NFR2 said sweep never writes. Resolved in NFR2's
favour, which means the `COMMAND_HEALABLE` category exists in the registry and holds **zero** checks.
A test asserts that emptiness, so registering one without `/sig:sweep --heal` existing to run it
fails the suite. **Whether `--heal` is ever worth building is a real open question** — the 16-finding
baseline produced exactly one category-2 case, and FR5 heals it automatically.
