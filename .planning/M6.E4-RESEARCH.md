## 1. There is no PLAN-task parser in this codebase. S1 must build one.

Searched every `export function parse*` in `plugin/tools/lib/`. What exists parses **other**
artifacts: `parseEntries` (inbox), `parseBacklogRows`, `parseStatusCell`, `parseDecisionSections`,
`parseEscalationHistory`, `parseTriggerWatchlist`, `parseExistingAnnotations`.

`retrospective.js#parseSections` is the closest and **does not fit**: it treats **only `## ` (h2)**
as a boundary and *drops everything before the first h2*. Real PLAN artifacts carry their tasks as
**`### ` slices** under a `## Slices` heading:

```
## Slices
### S1 — the receipt contract, and a SHIP gate that can refuse · **wave 1** · **M**
### S2 — `BUGS.md`: a row reads open, the work shipped · **M–L**
```

**Implication:** a new parser is unavoidable, so `B82`'s rule applies to what comes *after* — the
parser must be **one** implementation with **one** caller-facing contract. If S1's detector and any
later consumer both need "the tasks in this plan," they call the same function.

## 2. The check-module pattern to match

`defineCheck({ id, describe, healCategory, applicability, run })` — `state-drift.js`. Registries
compose as frozen arrays: `STATE_DRIFT_CHECKS`, `PUBLISHED_FACT_CHECKS`,
`ALL_DRIFT_CHECKS = [...both]` (`published-facts.js:427`).

**`applicability` is a first-class categorical**, not a threshold — a check declares itself
inapplicable and *says so* rather than quietly returning clean. This is the mechanism `AC1.1c`
needs; it already exists and must be used rather than re-invented.

## 3. Reach is published through one function, and nothing types the numbers

`published-facts.js:33` holds a frozen `REACH` table (`{evaluable, total, measured}` per check id),
and `describeReach()` is **"the one place a reach figure becomes prose."** `AC1.1d` has a home:
add a `plan-internal-consistency` row and call `describeReach`. Do not hand-write a reach sentence.

## 4. The HTML-comment marker S2 needs is an established shape here

Present in this corpus today: `<!-- backlog-key: … -->`, `<!-- bugs-key -->`, `<!-- evicted-key -->`,
`<!-- phase-log:archived -->`. So `<!-- standing -->` introduces **no new mechanism** — which is the
argument that settled `D-M6E4-4`.

`parseEntries` already scans an entry's **header region, fence-aware**, to find its Status line
(`drain.js:176-186`) and separately reads a leading blockquote stamp only on the *first non-blank
content line* — explicitly so a stamp quoted deeper in a body is not mistaken for a real one. **The
marker read reuses that exact discipline**, giving `AC2.1b` a precedent instead of a new rule.

## 5. ⚠ The detector produces a WORKLIST, not a finding list — and that changes its precision contract

This is the most important design consequence and it is easy to get backwards.

`M6.E2`'s checks assert **a defect exists**, so a false positive is a false alarm — which is why
`bug-status-vs-changelog` had to publish a measured 1-in-2 precision. S1's detector asserts only
**"this task carries a number and a criterion, so the reviewer must speak to it."** A false positive
costs the plan-checker one paragraph of attention; a false **negative** lets a contradiction through
unexamined.

**So S1 optimises recall, and precision is explicitly not the headline number.** Stating this in the
artifact matters because the repo's recent instinct — correctly learned from `M6.E2` — is to lead
with precision, and here that would be the wrong metric.

### ⚠ Why there is NO `##` fallback, refuted by measurement rather than declined by taste

The two non-evaluable projects use **`##` headings exclusively** — 12 each, zero `###`. The obvious
next move is "also parse `##`", taking reach from 10/13 to 12/13.

**Measured against a generic section vocabulary** (*phase goal / slices / dependencies / scope /
test strategy / environment / risk / open questions / …*), their h2 headings are
**8 of 12** and **10 of 12** section headings — not tasks. A fallback would therefore flag
`## Phase goal` and `## Dependencies` as tasks in most cases: **noise dressed as coverage.**

`cannot-check` with a stated reason is the honest answer, and it is a **real** state here, not a
hypothetical one — 3 of 13 projects land in it.
