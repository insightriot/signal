## The Epic's premise was wrong, and finding that out was the most valuable hour

`BACKLOG.md` and `STATE.md` both said *"M5.E18 built the engine and wired none of it,"* quoting the
retro's *"the library could do 110; nothing wired it."* **That sentence describes what M5.E18 found
in the middle of itself.** Its wave 6 fixed it; the release's headline — *114 files across 6
projects* — **is** the delivery. The backlog entry, written two days later, quoted a mid-Epic
finding as an end state.

It survived because the entry was **read** rather than **run**. Three greps and one execution
settled it: `applyArchiveTree({apply:true})` is reachable behind `if (archiveMoveMap.size > 0)`,
**ungated by layout version**. Archiving worked. The closure gate worked too — `senseArchiveTree`'s
union is default-deny.

**The word doing the damage was "wired."** It hid the difference between *called* and
*load-bearing*: `resolveClosures` **is** called at `migrate-memory.js:1975` — inside a `try/catch`,
feeding a dry-run explanation, with a comment saying *"an explanatory read on a dry-run display."*
Called, and carrying no weight.

The Epic got smaller and truer. That was put to Brett before PLAN rather than discovered at REVIEW,
and `B82` was split out to the fix lane on the reasoning that a live data-integrity defect should
not wait six phases for a feature nobody is blocked by.

## What assumptions broke

**"The bug is in Signal, so Signal's tree can show it."** `B82` splits units in `nextpass` and
`cm-mentor-coach` and **cannot occur here**: every Signal unit is a strict Epic ID whose files
really are `{EpicID}-{SUFFIX}.md`, so the template and the derivation agree *by construction*.
21 units, 88 moves, 0 stranded — before and after the fix. **Dogfooding was structurally blind**,
and the blindness was a property of the naming convention, not of effort.

**"A dry run is safe enough to point at a real project."** It is not, and being told so plainly was
the correction of the session. The reasoning offered — *"it writes nothing"* — was true and
irrelevant: a dry run is one typo from `--apply`, and the downside is asymmetric between a
hobby-scale tool and load-bearing production work. The real tell is that the suggestion was only
attractive **because the sandbox did not exist**. It exists now, `commands/archive.md` forbids the
alternative in writing, and the rule is in memory.

**"Run the existing machinery first" is a scheduling nicety.** It was the Epic. S1 — point the
current helpers at the sandbox and *write down what they print* — found that the output reports what
would move and what could not be evaluated, and says **nothing** about units considered and
**refused**: three of six vanished. Had S2's renderer been written first, it would have rendered the
same blind spot in new code and the Epic would have shipped a prettier version of the defect.

**"The doc drifts from the code."** Twice this Epic it went the other way. `commands/archive.md`
asserted *"an unreadable STATE refuses everything"* **before the implementation did it** — the
guard exists because a test written from that sentence failed. And the REVIEW rewrite fixed a
comment that was *right* about a mapping the code had stopped honouring.

## The defects, and who found them

**Five, and not one was found by reading the code.**

| What | Found by |
|---|---|
| The Epic's premise was false | running three greps against the claim |
| A safety bug: a plan built from the source that cannot see the danger | this Epic's own test (AC-S2.5) |
| `B87` — EXECUTE ran and never entered the ledger | reading the ledger at VERIFY |
| C1 — a comment asserting a property the code lacked | REVIEW, reading comment against code |
| C2 — a guard that guards nothing | REVIEW, in the same block |

The safety bug is the one worth carrying: `buildArchiveReport` took its **plan** from
`senseArchiveTree` and its **refusals** from `resolveClosures`, which disagree about an unreadable
`STATE.md`. The plan came from the half that cannot see the danger — so a project with no readable
STATE would have been handed a plan to archive work that might be the **current unit**. That is the
retired tool's exact failure, reproduced inside its replacement, in the module whose own
documentation forbids it.

## `B41` came back, and the fix that closed it cannot reach here

`completed_phases` reads `DISCUSS, PLAN, VERIFY, REVIEW`. **EXECUTE is missing, and EXECUTE ran** —
three files written and committed, five slices recorded in `PROGRESS`.

M5.E9 closed `B41` by putting `transitionPhase` **inside each phase command**. That does nothing for
a run that never invokes the commands — and **Signal-on-Signal is that run**, as is any Epic a
maintainer drives by hand, which is how most of this repo's Epics execute. So the accuracy of the
ledger depends on the operator remembering a call, **for the one project that produces all of
Signal's evidence.**

Filed as `B87` and deliberately **not repaired**: hand-inserting an entry to tidy an append-only log
is the falsification the rule exists to prevent (`B48`). The log is honest about what it observed;
it is the observation that is thin.

## What the next Epic should take

1. **Run the thing before improving it.** Three of five defects came from executing something —
   a claim, a helper, a ledger — that had only ever been read. This is now two Epics in a row.
2. **When a backlog entry quotes a retro, check whether the quote is a finding or a conclusion.**
   Mid-Epic findings read exactly like end states once they are out of their paragraph.
3. **`B87` needs a home.** A drift check comparing `completed_phases` against artifacts on disk is
   the obvious shape — `{Epic}-PROGRESS.md` exists ⇒ EXECUTE ran. Note `phase-behind-artifacts`
   compares `phase` to artifacts and is **blind to gaps in the log**, so this is a new check, not a
   widening of an existing one.
4. **The sandbox is now the place to test anything.** It answered its first real question this Epic.
   Its uncovered shapes are listed in its README and in the inbox entry, which stays open.
