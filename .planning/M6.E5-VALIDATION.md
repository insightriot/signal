### ⚠ This check could not be run with the shipped tool — `B100`, demonstrated

> **Correction (PR #211 review).** This was first written citing `B111`, an id that was never assigned. The defect is **`B100`** (`confirmed`, P2, filed 2026-08-14) and it was already known; `BUGS.md` was not grepped before filing. What follows is a second, independent measurement of it.

`requirement-coverage.js` reads both sides of its diff through `extractRequirementIds`, whose
`AC_ID_RE` lacks the `[a-z]?` that `FR_ID_RE` and `NFR_ID_RE` both carry. Run against this Epic's
REQUIREMENTS it returns:

```
shipped extractor:  ['AC1', 'AC2', 'AC3', 'AC4', 'AC5']        →  5 ids
corrected regex:     AC1.1a … AC5.3d                            → 34 ids
```

**So the shipped tool reports 5 criteria where 34 exist**, and a VERIFICATION naming one
sub-lettered criterion would mark its whole group covered. The totals above were produced with a
**corrected** regex, stated here so nobody reads them as the tool's output.

⚠ **The same collapse weakens `checkValidationConsistency` on this artifact.** It compares the table
above against the Nyquist map through the same extractor, so both sides collapse to `AC1`…`AC5`
identically and it can only confirm agreement at **group** granularity. A per-criterion
contradiction would pass it. Consistent-but-coarse, not consistent-and-verified.

**Consequence for this Epic's VERIFY:** the coverage tool cannot be trusted for `M6.E5`. Check by
hand against the artifact, or fix `B100` first. Carried in the STATE pointer and the PLAN's
assumptions.

## Dimension 3 — Testability

Every task names a test strategy, and each is TDD-ordered (failing test first) per
`tdd_required: true`.

**The four tests that carry the most weight, and why each is the one that can actually fail:**

1. **`S1.t2` — the whole-population classification test.** Fed the **live** scan output, not a
   fixture list. A fixture-based version would recreate the bug inside the test, which is exactly
   what `prescribed-cli.test.js` avoided by deriving its identity from the manifests.
2. **`S2.t1` — absent vs. malformed must not collapse.** Two failure modes that render identically
   is `B39`.
3. **`S4.t3` — no write path touches `.claude/` or `~/.claude/`.** Asserted over the module's actual
   write calls. `AC5.1a` is the one guarantee the whole design rests on, so it may not rest on a
   reviewer's reading.
4. **`S4.t1` — byte-identical double render.** `NFR4`'s ordinary causes (`readdirSync` order, `Set`
   iteration, unsorted merges) are precisely what eyes miss.

**PASS.**

## What this validation could not establish

- **Five of eight dimensions were not run** (tier choice): dependency correctness, scope discipline,
  context feasibility, risk coverage, vertical slicing.
- **The coverage numbers above are from a corrected regex, not from the shipped tool** (`B111`).
- **Doc-integrity assertions compare tokens, not meaning.** `AC3.2a` pins that the module *says* it
  is a new detector, not that the statement stays true.
- **`AC5.2d` proves nothing reads the file by name today**, not that nothing ever will.
- **No test here exercises the real Claude Code permission engine.** Everything validates what
  Signal *proposes*; whether an installed rule behaves as expected is the platform's, and is outside
  what this Epic can assert.
