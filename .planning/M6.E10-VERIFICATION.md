## FR4–FR6 are instructions, and calling them "verified" would be the defect this repo tracks

They live in `commands/drive.md` as prose an agent follows. **Nothing executes them, so nothing can
test them** — the same honest limit `M6.E9` recorded for its own FR2. A test could assert the file
*says* certain words; that pins wording, not behaviour, and this repo has been bitten by exactly
that (`B78`: a test asserting the literal string `'50 loc'`).

**What would actually verify them is a run.** The first `/sig:drive` invocation after this ships
either presents one combined question with a pre-selected default, or it does not.

## ⚠ A defect I introduced, caught by its own proof

`inboxHasDrainableEntries` first read `existsSync(resolveInboxPath(baseDir))`. **That helper returns
a repo-RELATIVE path**, so the check resolved against the process cwd and read whatever inbox sat
under the working directory. Vitest runs with cwd = this repo, whose inbox has zero drain candidates
— so the drainable fixture reported **dormant** and the proof passed against the wrong file.

Found because the proof asserted a *specific* outcome (floor goes live) rather than "tests pass".
Pinned by `reads the inbox under baseDir, not under the process cwd`.
