## What surprised us

**A backlog row quoted a source that never existed.** `S2`'s row cited a second standing entry
saying *"do not close this entry."* That phrase is absent from the repo **and from all git history**
(`git log -S` returns nothing). The row was written from the shape of the thing rather than the
artifact — `M6.E2`'s class — inside the row about not being able to tell checked from unchecked.
Measured instead: **one** standing entry, and it was the **only live candidate**, so the drain's
live count could never reach zero. The real problem was *sharper* than the row claimed, not smaller.

**Two slices' acceptance criteria named a dimension that does not run at their own tier.** `S1` and
`S3`'s done-whens both said *"fails the 8-dimension pass at scope discipline"* — and at FEATURE,
`plan_validation_dims: core` runs three dimensions, scope discipline not among them. As written,
this Epic's criteria would not have been exercised against this Epic's own plan.

**The first corpus measurement was wrong, and the fixture is what proved it.** Splitting plans on
`###` gave 28.6%. Then `AC1.1a`'s fixture turned out to be `#### S1.t11` — an h4 task under an h3
slice, the shape Signal's *older* plans use. **A method that cannot see the one task the check
exists to catch is the wrong method.** Corrected to level-3-or-deeper. Then measured a **third** time after the PR #200 review found two
`QUANTITY_RE` defects: reach **10 of 13** (never regex-dependent), **46 flagged (10.6%)** corpus-wide
against **14.0%** here.

**Three completeness faults in this Epic's own artifacts, and not one was found by reading.** A
denominator two short (`NFR1`/`NFR4` absent from a table claiming "24 of 24"), ids hidden inside
en-dash ranges — **`M5.E10`'s exact recorded finding** — and two compared sections keyed in different
namespaces. All three surfaced by *running* a derived check.

**The review found a defect the tests could not.** `listDrainCandidatesWithRecovery` kept a bare
`!dispositioned` filter while its sibling gained `!standing`, so a standing entry below a dangling
fence would be recovered back into the live set — S2's bug reintroduced by the one path that exists
for malformed inboxes. **Signal's own inbox could not have hit it** (its standing entry sits above
any fence). Nothing but a reader was ever going to catch it.

**A guard prevented a `B82` violation mid-slice.** The detector's first draft defined its own
`AC\d` pattern; `tests/requirement-ids.test.js` fails the suite if any second `tools/lib` module
does. Second implementation **prevented, not filed**.

### The reviewer found three more, after every phase had passed

`/sig:ship` read PR #200's findings before merge, as the standing instruction says. The first pass
returned three; two were already fixed by later commits, one was real. **Then the re-review, running
against the fixed tree, returned three more — all in the source code, all real:**

1. **`80%` never matched.** `\b` cannot hold after a non-word character, so percentage thresholds —
   one of the commonest ways a plan states a number — were invisible to a **recall-first** detector.
2. **ISO dates and adjacent list lines matched as arithmetic**, because `\s` spans newlines and `-`
   makes every date an expression.
3. **A leading code fence bypassed the window-close check**, so an entry with no Status line was
   scanned straight past its fence — the opposite of the "conservative by construction" its own
   comment promised.

**That is 10 of 10 real findings from this reviewer on this repository.** It ran after a green
2974-test suite (the count **at that moment**; the fixes took it to 2979), a mutation-verified
regression test, a PASS-WITH-FIXES review and a 26-of-26 VERIFY.

**And the consequence went further than the fixes.** Re-measuring with the corrected regex moved the
published numbers **in both directions** — corpus recall up, Signal's own rate down by a third — which
means the *"Signal's plans are ~2.2× denser"* finding this Epic published was an **artifact of the
defect**, not a property of Signal's plans. A wrong number in three documents, caught only because
the reviewer said the figures "were measured with issue 1 present."

**The lesson is not "read the reviewer" — that was already the rule.** It is that a number measured
by code is only as good as the code, and re-measuring after any change to the measuring instrument is
not optional.

## What we'd do differently

**Gate the commit on the test result.** `95b9df0` was pushed with two failing tests because
`npm test 2>&1 | tail -4 && git commit` **does not gate** — the pipe swallows npm's exit code. Every
later commit used `npm test && git commit`. The lesson is mechanical and worth keeping: *a pipeline's
exit status is the last command's.*

**Regenerate derived facts before committing, not after the suite goes red.** `ADHERENCE-LOG.md`
publishes a derived directive count; editing `plan.md` invalidated it twice. The first time it
failed the suite; the second time it was regenerated as part of the edit. Same for `REACH`.

**Measure before writing any number down.** The 28.6% figure reached a committed artifact before the
method was validated against the fixture. Cheap to fix here because the correction was one edit;
expensive if a reader had acted on it.

**Check both siblings when changing a predicate.** `grep -n "dispositioned"` would have surfaced
both filters in one command. The habit is: after changing a filter, search for its twin.

## What to feed back into Signal

**The `##`-fallback refusal is the reusable pattern, not the detector.** Extending reach 10/13 →
12/13 looked obviously right until the two projects' h2 headings were classified: **8 of 12** and
**10 of 12** were *section* vocabulary, not tasks. `cannot-check` with a stated reason beat coverage
that would have flagged `## Phase goal` as a task. **Refuse extensions on measurement, not taste** —
and record the measurement, since the next reader's instinct will be the same.

**A prompt cannot call a function, so pin its numbers with a test.** `plan-checker.md` states reach
in prose while `describeReach` exists so *"nothing types the numbers."* Static text cannot be made
dynamic — the resolution is **derive-then-compare**, `M6.E2`'s own mechanism, applied to a prompt.
This generalises: every hand-typed figure in a `commands/` or `agents/` file is a published fact with
no check behind it.

**`B75`'s shape recurred, at smaller radius, and shipped disclosed.** `AC1.2c` — nothing fails if
`plan-checker.md` ignores the detector's worklist. Written at the point of use with a `B75`
cross-reference and pinned by a test that the *disclosure* exists. **Candidate for the next
autonomy Epic**, alongside `B75` itself.

**`AC3.1b` is the honest debt.** *"An executor follows a named exemplar"* is verified only as an
**instruction** — no executor agent was dispatched this Epic, because this session's harness is
configured against subagents. **The behavioural half of `FR3.1` is unverified**, and one real
`/sig:execute` dispatch on a task carrying an exemplar reference would close it.

**The per-unit tier dial works and nothing was lost.** FEATURE inside a FULL project ran all seven
phases with 3 validation dimensions instead of 8 and `quality-only` REVIEW — and REVIEW still caught
the Epic's most interesting defect. `B90` measured 7 of 12 projects at FULL with **one** per-unit
profile ever written; this is evidence the dial is worth reaching for.
