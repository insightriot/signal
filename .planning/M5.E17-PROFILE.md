# M5.E17 — Epic-scoped calibration

**FEATURE, not the project's FULL.** This Epic is four small corrections to Signal's own
process documents plus one data triage. No new subsystem, no new public surface, no security
boundary touched, and every change is a `git revert` away from undone.

**Why the overrides, individually:**

- `research_parallelism: 0` — nothing to research. All four items were **found by doing the
  work** and each already carries its evidence in `BUGS.md` / the M5.E13 artifacts.
- `security_audit: none`, `performance_pass: false` — the changes are markdown instructions and
  one inbox data pass. There is no attack surface and no hot path.
- `nyquist_enforcement: basic` — tests must exist and cover the scenarios; the strict
  proof-of-fail record is not demanded for prose corrections whose "test" is a grep.
- `review_depth: quality-only` — no security/perf/simplification panel for doc edits.
- `gate_strictness: light` — confirm at phase close, not at every step.

**What is NOT relaxed:** `tdd_required: true` and `simplification_pass: true` stay on. Two of
these four items are *instructions that contradict other instructions*, and the only durable fix
for that is a test pinning the agreement — which is exactly what M5.E13 learned the hard way
(`B48`, `B51`, and REVIEW's own C1 all shipped because no test compared one instruction against
another).

**Escalate if:** the 48-entry triage turns out to need a schema change rather than a data pass,
or the `review.md` verdict-rule question turns out to be a real design disagreement rather than a
doc/practice mismatch. Either would make this a FULL-tier concern.
