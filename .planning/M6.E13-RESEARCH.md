## Codebase — the current library

- **One lock, `work`** (`work-store.js:43`, 120 s TTL).
  - The only nesting is state → work, at `checkpoint.js:326-335` and `archive-tree.js:594-603`.
    Nothing takes the locks in the opposite order.
  - `acquireLock` never waits and is not re-entrant (`file-lock.js:106-172`).
  - Two of today's flows take the lock twice in sequence, so neither is atomic: `promoteInStore`
    (`backlog.js:208-221`) and `applyTriage` dup/reject (`work-ops.js:1370-1385`).
- **`schema_version` is written and never read.** `work-migrate.js:955` writes it, and nothing reads
  it. AC4.2 therefore needs a new read, not a change to an existing one.
- **The item format** is YAML frontmatter, with keys in `FIELD_ORDER` (`work-item.js:42-57`), and
  folder = status (`work-store.js:253-295`).
  - Close is a `close` mapping, and reopen pushes onto `history[]`.
  - Epic membership comes from the path (`epicOf`, `work-ops.js:161`). A stored `epic` is a schema
    error today (`work-item.js:66`).
- **ID allocation** (`nextId`, `work-store.js:189-237`) reads the working tree and then
  `git log --all`, falling back to per-ref `ls-tree` on a shallow clone. ⚠ It sees `.md` names only
  (`parseItemFileName`, `:133`), so a `.json` record is invisible to it.
- **Views** are `generateAll` (`work-generate.js:325`), called from `regenerate()` after every
  mutation. `BUGS.md` shows `B{n}`. `ISSUES-INBOX.md` copies `WATCHLIST.md` verbatim, and
  `backlog.js` reads its `· SIG-n` status line back (`parseInboxStatusLine`).
- **Secret scrubbing** is `scrubSensitive` (`add.js:358`), wrapped by `scrubTexts` and
  `sensitivePending` (`work-ops.js:450-467`). It runs at five gate sites.
- **Moving files becomes dead code.** Under the stay-put design, the move paths of
  `work-links.js` and `relocate`/`moveFile`/`folderFor`/`placement` lose their purpose. Two things
  stay:
  - The body-link depth rewrite used when printing views (`work-generate.js:98`).
  - Everything about Epic folders, since Epics are unchanged by `D-M6E13-5`. `work-units.js` is not
    touched.
- **`closeEpic`** (`work-ops.js:1026`) gates on the files in the Epic folder (`:1063-1088`). That
  check becomes a query over `epic` fields.
- **`check-state-write.js`** handles `Edit|Write` and `.planning/STATE.md` only (`:52`, `:59`). It
  finds the project root with `resolve(file,'..','..')` (`:92`), which breaks for deeper paths.

## Risk — ranked

1. **HIGH: the hook would block every project without a store.** In every project except Signal,
   the views are typed by hand. The hook must:
   - resolve `realpath` (the M6.E3 `.ENV` lesson, `M6.E3-RETROSPECTIVE.md:41,52`);
   - walk up to `.planning/`;
   - read `WORK.md`;
   - block only at `schema_version: 2`;
   - load the store check lazily, after a cheap string test, because the hook runs on every edit in
     every repository.

   `MultiEdit` may be a retired tool name, and my two sources disagree. Keep it in the matcher and
   decide on `tool_input.file_path` alone.
2. **HIGH: migration traps.**
   - 42 relative links in 28 bodies sit at depth 2 or 3, and every v2 body sits at depth 3
     (`items/NN`). They need a link rewrite, with each rewrite listed in the manifest.
   - 133 of 267 bodies contain a pasted table row.
   - After relocation, v1 files under `archive/pre-work-store-v2/` share every ID with the
     records. The duplicate-ID check and `checkStore` must skip that folder.
   - Epic folders and documents must not be relocated. That is what blinded `closure.js` in M6.E11
     review pass 3.
   - 382 inbound links: 267 are in the generated `INDEX.md` (regenerate it), and most of the rest are
     in tests being rewritten anyway.
3. **MEDIUM-HIGH: `confirmCloses`.** Measured exit codes for `git merge-base --is-ancestor`: 0
   ancestor, 1 not, 128 unknown.
   - A proof string of `--all` returned 129, meaning the proof reached git as an option. Validate it
     with `COMMIT_TOKEN_RE` and pass `<sha>^{commit}`.
   - Use the default-branch lookup in `branch-guard.js`, not a hard-coded `origin/main`.
   - At `/sig:resume`, run it after the fetch (`state.js:1366`).
   - A squash-merged or rebased proof stays *closing* forever, and nobody would notice.
4. **MEDIUM: byte-identical serialisation.** `JSON.stringify` reorders integer-like keys, drops
   `undefined`, and turns `NaN` into `null`. Fixes:
   - Serialise from an explicit key list for each record and event type.
   - Validate before serialising.
   - Add `.gitattributes` `eol=lf` for `items/**/*.json`.
   - 248 of 267 bodies hold non-ASCII text. That is fine, because bodies are `.md`, but titles in
     JSON are written unescaped.
5. **MEDIUM: the schema validator.**
   - `plugin/` ships exactly one dependency (`yaml`), pinned by `plugin-dependency.test.js:48-51`.
     Adding ajv would break that test and pull in about 4 packages, so the validator is hand-rolled
     over a declared keyword subset.
   - A test fails if the schema uses a keyword the validator does not implement. An ignored keyword
     would pass every record, the same trap as `verifyCitations` returning `ok` over zero citations.
   - Use `pattern`, not `format`.
6. **MEDIUM: the lock.** Leave `file-lock.js` alone; M6.E11 drew four Important findings on it, one
   caused by a fix. Instead:
   - Only public entry points take the lock; internals receive a handle.
   - The inventory test also fails when one lock-taking export calls another.
7. **LOW: ID history.** `git log --all … -- .planning/work/ .planning/archive/` takes 0.09–0.2 s
   and lists 316 unique names. The highest `B{n}` is 127 and the highest SIG is 268. Assert
   B-max ≤ SIG-max once, at migration.
8. **Lessons from M6.E11** (retro, `:47-60`, `:82-87`):
   - Write the regenerate-and-diff test in the first slice.
   - Capture the store-off golden output from `v0.1.47` before touching any reader.
   - Make the lock its own concern.
   - A fix to a fix gets its own fresh review.
   - Build the migration aside and run it read-only first.

## Prior art

Sources: `analysis/STORAGE-ARCHITECTURE-PROPOSAL.md`, `analysis/item-architecture-research/*.md`.

- **The locked decisions overrode the research on several points:**
  - IDs stay `SIG-n` (not ULIDs).
  - Views stay committed (not gitignored).
  - Events go in an array (not one file per event), and there is no stored status.
  - Legacy closes stay closed with `legacy: true` (not quarantined).
  - The 14 contradictions are cleaned mechanically (not resolved by a person).
  - One lock (not per-record locks plus hashes).
  - No `blocked`/`verifying` states, and no SQLite.
- **Lessons applied:**
  - Beads: every mutating path mints an event, enforced by an inventory test (AC2.2), and a
    conformance suite.
  - git-bug: a bad record does not stop the rest of the import (AC8.1, per-record).
  - Taskmaster: path literals live in one resolver.
  - MADR: bucket by number, not by category.
  - GitHub Issues: a close counts when the change reaches the default branch (FR7).
  - Org mode: an ID link survives because the file never moves (`D-M6E13-18`).
- **Build order** (proposal §5, GPT §migration): pure schema, fold and serialiser first; then the
  write library with the inventory test; then the v1 guard; then pin store-off; then readers; then
  hook and views; then migration built aside with a manifest; then a differential old-vs-new read;
  then cutover; then re-verify on the merge SHA.

### Research gaps NOT taken (named so they are a decision)

Per-record provenance hashes, event IDs and parent links, a schema digest in each record, a source
digest in view headers, rollback refusal after v2 writes, typed links beyond `epic`/`dup_of`,
same-record conflict diagnostics, and a views-deleted-doesn't-change-queries test.

**Two are taken**, because they are small and close real risks:
- the **differential old-vs-new read** before cutover (S7);
- a **closing-too-long** advisory in the sweep (risk 3).
