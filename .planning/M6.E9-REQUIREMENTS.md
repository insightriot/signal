# M6.E9 — Every agent gets a determination

**Brett's framing, and it is the requirement:** *"Either WTF are they there? or WTF aren't they
wired up?"*

Signal ships **26** agents. **5** are dispatched. **21** are files nobody invokes. Every one of the
21 gets a verdict — **wire / cut / deliberately dormant** — and a wired one must name *when* it
runs, *which* command dispatches it, and *how* it is invoked. "Keep as documentation" is an allowed
verdict and must carry a reason. What is not allowed is another pass that leaves the roster as it is.

Source row: [`BACKLOG.md`](BACKLOG.md) (filed 2026-09-08). Prior scoping decision: `D-M5E10-1` put
dispatch machinery out of scope for `M5.E10` — *"wiring 22 agents is a build, not a note"*. That
reasoning held; nothing ever came back for the build.

## What DISCUSS measured, before deciding anything

Four findings, each from running the measurement rather than reading the page.

### 1. The roster page contradicts itself — `code-reviewer` is in both lists

`v0.1.39` wired `agents/specialists/code-reviewer.md` into `commands/review.md` § 4.5. The page's
**Dispatched by a command** table records that. Its **Not dispatched by any command** section still
lists `code-reviewer.md` under `` `agents/specialists/` (3) ``.

**The suite is green over this.** `tests/agent-reachability.test.js:84` checks the other direction —
that a *dispatched* agent's own file carries no stale `NOT DISPATCHED BY ANY COMMAND` banner — and
nothing checks the page's unreachable list for an agent that has since been wired. A guard built in
one direction, on the exact page built to hold this distinction.

### 2. Only two command files can dispatch anything at all

`subagent_type` appears in **`init.md` and `review.md`, and nowhere else** in `plugin/commands/`.
The other command files — including `discuss.md`, `plan.md`, `execute.md`, `verify.md` and `ship.md`
— contain no dispatch machinery. So "wire it up" is not a one-line edit for most of the 21: the
phase command has to grow a dispatch step first.

### 3. `plan.md` § 2 orders a run to spawn three agents that do not exist

Carried forward from `references/agent-reachability.md` § *"The one that is worse than unreachable"*.
The section instructs *"spawn up to 4 research agents in parallel"* and names **Domain researcher,
Codebase researcher, Risk researcher, Prior art researcher**. Only `codebase-researcher.md` exists.
This is the highest-priority determination because it sits in the phase every Epic runs, and because
an instruction naming fiction is worse than an un-wired mention.

### 4. ⚠ A measurement error made during this DISCUSS, recorded rather than discarded

A first pass reported **6 dispatched**, with `planner` matched from `discuss.md:252` — an
anti-rationalization row reading *"Are there unresolved gray areas that will block the planner?"* —
and this was briefly reported as a false positive in the detection rule.

**It was not.** The real rule requires the name in **backticks** *and* the file to contain
`subagent_type`; the repro used a bare-word regex against all command files. Corrected measurement:
**5 dispatched, 21 unreachable**, which is exactly what the page states.

It is recorded because the failure mode is the Epic's own subject — *a claim about a guard, made
from a re-implementation of the guard rather than the guard itself.* The page was right and the
check on it was wrong.

### 5. ⚠ A proof-of-fail that silently proved nothing, caught by re-running it properly

The first attempt at RED-first verification for FR7/FR8 used shell-escaped one-line `python3 -c`
edits. **The backticks did not survive the shell quoting, so `str.replace` matched nothing and wrote
the file back unchanged** — and the suite then passed, because the state it was supposed to be
testing had never been created.

**That reads identically to a vacuous guard**, and it was briefly reported as one: *"both new guards
are vacuous."* They are not. Re-run with heredoc'd Python and an assertion that the replacement
actually matched, all three fail exactly as designed.

**The lesson is the assertion, not the quoting.** A mutation step in a proof-of-fail must verify it
mutated. Without that, "no failure" is ambiguous between *the guard is broken* and *the proof is
broken*, and the two have opposite fixes. Same family as `M6.E7`'s vacuous-gate finding — a check
that passes over an empty input set.

## Functional requirements

**FR1 — Every one of the 26 agents carries an explicit determination.** `wired`, `cut`, or
`dormant`. No agent may be absent from the determination set.

**FR2 — A `wired` determination names when, which command, and how.** The phase it runs in, the
command file that dispatches it, and the invocation shape — including what context it receives,
since for `code-reviewer` the answer is deliberately none.

**FR3 — A `cut` determination removes the file and says why.** A file left on disk after a `cut`
verdict is the state this Epic exists to end.

**FR4 — A `dormant` determination carries a reason and a trigger.** What would have to be true for
it to be worth wiring. "Keep as documentation" is allowed here and nowhere else.

**FR5 — `plan.md` § 2 stops naming agents that do not exist.** Either the three fictional names are
replaced with real ones, or the instruction is rewritten to not name agents.

**FR6 — The roster page has exactly one entry per agent.** An agent may not appear in both the
dispatched table and the unreachable list. This is finding 1, fixed.

**FR7 — The suite fails on an agent with no determination.** `tests/agent-reachability.test.js`
gains an assertion so the next agent added cannot land undecided. This is the row's own *done-when*
and the only part that outlives the Epic.

**FR8 — The suite fails on a double-listed agent.** Finding 1's guard, in the direction that was
missing.

## Out of scope, stated so it is a decision and not a drift

- **Building the dispatch step in eight command files** is not assumed. Finding 2 means some `wired`
  determinations imply real work in the command; where that cost is large, `dormant` with a trigger
  is the honest verdict rather than a wiring promise this Epic will not keep.
- **Rewriting the agents themselves.** A determination is about reachability, not about whether the
  agent's instructions are any good.
