# M5.E19 — Epic-scoped calibration

**FEATURE, not the project's FULL.** M5.E18 already built and measured the hard half — the
derivation, the closure resolver, the archive tree. This Epic is **wiring**, plus one defect
(`B82`) in a function that already exists. No new subsystem and no new concept; the design
questions were answered by the Epic that built the library.

**Why several dials stay UP, against the tier's defaults.** This is a **destructive file mover**
replacing a tool that failed by being too permissive. FEATURE's defaults are calibrated for
additive feature work, and three of them are wrong for that:

- **`review_depth: full`, not `quality-only`.** This is deliberate and load-bearing. Under
  `quality-only`, `commands/review.md:17` skips Steps 2/3/4 **regardless of what
  `security_audit` / `performance_pass` / `simplification_pass` say** — so the two dials below
  would be inert and this file would assert rigor the Epic never receives. That exact
  contradiction is the unhomed finding carried from M5.E16's retro (`B59`'s shape one level up:
  a profile that *parses* and is then silently overridden). Setting `full` is what makes the
  next two lines mean anything.
- **`security_audit: basic`.** The mover writes paths derived from unit names read off disk.
  `isSafeUnitName` + `deriveUnitArchiveDir` are a path-confinement boundary — `..`, separators,
  and over-long names are refused — and a change to the mover is a change to what reaches them.
  Not `none`.
- **`nyquist_enforcement: strict`.** Every acceptance criterion needs a test. The bar is set by
  how the thing being replaced failed: `curator` matched filenames, never checked whether work
  was finished, and proposed archiving the same four **live** units twice. A refusal that is not
  pinned by a test is a warning wearing a gate's clothes.

**What is relaxed, and why that is safe:**

- `research_parallelism: 1` — the seam was read before this file was written
  (`resolveClosures` / `planArchiveMoves` / `deriveUnits`), and `B82` was reproduced by
  measurement rather than argument. One researcher for the closure-vs-mover contract, not four.
- `performance_pass: false` — a bounded directory walk over one project's `.planning/`. There is
  no hot path.
- `plan_validation_dims: core` — the plan is a wiring sequence over an existing library, not a
  new architecture.
- `gate_strictness: light` — confirm at phase close, not at every step. **Note this does not
  relax `anti_rationalization`,** which is only disabled at `off`.
- `context_rot_reread: false` — small Epic, few files.

**Measured evidence this Epic starts from** (2026-08-07, all 12 local projects with a
`.planning/`): `B82` splits **3 units across 2 projects, stranding 6 files** — `SLICE-SSO` in
both `eval-project-A` and `eval-project-D`, and `GATE-A` in `eval-project-A`. Those are **the two projects
archiving by hand-written runbook today**, i.e. the users this Epic exists for. The defect is not
theoretical and it is not confined to the one unit `BUGS.md` records.

**Escalate to FULL if:** the closure contract turns out to need a schema change to
`resolveClosures`' record rather than a consumer, or if wiring reveals that "closed" cannot be
decided deterministically for a material share of real units — either would make this a design
Epic rather than a wiring one, and `M5.E18`'s three-outcome closure record exists precisely
because that question has bitten before.
