## 2. Risk

- **A hand-broken YAML value breaks the whole file**, not just the new key (`parseFrontmatter` throws).
  So AC1.4's "does not parse" means a structurally invalid record inside valid YAML; that check lives
  in `loopStatusFor`.
- **Record shape:** keep entries short scalars, like `completed_phases`. The STATE write hook
  (`plugin/hooks/check-state-write.js` → `retrospective.js:665`) blocks prose only in
  `completed_phases`/`blockers`; a scalar list is safe under it.
- **Double counting:** a pass that ends and then leaves the phase appears in both sources. Taking the
  **larger** of the two (`D-M6E17-1`) counts it once.
- **`commands/*.md` edits** may move the adherence directive-line ceiling → regenerate
  `ADHERENCE-LOG.md`; merge is `--merge` (the only method on `main`).
- **No test ties a function named in `review.md`/`verify.md` to code** (only `drive.md` has a symbol
  contract, `tests/drive-doc-contract.test.js:73-101`). FR1/FR2's new names need their own test.

## 3. Prior art — FR3, the parent-run tool

- **No production code creates a worktree.** Tests do (`tests/branch-work.test.js:450`,
  `tests/git-env-planted-bare-repo.test.js:339`). Temp-dir exemplar with realpath (macOS `/var` →
  `/private/var`): `adherence-harness.js:257`.
- **Every git call must go through `gitEnv(cwd)`** (`plugin/tools/lib/git-env.js:184`) —
  `tests/git-env-inventory.test.js` fails otherwise. `GitUnusableError` (git < 2.38) maps to
  "could not run".
- **vitest 3.2.4: the exit code cannot separate the cases** — a failed test, "no test files found" and
  an import error all exit 1. Positional args are substring filters. So: one run per file, with
  `--reporter=json --outputFile=<tmp>`, classified from `testResults[]`: present with a failed assertion
  = failed; present with zero assertions and a `message` = could not run (load error); absent = could
  not run (no match). Check the file exists on the parent first (`git cat-file -e <parent>:<path>`).
- **node_modules:** a fresh worktree has none. Symlink the main checkout's `node_modules` into the
  worktree and run the main checkout's vitest with `--root <worktree>`. Remove the link, then
  `git worktree remove --force` + `prune`, in `finally`. A `package-lock.json` that differs between
  parent and HEAD is reported (`depsDiffer`) beside the result.
- **Where it lives:** only `./plugin` ships, so `plugin/tools/lib/parent-run.js`, CLI entry by the
  `import.meta.url` check (`tools/cut-release.js:485`), flags by `node:util` `parseArgs` with
  `strict: true` (unknown flags refused — the shape `SIG-249` asks for). `tests/guard-callers.test.js`
  scans only `tools/`, so it does not apply.

## 4. Domain — FR4, vitest

- Main config: `exclude: [...configDefaults.exclude, ...PERF_TESTS]`; `maxWorkers` capped when
  `process.env.CI` is unset (GitHub Actions sets `CI=true`, so CI keeps full parallelism).
- `vitest.perf.config.js`: `include: PERF_TESTS`, `fileParallelism: false`. Script `test:perf`. CI step
  after `npm test`.
- ⚠ **`SIG-303` names three files, and one is not a timing test.** `tests/planning-index.test.js` has no
  wall-clock assertion — its failures are 15 s timeouts, the `SIG-139` class. So the perf run takes
  **two** files (`tests/unit-records-perf.test.js`, and the 10,000-record case of
  `tests/work-records.test.js`, which moves to its own file); `planning-index` is covered by the worker cap.
- ⚠ **About fifteen other test files also assert a wall-clock or ratio budget** (`jev.test.js:257`,
  `unit-text-slow-input.test.js`, `work-migrate-hostile.test.js`, `hook-work-write-guard-r61.test.js`,
  and others — list in the research pass). Several are guards against catastrophically slow regex that
  belong in the main suite. So AC4.4's guard ships with a **grandfather list with a reason per file**
  (house rule: promotion needs a grandfather list), and fails only on a *new* budget outside the perf run.

  test file; `Date.now` used to build fixtures alone does not match.
