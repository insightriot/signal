## 2. Writing records (seams)

- Signal's lists went lists → v1 files (`planMigrationFromTexts`, `work-migrate.js:613`) → records
  (`migrateWorkStoreV2`, `work-migrate-v2.js:561`). There is no direct lists → records path.
- Event shapes (`work-convert.js` `convertV1Item` :248, `closeEvents` :161, not exported): `created {at, by}`,
  synthesized `triaged`, legacy `closed {at, by, reason, legacy: true, proof?, dup_of?}`.
- Every record must pass `validateRecord` (`work-record.js:164`, schema
  `plugin/references/work-item.schema.json`) and `checkEvents` (:430); written with `serializeRecord`
  (:230). First event `created`; a legacy `closed` is legal from any open status.
- `closed.reason` ∈ `fixed | stale | wontdo | dup | rejected` (schema :116). `proof` optional when
  `legacy: true`. **So `D-M6E15-3`'s "original wording as the reason" goes in `proof`** (`D-M6E15-18`).
- `newItems` (`work-records.js:892`) cannot set `legacy_id`, `migration_note` or a close, and needs a
  v2 `WORK.md`. The new path builds records itself, as `buildInto` (`work-migrate-v2.js:418`) did.
- Reusable: `tile()` (`work-migrate.js:78`, byte tiling), `rewriteRelativeLinks` (`work-links.js`),
  `bodyDirFor` (`work-convert.js:61`), `recordPath`/`bodyPath` (`work-records.js:82/92`), and from
  `work-migrate-v2.js`: `confineWrite`/`preflight` (:388/405), build-aside then `postBuildErrors`
  (:528, `listRecords` + `checkRecords`), dirty-tree and tracked-file checks (:570-576, :665-668).
- Not reusable (v1-specific): `convertStore`, `listV1Items`, `verifyConversion`, `v2WorkBody`
  (:311-327, names Signal's script — AC7.3), `NO_COMMIT_LEGACY_IDS` (`work-convert.js:30`, AC7.2).
- **Dates:** lists carry no per-row date. Views keep a close live for 30 days after the newest event
  (`work-views.js:127-131, 300-312`), so "today" on every legacy close floods the live views
  (`D-M6E15-19`). Precedent: `firstAddedDates` (`work-migrate-v2.js:121`).
