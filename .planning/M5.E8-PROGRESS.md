### Slice 2 — The harness skeleton (FR1)

- [x] **S2.t1** — entry point + scratch fixture + isolation assertion (AC1.1, AC1.3)

**The seam, decided before writing any of it.** AC1.2 ("no test imports the harness") and
F2 ("the suite tests the harness mechanics with a stub") cannot both hold for one file.
So there are two:

| File | What | Tested? |
|---|---|---|
| `tools/lib/adherence-harness.js` | pure mechanics — fixtures, isolation, trace capture, diffing, cost planning, surface detection. Never invokes an agent. | yes, directly |
| `tools/adherence-run.js` | the entry point that spends money. Invokes `claude -p`. | **never imported or spawned by any test** — asserted mechanically |

**AC1.3 is not `path-confine.js`.** That helper confines writes to `.planning/` *within* a
given base; the guarantee needed here is that the fixture is not, is not inside, and does
not contain the invoking project — plus must live under the OS temp dir. Four refusal
cases are tested, including the pathological inverse (a "fixture" root high enough that
the real repo sits inside it).

**AC1.4 verified end-to-end, not just by unit test:** running the entry point with `claude`
genuinely off `PATH` aborts with *"This is not a measurement of zero — no measurement was
taken"* and exits 1. The surface is resolved **before any fixture is built**, so an
unreachable CLI costs nothing and can never produce a result-shaped output.

**The skeleton reports observations, not verdicts, and says so in its own output.** Without
S3's control arm a trace could be caused by the instruction *or* by the agent doing it
anyway — opposite findings. The banner stays until S3 lands.

**Two self-corrections worth recording:** the first draft of the suite-guard flagged
`adherence-harness.test.js` for *mentioning* the entry point in a doc comment — scoped to
real spawn sites. And the trace reader shelled out to `cat` to read a file; replaced with
`readFileSync` (non-portable, and pointless).

## Wave 1 → 2 gate: the seam probe (run 2026-07-28, 2 agent calls)

**Result: SEAM OK. S3 is unblocked.**

| Probe | What it proves | Verdict |
|---|---|---|
| `discovery` — a NEW command that exists only in the copy | `--plugin-dir` loads the copied tree at all | **PASS** |
| `precedence` — an EXISTING command (`status.md`) overwritten in the copy | the copy **shadows** the installed `sig` plugin | **PASS** |

**The conflict was real, verified without spending a further call:**
`~/.claude/settings.json` carries `"sig@signal": true` at **user scope**, so the installed
v0.1.11 plugin was active in the temp fixture too. Both trees offered `/sig:status`; the
`--plugin-dir` copy won.

**Why this gate existed at all.** S2 originally set `CLAUDE_PLUGIN_ROOT` and assumed it
redirects *which* command file is loaded. It doesn't — that variable is substituted *inside*
an already-loaded command for skill paths. Command **resolution** is a different mechanism,
and this session had direct counter-evidence: invoking `Skill(sig:execute)` loaded the
**0.1.11 plugin cache**, not this repo. The real seam is the `--plugin-dir` flag.

**The failure mode this closes is the Epic's worst one.** If the mutation never reaches the
agent, both arms produce the trace, and the harness reports **`inert`** — which this plan
pre-committed to as an acceptable, expected outcome. A plumbing failure would have passed
straight through the one guardrail meant to catch surprises and been written into
`ADHERENCE-LOG.md` as a measurement. The probe is therefore **permanent**, not a one-off:
S3 must run it as a precondition and refuse to emit any verdict if it fails.

## Wave 2 — S3 (the control arm)

- [x] **S3.t1** — mutated copy of the command tree (AC2.4)
- [x] **S3.t2** — two arms × N runs, difference + spread (AC2.1, AC2.3)
- [x] **S3.t3** — trace in both arms ⇒ `inert` (AC2.2)
- [x] **S3.t4** — canary registry, starting with `B41`'s phase-entry rule (AC3.1–3.3)

**The verdict function was fixed before any run produced a number.** AC3.3 pins *traces*
pre-run; the mapping from run counts to a verdict is pinned the same way, in
`references/adherence-canaries.json` → `verdictRule`. Otherwise the threshold gets chosen
after seeing 3/3 vs 2/3, which is the rationalization AC3.3 exists to prevent.

**Four verdicts, and three of them are not "pass":** `obeyed` · `inert` (the trace in both
arms — a finding, never retried until it passes) · `absent` · `indeterminate` (a split vote,
a failed run, or a backwards result — an honest *we don't know* rather than a rounded
finding). Deliberately conservative: anything short of a unanimous split is
`indeterminate`.

**And one refusal that outranks all four:** no verdict at all unless the seam probe proved
the mutation reached the agent.

**Three throw-rather-than-degrade paths, all guarding the same disguised failure.** A
deletion target that is missing, a deletion target that matches twice, and an unknown trace
field would each produce two identical arms — which reads as `inert`. Each throws instead.

## Wave 3 — S4 (the record and the anchor)

- [x] **S4.t1** — append-only log (AC4.1, AC4.2)
- [x] **S4.t2** — reproducibility from the record (AC4.3)
- [x] **S4.t3** — `ship.md` checklist line + presence test (AC6.1–6.3)

**Append-only is structural, not procedural.** `appendRunRecord` is a pure concatenation:
there is no code path that reads an existing record, so there is none that can rewrite one.
M5.E9 established that a past collapse is **not detectable from the file afterwards** —
the evidence is exactly what gets destroyed — so the guarantee had to be built in rather
than checked for.

**The ship anchor is labelled presence-not-obedience**, per M5.E9's precedent, in the test
file itself. It proves a line exists in `ship.md`. It cannot prove a maintainer reads it.

**A limit found by shipping FR6's own line:** adding the adherence checklist item did not
move the published ceiling, because checklist items are written as completed states
("*docs/map refreshed if…*", "*All tests pass*"), so neither stage-A rule fires. Whether
those count as directives is arguable; they are excluded, and the exclusion is now recorded
in the classifier's documented limits rather than left to be discovered by diffing.
