`CONTEXT.md`) into units and archiving live files. The dry-run reports unmatched files by count so
the gap is visible rather than silent.

## What this Epic does for the first time — and it is wave 1

Per `plan.md`'s first-use instruction (M5.E17 FR1). Not what the Epic *builds* — what it **runs**.

> **`isStub` has been computed since M4.5.E9 and thrown away at the one call site that decides
> archiving.** `retro-index.js` computes it per retro; `archive-tree.js:357` does
> `closedEpicIds = retros.map(r => r.epicId)` and drops it. **FR5 is the first time that value is
> read for a decision** — and today Signal's own four stub retros (`M4.5.E1`, `M4.5.E3`, `M4.5.E6`,
> `M4.5.E7`) are treated by the archive path as proof of closure.
>
> **Second: `path-confine.js` receives its first arbitrary name.** Every name reaching the archive
> path so far passed `EPIC_ID_STRICT_RE`, which cannot express a traversal — safe *before* arrival.
> FR1's names come from arbitrary filenames on disk (NFR4).
>
> **Therefore S1 is wave 1: derivation plus a read-only dry-run over all 12 real trees, before any
> mover, any status renderer, any `--apply`.** The RESEARCH measurements *are* what a wave-1 dry-run
> produces, and running that rule early is what caught the split-unit defect. Had FR4's reporting
> been built first, it would have rendered a four-status report over a rule that halves slices.

### S1 — Units derived from filenames, in one home (wave 1) · **L**

**FR1, NFR4-prep.** The first-use slice.

`WORKED_UNIT_IN_FILENAME` (`state-drift.js:421`) already implements two-thirds of FR1, written by
M5.E16's `C1` fix. **It is extracted, not duplicated** — PLAN open question 1 answered: a new shared
module `tools/lib/work-units.js`, consumed by `state-drift.js` and the archive planner both. Two
implementations of one rule is the shape M5.E13 REVIEW flagged.

| Task | What |
|---|---|
| **t1** | `tools/lib/work-units.js` — `deriveUnits(filenames) → {units: Map<string, Artifact[]>, ungrouped: string[]}`. Right-anchored suffix match over `SCAFFOLD_SUFFIXES`; categorical exclusion of the seven phase names; leading-phase-marker strip (AC1.2 as corrected). RED-first. |
| **t2** | Repoint `state-drift.js` at the shared module; **delete** the local regex. Check `(c)`'s existing tests must pass unchanged — that is the proof the extraction is behaviour-preserving. |
| **t3** | A corpus harness: run `deriveUnits` over all 12 trees, assert the measured unit sets from RESEARCH §1. Fixture-backed so it runs in CI without the real trees. |

**Acceptance criteria**

- **AC1.1** `PHASE10-S4-PLAN.md` → `PHASE10-S4` (right-anchored, not first-hyphen).
- **AC1.2′** **All four measured split pairs resolve to one unit each.** A bare phase-name strip
  merges only three of them — measured, not assumed:

  | Plan-side files | Execution-side files | Bare `PLAN-` strip gives | Merges? |
  |---|---|---|---|
  | `PLAN-GATE-A-*` | `GATE-A-PROGRESS.md` | `GATE-A` | ✅ |
  | `PLAN-SC1-*` | `SC1-PROGRESS/VERIFICATION.md` | `SC1` | ✅ |
  | `PLAN-SLICE-SSO-*` | `SLICE-SSO-PROGRESS/REVIEW/VERIFICATION.md` | `SLICE-SSO` | ✅ |
  | `PLAN-SLICE-VOICE1-*` | **`VOICE1-PROGRESS.md`** | `SLICE-VOICE1` | ❌ |

  **nextpass is internally inconsistent** — `SLICE-SSO` keeps its `SLICE-` prefix on the execution
  side, `VOICE1` drops it. So no single lexical strip merges all four, and `SLICE-` cannot be
  stripped unconditionally: `SLICE-SSO` *is* the canonical unit name there.

  **The rule is therefore two passes, not one:** (1) strip a leading phase name; (2) **fold unit `U`
  into unit `V` when `U` ends with `-V` and `V` exists independently.** `SLICE-VOICE1` folds into
  `VOICE1`; `SLICE-SSO` does not fold because no other unit ends `-SSO`.

  **RED-first, and the test asserts all four pairs** — a test that passes on `GATE-A` alone would
  leave `VOICE1` split, which is the exact failure this correction exists to prevent.
- **AC1.2″ (new)** The fold is conservative: a unit is folded **only** when the target exists as an
  independently-derived unit. No unit is folded into a name that is not already present.
- **AC1.3** `M1-PLAN.md` → `M1`; `M5.E16-PLAN.md` → `M5.E16`.
- **AC1.4′** `traction-engine` derives exactly the corrected set above, and `CONTEXT.md`,
  `DECISIONS.md`, `INDEX.md`, `LANDSCAPE.md`, `OPEN-QUESTIONS.md`, `FUTURE-IDEAS.md` are in no unit.
- **AC1.5** `NEXTPASS-STACK-DECISION.md`, `BUGHUNT-2026-06-12.md`, `PLAN-SLICE-VOICE1.md` land in
  `ungrouped`; the count prints **unconditionally, including zero**.
- **AC1.6 (new)** No unit is ever named one of the seven canonical phases. `agent-builder` derives
  **zero** units from `PLAN-PLAN.md` / `REVIEW-REVIEW.md` / `VERIFY-VERIFICATION.md`. RED-first —
  today it derives three.
- **AC1.7′ (corrected before approval — the original was unachievable)** The extraction's effect on
  check `(c)` is **enumerated and ratified**, not assumed away. Measured: the local regex carries
  **4** suffixes, `SCAFFOLD_SUFFIXES` carries **8**, and the 8-suffix list derives **more** units on
  3 of 12 projects — `cm-mentor-coach` +`PLAN-SLICE-SSO`, `conversor` +`PLAN`, `nextpass` +4. So
  "byte-identical findings" is **false against a correct implementation** and would have failed S1 on
  a criterion that cannot be met.

  What t2 must instead prove: every difference in check `(c)`'s findings is **listed**, and each is
  either (a) eliminated by AC1.2′'s fold or AC1.6's phase-name exclusion, or (b) explicitly ratified
  as a genuine improvement. *Prediction to test, not to trust: most of the extra units disappear
  again once the fold and the exclusion run — `conversor`'s `PLAN` is killed by AC1.6, and nextpass's
  four fold into their siblings. S1 measures whether that holds.*

**Tests.** Unit: the derivation table (every AC above, one case each) + property test that
`deriveUnits` is idempotent and total (every input file lands in exactly one of `units`/`ungrouped`).
Integration: t3's corpus harness. **Nyquist: 8 ACs → 8+ tests, each RED first.**

### S4 — Closure has three outcomes · **M**

**FR2.** Depends on S1, S2, S3.

`closed` requires all three: a terminal artifact · not the current unit · a **passing readable**
verdict. Anything else that is not clearly `open` is `cannotDetermine`.

**Acceptance criteria**

- **AC2.1** `cannotDetermine` is a value in the returned structure, not a rendering decision — a

- **AC2.5** A readable **FAIL** → `open`, not `closed`.
- **AC2.10 (new)** A unit merged from a split pair (S1's AC1.2′) whose halves disagree — two

### S6 — Where a non-Epic unit archives to, safely · **M**

**NFR4 + PLAN open question 2.** Depends on S1, S4.

`deriveEpicArchiveDir` yields `.planning/archive/{M}/E{n}` from a strict ID and **throws** otherwise.
`PHASE10-S4` and `GATE-A` have no milestone to key on.

**Proposed layout:** `.planning/archive/{unit}/` — flat, one directory per unit, no derived
hierarchy. Strict Epic IDs keep their existing `{M}/E{n}` path so nothing that works today moves.

**Stability comes free** (RESEARCH §5.2): derivation reads only the top level, and archived files
have left it — so a second dry-run proposes nothing **by construction**, provided `archive/` is
excluded from the scan. That exclusion is an AC, not an assumption.

**Acceptance criteria**

- **AC6.1 (new)** A non-Epic unit archives to `.planning/archive/{unit}/`; a strict Epic ID keeps
  `.planning/archive/{M}/E{n}/`. No existing Epic move changes.
- **AC6.2 (NFR4)** Unit names route through `path-confine.js`. A name containing `..`, `/`, `\`, or a
  leading `.` **cannot** escape `.planning/archive/`. Adversarial fixtures — the corpus has none
  today, which is luck of inventory, not safety.
- **AC6.3 (NFR2)** Second dry-run immediately after an apply proposes **zero** moves. `archive/` is
  excluded from the scan; asserted.
- **AC6.4 (NFR1)** Dry-run is default and writes nothing — `.planning/` byte-identical after.

**Tests.** Unit (path derivation + adversarial confinement) + integration (apply → re-dry-run).
**4 ACs → 7+ tests.**

## Risks

| Risk | Mitigation |
|---|---|
| The phase-marker strip merges two units that are genuinely distinct | The seven phase names are a **closed enumerated set**, and the strip only fires when the remainder is non-empty and itself forms a unit. AC1.2′ pins the merge; a new AC pins that a unit legitimately named e.g. `PLANNER-X` is untouched. |
| Extracting `WORKED_UNIT_IN_FILENAME` regresses check `(c)` | AC1.7 — `(c)`'s existing tests must pass byte-identically. The extraction is proven by the tests that already exist, not by new ones. |
| `--apply` moves the wrong files on a real project | Dry-run is default (AC6.4); relocate-never-delete; git-reversible. First `--apply` runs against a **copy** of a real tree, not the tree. |
| 35% `cannotDetermine` reads as failure | It is the honest answer, and FR4's whole purpose. Reported as a first-class count (AC4.1), never as `0`. |
