# M6.E18 — Plan: the review loop's signals become trustworthy

**Goal:** every signal the review loop stops on — the PR reviewer's verdict, the loop ceiling, a pass
record, a fix round's proof, SHIP's "what is left" — says what actually happened, and this Epic's own
driven run is the first to rely on all of them.

Requirements: [`M6.E18-REQUIREMENTS.md`](M6.E18-REQUIREMENTS.md). Research:
[`M6.E18-RESEARCH.md`](M6.E18-RESEARCH.md). Test mapping:
[`M6.E18-VALIDATION.md`](M6.E18-VALIDATION.md). Decisions `D-M6E18-1` … `-8`. Items started under
M6.E18: `SIG-348`, `SIG-285`, `SIG-349`, `SIG-337`, `SIG-344`, `SIG-335`, `SIG-343`, `SIG-319`,
`SIG-342`. Tier FULL, strict TDD, `attention: checkpointed`, driven by `/sig:drive`.
**Runtime:** Node 22+ (dev machine 22.13.0), vitest 3.2.4, git 2.39.3 (≥ 2.38). No new dependency.

## What this Epic does for the first time

1. **A PR gets a real review of its head commit after Claude has already commented.** Nothing has
   ever done that here: all ten of #304's runs after the first stopped at step 1. **S1 is wave 1** and
   ships alone (`D-M6E18-7`), so the first on-demand run is this Epic's own PR at SHIP, after `main`
   is merged into this branch.
2. **A driven run's ceiling reads a visit marker.** The installed `0.1.52` has no marker, so from S2's
   merge into this branch onward, **VERIFY and REVIEW for this Epic call `./plugin/tools/lib/`** (this
   branch's code), not the plugin cache, for `transitionPhase`, `recordPass`, `loopStatusFor` and
   `checkFixRounds`. **S2 is wave 1**, so this Epic's own VERIFY is the first visit ever marked.

## Rules for every task

- Re-grep before relying on a research line number.
- Failing test first; run each slice's new tests with
  `node plugin/tools/lib/parent-run.js --base <slice base> <tests…>` and paste its summary line into
  `M6.E18-PROGRESS.md`. A missing result is a stated gap, not a pass.
- Every git call takes `gitEnv(cwd)` (`tools/lib/git-env.js`). Read exit codes, not last lines. Never
  `git stash`.
- Prove a claim about a command's flow by running its documented steps in order (M6.E17 retro).
- Edits to `commands/*.md` keep `tests/review-loop-doc-contract.test.js` and
  `tests/loop-ceiling.test.js`'s required strings intact.

### S4 — `checkFixRounds` checks what a round claims (wave 2, after S2) · M — `SIG-335`, `SIG-344`
- **t4.1** A round's **Parent run:** sha is resolved (`git rev-parse --verify <sha>^{commit}` under
  `gitEnv`) and must equal the base of its fresh-read range; refuse unresolvable or mismatched. Git is
  injected (`opts.git`) so the parser stays testable; with no git available the round is a stated gap,
  never a pass.
- **t4.2** Round N+1's range base equals round N's range head; `review.md` § 4.6 says a later round's
  base is the previous round's head.
- **t4.3** Strip HTML comments the way `unfence` strips fences (offsets kept) before finding headings.
- **t4.4** `PASS_HEADING_RE` also accepts `## Pass N, at <sha>`; commits after the newest pass's sha
  that no round's range covers are reported (`git rev-list <passSha>..HEAD` under `gitEnv`).
- **t4.5** `recordPass` for REVIEW refuses, naming `checkFixRounds`, when the report has a fix round
  whose check has not passed (AC3.5) — `recordPass` takes the check's result, not the report.
- **AC:** AC3.5, AC4.1–AC4.4. **Files:** `tools/lib/review-rounds.js`, `tools/lib/state.js`,
  `commands/review.md`, tests `review-rounds`, `review-loop-doc-contract`. **Out of scope:** `SIG-336`'s

## Plan validation (8 dimensions, run in-session 2026-10-20)

1. **Goal alignment** — every slice serves one signal named in the goal: S1/S3 the PR reviewer, S2 the
   ceiling and pass record, S4 the fix round's proof, S5/S6 SHIP. S7 is close-out.
2. **Completeness** — FR1 → S1, S3; FR2 → S2; FR3 → S2 (AC3.1–3.4, 3.6), S4 (AC3.5); FR4 → S4;
   FR5 → S5; FR6 → S6. All 25 criteria are in `M6.E18-VALIDATION.md` (derived, see its footer).
3. **Dependencies** — S3 needs S1's outcome-line *format*, not its merge. S4 and S5 both edit
   `state.js` after S2 (`recordPass`, `transitionPhase`), so they start from S2's commit. S7.t3 needs
   S1 on `main`. Nothing else is ordered.
4. **Testability** — every criterion has an automated test; the two live rows are observations named
   with where they are checked.
5. **Scope** — the out-of-scope lines and *Residue at SHIP* hold `D-M6E18-2`'s cut; no slice adds a
   floor, changes the ceiling, or touches the upstream command.
6. **Context** — each slice is one or two lib files plus one command file; none needs another slice's
   files open.
7. **Risk** — research § 3's five risks: marker drift → t2.2's `null` rule; prompt drift → t1.4; git in
   the parser → t4.1's injected, `gitEnv`-routed call; the cache-vs-branch run → *first time* § 2;
   doc-contract churn → S7.
8. **Vertical slicing** — each slice ships a behaviour with its test and its doc line; S1 ships on its
   own.
