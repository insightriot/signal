- **Open process risk:** during PLAN, all four research agents completed and went idle **without
  delivering**; each needed an explicit re-request. Applying the mitigation here — every delegated
  task is confirmed landed (file on disk + commit sha) before its row is marked done. Never mark a
  task done on an agent's self-report alone (demand item #17). **It paid off immediately:** t4
  reported complete while its file was still untracked.

- **⚠ CONCURRENT-DISPATCH RACE REPRODUCED LIVE — this Epic hit the exact hazard it harvested.**
  Demand item **#32** (M5.E5 retro) says: *"EXECUTE guidance should distinguish 'logically
  parallel' from 'safe to dispatch concurrently' … every executor runs the full suite + commits
  against a shared index, so concurrent dispatch races."* Three agents were dispatched
  concurrently against one worktree. **Two of them silently absorbed a sibling's file** via
  `git commit --amend`, which targets whatever HEAD is at that instant rather than the agent's own
  commit; a `git reset` was needed to unpick it. Reflog trail: `545e685` → amended twice → `6b5db56`
  → reset to `136e598` → `1d057d7` → amended into a sibling's commit → reset → `3c5d8d3`.
  **Verified independently: no work lost**, each final commit holds exactly one agent's file.
  **Two mitigations, both cheap and known:** (1) `isolation: "worktree"` per dispatched agent;
  (2) an executor rule — `git add <path> && git commit`, **never** `git commit --amend`, on a
  shared worktree. *Second-order significance: item #32 is no longer merely un-tracked, it is
  actively costing — which strengthens Theme F's case in S1.t3 beyond "raised three times."*
