## What changed mid-flight

**The scope grew twice, both times from measurement rather than opinion.**

**S5 was planned as two decision sites and shipped as five.** The sibling sweep (`t4`) was scheduled
last, as confirmation. Run **first**, it changed the slice: the class — *a retro file existing is not
a finished unit* — had five sites. Three the plan never named, including `detectDirtyExecute` (the
banner whose whole job is to say *write the retro*, silenced by writing the placeholder) and
`checkEpicWithoutRetro` — **the check M5.E16 had shipped eight days earlier to catch exactly this**,
which a stub made go quiet.

**Wave 6 existed because a question exposed that the Epic hadn't delivered its own premise.** Asked
whether a standalone preview page was worth keeping, Brett asked instead: *is this a record of
archiving, or the archiving itself?* Measuring to answer it found the command archived **67 files
across 1 of 12 projects — all 67 of them Signal's own tree.** The library could do 110; nothing
wired it. The published 63 → 110 figure described a capability, not a delivery.

## What assumptions broke

**"One of the two definitions of *done* must be the right one."** Wrong in both directions.
Retro-only sees 67 files and is blind to 8 projects. Verdict-only sees 110 but **loses 4** —
`M5.E17` has a retrospective and never wrote a VERIFICATION, so the verdict rule reads a shipped
Epic as still running. The answer was the **union** (114 files, 6 projects, nothing lost), and it
only became visible by measuring the swap in *both* directions instead of the one that flattered the
new code.

**"`isStubRetro` is used."** It had existed since M4.5.E9 and `enumerateRetros` reported it on every
record — consumed in **exactly one place**, rendering `*stub*` into `INDEX.md`. Every caller that
used a retrospective to make a *decision* threw it away. Not five bugs: one value that never reached
any of its five decision points.

**"A comment describing behaviour stays true."** Three versions of one wiring comment; **two of them
wrong**, including my own correction, which was wrong in the opposite direction from the original.

## What surprised us

**The Epic reproduced its own defect classes four times, in its own code.**

| | |
|---|---|
| `renderArchivePlan` kept a second copy of the distinction its own docblock said could not drift | REVIEW 1 |
| a wiring comment asserted a property the code no longer had | REVIEW 2 |
| S4's counts made *"could not look"* byte-identical to *"nothing to look at"* | VERIFY 1, first use |
| `renderMoveBreakdown` inferred unit names and mislabelled two renames | wave 6, first use |

**Three separate "correct library code, no command path" gaps.** `B63`'s wiring (caught internally),
the mover's closed-set (caught by a user's question), `AC4.5`'s second half (caught by the second
VERIFY). **None was caught by the same mechanism twice**, which means no single check is covering
this — and it is the highest-value thing this Epic learned about itself.

**Two misleading performance numbers, both from a badly-chosen baseline.** One compared separate
node processes and reported the instrumented path as *faster*; one compared against a variant that
also skipped 74 moves of link work. Both caught before publishing, neither by a process — by
noticing the number was implausible.

## What we'd do differently

1. **Schedule the sibling sweep before the fixes it confirms, not after.** `plan.md` already
   schedules *first use* in wave 1 (M5.E17's addition). The same argument applies to *"find the
   other instances"*: ordered last it is a formality; ordered first it sizes the slice.
2. **Make "reachable from a command" an acceptance criterion, not a review question.** Every AC here
   was satisfiable by a unit test against an unreachable function, and three were.
3. **Write the test before the comment.** Every prose claim about behaviour that had no failing test
   behind it went stale — three times, in one Epic.
4. **Measure a swap in both directions before calling it an improvement.** The union only exists
   because the losing direction was measured.

## What to feed back into Signal

- **`plan.md`** — extend the wave-1 first-use rule to cover sibling sweeps. *(Filed.)*
- **An AC-shape rule** — a criterion satisfied only by a direct library call is not satisfied.
  Candidate for the `verify.md` goal-backward step, which caught two of the three gaps here **only
  because it was made the phase's first question by hand.**
- **`B78` was load-bearing, twice.** REVIEW 1 FAILed on the LOC cap; REVIEW 2 passed *because the
  corrected rule made the required new test an obligation rather than a disqualifier*. Under the old
  wording REVIEW 2 would have FAILed for needing a test. The fix discriminated between two real
  cases one day after landing.
- **`B52` was sighted five times in one Epic** — every `/sig:` command in this session loaded from
  the `0.1.16` cache while `0.1.17` was installed, so **both REVIEW passes were handed the
  pre-`B78` rule text** and the on-disk rule had to be applied by hand. A stale-binding defect that
  serves the *wrong version of a decision document* is worse than one that serves stale code.

## Anti-rationalization moment

**REVIEW 1's FAIL.** The fix was 112 LOC of non-test source against a ≤ 50 cap — but **71 of those
were deletions of a duplicate**, and the argument *"removing code is not the risk the cap guards"*
was right there and genuinely persuasive.

It was rejected because **"insertions plus deletions" had been written into the rule the previous
day**, by me, specifically to close that ambiguity (`D-M5E18-6`). Reading past it one day later
would have made the fix worthless. `D-M5E17-1` records the same trap in general form: *"the diff was
small" is exactly how something gets under-fixed.*

It was also substantively right, not ceremony: AC4.2/AC4.4's golden tests were exercising **different
code** than VERIFY had signed off on. The loop-back bought a real re-verification, and that second
VERIFY found `AC4.5`'s unreachable half.

**The near-miss worth recording:** at SHIP, the FR1 gate reported it **could not evaluate** because
the milestone row was stale (`B36`). Had it stayed silent, this Epic would have shipped with no
retrospective and nothing saying so — which is exactly what happened three times before `B36` was
made loud. **The fix for a silent gate paid off in the Epic that most needed it.**
