## 5. The defect this Epic found in its own product

`buildArchiveReport` composed `plan` from `senseArchiveTree` and `refusals` from `resolveClosures`.
Those two disagree about an unreadable `STATE.md`: `resolveClosures` degrades every unit to
`cannotDetermine`, while `senseArchiveTree`'s retro-derived half needs no STATE at all and still
reports a unit closed on the strength of a retrospective file.

**The plan came from the source that cannot see the danger.** A project with no readable `STATE.md`
would have been handed a plan to archive work that might be the current unit — the retired tool's
exact failure, reproduced inside its replacement.

`commands/archive.md` asserted the correct behaviour *before the code did it*. **The prose was right
and the implementation was wrong** — the reverse of this repo's usual failure, where the code is
right and a document has gone stale. Guarded, reasoning inline, pinned by AC-S2.5.

## 6. The defect this Epic found in its own PROCESS — `B41`'s shape, in the ledger, today

**`completed_phases` reads `DISCUSS, PLAN`. EXECUTE is absent, and EXECUTE ran.**

The command was built, committed (`cafab4a`), and `M5.E19-PROGRESS.md` records all five slices — but
`transitionPhase('EXECUTE')` was **never called**, because this Epic was driven by hand rather than
through `/sig:execute`. `transitionPhase` records the phase being *left*, so going PLAN → VERIFY
appended `PLAN` and EXECUTE simply never entered the ledger.

**Not repaired, deliberately.** The phase log is append-only with no dedupe (`D-M5E9-5`); hand-
inserting an entry to make the record look tidy is precisely the falsification the append-only rule
exists to prevent, and `B48` established that writing a phase entry the flow did not produce is the
wrong move even when the instruction demands it.

**What it actually means:** this is `B41` — *"four phase commands never call `transitionPhase`, so a
project finishes a full build with phases never recorded"* — reproduced by a **human-driven** run
rather than a command-driven one. The fix that closed `B41` put the call inside each command; it
cannot help a run that does not invoke the commands. **Signal-on-Signal is exactly that run**, and
this is the first time the gap has been caught while it was happening rather than reconstructed
afterwards.

Filed for triage rather than fixed inside VERIFY. Candidate shapes: a `/sig:execute` entry that
works for hand-driven Epics, or a drift check comparing `completed_phases` against the artifacts on
disk (`{Epic}-PROGRESS.md` exists ⇒ EXECUTE ran) — note `phase-behind-artifacts` already compares
`phase` to artifacts but says nothing about **gaps in the log**.
