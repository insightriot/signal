Install Signal

Signal is a Claude Code plugin that puts a disciplined workflow around AI-assisted development — and right-sizes how much rigor you get, so a throwaway script isn't treated like a payments system. This page gets it installed and gets your first project running on it.

01Before you start

WhatWhy
Node.js 22+Signal's tooling is ESM. No native modules to build.
Claude Code 2.1.141+Earlier versions lack an env var the install troubleshooting relies on.
GitSignal keeps your project's memory in .planning/, tracked in git. Without a repo it still runs, but you lose the point of it.
macOSVerified there. Linux and WSL are untested rather than known-broken.

02Install the plugin

Three lines in Claude Code:

/plugin marketplace add https://signal.insightriot.com/install/marketplace.json
/plugin install sig@signal
/reload-plugins

Then type /sig: and check the commands autocomplete. That's the whole install.

Installed Signal before? If you added the marketplace as insightriot/signal, it still works — nothing is broken and you are not stranded. But that form clones the entire repository (~19 MB) every time it refreshes, where the address above fetches a single file. To switch: 
/plugin marketplace remove signal
/plugin marketplace add https://signal.insightriot.com/install/marketplace.json
/plugin install sig@signal

All three lines are required. marketplace remove uninstalls the plugin, and add alone does not bring it back — so run them together rather than stopping after the second. Your settings and your projects are untouched; the plugin itself is removed and reinstalled. /sig:doctor will also tell you if you're still on the old form — you don't have to remember to check.

You do not need to delete anything under ~/.claude/plugins/cache/. Old plugin versions are swept automatically about two weeks after they're replaced. The marketplace clone is the one thing that doesn't clean itself up, which is what the remove line above handles.

If the install fails with a permissions or SSH error, your machine has a non-default SSH setup and the plugin loader is reaching for SSH when it should use HTTPS. Run export CLAUDE_CODE_PLUGIN_PREFER_HTTPS=1 in your shell and retry. Other symptoms are covered in install troubleshooting.

03Start a new project

  1. Make it a git repo

    Signal stores your project's memory in .planning/, and that only survives if it's tracked.

    mkdir my-project && cd my-project
git init

  2. Say what you're building

    Five questions about intent. Produces .planning/PROJECT.md.

    /sig:new-project

  3. Calibrate the rigor

    This is the part that makes Signal different. Five diagnostic questions — scope, stakes, novelty, reversibility, and time horizon — decide how much process you actually get.

    /sig:calibrate

    Out comes .planning/PROFILE.md: your tier (SKETCH, FEATURE, SPIKE or FULL) and the rigor toggles every later command reads — whether tests come first, how deep security review goes, how strictly test coverage is mapped.

04Or bring Signal to code you already have

This is the more common path. Use /sig:init instead of /sig:new-project — it reads your repo first, so you're not describing a codebase Signal could have just looked at.

# in a git repo that already has commits
/sig:init
/sig:calibrate

/sig:init runs four read-only scanners over your code — no installs, no edits — and writes a LANDSCAPE.md describing what it found, plus a draft PROJECT.md.

Read LANDSCAPE.md and PROJECT.md before you calibrate. Anything Signal inferred is marked [INFERRED — please verify], and anything it couldn't infer is marked [FILL IN]. Calibration depends on stakes, reversibility and horizon — none of which live in your code. Answering those from an unreviewed draft gets you the wrong tier.

05Then walk the phases

Six commands, in order. Each one reads your tier first and skips itself if your tier doesn't need it.

/sig:discuss   # lock the decisions before writing code
/sig:plan      # research, then a plan sliced into tasks
/sig:execute   # build it, committing as you go
/sig:verify    # run the suite, check it against the criteria
/sig:review    # quality, security, performance, simplification
/sig:ship      # pre-ship checklist, clean history, PR

You don't have to remember which apply. A SKETCH project skips /sig:review entirely; a SPIKE skips /sig:ship, because its output is a finding rather than a deliverable. The commands know.

06Day to day

CommandWhen you'd reach for it
/sig:statusWhere am I? Read-only, changes nothing.
/sig:resumeComing back after a break or a context clear. Re-orients you.
/sig:add "…"An idea arrives mid-flow. Captures it without derailing the phase you're in.
/sig:checkpointBefore clearing context or switching machines. Refreshes the saved state.
/sig:escalateThe work turned out bigger — or smaller — than you calibrated for. Moves the tier either way.
/sig:doctorSomething's off with the install itself.
/sig:updateShows your version against the latest, plus what changed in between.

There are 20 commands in total. These are the ones worth knowing on day one.

07One thing that trips people up

Keep .planning/ in git. It looks like scratch state and it is not — it's the project's memory. It's what lets a fresh session pick up where the last one stopped, and what makes /sig:resume worth running. Add it to .gitignore and you get a workflow with amnesia.
